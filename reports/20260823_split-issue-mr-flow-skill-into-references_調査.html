C-0. DDR i0113-01 が同じ材料を却下した理由は、本件にも当てはまるか

i0113-01 の却下文（原文）:

判定を HANDOFF.md の進捗表の有無で行う。…HANDOFF.md はリセット直後（flow-id 5-3 の直後）や ブランチ作成直後には空であり、フローの最初と最後で取りこぼす。また表の書式の変更に判定が引きずられる。
却下理由本件に当てはまるか理由
(1) フローの最初と最後で取りこぼす当てはまらない 失敗時の損失が非対称である。 i0113-01 の判定対象は「SKILL.md を読み直させるか」で、取りこぼすと手順が丸ごと失われる。 本件は「どの参照ファイルを名指しするか」で、取りこぼしても1行が出ないだけ。SKILL.md 本文は従来どおり読み直され、 参照ファイルは全体フロー表に明記されているので表から自力で辿れる。取りこぼす時期は具体的には flow-id 1-1〜1-5（進捗表は 1-6 で書かれる）と 5-4 のリセット後（5-5 / 5-6）で、E-1 のとおり 1-2 / 1-3 は start-resume.md、 5-5 は review-loop.md を要する時期である。「名指しが要らない時期と重なる」わけではない。 それでも採用してよいのは、上の非対称——出ないのは1行だけで表から自力で辿れる——が成り立つからである
(2) 表の書式の変更に引きずられる当てはまる。ただし解消できる 書式の正は既に update-handoff-progress.sh の parse_table_row_to_reply が持っている。 同じ正規表現を共有すれば二重管理にならない。 パースできなければ空を返す（fail-open）
結論 採用してよい。 ただし本件は i0113-01 の判定（対象ブランチか）を置き換えるものではなく、その上に足す。 この非対称の議論は DDR へ残す。

C-1 / C-2. 現在地flow-idの解決方式と縮退

個別調査計画が当初書いていた「awkで最初の [] 行を採る」方式は誤りだった。 本ブランチの HANDOFF.md は 1-5（人間の合意）が [] のまま 1-6 が [x] である。

単純な最初の[] : 1-5   ← 誤り
最後の完了の次  : 2-1   ← 正しい
縮退ケース入力返り値扱い
(i) 進捗表そのものが無いcleanup-task.sh のテンプレート空行を注入しない（fail-open）
(ii) 全行が []着手直後1-1先頭から始める
(iii) 穴あき・[-] 混在[x] 1-6 / [-] 2-1 / [-] 2-2 / [] 3-13-1正しい
(iv) 書式が想定と違うパースできない行空行を注入しない（fail-open）
結論 採用する方式は「最後の [x] または [-] の行より後に現れる、最初の [] の行」。 穴あきは例外ではなく既定である（非対話セッションでは人間担当のステップが [] のまま残り、ループ範囲も1周完了まで [] のまま）。
