ベースブランチ追従確認の差し込み地点と検知方法

実施日 2026-08-19 ／ 実施環境 Claude Code on the web（Linux, git 2.x, gh CLI 無し）

正文は reports/20260819_base-branch-sync-check_調査結果.md。本ページはその視覚化です。

結論

1. 前提は崩れていない

「コンフリクトは無いが遅れている」状態を検知する機構は、このリポジトリに1つも無い。

2. 判定は1コマンドで足りる

git rev-list --left-right --count origin/<base>...HEAD で behind・ahead 両方。変更ファイルは3ドット記法必須。

3. merge-base 無しで落ちる

3ドットdiff は fatal・終了コード128。set -euo pipefail 配下ではスクリプトごと停止するため事前判定が必須。

4. サマリ組み立て時は未fetch

issue-mr-resume が現在地サマリを作る時点ではまだ fetch されていない。そのまま behind を足すと古い参照を見て「遅れていない」と報告する。fetch は新スクリプト側の責務にする。

設計への反映（フェーズ3への申し送り）

A. check-base-sync.sh（新設）

  • --base / --head / --no-fetch。fetchは既定でこのスクリプトが行う（refspec形・fetchOk を出力）
  • behind・ahead は rev-list --left-right --count 1回
  • 変更ファイルは3ドット記法。その前に merge-base の有無を必ず判定

確かめられなかったこと

  • git bash（MSYS）実機での挙動。本調査は Linux 上。
  • 巨大リポジトリでの所要時間。rev-list --count は履歴長に比例するが未実測。
  • --no-fetch の有無による実測差。git の仕様から述べているだけ。
  • merge-base が shallow 境界の外にある場合の値。このリポジトリでは再現できなかったため、isShallow の出力で設計側から吸収する。
