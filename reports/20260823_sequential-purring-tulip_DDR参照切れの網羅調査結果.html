サマリ（結論の一覧）

  • リポジトリ全体で、実在しないファイルを指すDDRパス形式の参照は.gitignoreの2件のみ（28行目・40行目）。他に参照切れは無い。
  • issue本文の前提（「i00-13参照はissue #70で既に消えた」）は誤り。実際には28行目にまだ残っている。
  • 単純な正規表現走査だけでは大量の誤検知（テストフィクスチャ・コード例）が発生することが判明。「テストファイル除外」「コードフェンス内除外」「省略記法除外」の3フィルタで誤検知をゼロにできた。

実施条件（測った対象・環境）

対象: git ls-filesで取得したリポジトリ内の.md / .sh / .gitignore（バイナリ除く）。 正規表現 \.claude/docs/ddr/i[0-9]+-[0-9]{2}-[終端文字を除く任意文字]*\.md でDDRパス形式の参照候補を抽出し、 test -fで実在確認した。

確定した参照切れ（2件）

実ファイルはそれぞれi0000-13-...md、i0036-01-...md。

issue本文の前提との差分

前提の誤り issue本文は「i00-13参照はissue #70で既に消えた」としているが、実際には .gitignoreの28行目にまだ残っている（issue #70で削除されたのは別ブロックの .gemini/docs等9行のignoreパターンで、コメント行自体は別ブロックにあるため 削除されなかったと見られる）。

検出方式の設計

  1. 対象ファイル: git ls-filesの.md / .sh / .gitignore。
  2. .claude/scripts/test/配下は除外（テストの意図的な架空フィクスチャを含むため）。
  3. Markdownのコードフェンス内の行は除外（specのコード例を誤検知するため）。
  4. 正規表現でDDRパス候補を抽出（終端は空白・) ] " ' ` (のいずれか、.mdで終わることを要求）。
  5. ...または…を含む候補は除外（省略記法のため）。
  6. 残った候補について実在確認する。

置き場所は新規スクリプト.claude/scripts/src/check-doc-references.shとして独立させる方針。 比較検討した案（既存スクリプトへの追記2案）はいずれも目的の異なる処理を混ぜることになるため却下した。 実行タイミングは手動実行を基本とする（起動コストの規約に照らし自動組み込みは見送る）。

確かめられなかったこと

DDR以外（spec・rules等）への相互参照切れは調査対象外（全体作業計画でスコープ外と合意済み）。 今回の3フィルタ設計が他ドキュメントへの参照切れ検出にそのまま流用できるかは未検証。

設計への反映

フェーズ3で.gitignoreの2箇所を修正し、上記の検出方式に基づく check-doc-references.shと単体テストを実装する。フェーズ4で今回の設計判断を DDRとして記録する。

想定と異なった点

全体作業計画の時点では「パス形式に限定すれば誤検知を避けられる」と見込んでいたが、 実際にはパス形式に限定してもなお、テストフィクスチャとコード例という2種類の誤検知源が 残ることが分かった。これに対処する「テストファイル除外」「コードフェンス内除外」の 2フィルタは、計画時点では想定していなかった追加要件である。
