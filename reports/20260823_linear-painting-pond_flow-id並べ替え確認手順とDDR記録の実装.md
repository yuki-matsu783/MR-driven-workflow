### 4. 「変更しない」と宣言したファイルの検証

計画のやらないこと・受け入れ条件(3)で「`docs-workflow.md`本体・過去changelog・DDR本文は変更
しない」と宣言していたため、機械的に確認した。

当初`git diff <分岐点SHA> -- .claude/docs/spec/ .claude/docs/ddr/ | grep -c '^-[^-]'`で検証したが、
敵対的レビュー2回目で2つの不備が指摘された。(a) `docs-workflow.md`の実体は`.claude/rules/`配下で
あり、`.claude/docs/spec/` `.claude/docs/ddr/`だけを見る元のコマンドではその本体を検証していな
かった。(b) `grep -c '^-[^-]'`は削除された箇条書き行（diff上`-- item`となり2文字目が`-`で不一致）・
削除された空行（diff上`-`1文字のみで2文字に満たず不一致）を検出できない**盲点**があった
（合成diffで検証: 箇条書き1行・空行1行の削除が実際に起きたケースで、この方法は0件のまま検出
できなかった）。指摘を受け、走査範囲を`.claude/`全体へ広げ、検出方法を`git diff --numstat`の
削除列（2列目）へ置き換えた。

```
$ git diff --numstat 0aa9874d18032a9a85d5bc98075511fa11ce0cc3 -- .claude/
1	0	.claude/docs/README.md
122	0	.claude/docs/ddr/i0143-01-flow-id並べ替え時の確認手順をSKILL.mdへ明記しDDRで記録する.md
43	0	.claude/skills/issue-mr-flow/SKILL.md
```

3ファイルとも削除列（2列目）が0であることを確認した（新規追加した`i0143-01`・変更した
`README.md`・`SKILL.md`のいずれも追加行のみで、削除は無い）。`--numstat`の削除カウントが
実際の削除行（箇条書き・空行を含む）を正しく検出できることは、上記の合成diffによる自己検証で
確かめている。

<!-- 結論box -->
**結論**: 受け入れ条件(3)を満たしている。`.claude/`配下（`docs-workflow.md`本体を含む）・
過去changelog・DDR本文への意図しない変更は無い。

## 確かめられなかったこと

- 追記したSKILL.mdの節の実効性（次に実際にflow-idを並べ替える作業者が、この手順に沿って確認を
  行うかどうか）は、次の並べ替え作業が発生するまで確認できない。
- `origin/main`取り込み後の再確認（本ブランチが追加した記述のflow-id番号が、取り込み後の実際の
  番号と整合しているか）は、この時点ではまだ実施していない。**トリガーをflow-id 5-1に限定しない
  よう敵対的レビュー2回目で指摘を受けた**（`bash .claude/scripts/src/check-base-conflicts.sh`が
  `hasConflict`を偽と判定した場合、5-1はorigin/mainを取り込まずそのまま5-2へ進むため、
  「5-1で取り込む」という前提そのものが成立しないことがある）。実施タイミングは
  「ベースブランチ追従確認（start/resume/sync）または5-1のいずれかでorigin/mainを取り込んだ
  直後」と修正した（下記「残課題」も同様に修正済み）。
