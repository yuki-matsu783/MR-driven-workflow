create-commit.sh は本当に削除済みファイルを引数に取れないのか

検証日 2026-08-19 ／ git version 2.39.2.windows.1（git bash / MSYS, bash 5.2.12）／ 一時リポジトリ4本・計36ケースを実測

結論（3行）

① 前提が再現しない

git add -- <追跡済みの削除パス> は rc=0 で成功し、削除がステージされる。 issue本文の「削除済みパスを渡すと fatal」は、この条件では起きない。

② 実装案 -A は効かない

-A を付けても失敗ケースは1つも救われない。 さらに引数が空のときリポジトリ全体をステージするため、 安全側の性質を失う。

③ 真犯人は「回避策」自体

git rm で削除を先にステージしたパスを ラッパーへ渡すと fatal になる。issueが回避策と呼ぶ2段構えの手順が、失敗条件そのもの。

git add が did not match any files で落ちる条件

判定は「ワーキングツリーに存在するか」ではなく 「インデックスにエントリがあるか」。 両方に無いパスだけが fatal（rc=128）になる。

issue の実装案 git add -A -- "${files[@]}" の評価

効果: なし

  • 追跡済みの削除は -A なしで既にステージできる
  • fatal になる3ケースは -A でも同じく fatal
  • ディレクトリ指定時の差も観測されず（git add -- dir/ が削除も拾う）

副作用: 安全性の低下

引数が空のとき、git add -- は "Nothing specified, nothing added." で何もしないが、 git add -A -- は リポジトリ全体（pathspec 外の変更・未追跡ファイルを含む）をステージする。

受け入れ条件「無制限のステージングは構造的に不可能」を、引数バリデーション1枚だけに依存させることになる。

なお -A は pathspec と併用した場合スコープが限定される、という issue の前提自体は正しい （pathspec 外の other/ の変更は一切ステージされないことを確認済み）。問題は「効果が無い」ことと「空引数時の挙動」。

推奨する実装案: パスを3分類してから git add

外部コマンドは git ls-files -z と git ls-tree -r -z --name-only HEAD の 2回のみ（ループ内 fork なし。shell-script-style.md「外部プロセス起動のコスト」に適合）。 どちらも日本語パスを8進エスケープせずそのまま出力することを確認済み。

ADD

worktree に在る、または index にエントリがある

→ git add -- <ADD>（通常変更・新規・追跡済みの削除）

SKIP

worktree にも index にも無いが HEAD にはある

→ 既に削除がステージ済み。冪等にスキップして成功させる

UNKNOWN

どこにも無い（未追跡のまま削除・綴り誤り）

→ 何をどう直せばよいか分かる文言で エラー終了（タイプミス検知は維持）

declare -A in_index=() in_head=()
while IFS= read -r -d '' p; do in_index["$p"]=1; done < <(git ls-files -z -- "$@")
while IFS= read -r -d '' p; do in_head["$p"]=1;  done < <(git ls-tree -r -z --name-only HEAD -- "$@")
for p in "$@"; do
  if   [ -e "$p" ] || [ -n "${in_index[$p]:-}" ]; then add+=("$p")
  elif [ -n "${in_head[$p]:-}" ];                 then skip+=("$p")   # 既に削除がステージ済み
  else                                                 unknown+=("$p")
  fi
done
[ "${#add[@]}" -gt 0 ] && git add -- "${add[@]}"   # ← 空配列を渡さないガードが必須

実測（一時リポジトリ）: 4パス（変更済み1・追跡済み削除1・ステージ済み削除1・存在しない1）を渡して ADD 2件 / SKIP 1件 / UNKNOWN 1件に正しく分類でき、git add 後のステージ内容に pathspec 外の巻き込みは無かった。ADD が空（SKIP のみ）でも既に削除がステージ済みのためコミットは成立する。
