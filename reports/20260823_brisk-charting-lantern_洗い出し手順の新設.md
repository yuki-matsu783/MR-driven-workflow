### 1. 除外規定の書き換え

**照合文字列**: `` `.claude/scripts/`配下のスクリプト ``（1件・163行目）。

置換前:

```
`.claude/scripts/`配下のスクリプトは実装コードと
  同じ性質（単体テストを持つ等）を持つため対象に含めない（`【実装】`/`【実装反映】`側で扱う）。
```

置換後:

```
`.claude/scripts/`配下のスクリプトは実装コードと
  同じ性質（単体テストを持つ等）を持つため、**フェーズ3では**対象に含めない（`【実装】`側で
  扱う）。**フェーズ4で副産物として反映する場合は、`.claude/scripts/` `.claude/hooks/` 配下も
  AIアセットとして`【AIアセット反映】`で扱う**（下記「AIアセット反映の対象の洗い出し」）。
```

**2026-08-23 のユーザー判断**（`scripts` / `hooks` もAIアセットとして扱い、種別を
`【AIアセット反映】` へ揃える）に沿った形である。当初案の「除外の主語へ `.claude/hooks/` を

（issue #110 の判断であり、ユーザー判断の対象ではない）。書き換えたのは、その規定が
**フェーズ4の扱い**まで `【実装反映】` だと述べていた部分だけである。

### 2. 新節の追加（341行目〜、90行）

**挿入位置**: `## 全体フロー` 配下の h3 として、`### issueが大きすぎる場合の分割提案（issue #64）`
の直後・`### 計画と実施結果の分離（issue #87）` の直前。

**「下記」が本当に下記になっていることを実測した。**


参照元5箇所（82・87・131・134・167行目）はいずれも341行目より前にある。

**直前の節の係り先を壊していないことも確認した。** `### issueが大きすぎる場合の分割提案` の
末尾は「**分割することになった場合**」というラベル付きの箇条書きで終わっており、節全体にかかる
地の文を持たない（`.claude/rules/docs-workflow.md`）。

節の構成:

| 手順 | 内容 | 持たせたもの |
|---|---|---|
| 手順1 | 起点の列挙 | `worklog/` を入力にする。過去MRを遡らない |
| 手順2 | 4類型への分類 | **4列の表**（類型／意味／反映の向き／**証拠を要求するか**） |

**4類型の表は4列にした**（計画では3列としていた）。「反映の向き」（新規作成／訂正／追記／導線の
改善）を足したほうが、分類がそのまま次の行動に繋がるため。受け入れ条件が求める「4類型と、
再現性の証拠を要求する範囲が表で示されている」は、列が増えても満たしている。
