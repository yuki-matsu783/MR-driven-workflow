実施した内容と結果

1. 敵対的レビュー（1回目・計画レビュー）で判明した設計上の欠陥

個別作業計画に対する敵対的レビューで8件の指摘を受けた。主要な4件（major）は次のとおり。

  • _CP_PREFIX_WORDS（sudo/if/timeout等）を通るとstickyが次のセパレータまで解除されず、sudo cat <path> / if grep -q x <path>; then... / timeout 5 grep -rn x <path> のような、無関係なコマンドの引数に現れるだけのケースで誤発火する
  • ${VAR}/path のようなパラメータ展開の直後で誤発火する（{/} を人工的な空白挿入の対象に含めていたため）
  • eval/bash -c 経由の保守的フォールバックが設計に無く、既存の部分一致より検知が後退する
  • 3段ガードをmain()内で定義する案は、sourceしてmain()を実行せずis_issue_create_callを直接呼ぶ既存テスト4件を落とす
結論 計画を改訂し、いずれも実装へ反映した（下記2.）。

2. 実装した修正

_cp_scan_tokens_for_scriptでは、prefix word通過後は「次の非オプション・非代入トークンを実コマンドとして1回だけ判定し、そこでコマンド位置を終える」設計にした。人工的な空白挿入から{/}を除外した（ブレースグループ{ cmd; }は素の空白分割で判定できるため検知は失われない）。command_invokes_git_subcommandと同じ_CP_OPAQUE_FOUNDフォールバックを追加した。3段ガードはトップレベルで一度だけ確定させる設計に変更した。

$ source .claude/hooks/lib/CommandPosition.sh
$ command_invokes_script 'sudo cat .claude/scripts/src/create-issue.sh' 'create-issue.sh'; echo $?
1   # miss（修正前は 0 = hit だった）
$ command_invokes_script 'cat ${REPO}/.claude/scripts/src/create-issue.sh' 'create-issue.sh'; echo $?
1   # miss（修正前は 0 = hit だった）
$ command_invokes_script 'eval "bash .claude/scripts/src/create-issue.sh"' 'create-issue.sh'; echo $?
0   # hit（フォールバックにより検知）
結論 敵対的レビューの再現コマンドがいずれも意図どおりの結果（miss/hit）になることを実測で確認した。
