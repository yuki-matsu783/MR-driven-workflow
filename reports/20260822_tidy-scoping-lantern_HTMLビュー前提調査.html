Q1. 外部依存方式 — TailwindCSS CDN か、自己完結CSSか

判断軸（決定規則）

到達性のうち「閲覧可用性」は主根拠にしない／「検証可能性」は外さない レビュアーがブラウザでHTMLを開けるかは環境ごとに異なり、到達不可という事実自体は DDR i0141-01 が既に記録している。それを知ったうえで同DDRは reports/ の通常HTMLを CDN方式に据え置いた。同じ事実から逆の結論を出すことになるため、閲覧可用性は根拠から外す。
一方、書いた本人が成果物の表示を1度も確認できないまま納品することになるかは別の問題であり、 i0141-01 もこれを canvas を分ける理由の1つに挙げている。2つは同じ curl の実測に由来するが、 問うている対象が違う（前者は読み手、後者は書き手）。
  1. i0000-11（reports/*.html にCDNを選んだDDR）の根拠が、テンプレート化後も成り立つか。
  2. i0141-01 が canvas を分けた実際の理由が、新設テンプレートにも当てはまるか。
決定規則と閾値 1・2 のいずれかが「CDN不利」と出たら自己完結CSSを採る（どちらも成り立つなら現行のCDN方式を維持する）。 軸2の閾値は「3つの理由のうち1つ以上が当てはまれば CDN不利」とする。canvas は3つすべてが当てはまって 分離されたが、i0141-01 は「3つ揃ったから」とは書いておらず閾値を定めていない。ここでは テンプレートが一度作れば長く使われる成果物であることを理由に、1件でも不利が残るなら避ける側へ倒す。

軸1: i0000-11 の根拠はテンプレート化後も成り立つか

i0000-11 の根拠テンプレート化後
(a) ビルドステップ無しで整形できる 成り立つ ただし自前CSSでも同じ。<style> に直書きするだけでビルドは要らない。 i0000-11 が却下したのは「Tailwindをビルドして同梱する」案であって、CSSを手で書く案ではない
(b) 出力トークン量と表現力のバランスが良い 成り立たない テンプレート化後、CSSを書くのはテンプレートを1回作るときだけ。 生成側はコピーして本文を差し替えるので、生成のたびに節約されるトークンは無い

根拠(b)が失われる一方、CDN依存のコスト（オフライン・遮断環境で崩れる）は生成のたびに残る。 → 軸1は「CDN不利」。 なお i0000-11 は「テンプレート化は行わず、複数件運用してから判断する」とも決めており、 本issueはその保留を解く作業である。

使わなかった論法（循環するため） reports/REVIEW-POINTS.md:31 は「自己完結しているか（TailwindCSS CDN以外の外部依存・ ローカル参照が無い）」と書いており、CDNは例外として明示的に許可されている。したがって 「レビュー観点の自己完結を満たせない」は根拠にならない（この観点自体が現行方式に合わせて書かれているため）。 方式を変えるなら、この行の方を改める（Q5-1 #12）。

軸2: canvas を分けた理由は新設テンプレートにも当てはまるか

i0141-01 の理由新設テンプレートでの成否
ユーティリティクラスの適用範囲外のスタイル制御（動的z-index・カスタムkeyframes・属性セレクタ）が主体 当てはまらない 一覧・表形式は見出し・表・コードブロック・注意ボックスが中心で、Tailwindの守備範囲に収まる
存在しないクラスが黙って無視され、実行時まで誤りに気づけない 当てはまる テンプレートは一度作れば長く使われるため不利に働く
CDN遮断環境ではブラウザ実機検証ができない 当てはまる（下記の実測）。これは閲覧可用性ではなく検証可能性の問題であり、上記の除外対象ではない

→ 軸2も「CDN不利」（3件中2件が当てはまり、閾値1件を超える）。

閲覧可用性由来の分を仮にすべて外しても結論は変わらない 3行目を丸ごと除いた場合でも2行目（存在しないクラスが黙って無視され、実行時まで誤りに気づけない）が残り、 閾値1件を満たす。2行目は curl の実測とは独立で、Tailwind の仕様そのものに由来する。

補強材料: CDN到達性の実測

$ curl -sS -o /dev/null -w '%{http_code}\n' --max-time 15 https://cdn.tailwindcss.com
curl: (56) CONNECT tunnel failed, response 403
000
$ curl -sS -o /dev/null -w '%{http_code}\n' --max-time 15 https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.min.js
curl: (56) CONNECT tunnel failed, response 403
000
結論の主語と、測った環境 この結論の主語は「この実行環境のプロキシ経由での到達性」であり、cdn.tailwindcss.com の可用性ではない。 403 を返しているのはエージェントプロキシである。測った環境は Claude Code on the web のリモート実行環境1つ（2026-08-22）で、 ユーザーの常用環境やレビュアーのブラウザからの到達性は、この測定からは言えない。 同じ遮断は issue #141 対応時にも観測されているので、この環境では再現性がある。
結論 新設する2テンプレートは外部依存を持たない自己完結CSSで作る（軸1・軸2ともCDN不利）。 あわせて、方式を「TailwindCSS CDN方式」と書いている既存記述（Q5-1）を、テンプレートを正とする書き方へ改める。 i0141-01 が置いた限定は本issueで上書きされるが、canvas形式についての決定そのものは覆らない。
issue本文との差異（要確認事項） issue #54 本文「期待する動作」は reports.template.html を「TailwindCSS CDN通常版」と書いている。 本調査の結論はこれと異なる。 受け入れ条件には方式の指定が無いため受け入れ条件は満たせるが、 本文の記述からは外れる。レビューで差し戻しがあれば方式を戻す。
確かめられなかったこと
  • 他環境でCDNが到達可能かどうか。本結論は「到達できない環境が実在する」ことを軸2の一部として用いており、 「どこからも到達できない」ことは主張していない。
  • 自己完結CSSにした場合の見た目の水準。テンプレートを書いてブラウザで確認するのはフェーズ3の作業。

Q8. HANDOFF.md のテンプレート外だしを本issueへ含めるか

(1) frontmatterの type の判断が増える当てはまらない HTMLはfrontmatterを持たない（Q7）
(2) index.jsonl にテンプレート自身が載る当てはまらない（Q7）

フェーズ4（設計反映）へ持ち越すこと

  1. Q1の決定はDDRに残す。「reports/*.html の外部依存方式を、テンプレート化を機に CDNから自己完結CSSへ変える」は、i0000-11 の根拠(b)が成り立たなくなったという 既存の意思決定の前提の変化に基づく判断であり、却下案（CDN維持）を持つ。 同じDDRで「バンドルリソースのディレクトリ名は templates/ ではなく assets/」（Q9）も扱う。
  2. i0000-11 と i0141-01 の frontmatter へ note を足す。 どちらも本文は変更しない（DDR本文は不変）。i0000-11 は方式が変わったこと、 i0141-01 は「通常の一覧・表形式HTMLは引き続きCDN方式」という限定が上書きされたことを1行で添える。 status: superseded は使わない——決定の一部だけが変わったケースであり、 markdown-frontmatter.md「DDRのnote」の類型そのものである。

この調査自身の限界

  • Q1 の実測はこの実行環境1つでの観測であり、結論の主語をそこへ限定している。
  • Q2 の実例は標本3件であり、母集団（マージ済みPR全件）を走査していない。 plans/*.html の実例は存在しないため、plans側テンプレートの必須／任意は実例による裏付けを持たない。
