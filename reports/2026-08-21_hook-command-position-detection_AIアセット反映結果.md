# AIアセット反映結果: hook誤検知の回避策の書き分け

- issue: [#53](https://github.com/yuki-matsu783/MR-driven-workflow/issues/53)
- 個別反映計画: `plans/【AIアセット反映】hook誤検知の回避策を実装に合わせて見直す.md`

## 結論: 回避策は消さず「いつ必要か」を書き分けた

計画の時点で見立てたとおり、**回避策を一律に削除できる状態にはなっていない**。判定が部分一致へ
縮退する場面が残るためである。5ファイルすべてで、削除ではなく条件付けを行った。

| まだ部分一致で判定される場面 | 対象のhook |
|---|---|
| `.claude/settings.json` の `if: "Bash(git push*)"` の照合 | push検知の2本 |
| 1行が8192バイトを超えるコマンド | 3本すべて |
| `eval` / `bash -c` など静的に読めない実行体がコマンド位置にある | 3本すべて |
| bash 4.3未満・判定ライブラリの配布漏れ・構文エラー | 3本すべて |

**この表を4ファイルへ同じ形で置いた**（`git-workflow.md`・`ai-command-style.md`・
ルート `REVIEW-POINTS.md`・`command-position.md`）。二重管理にはなるが、読み手が
「いま自分は連続させてよいのか」を判断する場所がそれぞれ違うため、参照だけでは足りないと判断した。

## あわせて記録した運用上の発見

### 1. MCPの返信投稿が本文を無言で切り捨てる

`mcp__github__add_reply_to_pull_request_comment` の `body` に**不等号で始まる語**が含まれると、
その手前で本文が切り捨てられて投稿される。**エラーは返らず、`id` と `url` を含む正常な結果が
返る**ため、投稿後に読み返すまで気づけない。

flow-id 3-9 の返信で実際に踏み、記号を避けた補足を追加投稿して対処した。
`.claude/skills/issue-mr-flow/SKILL.md` へ、対処（投稿後に末尾を確認する）と予防（記号そのものを
書かず語で説明する）を書いた。

### 2. `post-issue-create-notice.sh` の誤発火を実地で踏んだ

本作業中、コマンド文字列にそのスクリプトのファイル名が**語として**含まれただけで、起票検知hookが
**3回**発火した（いずれもissueは起票していない）。1回目は本レポート群の編集中、2回目は本節を
書いている最中、3回目はその実例を「2回」から書き直している最中である。**この節に触れるたびに
発火する**という形で、部分文字列マッチの性質がそのまま現れた。

これは issue #53 が名指ししておらずスコープ外とした**4本目のhook**であり、同じ部分文字列マッチの
構造がそのまま残っていることの実証になった。`command-position.md` の「未決定事項・懸念点」へ
非対称であることを記載済みで、**別issueとして切り出す候補である**（本作業では対応しない）。

## やらなかったこと

- **回避策の一律削除。** 上表のとおり必要な場面が残る。
- **`.claude/settings.json` の `if` フィルタの変更。** 発火が増える方向で本issueと逆向き。
- **`post-issue-create-notice.sh` の判定差し替え。** スコープ外（上記2）。
- **`.claude/rules/powershell-encoding.md`。** 今回の変更と無関係。
