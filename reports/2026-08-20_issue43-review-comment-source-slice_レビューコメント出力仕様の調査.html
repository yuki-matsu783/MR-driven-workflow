レビューコメント取得APIの返却フィールドと断面

diffHunk廃止・断面ソースの前後行スライス化にあたっての調査結果（正文は同名の .md）

結論

1

正規化JSONは GitHub / GitLab 双方から埋められる。位置は path＋line＋originalLine＋isOutdated、断面は sha の1キーで表現できる。

2

断面のblobは shallow clone でもローカルで解決できた（depth 190 で実測）。保証は無いため事前判定＋4段階のフォールバックを置く。

3

行数だけでは上限にならない。同一ファイルの ±10行で 684B〜8,971B（13.1倍）の開き。バイト上限の併用は必須。

D. 上限制御の実測

.claude/rules/docs-workflow.md（131行 / 18,441B、平均141B/行）で指摘行を変えて ±10行のバイト数を測った。

既定値: 前後行数

10 行

指摘行を含め最大21行。REVIEW_SOURCE_CONTEXT_LINES で上書き可。

既定値: バイト上限

2,000 B

最大 8,971B を約1/4.5へ。スレッド10件でも約20KB。REVIEW_SOURCE_MAX_BYTES で上書き可。

C. 断面取得のフォールバック（4段階）

1

ローカルのblob

git cat-file -e <sha>:<path> で判定 → git show <sha>:<path>。出力への注記なし。

2

プロバイダ別ファイル取得API（同じ断面）

GitHub gh api repos/{owner}/{repo}/contents/<path>?ref=<sha>（.content はbase64）／GitLab glab api projects/:id/repository/files/<encoded>/raw?ref=<sha>。注記なし。

3

現HEAD

git show HEAD:<path>。出力へ 「断面 <sha> を取得できず現HEADを表示」 を明示。

4

取得不可

「（ソース取得不可）」を添える。コメント本文だけは必ず出す（ソースが取れないことでコメントまで落としてはならない）。

$ git rev-parse --is-shallow-repository true $ wc -l .git/shallow 10 .git/shallow $ git rev-list --count HEAD 190 $ for c in 4b8fb20 d48b698 846c536 88e03b9; do git cat-file -e "$c:.claude/rules/docs-workflow.md"; done → 全て OK（shallowでも切断点より新しいcommitのblobは存在する）

副次的に判明した不具合

GitLabリポジトリでは未解決レビューコメントが常に0件と表示される

行頭ラベルが GitHub は [review unresolved threadId=…]、GitLab は [unresolved threadId=…] と非対称である。session-start.sh:169 は ^\[review unresolved threadId= で数えているため、GitLab側は1件も一致しない。

整形を共通化すれば副次的に解消する。（issue本文の項目5「実装の非対称」の具体的な帰結）

A. MCP経路の制約（実測）

PR #37 に対し mcp__github__pull_request_read (method="get_review_comments") を実行した結果:

{"review_threads":[{"id":"PRRT_kwDOT7UgWc6aS9t8","is_resolved":true,"is_outdated":true, "is_collapsed":true,"comments":[{"body":"…","path":"plans/【設計反映】…md", "author":"yuki-matsu783","html_url":"…#discussion_r3808796698"}],"total_count":2}],"totalCount":1}

返る

is_resolved / is_outdated / is_collapsed / path / html_url

返らない

line / original_line / commitのsha

MCP経路ではソーススライスを作れない。これは GitHub MCPサーバー側の制約であり本issueでは変えられない。SKILL.mdの対応表へ注記するに留める。

確かめられなかったこと（【未検証】）

  • GitHub GraphQL の実フィールド：この環境に gh が無く実行できない（get_vcs_access_mode が mcp）。公開スキーマに基づく設計であり、実装側は「null で返っても壊れない」形にする。gh のある環境で comments を1回実行すれば確認できる。
