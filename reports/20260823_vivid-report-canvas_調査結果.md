## Q2. 現テンプレートの節ごとの維持／移動／改修／新設

**節名（見出しテキスト）は既存の全節で維持する。** Q1のとおり、節名を参照するドキュメントが
3系統（planning.md・REVIEW-POINTS・spec changelog）あり、名前を変えると矛盾が波及する。
変えるのは**並び順・表現・内部構造**のみ。

| 節（現行順） | 判定 | 内容 |
|---|---|---|
| ヘッダ帯（.band） | 維持＋小改修 | メタ情報はそのまま。結論件数のチップ（良N・注意N・問題N）を追加 |
| 目次（nav.toc） | 維持 | 新しい節順に追随 |
| **重点レビュー依頼** | **新設（必須・冒頭）** | 3段階（特に見てほしい／承認が欲しい／細かいレビューは不要）の枠。各項目から該当章へリンク |
| サマリ（結論の一覧） | **改修（必須）** | 表形式→結論カードのリスト。1件＝記号＋短い結論＋章リンク。性質（良／注意／問題）ごとに色分け |
| **確かめられなかったこと** | **前半へ移動（必須）** | サマリ直後に一覧（1行1件＋関連章リンク）。詳細は各章内の専用callout（`.unverified-detail`）で語る |
| 実施条件（測った対象・環境） | 維持（任意） | 位置は「確かめられなかったこと」の後 |
| 実施した内容と結果 | 改修（必須） | 各h3章に (1) 章ID（`f1`〜連番） (2) 結論の性質チップ (3) 必要なら「確かめられなかったこと（詳細）」callout |
| 設計への反映 | 維持（必須・後半のまま） | 位置・意味とも変更なし |
| 想定と異なった点 | 維持（任意） | 変更なし |
| 残課題 | 維持（任意） | 変更なし |
| フッタ | 維持 | 変更なし |

- **受け入れ条件のうち既に部分的に満たされているもの**: サマリ節のコメント「各行から本文の
  該当節へリンクする」が既にあるが、**マークアップの形（リンク先IDの規則）が無く指示止まり**
  だった。新テンプレートでは結論カード自体に `href="#f1"` の形の実マークアップ例を持たせ、
  コメント指示との二重化を防ぐ（コメントは「なぜこの形か」の説明に置き換える）。
- **アンカー設計**: 章IDは `f1` `f2` …の連番（結論カード・未確認一覧・重点レビュー依頼の
  3箇所から同じIDを参照する）。既存の節ID（`summary` `unverified` `conditions` `findings`
  `next` `surprises` `todo`）は維持し、新設節は `review-focus` とする。アンカー移動時の
  位置ずれ対策として `section[id], h3[id] { scroll-margin-top: 16px; }` を追加する
  （固定ヘッダは無いため小さめで足りる）。
- プレースホルダ検査手順（`grep -c '<!-- ここに書く'`）・自己完結性・md/html併存は変更しない。

## Q3. 色トークンの設計

| 性質 | トークン | ライト | ダーク | 記号・ラベル |
|---|---|---|---|---|
| 良かった | `--good` / `--good-soft`（**新設**） | `#1d4ed8` / `#e7edfd` | `#8ab4f8` / `#17233a` | ◎＋「良」 |
| 気になる | `--warn` / `--warn-soft`（既存を流用） | `#a35a00` / `#fdf1e0` | `#f0b866` / `#2a2113` | △＋「注意」 |
| 悪かった | `--stop` / `--stop-soft`（既存を流用） | `#b3261e` / `#fdecea` | `#f2857c` / `#2b1614` | ✕＋「問題」 |

- **`--good` を新設し、`--accent`（リンク・見出しの青 `#2563eb`）とは分離する。** 同じ青系だが、
  リンク色と結論色を同一トークンにすると片方だけ調整できなくなる。視覚上は「濃い青の
  塗り（badge）＋薄い青の地」で、下線付きテキストのリンクと区別できる。
- **`--ok`（緑）は「決めたこと・手順の成功」を表すboxトークンとして存続させる。** 結論の性質
  （良かった）とは役割が異なることをテンプレートコメントに明記する（緑を結論の色に使わない。
  issueの指定は青であり、緑と青の併用は「良かった」の表現が2系統に割れるため）。
- **色だけに依存しない**: 記号（◎△✕）と1文字ラベルを必ず併記する（色覚多様性への配慮）。
  重大度の並び順も常に「問題→注意→良」（悪い話が先）で固定し、位置でも判別できるようにする。
- ダークモードは既存の `@media (prefers-color-scheme: dark)` ブロックへ `--good` 系2値を
  追加するだけで維持できる。

## Q4. フェーズごとの読み替えの引き継ぎ

現行テンプレートの「フェーズごとの読み替え」コメントを次のとおり更新する。

| 節 | 調査(2-6)・作業(3-6) | 反映(4-6) | 統括(5-4) |
|---|---|---|---|
| 重点レビュー依頼 | そのまま使う | そのまま使う | 「マージ判断で最後に見てほしい点」として読み替える |
| 確かめられなかったこと（前半の一覧） | そのまま使う | そのまま使う | **残っている**未確認事項だけを書く（従来どおり水増ししない） |
| 設計への反映 | そのまま使う | 「反映しきれず次のissueへ回したもの」（従来どおり） | 従来どおり |

「重点レビュー依頼」は全フェーズで意味が通る（レビュー往復を前提とするフローのため、
どのフェーズのレポートにもレビュアーが存在する）。統括のみ読み替えコメントを添える。
