実施した内容と結果

1〜2. CR の入口と出口

当初は出口だけを想定していたが、入口も同じ根の問題だった。

箇所何が起きるか対処
入口: agents/*.md の読み込みmapfile は改行だけを区切りにするため、CRLF では1行目が $'---\r' になり「frontmatter がありません」で落ちるmapfile 直後に ${lines[i]%$'\r'}
出口: settings.json の書き出しWindows native jq が標準出力へ CR を付ける。.gemini/settings.json だけが CRLF になり --check が環境で食い違うconvert_settings … | tr -d '\r' > …

.gitattributes の配布行が eol=lf を保証するのは .sh だけで、.md は配布先の core.autocrlf 次第で CRLF になりうる。配布行は増やさずスクリプト側で吸収した（配布先の .gitattributes へ追記される行なので、影響がこのリポジトリに閉じないため）。

結論 検証は スタブ jq（sed '$!s/$/\r/'）を PATH 先頭へ置いて行った。スタブ自身が実際に CR を付けることも同じテストで表明している——付けないスタブなら、CR 検査は無条件に通ってしまう。

3. ローカル設定の除外

計画は「.gitignore へ追加する」と書いていたが、実際には既に入っていた（main の PR #158 が OTel 対応で追加済み）。残っていたのは配布先側で、install-to-project.sh の ignore ルールと commit スキルのフィルタへ足した（前者が無いと --exclude-standard が落とせず、後者が無いと配布先でコミットに混ざる）。

COPY_EXCLUDED_PREFIXES へは足していない（計画どおり）。除外の定義が2箇所へ分かれるほうが危うい。テストでは「除外できている」だけでなく、ignore されていない未追跡ファイルは載ることも併せて表明した（前者だけだと、未追跡が全部落ちていても通ってしまう）。

5. read -d '' の実機計測

main が先に片付けていた。 PR #162（issue #159）が .claude/rules/shell-script-style.md へ「1バイトずつ read(2) する／この特性自体は未計測」という注意を既に入れていた。残っていたのは「ではどう測るのか」だけなので、同じ節へ計測手順を足した（ペイロード3種／空hookをベースライン／同一セッション内で連続測定／判断は絶対値でなく差で行う）。

置き場所は計画が言っていた .claude/docs/spec/ ではなく .claude/rules/ にした。注意そのものが既にそちらにあり、手順だけを別ファイルへ置くと、読む人が両方を突き合わせないと判断できなくなるためである。

この結果が言っていないこと コードは変えていない。「測れないから現状維持」であって「測ったうえで現状維持」ではない。 Linux の fork/exec は git bash より桁で速く、fork が高い側と syscall が高い側のどちらへ倒れるかがそもそも変わるため、この環境での計測は結論にならない。

6.（新規）前置フィルタが超集合でなかった

上の5の注記を書いている最中に、自分で踏んだ。「push系2本は判定本体がコマンド位置ベースなのでバックスラッシュ除去は要らない」と書こうとして根拠を確かめたところ、偽だった。

cmd=git push       精密=1 前置=1
cmd=git pu\sh      精密=1 前置=0   ← 取りこぼし
cmd=git pus\h      精密=1 前置=0   ← 取りこぼし

git pu\sh は精密判定では push と読まれるが、hook が受け取る生JSONには pu\\sh としか現れないため *push* に一致しない。さらに git pu\<改行>sh は JSON 化すると pu\\\nsh になり、バックスラッシュ1文字だけの除去では punsh になってやはり取りこぼす。

これが意味すること issue #159 が commit 側で塞いだのとまったく同じ穴を、push 側へ開けたまま出していた。 しかも T11 のテストは「超集合であること」を主張していたのに、ケース一覧にバックスラッシュが1件も無かったため通っていた。主張とケースが噛み合っていないテストは、通っていても根拠にならない。

対処は block-direct-git-commit.sh と同型で、判定を純粋関数 raw_hints_at_git_push へ切り出し、JSON 文字列エスケープの2文字シーケンスをまとめて除去してからブラケット式で比較する（${var,,} は使わない）。2本の実装が同一であることもテストで固定した。ケースを4件足し、併せて prefilter_passes の写経をやめて実装を source して呼ぶ形へ変えた。
