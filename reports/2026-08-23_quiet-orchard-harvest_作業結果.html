実装の要点

  • scan の出力: {"schemaVersion":1,"targets":[...]}。配布先単位のエラー隔離（読めない配布先は error レコード、manifest は [ -s ]→jq -e '(.schemaVersion == 1) and ((.files | length) > 0)' の順で検証し、妥当な JSON でも .files が空・レコードを1件も読めない場合は縮退へ倒す——通常経路へ進むと全ファイルを added と誤報するため）。エラー隔離は set +e; ( set -e; scan_one_dest ); rc=$?; set -e の形——( f ) || rc=$? は errexit の一時停止がサブシェル内部へ伝播し内部失敗が素通りする（bash 5.2.21 で実測）。
  • 分類: modified は層・strategy 別（core=LF正規化sha256／merge/lines-marker=LF正規化後の全体sha256／merge/json-keys=キーごとの jq -c getpath 出力のsha256）。deleted は core/merge 限定で、本家HEADにも無いものは removedUpstream（収穫対象外の別枠）。added は配布先 dist-layers.json の自前 pathspec 照合＋gitignorePattern 照合（自前実装のみ・check-ignore 不使用）＋機構生成物（manifest 自身・*.bak）の明示除外。merge の strategy は明示分岐し、未知・欠落・keys 空は「変更あり」側へ倒す。縮退モードのレコードも emit_record 経由で出し、git 配布先なら判断材料が埋まる。
  • conflict: core かつ base 解決可のときだけ git merge-file で事前判定（0=clean／1〜127=conflict／それ以外=unknown）。-dirty 付き記録SHAは -dirty を落として 3-way を実行し baseApproximate=true を立てる。merge 層と dist-layers.json は 3-way 対象外。
  • merge3 の終了コード: 0=衝突なし／1=衝突あり／2=base取得不可で2-wayへ縮退／3=その他エラー（層を判定できない場合のフェイルクローズを含む）／4=3-wayの対象外（merge 層・seed 層・dist-layers.json）。層の判定は manifest の .files[].layer を第一情報源にする。
  • git 起動の一括化: ls-tree 1回・log --diff-filter=D 1回・log --name-only 1回（awkで畳み込み）・縮退時の本家HEAD展開は git archive | tar 1回（終了コードと展開結果の非空を明示検査）。2本の git log には -c core.quotepath=false を付け（非ASCIIパスの突き合わせ空振り防止）、削除履歴は --no-renames で改名の旧パスも拾う。ファイル数比例の起動は「core かつ modified」に限定した git show と merge-file のみ。
  • 読み取り専用: 書き込みは mktemp の一時領域のみ。git は読み取り専用サブコマンド（show / cat-file / ls-files / ls-tree / log / rev-parse / archive / merge-file）に限定。
