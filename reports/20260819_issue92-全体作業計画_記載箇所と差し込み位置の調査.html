issue #92 / フェーズ2〈調査〉 / 2026-08-19

全体作業計画へのフェーズ必須化 — 記載箇所と差し込み位置の調査

「調査・反映の枠を必ず残す」ルールを、どのファイルのどの位置へ、既存記述と矛盾しない形で書けるかを確定した。

1. 現状の空白

SKILL.md（flow-id 1-4・計画の2階層構造）

規定しているのは「planツールで作る」「出力先」「既にあれば作らない」「issue分割の判定」の4点のみ。計画の中身（どのフェーズを節として置くか）は未規定。

docs-workflow.md（進捗記号 [-]）

「フェーズ単位・ループ範囲単位でまとめて」という粒度の規定のみ。いつ決めてよいか（タイミング）が無い。

実例: 直近の issue #39 の HANDOFF.md は、着手時点で flow-id 1-4/1-5 とフェーズ2の全行が [-] になっていた。

2. 差し込み位置の判定

候補位置直前の要素判定
全体フロー表の直後（### 計画の2階層構造 の直前） flow-id 表の最終行 採用（表の直後で係り先が変わらない）
「計画の2階層構造」節の末尾 HANDOFF更新に関する地の文・箇条書き 不採用（issue #64 と同じ形）
「issueが大きすぎる場合の分割提案」節の末尾 分割時の運用に関する箇条書き 不採用（同上）

3. 検出した矛盾（要調整）

全体フロー節の一文「フェーズ1,4,5についてはこのフローを利用する際は必ず実施する」は、issue #92 の「反映対象が無ければ flow-id 4-1 でスキップ判断してよい」と表面上ぶつかる。

整理: フェーズ4は必ず通る（4-1で反映対象を洗い出す）／洗い出した結果が空なら以降をスキップしてよい。

4. フェーズ3への引き渡し

  1. SKILL.md の全体フロー表の直後へ ### 全体作業計画に必ず含めるフェーズ（issue #92） を新設する。
  2. 全体フロー表の直前の一文と flow-id 1-4 の行へ、新節への参照を足して矛盾を解消する。
  3. docs-workflow.md の [-] 段落の直後へ「[-] を決めてよいタイミング」を追記する。
  4. 反映（フェーズ4）の見込み: spec の仕様節・## 影響範囲、DDR 0040、README のDDR一覧。
