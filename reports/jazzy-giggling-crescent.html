post-push-save-logs.sh の Gemini CLI / Claude Code 自動判定化

調査結果まとめ（2026-08-18）

現状

  • .claude/hooks/post-push-save-logs.sh はどちらのCLIのhooksにも未登録で、現状発火しない。
  • 内部は tool_name で run_shell_command（Gemini CLI）と Bash/PowerShell（Claude Code）を判定できる下地があるが、ログ探索ロジックはGemini CLI構造専用。
  • logs/ は .gitignore 未登録（commitスキルの除外リストのみ存在）。

調査結果サマリ

① エンジン判定

tool_name を一次判定に使う。両CLIの値集合は重複しないため機械的に一意判定できる。環境変数はプロジェクトルート特定のフォールバックとして併用。

② Claude Code側ログ収集

UsageTracking.sh の _usage_sync_session_logs パターン（メイン transcript ＋ subagents/agent-*.jsonl + .meta.json）を転用する。

③ Claude Code側hook登録

.claude/settings.json の PostToolUse へ既存2エントリと同じパターン（matcher + if フィルタ）で追加登録できる。

④ Gemini CLI側hook登録

PRレビューでリポジトリオーナーから.gemini/settings.jsonの完成形が提示された。SessionStart/BeforeTool/AfterTool一式（既存の.claude/hooks/*.sh全部）をまとめて配線する方針に拡大。

⑤ .gitignore

/usage/ と同様に /logs/ を追記する方針。

⑥ 検証方法

tests/ は未導入のため、bash -n 構文チェック＋疑似hook入力JSONによる手動シミュレーションで代替する。

.gemini/settings.json hooks設定（PRレビューでの確定版）

{
  "hooks": {
    "SessionStart": [
      { "matcher": "startup|resume|clear", "hooks": [
        { "name": "session-start", "type": "command",
          "command": "bash \"${GEMINI_PROJECT_DIR}/.gemini/hooks/session-start.sh\"", "timeout": 30000 }
      ] }
    ],
    "BeforeTool": [
      { "matcher": "run_shell_command|Bash|PowerShell", "hooks": [
        { "name": "block-direct-git-commit", "type": "command",
          "command": "bash \"${GEMINI_PROJECT_DIR}/.gemini/hooks/block-direct-git-commit.sh\"", "timeout": 10000 }
      ] }
    ],
    "AfterTool": [
      { "matcher": "run_shell_command|Bash|PowerShell", "hooks": [
        { "name": "post-push-usage-report", "type": "command",
          "command": "bash \"${GEMINI_PROJECT_DIR}/.gemini/hooks/post-push-usage-report.sh\"", "timeout": 20000 },
        { "name": "post-push-compact-prompt", "type": "command",
          "command": "bash \"${GEMINI_PROJECT_DIR}/.gemini/hooks/post-push-compact-prompt.sh\"", "timeout": 20000 },
        { "name": "post-push-save-logs", "type": "command",
          "command": "bash \"${GEMINI_PROJECT_DIR}/.gemini/hooks/post-push-save-logs.sh\"", "timeout": 20000 }
      ] }
    ]
  }
}

出典: PR #5 レビューコメント（リポジトリオーナー提示）。当初のWeb一次情報 （Hooks reference, Writing hooks, Shell tool） は大枠（AfterTool + matcher + 単一シェル文字列command）の裏付けとして使う。

未検証・スコープ外とした懸念

GitHub Issue #20258 によれば、現行Gemini CLIではサブエージェントが親と同じセッションIDで動作するとの報告があり、既存スクリプトが前提とする「<session_id>/ ディレクトリにサブエージェント専用ログがある」という構造と実態がズレている可能性がある。

これは既存のGemini CLI分岐ロジック自体の問題であり、今回のissue（Claude Code対応の追加）のスコープには含めない。動作を変更せずそのまま残し、コードコメントに既知の懸念として記録するに留める。
