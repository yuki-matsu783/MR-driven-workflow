# 実施結果: HANDOFF進捗表の連結表記を廃止し周回数をヘッダへ集約する（issue #58）

対象: issue #58 / PR #93（2026-08-19）。個別作業計画:
`plans/【設計】【実装】HANDOFF進捗表のループ周回数をヘッダ行へ明示する.md`

## 結論

レビュー往復の周回数を、進捗表の反復記号（`[x][x][]`）ではなく **`HANDOFF.md` ヘッダの1行**
（`- 現在のループ: 3-6〜3-9 の3周目（進行中）`）だけで持つようにした。進捗表はループ範囲の行を
含めて**どの行も記号1つ**になり、往復が何回になっても増えない。

## 実施内容と結果

### 1. `update-handoff-progress.sh`

| サブコマンド | 変更後の挙動 | 実測 |
|---|---|---|
| `add-round <flow-id>` | ヘッダの周回数を+1し、範囲の全行の記号を `[]` へ戻す | `1周目（完了）` → `2周目（進行中）`／セル `[x]` → `[]` |
| `mark-done <flow-id>`（ループ範囲） | 周回数は据え置き、記号を `[x]`・状態を（完了）へ | `2周目（進行中）` → `2周目（完了）`／セル `[]` → `[x]` |
| `mark-done <flow-id>`（単発） | 従来どおり。ヘッダに触れない | ヘッダ行が生成されないことを確認 |
| `set-header --loop <text>` | ヘッダ行を任意の文字列で書き換える | `なし` を書けることを確認 |

追加関数: `count_rounds_to_reply` / `format_loop_status_to_reply` / `parse_loop_header_to_reply` /
`resolve_loop_rounds_to_reply` / `set_loop_header_in_lines` / `follow_loop_header_in_lines`

### 2. 旧表記からの自動移行（実測）

ヘッダ行が無い（または別のループ範囲を指す）場合、周回数は進捗列の記号の個数から読む。これがその
まま旧表記からの移行経路になる。

| 操作前のセル | 操作 | 操作後のセル | 操作後のヘッダ |
|---|---|---|---|
| `[x][x][]` | `mark-done` | `[x]` | `… の3周目（完了）` |
| `[x][x]` | `add-round` | `[]` | `… の3周目（進行中）` |
| `[]`（新表記） | `mark-done` | `[x]` | `… の1周目（完了）` |
| 別範囲を指すヘッダあり | `mark-done` | `[x]` | `… の1周目（完了）`（数え直し） |

ループ範囲は互いに素なので、ヘッダの解析は先頭flow-idと周回数だけを取り出せば足りる。区切り文字
`〜` は正規表現へ書かず `.*` で読み飛ばしている。

### 3. 挿入位置

`- 現在のループ:` 行が無い `HANDOFF.md` でも自動で挿入される。

- ヘッダ項目（`- issue:` / `- ブランチ:` / `- PR:` / `- push回数:`）があれば、その最後の行の直後
- ヘッダ項目が1つも無ければ `## フロー進捗状況` 見出しの直前へ、後ろに空行を1つ添えて
- どちらの基準も無ければ、`mark-done`/`add-round` は警告を出して**進捗表の更新だけ**書き戻す
  （`set-header --loop` はエラー）

## トレードオフ

**進捗表から周回数を消したため、過去に何周完了したかは表から追えなくなる。** `[x][x][]` は
「2周完了して3周目が進行中」という履歴を持っていたが、新表記のヘッダは現在地だけを表す。履歴が
必要ならブランチ上のcommit履歴（`HANDOFF.md` の差分）を見る。読み取りの確実さを履歴性より優先した。
