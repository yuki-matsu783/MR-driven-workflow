### 判断の要点

- **PR/MRテンプレートに見出しを増やさなかった。** `describe` サブコマンドが description を全文置換
  するため、テンプレートにしか無い見出しは初回の `describe`（flow-id 2-5）で消える。記入ガイドは
  HTMLコメントに置き、置換されても情報を失わない形にした。
- **`.claude/VERSION` は配置だけならスクリプト変更なしで配布経路に載った**（`sync-assets.sh` の
  `.claude/*` ループと `install-to-project.sh` の `safe_copy_dir` が既に配下の全ファイルを対象に
  しているため）。ルートに置く案は、配布先が自分のアプリの版として `VERSION` を持つ場合に
  それを上書きしてしまうため採らなかった。ただし**「差分があれば `.bak` 退避して警告」の既定に
  載せてはいけない**ことが敵対的レビューで判明し、無条件上書きの経路を足した（下記）。
- **`.gitattributes` は行追記にした。** 全文置換は配布先の `*.png binary` のような設定を消し、
  バイナリのテキスト化という履歴に残る破損を招く。`.gitattributes` は後の行が優先されるため、
  末尾追記は意味論としても正しい。
- **判定は部分一致ではなく行全体の一致（`grep -Fxq`）にした。** 部分一致だと、配布先が
  `# *.sh text eol=lf を入れるか検討中` のようにコメントで言及しているだけの場合に「もう有る」と
  誤判定し、**必要な指定が入らないまま無言で終わる**。配布したスクリプトがCRLFで壊れても
  気づけないため、失敗の向きとして受け入れられない。
- **`* text=auto` は配らない。** リポジトリ全体の正規化方針は配布先が決めるべきもので、勝手に
  足すと配布先の既存ファイルが次のコミットで一斉に正規化されうる。

### 指摘のうち、事実確認して訂正したもの

指摘4は「`HAS_WARNED` が立つのでATTENTIONブロックが毎回出る」としていたが、**実機で確認したところ
ATTENTIONブロックは出なかった**。`safe_copy_dir` の `find ... | while ...` はパイプラインのため
サブシェルで実行され、そこで立てた `HAS_WARNED=true` は呼び出し元へ伝わらないためである。
出るのは個別のWARNING行と `.bak` までで、そこは指摘のとおり。**この「ATTENTIONブロックが
そもそも機能していない」こと自体が別の欠陥**なので、specの「未決定事項」へ #26 向けに記録した。

### 修正後の再検証（変異テスト）

修正した3点について、**わざと壊すと落ちること**を確認した。

| 変異 | 結果 |
|---|---|
| CR除去（`tr -d '\r'`）を外す | `CRLFの配布先でも*.shの指定は1行のまま` が `expected: 1 / actual: 3` で失敗（`passed=20 failures=2`） |
| `ALWAYS_OVERWRITE_RELPATHS` の分岐を外す | `VERSIONの.bakを作らない` `VERSIONについて警告を出さない` が失敗（`passed=20 failures=2`） |
| `.gitattributes` のマーカー名を壊す | 配布行が0件になり9件失敗（`passed=13 failures=9`） |

いずれも復元後は `passed=22 failures=0`。

## 未解決・持ち越し

- **Windows実機での改行の挙動は未確認**（この実行環境はLinuxコンテナ）。`.gitattributes` の追加が
  意図どおり効くかは、git bash環境での確認が残る。CRLFまわりの冪等性については、
  「適用のたびに全体をCRLFへ正規化する」フィクスチャで**壊れ方を再現したうえで**直している。
- `install-to-project.sh` の既存の `.gitignore` 追記処理は、(1) 空行を毎回無条件で追記するため
  再適用のたびに空行が1行増える、(2) 判定が部分一致のまま、(3) 追記する行が実際の状態ディレクトリ
  （`/usage/`・`/.claude/state/`）と食い違う、という3点を抱えている。今回追加した `.gitattributes`
  側は同じ作りにせず直したが、**既存の `.gitignore` 側は直していない**（本issueの範囲外。
  issue #26 の `merge` 層の設計でまとめて扱うのが妥当）。`HAS_WARNED` がサブシェルの外へ
  伝わらない件も同様に記録のみ。
