### 判断の要点

- **PR/MRテンプレートに見出しを増やさなかった。** `describe` サブコマンドが description を全文置換
  するため、テンプレートにしか無い見出しは初回の `describe`（flow-id 2-5）で消える。記入ガイドは
  HTMLコメントに置き、置換されても情報を失わない形にした。
- **`.claude/VERSION` はスクリプト変更なしで配布経路に載った。** `sync-assets.sh` の `.claude/*`
  ループと `install-to-project.sh` の `safe_copy_dir`（`find -type f`）が既に配下の全ファイルを
  対象にしているため。ルートに置く案は、配布先が自分のアプリの版として `VERSION` を持つ場合に
  それを上書きしてしまうため採らなかった。
- **`.gitattributes` は行追記にした。** 全文置換は配布先の `*.png binary` のような設定を消し、
  バイナリのテキスト化という履歴に残る破損を招く。`.gitattributes` は後の行が優先されるため、
  末尾追記は意味論としても正しい。
- **判定は部分一致ではなく行全体の一致（`grep -Fxq`）にした。** 部分一致だと、配布先が
  `# *.sh text eol=lf を入れるか検討中` のようにコメントで言及しているだけの場合に「もう有る」と
  誤判定し、**必要な指定が入らないまま無言で終わる**。配布したスクリプトがCRLFで壊れても
  気づけないため、失敗の向きとして受け入れられない。
- **`* text=auto` は配らない。** リポジトリ全体の正規化方針は配布先が決めるべきもので、勝手に
  足すと配布先の既存ファイルが次のコミットで一斉に正規化されうる。

### 4. 既存の `.gitattributes` を持つ配布先への適用（実機）

配布先に3行の独自設定を置き、かつ**末尾に改行が無い状態**（追記行が直前の行と連結する条件）を
意図的に作って適用した。

- 既存3行の残存件数: **3**（すべて残った）。
- 末尾改行が無くても `*.md text eol=lf diff=markdown` は完全な1行として残った（連結していない）。
- `.gitattributes.bak` は**作られなかった**（＝全文置換になっていない）。

### 5. 冪等性（実機）

同じ配布先へ計3回適用した結果、`*.sh text eol=lf` の件数は **1**、ヘッダコメントの件数も **1**、
総行数は6行のまま増えなかった。

### 6. 検証が「異常を検出できること」の確認（変異テスト）

「異常が無ければ何も出ない」形の検証は、判定が実物に合っていないと常に成功する。そこで
**判定を意図的に部分一致（`grep -Fq`）へ戻して**テストを流し、落ちることを確かめた。

```
FAIL: コメント中の言及を実設定と誤認しない
  expected: 1
  actual  : 0
passed=13 failures=1
```

元に戻すと `passed=14 failures=0`。テストが規約違反を実際に検出できることを確認できた。
