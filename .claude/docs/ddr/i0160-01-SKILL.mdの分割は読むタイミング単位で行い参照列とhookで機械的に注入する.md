# i0160-01. SKILL.mdの分割は読むタイミング単位で行い参照列とhookで機械的に注入する

- ステータス: 承認済み
- 日付: 2026-08-23
- issue: #160 / PR #161

## 文脈

`.claude/skills/issue-mr-flow/SKILL.md` は約1,100行に達し、セッション開始・compact直後の
再読み込み（DDR `i0113-01`）のたびに全文を読むコストが無視できなくなっていた。一方で、
各flow-idの実行時に実際へ必要な節は全体の一部である（フェーズ2の実行中にフェーズ5のクローズ
手順は要らない）。issue #160 は SKILL.md を分割し、**どの参照をいつ読むかを機械的に決める**
ことを求めた。

## 決定

1. **分割単位は「いつ読むか」（読むタイミング）で切る。** 本文（入口）には全体フロー表・
   PR/MR担当・対応表だけを残し、詳細は `references/` 配下の7ファイル
   （`planning` / `deliverables` / `start-resume` / `review-loop` / `base-branch-followup` /
   `mcp-fallback` / `phase5-close`）へ移す。各ファイルは「同じflow-id群の実行前にまとめて
   開かれる」ことを単位に束ねた（フェーズ2で計画系、レビュー往復でreview-loop、クローズで
   phase5-close、のように）。
2. **参照タイミングは全体フロー表へ新設した「参照」列を唯一の正とし、SessionStart hookが
   現在地のflow-idからこの列を読み出して注入する。** 現在地は `HANDOFF.md` の進捗表から
   「最後の `[x]`/`[-]` より後の最初の `[]`」で解決する（`current_flow_id_to_reply`）。
3. **hookはfail-openを4段で守る**（現在地が解決できない／進捗セルが記号ちょうど1つでない／
   参照セルが規定の形でない／参照が `—`——のいずれでも参照行を出さない）。誤ったファイルを
   名指しするより、出ないほうが害が小さい。
4. **進捗表の行判定の正規表現 `ROW_RE` は `update-handoff-progress.sh` から同一リテラルで
   複製し、一致をテストで表明する**（`test_session_start.sh`）。
5. **`references/mcp-fallback.md` だけは参照列で指さない。** `gh`/`glab` CLIの有無はflow-idでは
   なく実行環境で決まるため、hookがMCP経路と判定したときに限り別の行で名指しで注入する。

## 却下した代替案

- **サイズ均等の4分割**: 行数を揃える分割は「1ステップの実行に2〜3ファイルへまたがって読む」
  状態を作り、読むタイミングと切れ目が一致しない。flow-idごとの読み込みバイト数を試算した結果、
  タイミング単位のほうが各ステップの読み込み量が小さくなった（フェーズ2調査の実測が根拠）。
- **本文にポインタだけ置き、読むかどうかはAIの判断に委ねる**: 「必要になったら読む」は、
  compact要約後に「読んだ」という認識だけが残る失敗モード（issue #113・DDR `i0057-01` と同型）
  を references/ の粒度で再生産する。参照列＋hook注入で「いつ読むか」を機械の側へ倒した。
- **hook側にflow-id→参照の対応表を持つ**: 表とhookの二重管理になり、フロー表の行の追加・
  繰り下げ（実際にissue #70で5-3挿入が起きた）へ追従できず、誤った参照を注入し続ける。
  ヘッダ行から「参照」列の位置を求めて表から直接読む方式にした。
- **「表全体で最初の `[]`」で現在地を解決する**: 非対話環境では人間レビュー行（2-3等）が
  `[]` のまま残る運用（`.claude/rules/docs-workflow.md`）のため、永遠にそこを指し続ける。
  「最後の完了行より後」を起点にすることでこの運用と両立させた。
- **`ROW_RE` を `source` で共有する／`hooks/lib/` へ切り出す**: `update-handoff-progress.sh` は
  `set -euo pipefail` を宣言しており、`source` するとhook側にも効いてfail-open設計（失敗しても
  注入の他項目を続ける）を壊す。`lib/` への切り出しは配布漏れという新しい失敗点を作る
  （`CommandPosition.sh` の配布漏れが既知の縮退条件になっている前例）。同一リテラルの複製＋
  一致テストが、失敗の影響を最小にする。
- **DDR `i0113-01` が却下した「HANDOFF.mdから現在地を解決して注入する」との関係**: あちらは
  「現在地の**要約文**を注入する」案を、誤った現在地を断定的に注入する損失の大きさを理由に
  却下した。本決定の参照注入は、解決に失敗したら**行ごと出さない**（fail-open）ことで
  この非対称を保っている——誤りうる情報を出すのではなく、確実なときだけ出す。

## 影響

- 仕様の反映先: `.claude/docs/spec/issue-mr-workflow.md`「セッション開始時の自動コンテキスト
  注入」（「現在地flow-idと参照ファイルの注入」項）・「コンポーネント構成」、
  `.claude/docs/spec/update-handoff-progress.md`「制約・設計判断」（`ROW_RE` 複製）。
- 旧節名からの導線: DDR本文・specの過去changelogは書き換えない運用のため、旧節名で参照して
  いる読み手は SKILL.md の「旧節名→新しい場所の対応表」で辿る。
- `references/*.md` は frontmatter `type: skill-reference`（`.claude/rules/markdown-frontmatter.md`）。
