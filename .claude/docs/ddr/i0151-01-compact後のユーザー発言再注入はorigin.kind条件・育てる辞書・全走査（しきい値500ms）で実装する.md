# i0151-01. compact後のユーザー発言再注入はorigin.kind条件・育てる辞書・全走査（しきい値500ms）で実装する

issue #151（PR #197）。

## 背景

issue #57（DDR `i0057-01`）でSessionStart hookはcompact後に「現在地」（ブランチ／issue／PR／
`HANDOFF.md`の次にやること）を再注入するようになったが、**ユーザー自身が何を頼んだかという生の
発言**は対象外だった。compactの要約が手順理解を欠落させることはissue #113・#160で扱われているが、
「そもそも何を依頼されたか」が要約の精度次第で失われる問題は残っていた。本DDRは、この再注入を
どう設計したかの決定を記録する。

## 決定

### 母集団の抽出条件

1. **抽出条件に `origin.kind == "human"` を加える（肯定形で書く）。** 既存4条件
   （`type=="user"` かつ `message.content` が文字列型 かつ `userType=="external"` かつ
   `isSidechain==false`）だけでは、`task-notification`（機械生成のユーザーターン）が素通りした
   （実測: 24件 → 7件）。**否定形（`!= "task-notification"`）は採らない** —
   `origin` キー自体を持たない行が6件あり、否定形だとそれらが混入する。
2. **`isSidechain` の判定は `//` 演算子を使わず直接比較で書く。** `(.isSidechain // null) != false`
   は`isSidechain: false`の行まで除外してしまう（`//`は`false`もfalsyとして扱うため）。実装中に
   発見した既存ロジックの潜在バグで、`.claude/rules/shell-script-style.md`「JSON操作」節へ
   教訓として反映済み（本DDRでは設計判断としてのみ記録する）。
3. **`uuid`（無ければ行番号）による重複除去を行う。** 同じ行が異なる`gitBranch`ラベルで
   再出現しうるため（issue #37と同型）。

### 選定パラメータ

4. **切り出しは `jq` の `.[0:N]` で行い、`${var:0:N}` は使わない。** `${var:0:N}`は環境により
   バイト単位で切れ日本語が壊れる。ロケール2条件（`LANG`空 / `C.UTF-8`）で文字単位の挙動を確認した。
5. **jqへパス名を渡さず標準入力へ繋ぐ。** git bashでの`transcript_path`の表記（Windows形式
   `C:\...`かMSYS形式`/c/...`か）が未確認のため、パス表記の不確実性を実装から切り離した
   （両形の出力がmd5一致することはLinux上で確認済み）。
6. **件数・文字数の配分（先頭3件＋直近7件・最大10件、頭120字+末尾40字／頭80字+末尾30字）は
   現状維持とする。** 母数7件では分位点が脆く、変える実データ上の根拠が無い。

### 除外辞書

7. **除外辞書は継続し、`ok`/`OK`だけを外す。** `ok`がflow-id 1-5の合意そのものを落とした
   （過剰除去1件）。外した後の再測で除外0件・残7件を確認した。
8. **辞書は固定リストにせず「育てる」運用にする。** 初期辞書12語のうち実際に働いたのは`ok`の
   1語だけで、残り11語はこの断面で一度も働かなかった。机上の網羅が実運用に当たる保証は無い。
   実装は次の4点で構成する: 初期辞書は現行12語から`ok`/`OK`を除いた10語をそのまま使う
   （実測不使用を理由に先回りして削らない）／置き場所は
   `.claude/hooks/session-start-ack-words.txt`（プレーンテキスト、1行1語。JSON化は
   メタデータの必要性が未実証のため却下）／**除外実績を可視化する**（当該セッションの除外内訳を
   注入テキストへ1行足す＋累積カウントを`wip/state/session-start-ack-exclusion-counts.json`
   （gitignore対象）へ持つ2段構え。**発言本文は一切保存しない**）／記録先は新設せず、辞書
   ファイル自体のgit履歴（コミットメッセージ）とする。
   - **可視化が要である。** 本issueの調査で過剰除去（`ok`）に気づけたのは除外前後の件数を
     突き合わせたからで、通常運用ではhookは黙って落とす。可視化が無ければ辞書は育たない。

### サイズ管理

9. **サイズを割合で断定しない。** 既存注入量3,252Bのうち79%が可変（HANDOFF「次にやること」抜粋・
   作業ファイル一覧）で、悲観値では約9,700Bとなり上限8,000Bを超える。発言節のバイト上限は
   6,000Bとする。

### transcript_pathの受け渡しと再注入バイト数の返却

10. **`transcript_path`は関数引数で下方向へ、再注入バイト数はセンチネル行で上方向へ返す。**
    `main`→`build_context`→`build_work_context`→`build_user_utterance_context`という既存の
    二重コマンド置換構造では、下方向は関数引数で素直に渡せるが、上方向（呼び出し元が結果を
    受け取る側）はコマンド置換のサブシェル境界を越えられない。センチネル行
    `__USER_UTTERANCE_BYTES__:<N>`を標準出力の末尾に載せ、`strip_utterance_sentinel_to_reply`
    が本文から取り除く形にした（issue #43で踏んだ落とし穴と同型）。
11. **`append_size_warning`の新パラメータ（`excluded_bytes`）は末尾へ追加し、省略可・既定0にする。**
    第2引数へ差し込むと、既存呼び出し6箇所（`test_session_start.sh`）が無言で別の意味に変わる。
12. **累積カウントは`uuid`集合（`countedUuids`）で重複計上を防ぐ。** SessionStart hookは
    resume/compact/clearのたびに再発火し同一transcriptを何度も読み直すため、素朴に加算すると
    同じ発言の除外が複数回カウントされる。

### 走査方式としきい値

13. **走査は全走査（`jq -R -n` + `inputs`）のまま採る。**
14. **走査コストのしきい値を200ms→500msへ改定する。** git bash見積もり約208msは、当初の
    しきい値200msに対しては不合格（104%）だったが、人間レビュー（flow-id 2-8）で500msへ
    改定され合格（42%）になった。**この改定はAIエージェントが自分の判断で緩めたものではない。**
    計画の停止条件「しきい値を後から緩めない」は「AIが自分の判断で緩めることを禁じる」規則で
    あり、今回はAIが不合格と結論して案A/B/Cを人間へ提示し、**人間が値そのものを改めた**。
    改定は「+4.6MBという見積もりが実は10倍甘かった」という誤りを訂正した**後**に行われており、
    誤った値を根拠に緩めたのではない。

### 実装時の設計変更

15. **出力スキーマを計画の`selected`/`excludedCounts`から`sectionText`/`excludedEvents`へ
    変更した。** `sectionText`はjq側で整形済みのテキストを直接組み立てて返す。`excludedEvents`
    は`{uuid, word}`の配列で、上記12の`uuid`単位の重複計上対策に必要だった。計画時のスキーマ
    ではこの対策が組みにくく、jq側で完結させる形のほうが単純だった。

## 却下した案

- **封筒プレフィックスの文字列で除外する。** `origin.kind`の1条件で構造的に落ちた。構造で落ちる
  ものを文字列で判定しようとしていた。
- **抽出条件を否定形（`origin.kind != "task-notification"`）で書く。** `origin`キー自体を
  持たない行が6件あり、否定形だと混入する（上記「決定」1参照）。
- **走査を2パス化する（末尾からの逆走査＋先頭固定行数）。** しきい値改定後は全走査で収まる。
  実装の複雑さに見合わない。手札として残す。
- **抽出結果をキャッシュし差分だけ走査する。** 状態ファイルが増え、破損時の自己回復ロジックまで
  要る。得る余裕に見合わない。同じく手札として残す。
- **相槌辞書をやめる（除外規則を廃止する）。** 完全一致なので1語単位で取り消せる。方式ごと
  捨てる理由にならない。
- **相槌の判定に文字数しきい値を使う。** 「ダメ、やり直して」のような短くて重要な指示を落とす。
- **`type == "last-prompt"` の行を代替として使う。** 原文ではない。改行を空白へ潰し、約200字で
  切り詰めている（コードポイント単位で差分を特定済み）。
- **Gemini CLI 経路を本issueで扱う。** ブランチ絞りが原理的に不可能（DDR `i0097-04`）なうえ、
  `session-start.sh`が`CLAUDE_PROJECT_DIR`必須で冒頭`exit 0`する・SessionStartに`compact`起動
  要因が無い・ログ構造が違う、の3つの壁がある。issue #201へ切り出し済み（ユーザー提案の
  フラグファイル中継を案A・第一候補として本文へ据えた）。
- **`excluded_bytes`を`append_size_warning`の第2引数へ差し込む。** 既存呼び出し6箇所が無言で
  意味を変える（上記「決定」11参照）。
- **再注入バイト数を専用の状態ファイル経由で`main`へ渡す。** 1回の実行内で完結する値を
  ファイルI/Oで往復させる必要が無い。センチネル行のほうが単純。
- **累積カウントを`session_id`単位のカーソルで重複除去する。** `usage/state/session-cursors/`と
  役割が重複するうえ、compact後の行番号再採番が未確認。

## スコープ外（本issueでは対応しない）

- **Gemini CLI経路の対応**: issue #201へ切り出し済み。
- **過去transcriptの走査**: この実行環境では過去transcriptが0本のため、案の成立自体が確認
  できない。`HANDOFF.md`「次にやること」節の既存注入（DDR `i0057-01`）で代替する。
- **`AskUserQuestion`回答の母集団への混入対応**: `tool_result`に
  `Your questions have been answered: "質問"="回答"`の形で入るため、人間の意思決定がstring
  contentからは拾えない。抽出条件の再設計に近い規模のため見送る。
- **除外辞書の配布層（core/seed等）判断**: 配布アーキテクチャ全体の判断で本issueのスコープを
  超える。issue #207へ切り出し済み。

## 未確認事項（やらないと決めたのではなく、確認できていないもの）

上記「スコープ外」とは異なり、以下は**確認する意図はあるが本issueの実行環境では確認できな
かった**もの。DDR本文は一度マージしたら変更しない運用のため、将来git bash実機で確認できた
時点での反映先は`.claude/docs/spec/issue-mr-workflow.md`側とする（性能記述の更新、または
「未決定事項・懸念点」への追記）。本DDRのfrontmatterを更新するのは、実測の結果この決定自体が
置き換わったとき（`status: superseded`）に限る（`.claude/rules/markdown-frontmatter.md`
「DDRのstatus」）。

- **git bash実機での走査コスト。** 約208msという値はLinux実測（jq起動138ms実測＋走査約70ms
  実測）からの見積もりであり、実測ではない。レートがLinuxの1/4まで落ちると、しきい値500msに
  収まる総量は約24.4MB→約6.1MBまで縮む。
- **git bash実機での`transcript_path`の表記（Windows形式かMSYS形式か）。** 標準入力へ繋ぐ
  設計（上記「決定」5）にしているため、この値自体が判明しなくても実装は動作する。
- **ブランチ絞りの効き。** 絞る手段はあるが、実データでは1件も落ちず、除外が実際に働く断面での
  確認ができていない。
