# i0171-01. DDR参照切れ検出は絶対パス形式に限定しgrep一括抽出で実装する

## 背景

issue #133で全DDRを4桁ゼロ埋めのissue番号ベース識別子（`i0000-01`形式）へ一括改番した際、
`.gitignore`内のコメントに書かれた**参照文字列**は改番対象に含まれず、古い識別子のまま
取り残された。issue #171はこの取りこぼし（`.gitignore`の2箇所: `i00-13` → `i0000-13`、
`i36-01` → `i0036-01`）を修正するとともに、実在しないドキュメントを指す参照を機械的に検出
できるようにすることを求めていた。

issueの「現状」節は「`i00-13`を指す参照はissue #70で既に消えた」としていたが、事前調査の
結果、実際には`.gitignore`の28行目にまだ`i00-13`参照が残っていることが判明し、issue本文の
前提が古いことが分かった。修正対象は40行目だけでなく28行目も含めて2箇所である。

## 決定

1. **検出対象を「`.claude/docs/ddr/`配下のDDRファイルパスへの絶対パス参照」に限定する。**
   パスを伴わない裸の識別子表記（例:「DDR i0159-01参照」）・相対パス表記
   （`../docs/ddr/…`、`ddr/…`）は対象外とする。
2. **検出方式は、grepによる候補の一括抽出＋bashの純粋関数による後処理（除外判定・実在確認）
   とする。** 正規表現へ多バイト文字（全角句読点等）を直接埋め込む設計は採らない。
3. **実行タイミングは手動実行のみとし、hook・CI等へは組み込まない。**
4. **`.claude/docs/spec/check-doc-references.md`を新設し、呼び出し方・実行タイミング等の
   運用手順を恒久的に記録する。**

## 理由

### 1. 検出対象を絶対パス形式に限定する理由

- 裸の識別子表記は、規約説明の例示として本リポジトリのドキュメント中に頻出し
  （例:「識別子は`i0133-01`のような形式」）、これを参照切れの候補として拾うと誤検知が
  大量に発生する。
- 相対パス表記は、パスの起点（呼び出し元ファイルの場所）を解決する処理が別途必要になり、
  今回のissueが主眼とする「`.gitignore`のようなコメント内の絶対パス参照」とは検出ロジックの
  難度が異なる。実際に調査（flow-id 2-6）で走査したところ、相対パス表記の候補は約79件
  あり、今回のスコープには含めないことにした（下記「影響」参照）。
- 旧形式（4桁連番、`i`接頭辞なし）の参照は、本リポジトリには現存しない
  （`.claude/rules/markdown-frontmatter.md`「旧方式（4桁連番）の扱い」のとおり、issue #133の
  改番で全56件が新形式へ置き換わっている）ため対象外とした。配布先で必要になった場合の
  拡張余地として、ここに記録しておく。

### 2. grep一括抽出方式を採る理由（実装の変遷）

実装（`.claude/scripts/src/check-doc-references.sh`）は2回の敵対的レビューを経て、次の順に
変遷した。

1. **初版**: `git ls-files`で得た対象ファイルをbashの`while read`ループで1行ずつ読み、
   `[[ "$line" =~ $regex ]]`で候補を抽出する設計。フェンス（コードブロック）除外は、対象外の
   行を検出のたびに削除する「行削除の2パス」方式で実装した。
2. **1回目の敵対的レビュー対応**: 終端文字集合の指定誤り（`\t`という4文字のリテラルを
   意図していたが、実際にはエスケープが効かず文字どおりの4文字として扱われていた）という
   blocker、および`plans/` `reports/` `worklog/`（寿命の短いファイル）を除外対象に含めて
   いなかったことによる誤検知を修正した。
3. **2回目の敵対的レビュー対応（設計判断そのものが変わった点）**:
   - **フェンス除外を「行削除」から「行番号の集合を求め、走査結果の元の行番号と突き合わせる」
     方式へ変更した。** 行削除方式は、削除後に残った行を再度カウントし直すため、報告する
     行番号が実ファイルの行番号とずれるバグを実機の再現ケースで確認したため。
   - **フェンス判定ロジックを「開始行と同じマーカー種別（`` ` ``/`~`）・同じ長さ以上でのみ
     閉じる」方式へ変更した。** 単純な「出現回数の偶奇」でトグルする判定は、種別の異なる
     フェンス風の行（例: `` ``` `` の中に`~~~`が現れる）が挟まると偶数回トグルになり、
     フェンス内であるべき行がフェンス外と誤判定され、そこに書かれた参照切れの実例を無言で
     見逃す偽陰性を実機の再現ケースで確認したため。
   - **全角句読点等による参照の連結（例: `i0159-01…md`のように全角の省略記号で2つの参照が
     連結されてしまうケース）への対策で、正規表現の文字クラスへ多バイト文字を直接追加する
     案を採用しなかった。** 採用を試みたところ、**この実行環境（`LANG`未設定のPOSIX
     ロケール）では、POSIX ERE のブラケット式（`[...]`）へ多バイト文字を含めると、
     `grep -E`・bashの`[[ =~ ]]`のいずれも、その文字にマッチしないだけでなく、
     リポジトリ全体に対する候補抽出結果が121件から0件へ落ちる**という致命的な破綻を実機で
     発見した。`LC_ALL=C.UTF-8`を明示すれば再現しないが、この機構の主な配布先である
     git bash/Windows環境ではロケールを制御できない前提のため、**正規表現自体には多バイト
     文字を含めず、抽出後の文字列をASCII構造（`.claude/docs/ddr/`という固定プレフィックスの
     再出現位置）だけで判定する後処理方式**（`split_concatenated_candidates_to_reply`）へ
     設計変更した。
   - **候補抽出をbash単独ループからgrep一括抽出へ変更した。** リポジトリ全体約37,000行に
     対する走査時間を実測したところ、bash単独ループ方式が5.2秒、grep一括抽出方式が0.96秒
     だった。`.claude/rules/shell-script-style.md`「外部プロセス起動のコスト」が原則とする
     「ループ内で外部コマンドを呼ばない」から見ると一見逆行するようだが、grepを1回だけ呼び
     bashのループ自体を無くす設計であるため、同原則が禁止する「ファイルごと・行ごとに外部
     コマンドを呼び直す」設計とは異なる。

### 3. 手動実行のみとする理由

`.claude/rules/shell-script-style.md`「外部プロセス起動のコスト」に照らし、頻度の低い整合性
チェックを毎ツール呼び出し・毎コミットで自動実行する価値は無いと判断した。将来
`resolve-conflict`スキル等の既存フローへの合流が必要になれば、そのときに別issueで検討する。

### 4. 新規specを作る理由

「規模の小さいスクリプトのため計画＋テストコード＋DDRで十分」という判断を実装当初は採ったが、
`plans/`配下の計画ファイルはflow-id 5-4で削除されmainに残らないことに気づき、撤回した。
DDRは「〇〇を決めた」という意思決定の記録であって「現在の正史（呼び出し方・実行タイミング等の
運用手順）」ではなく、後者の役割は`.claude/docs/spec/`が担う
（`.claude/rules/docs-workflow.md`のライフサイクル表）。手動実行のみという運用が、マージ後に
恒久ドキュメントのどこにも書かれていない状態を避けるため、新設することにした。

## 却下した案

- **検出の仕組みを作らず、目視確認のみで済ませる案**: issueタイトルが「検出できるようにする」
  と明記しており、調査（flow-id 2-6）の結果、判定ロジック（正規表現＋除外フィルタ）が確立し
  実装可能な見通しが立ったため却下した。
- **正規表現の文字クラスへ全角句読点を直接追加する案**: 上記「理由」2参照。この実行環境の
  ロケールで致命的に破綻することを実機で発見したため却下した。
- **新規specファイルを作らない案**: 上記「理由」4参照。フェーズ4の反映計画への敵対的レビューで
  「計画自体もマージ後に残らない」という指摘を受け、実装当初の判断を撤回した。

## 影響

- **相対パス表記のDDR参照（約79件）は今回の検出対象外のまま残る。** 追跡先の新規issueは
  本issue #171では起票していない（`.claude/skills/issue-create/SKILL.md`が求める重複
  チェック・最終確認は、非対話セッションでは人間との対話が成立せず実施できないため）。最終
  統括レポート・関連issue通知（flow-id 5-2/5-3）で人間へ提示し、起票の要否を委ねた。
- **ロケール依存の正規表現マッチ罠、およびgrep一括抽出が有利になる実測は、DDRだけでなく
  `.claude/rules/shell-script-style.md`へも反映した**（他プロジェクトへの配布時に同じ罠を
  再現しうるため。反映内容は同ファイル「文字コード」節・「外部プロセス起動のコスト」節を
  参照）。
- 配布対象アセット（`.claude/scripts/src/check-doc-references.sh`・
  `.claude/scripts/test/test_check_doc_references.sh`・
  `.claude/docs/spec/check-doc-references.md`）を新設したため、`.claude/VERSION`のMINOR
  増分を人間へ提案した（増分の実施自体は人間の承認後に行う）。
