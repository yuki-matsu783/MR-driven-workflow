# i0203-01. レポートHTMLビューは共通DOMと4スタイルで持ち現行を残す

## 背景

issue #203 は、別ブランチで試作した16案のデザインサンプルのうち4案（06・10・12・13）を、
`wip/reports/` のHTMLビュー用テンプレートとして使える形にすることを求めた。

サンプルはいずれも **Tailwind CDN を読み込むHTML**であり、そのままでは
**「外部依存を持たない自己完結HTML」という既存の条件**（DDR `i0054-01`）を満たさない。
また4案は別々に書かれたため、**同じ内容を表す箇所でDOMが食い違っていた**
（`<p>` と `<span>`、`<mark>` と `<strong>`、目次の項目数）。

## 決めたこと

**4デザインを「共通DOM＋4通りの `<style>`」として持ち、現行テンプレートは残す。既定は
`reports-clean.template.html` とする。**

| 決めた点 | 内容 |
|---|---|
| 構成 | 使い方コメント・DOM本体・スタイルの骨格を**共有パーツとして持ち、連結して4本を生成する** |
| 不変条件 | **`<style>` を除いた残りが、4本でバイト単位に完全一致する**（実測 359行 / 22346バイト） |
| 既定 | `reports-clean`（案06） |
| 現行の扱い | **併存**（据え置き）。新規作成で選ぶ理由は無く、移行期のみ使う |
| 選択基準の正 | `.claude/skills/issue-mr-flow/references/deliverables.md`「レポートテンプレートの選び方」**1箇所** |
| 検査手順の正 | 同ファイル「検査手順の正はこの節にある」**1箇所**（テンプレート冒頭コメントは使い方の説明として残す） |

**デザイン固有の説明文は、冒頭コメントではなく `<style>` 先頭のCSSコメントへ置く。**
冒頭コメントへ置くと**そこだけが4本で異なり、上記の不変条件が成り立たなくなる**。

**案12（mono）の `.box.ok`（決めたこと・手順の成功）には色を与えず、CSS `::after` で
「（決定）」というラベルを与える。** 案12は緑系の色を持たず、かつ「色が見えたら結論の性質」
という方針を持つため。**ラベルをHTMLへ書き足すとDOMが4本で分岐する**ので、CSSで与える。

## 却下した案

### 4本を独立したHTMLとして持つ

サンプルをそれぞれ整形して4本のテンプレートにする案。**採らなかった。**

使い方コメント（約96行）・検査手順・節構成・プレースホルダが**4重管理**になる。これらは
「どう書くか」の正であり、片方だけ古くなると**書き手が受け取る指示が食い違う**。実際、
issue #186 で節構成を9節へ全面改修した実績があり、同種の改訂は今後も起こる。

### 現行を置き換える（1本に絞る）

`reports.template.html` を新デザインで上書きし、テンプレートを1本に保つ案。**採らなかった。**

既存の成果物が現行テンプレートの節構成に依存しており、更新時に**節ごと作り直す**ことになる。
また、issue #203 の受け入れ条件は4案の**テンプレート化**を求めており、1本に絞ると
「4案を持つ」という要求自体を満たさない。

## あわせて残す: 機械的に検査するときの一般則

**この作業で同じ種類の失敗を繰り返したため、一般則として残す。**
（適用先: `wip/reports/REVIEW-POINTS.md`・`references/deliverables.md`）

### 1. コメントと地の文を先に除く

HTMLコメントの中に地の文として書かれた `<li>` `<details>` をタグとして数え、開閉が合わないと
いう誤検知が出た。**「検査が失敗した＝成果物が壊れている」とは限らない。**
同じ性質の誤検知が外部依存検査でも起きる（`&lt;script src="https://…"&gt;` のような
エスケープ済みの引用に当たる）。**ヒット0件を機械的な合格条件にせず、ヒットしたら中身を見る。**

**この失敗は2つの別の検査で繰り返した。** 1回目（タグの開閉バランス）で気づいたはずの罠に、
2回目（DOMの同一性比較）でも同じようにかかった。

### 2. 「出力なし＝合格」の検査は、負のコントロールを取る

**検査コマンド自体が壊れていても、同じく無出力になる。** 意図的に壊したコピーで検出できることまで
確かめて初めて、「出力が無い」が合格の根拠になる。

`<h3 id="f1">` を `id="overview"` へ変えると、**リンク破断検査と重複ID検査の両方が反応する**。
1つの操作で2つの検査が反応することが、2つを併設している理由（DDR `i0186-02`）をそのまま示す。

**あわせて空振りガード（拾えた件数）を出す。** href・idが0件なら、抽出そのものが壊れている。

### 3. 構造の同一性は、タグ名ではなくバイト単位で比べる

`grep -oE '</?[a-z][a-z0-9]*'` によるタグ名の並びの比較は、**属性もテキストも見ない**。
「タグ構成は同じだが中身が違う」状態を素通りする。

**この作業では、その比較が通っていたのに実際には4本が同一でなかった**（冒頭コメントの
デザイン説明8〜9行が違っていた）。**通ったこと自体が、主張の根拠になっていなかった。**

```bash
tmp=$(mktemp -d)
for F in reports-clean reports-neobrutal reports-mono reports-paper; do
  sed '/^<style>$/,/^<\/style>$/d' "$F.template.html" > "$tmp/$F.nostyle"
  n=$(wc -l < "$tmp/$F.nostyle")
  [ "$n" -lt 100 ] && { echo "FAIL $F: 抽出が $n 行"; exit 1; }   # 空振りガード
done
md5sum "$tmp"/*.nostyle | awk '{print $1}' | sort -u | wc -l   # 1 なら4本一致
```

### 検査を3種から6種へ増やした

外部依存2種（`src`/`href`・`url()`/`@import`）と、**構造の妥当性**（`<style>` がちょうど1つ）である。

最後のものは、この作業中に実際に踏んだ不具合から足した。**`<style>` が二重に出力されると、
2つ目はCSSのテキストとして扱われ、続く `:root { … }` ブロックごと破棄される。**
ダーク環境ではメディアクエリ内で `:root` を再定義しているため正常に見え、
**ライト環境でだけ配色・枠線・強調色が初期値へ落ちる**。
**既存の5種はどれも捕まえなかった**（アンカー・IDと外部依存しか見ないため）。

## 未確認事項

### ブラウザでの実表示（6項目）

**4本とも、実ブラウザでの表示を1件も確認していない。** 作業した実行環境に表示確認の手段が無く、
確かめられたのはHTML/CSSの構造とテキストだけである。内訳は
`.claude/docs/spec/issue-mr-workflow.md`「未決定事項・懸念点」を参照。

### 現行テンプレートをいつ廃止するか

**現行を残すのは移行のためだが、廃止時期は決めていない。**
`wip/reports/` の成果物は flow-id 5-5 で削除されmainに残らないため、「現行で作られた既存の
成果物を更新する」という場面は、未片付けのブランチが尽きた時点で消える。

**廃止するときは配布先への伝播に注意が要る。** `install-to-project.sh` は上流で消えたファイルを
配布先から削除しない（コピーのみ）ため、**配布先には旧テンプレートが残る**
（`.claude/docs/spec/distribution-assets.md`）。

### `.claude/VERSION` の増分

配布対象アセットを4本追加したが、**`0.4.0` のまま据え置いた**。根拠は
`.claude/docs/spec/issue-mr-workflow.md` の `### issue #203` changelog に記録した。
