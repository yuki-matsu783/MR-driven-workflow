# i0186-02. リンク破断検査はID抽出をタグ内に限定し重複ID検査を併設する

## 状況

issue #186 で `reports.template.html` に章ID（`f1`〜連番）を複数箇所（結論カード・
未確認一覧・重点レビュー依頼）から参照する設計を導入したため、`href="#…"` が存在しない
IDを指す破断を検出する検査が必要になった。当初の検査はhref側・id側とも無限定のgrepで
抽出していた。

## 決定

- **ID定義側の抽出は、開きタグ内の `id` 属性に限定する**（タグ開始に続く形だけを拾い、
  HTMLコメント・`code` 内・地の文に現れた `id="…"` という文字列を定義として数えない）。
- **重複ID検査を併設する**（タグ内限定の抽出結果から重複を検出し、出力なしを合格とする）。
  h3をコピーして項目を増やす運用のため、IDの振り直し忘れは最も起きやすい誤りであり、
  そのとき参照は全て解決してしまうので破断検査だけでは素通りする。
- **検査コマンドそのものの正は `reports.template.html` 冒頭コメント**に置く（specの
  「どこに何の正があるか」の委譲構造を崩さない。本DDRは理由と却下案だけを持つ）。

## 理由

無限定grepの検査は「異常が無ければ何も出ない」形であり、抽出パターンが拾う母集団が
汚染されていると**常に合格し続けて発覚しない**。実際、テンプレート自身の節コメントが
`id="f1"` という文字列を含むため、本体のh3のIDを `f1`→`f9` へ書き換えた変異コピーに
旧検査を流しても出力0行（合格）になることを実測で確認した（汚染は仮定ではなく既に
起きていた）。タグ内限定へ変えた検査は同じ変異コピーで参照切れ `f1` を1行検出する。

## 却下した案

- **無限定grepのまま運用する**: 上記のとおり変異テストで破断のすり抜けを実証したため却下。
  「地の文で `id="f1"` を引用するときのエスケープ」を書き手へ課す代替も、href側の
  エスケープ流儀と違い定義側は引用箇所が多く徹底できないため採らない（タグ内限定なら
  地の文の引用はエスケープ不要になる）。
- **検査前にHTMLコメントを除去する前処理**: 1行コマンドに収まらず、テンプレートの
  冒頭コメントから書き手へ伝承しにくい。抽出側の限定で同じ効果が得られるため却下。
