# 配布先の改善を本家へ収穫する

## どんな場面か

このリポジトリ（本家）から `apply-mr-workflow-to-project` スキルで別プロジェクトへ配布した
AIアセット（`.claude/` 一式等）が、配布先で改善された。その改善を本家へ取り込んで、
以降の配布に反映したい場面。

## 使う機能と流れの概要

- 収穫は `harvest-from-projects` スキルが担う（**本家専用**。層は `exclude` で配布されない）。
  配布先の `.claude/.asset-manifest.json` を読み、変更・追加・削除と本家側変更との衝突有無を
  **読み取り専用**で分析して表で提示する。manifest が無い・壊れている配布先も、縮退モード
  （2-way差分の一覧）で分析できる。
- **出口は issue 起票（＋任意で個別作業計画の草案）まで。** どの改善を取り込むかは人間が
  選択し、取り込みの実装は起票した issue を起点とする通常の issue-mr-flow が行う
  （本家の正史をスキルが直接書き換えることはない）。
- 配布先で機構（`.claude/` 一式）の不備に気づいた場合は、配布先リポジトリへDDRを書かず
  本家へ issue を起票する（`markdown-frontmatter.md`「配布先プロジェクトでの機構DDRの扱い」）。
  収穫はその差分を回収する経路でもある。

## 何が得られるか

- 配布先ごとの改善差分の一覧（層・分類・衝突有無・判断材料付き）と、取り込み候補の
  issue 起票までの接続。
- 配布（本家→配布先）と収穫（配布先→本家）で、AIアセットの双方向の還流が完成する。
