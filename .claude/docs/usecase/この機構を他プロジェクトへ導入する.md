# この機構を他プロジェクトへ導入する

## どんな場面か

このリポジトリに同梱されたissue駆動MRワークフロー機構（`.claude/` 一式・`.mrworkflow.json`・
issue/PRテンプレート等）を、別のプロジェクトでも使いたい場面。

## 使う機能と流れの概要

- 導入は `apply-mr-workflow-to-project` スキルが担う。**何をどう配るかは配布元の
  `.claude/dist-layers.json`（5層の層分け定義）が単一の正**として持ち、配布結果は導入先の
  `.claude/.asset-manifest.json` へ記録される。`.claude/` 配下一式（usecase文書を含む
  設計ドキュメントも同梱）は `core` 層として配布される。導入先固有の設定（ブランチ命名規則・
  `plans/` 等の場所）は `.mrworkflow.json` の書き換えで吸収する。
- 配布資産のうち**PR/MRテンプレート・`.gitattributes`・`.claude/VERSION` の3つ**は、
  配布経路での個別の扱い（行単位の追記・版の運用）を distribution-assets 仕様が正として
  定めている。
- `.gemini/` 配下は配布されない（`.claude/` からの変換生成物のため）。導入時にインストーラが
  導入先で変換同期を実行して生成する。

## 何が得られるか

- 導入先のリポジトリでも、issue起票からマージまでの同じフロー（レビュー往復・HANDOFF・
  敵対的レビュー等）がそのまま使える。
- 機構側の更新を再度同期するときも、導入先固有の設定と衝突しない形で追従できる。
