# この機構を他プロジェクトへ導入する

## どんな場面か

このリポジトリに同梱されたissue駆動MRワークフロー機構（`.claude/` 一式・`.mrworkflow.json`・
issue/PRテンプレート等）を、別のプロジェクトでも使いたい場面。

## 使う機能と流れの概要

- 導入は `apply-mr-workflow-to-project` スキルが担う。配布対象の資産（`.claude/` 配下一式と、
  リポジトリ直下のテンプレート類）を導入先へ同期し、導入先固有の設定（ブランチ命名規則・
  `plans/` 等の場所）は `.mrworkflow.json` の書き換えで吸収する。
- 配布資産のうち**PR/MRテンプレート・`.gitattributes`・`.claude/VERSION` の3つ**は、
  配布経路での扱い（丸ごとコピーか・行単位の追記か）を distribution-assets 仕様が正として
  定めている。`.claude/` 配下一式（usecase文書を含む設計ドキュメントも同梱）の同期自体は
  apply-mr-workflow-to-project スキルが担う。
- 導入後にGemini CLIも使う場合は、`.claude/` 配下へのローカルリンクを生成するセットアップ
  スクリプトを1回実行する（`.claude/rules/directory-structure.md` 参照）。

## 何が得られるか

- 導入先のリポジトリでも、issue起票からマージまでの同じフロー（レビュー往復・HANDOFF・
  敵対的レビュー等）がそのまま使える。
- 機構側の更新を再度同期するときも、導入先固有の設定と衝突しない形で追従できる。
