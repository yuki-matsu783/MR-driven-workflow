# ベースブランチとのコンフリクトを解消する

## どんな場面か

レビューを待っている間にdefaultブランチ（main）が進み、作業ブランチがマージできなくなった。
あるいはマージ依頼の前・作業再開の時点で、ベースブランチから遅れていることが分かった場面。

## 使う機能と流れの概要

- **検知**は2つのスクリプトが担う。check-base-sync は作業開始・再開時に「ベースから何コミット
  遅れているか（isBehind）」を判定し、check-base-conflicts はマージ依頼の直前（flow-id 5-1）に
  実際のコンフリクトの有無と、gitでは衝突にならないDDR識別子の重複まで検知する。
- **解消**は `resolve-conflict` スキルが正で、コンフリクトの類型ごとに手順が決まっている
  （DDR識別子の重複＝類型Aの改番手順を含む）。取り込みは常に `git merge` で行い、rebaseは
  使わない（作業ブランチは共有済みで、履歴の書き換えは他者のチェックアウトを壊すため）。
- 遅れの取り込みはユーザーの承認を得てから行う。同じロジックを両ブランチが変更した競合は
  自動で解消せず、人間の判断を仰ぐ。

## 何が得られるか

- コンフリクトを「マージしようとして初めて気づく」のではなく、作業再開時・マージ依頼前の
  決まった地点で検知できる。
- gitが検知できない衝突（同じDDR識別子の二重採番）も同じ流れで拾える。
