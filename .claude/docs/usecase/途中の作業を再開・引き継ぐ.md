# 途中の作業を再開・引き継ぐ

## どんな場面か

昨日まで進めていたissue対応を新しいセッションで続けたい。あるいは、他の人（他のAIセッション）が
途中まで進めたブランチを引き継ぎたい。ブランチ名は分かっていても、「どのフェーズまで進んだか」
「未解決のレビューコメントが残っていないか」「ベースブランチから遅れていないか」までは
分からない場面。

## 使う機能と流れの概要

- 新しいセッションの最初の一手は `/issue-mr-flow resume` と決まっている。専任サブエージェント
  （issue-mr-resume）が、現在のブランチを手がかりにissue・PR/MRの状態・未解決コメント件数・
  ブランチ固有の計画/ログファイル・ベースブランチとの差分・`HANDOFF.md` の内容を集約し、
  矛盾があれば指摘したうえで「現在地サマリ」を報告する。
- `HANDOFF.md` はブランチの現状を常に表す引き継ぎメモで、フロー進捗表（43ステップの記号）と
  「やったこと」「次にやること」「未解決の内容」を持つ。resumeのサマリと突き合わせて現在地を
  確定してから、次のflow-idに着手する。
- 再開時にはベースブランチから遅れていないか（`isBehind`）も確認し、遅れがあれば取り込みの
  承認をユーザーへ求める。ブランチの最新化だけが目的なら `sync` サブコマンドを使う
  （`resume` / `start` で現在地確認が済んだ後に限る。新しいセッションの最初の一手には使わない）。

## 何が得られるか

- ブランチ名だけでは分からない「今どこにいるか」が、着手前に1回で揃う。
- 引き継ぎ元との認識ずれ（HANDOFF.mdと実態の矛盾・未返信のレビューコメント）を、作業を
  始める前に検出できる。
