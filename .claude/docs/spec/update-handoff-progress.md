# HANDOFF進捗自動更新スクリプト（update-handoff-progress.sh）

## 背景・目的

issue #20対応。`.claude/rules/docs-workflow.md`と`.claude/skills/issue-mr-flow/SKILL.md`は
「flow-idが1つ進むごとに`HANDOFF.md`を更新し、commitより前に同じcommitへ含める」ことを求めているが、
更新はメインエージェントの手作業に依存していた。進捗表は40行あり、記号の規則（ループ扱いのステップは
往復1回につき`[]`を1つ追加し、同じループ範囲内のステップは常に同数を保つ）も細かいため、書き間違い・
更新漏れが起きやすい。これを解消するため、進捗表の記号・ヘッダ情報の更新を機械化した。

## 仕様

### 実行方法

```bash
bash .claude/scripts/src/update-handoff-progress.sh mark-done <flow-id> [--file <path>]
bash .claude/scripts/src/update-handoff-progress.sh mark-skip <flow-id> [<flow-id>...] [--file <path>]
bash .claude/scripts/src/update-handoff-progress.sh add-round <flow-id> [--file <path>]
bash .claude/scripts/src/update-handoff-progress.sh set-header [--issue <text>] [--branch <text>] \
  [--pr <text>] [--push-count <n>] [--loop <text>] [--file <path>]
```

`--file <path>`は全サブコマンド共通のオプションで、操作対象ファイルを切り替える（省略時
`HANDOFF.md`）。テストからフィクスチャファイルを指定する用途を想定している。

### 進捗記号とループ範囲

進捗記号は`[x]`（完了）/ `[]`（未着手・進行中）/ `[-]`（今回は実施しない・スキップ）の3種類
（`.claude/rules/docs-workflow.md`参照）。

進捗列は**どの行も記号1つ**であり、ループ扱いのflow-id（「〜を合意まで繰り返す」と書かれたステップ）も
例外ではない。レビュー往復が何周目かは進捗表ではなくヘッダの`- 現在のループ:`行が持つ（下記）。
ループ範囲は以下の6つで、スクリプト内に定数
（`LOOP_RANGES`）として保持している。範囲・並びを変える場合は`.claude/rules/docs-workflow.md`と
両方を更新すること。

```
2-3 2-4
2-6 2-7 2-8 2-9
3-3 3-4
3-6 3-7 3-8 3-9
4-3 4-4
4-6 4-7 4-8 4-9
```

同じループ範囲内のflow-idは常に同じ記号を持つ、という既存ルールを機械的に保証するため、
`mark-done`/`add-round`はループ範囲に属するflow-idを操作する際、**範囲内の全flow-id行へ同じ操作を
一括適用する**。

### サブコマンド

| サブコマンド | 挙動 | エラー条件 |
|---|---|---|
| `mark-done <flow-id>` | 対象行（ループ範囲なら範囲内の全flow-id行）の進捗列を`[x]`にする。対象がループ範囲なら、ヘッダの`- 現在のループ:`行を**周回数据え置き・状態（完了）**へ更新する（単発ステップでは触らない） | 対象行のいずれかで末尾が`[]`でない場合（既に完了済み等） |
| `mark-skip <flow-id> [<flow-id>...]` | 指定した各flow-id行の進捗列を`[-]`へ丸ごと上書きする（複数指定可） | 指定flow-idの一部が表に見つからない場合 |
| `add-round <flow-id>` | 次の往復が始まったことを表す。ヘッダの`- 現在のループ:`行の**周回数を1つ進め**、ループ範囲内の全flow-id行の進捗列を`[]`へ戻す | 対象flow-idがループ範囲に属さない場合／対象行のいずれかで末尾が既に`[]`の場合（前回往復が未完了） |
| `set-header` | `--issue`/`--branch`/`--pr`/`--push-count`/`--loop`のうち指定されたオプションのみ、対応するヘッダ行を書き換える。未指定の項目は現状維持。探索範囲は下記「HANDOFF.mdのヘッダ行」のヘッダブロックに限る | 指定した項目のヘッダ行が**ちょうど1件見つからなかった**場合（0件＝行が無い／表記が違う、2件以上＝1行という前提が崩れている）／`--loop`指定時に行の挿入位置が見つからない場合／**項目オプションを1つも指定しなかった場合**。いずれもファイルを書き戻さずに終了する |

### HANDOFF.mdのヘッダ行（issue #66）

**ヘッダ行の正しい表記は本節が正である。** 他のファイルは本節を参照し、表記そのものを再掲しない。

```
## フロー進捗状況

- issue: #66
- ブランチ: `claude/set-header-silent-failure-p3izl0`
- PR: #146（https://github.com/yuki-matsu783/MR-driven-workflow/pull/146 ）
- push回数: 2
- 現在のループ: なし
- 追従監視: なし
```

- 行頭は `- <項目名>: `（半角ハイフン・半角スペース・項目名・半角コロン・半角スペース）。
- **項目名は `issue` / `ブランチ` / `PR` / `push回数` / `現在のループ` / `追従監視` の6つに固定する。**
  `- Draft PR:` のような別名は使わない（Draftかどうかは値の側に書く。例: `#146（Draft）`）。
- **1項目1行**、上記の順で並べ、`## フロー進捗状況` 見出しの直下に置く。
  `- 現在のループ:` `- 追従監視:` は作業が進んでから増える項目なので後ろに置く。
- 値の書式は定めない（`#146` だけでも、URLを添えてもよい）。定めるのは**項目名と行の形**である。
- `- 追従監視:` だけは `set-header` の対象外で、手で書き換える（issue #88。
  `.claude/docs/spec/issue-mr-workflow.md`「PR作成後のdefaultブランチ追従」）。

この表記は `cleanup-task.sh` の `HANDOFF_TEMPLATE` が雛形として持つため、flow-id 5-3 のリセットを
経たHANDOFF.mdには必ず6行が揃っている。**タスクごとにAIエージェントが書き起こさない。**

#### ヘッダブロック（探索範囲）

`set-header` と `- 現在のループ:` 行の読み書きは、**ヘッダブロック**の中だけで行う。

> ヘッダブロック = ファイル先頭から、**最初に現れる「`## フロー進捗状況`」以外の `## ` 見出し**の
> 直前まで。`## ` 見出しが1つも無いファイル（テスト用の最小フィクスチャ等）では全体。

- 「やったこと」節などで `- PR: …` のように**引用された行を書き換えない**ため。
- 打ち切りは `## フロー進捗状況` 見出しの有無に依らない。見出しが無いときだけ全体へ広げると、
  まさに防ぎたい取り違えが残る。
- ヘッダブロックが見出しの**前**にある版と**後**にある版が履歴上どちらも存在する
  （実測: 後23断面／前9断面）ため、開始位置はファイル先頭に置いて両方を拾う。
- **周回数の読み取り（`resolve_loop_rounds_to_reply`）も同じ範囲に限る。** 書き換え側だけを
  限定すると、引用行から周回数を拾って誤った値がヘッダへ書かれる（周回数の記録場所はヘッダの
  1行だけなので、誤読した値がそのまま唯一の正になる）。

#### 書き換え対象が見つからないときの扱い（スクリプト全体の方針）

**書き換えを求められた対象が見つからなかった場合、このスクリプトはファイルを書き戻さずに非0で
終了する。**「呼び出しは成功したが、ファイルは期待した状態になっていない」状態を作らない。

issue #66以前は `set-header` だけがこの方針から外れており、`- Draft PR:` 表記のファイルに対して
`set-header --pr` を実行すると、**1件も書き換えないまま終了コード0を返して**いた。エラーも警告も
出ないため、AIエージェントは更新できたと誤認する。`mark-done` は当初から想定数と一致しなければ
失敗していたので、`set-header` をそれに揃えた形である。

**`mark-skip` が作りうる「不整合」（ループ範囲の一部だけが `[-]` になる状態）は、この方針の
射程外である。** そちらは「対象が見つからない」のではなく「指示どおり書き換えた結果がルールに
反する」ケースで、正しい挙動自体がまだ決まっていない。issue #140 で扱う（下記「制約・設計判断」）。

### ヘッダの「- 現在のループ:」行（issue #58）

issue #58以前は、レビュー往復1回につき`[]`を1つ足して`[x][x][]`のように周回数を表していた。この表記
には3つの読みにくさがあった。

1. 周回数を得るのに同一トークンの数え上げが必要で、往復が増えるほど誤読しやすい（LLMが最も誤りやすい処理）。
2. 周回数は本来ループ範囲につき1つの値なのに、範囲内の全行（最大4行）へ同じ文字列が複製される。
3. `[]`が「未着手」と「進行中」を兼ねており、末尾の`[]`がどちらなのか表から判別できない。

そこで**この表記そのものを廃止し**、周回数と進行状態をヘッダの1行だけで持つことにした。進捗表は
どの行も記号1つになる。

```
- 現在のループ: 3-6〜3-9 の3周目（進行中）
```

- 書式は`<開始flow-id>〜<終了flow-id> の<N>周目（進行中|完了）`。ループ範囲の外にいる間は
  `- 現在のループ: なし`と書く（`set-header --loop 'なし'`）。
- **周回数の記録場所はこの1行だけで、進捗表には持たせない。** `add-round`は現在の周回数を読んで+1し、
  範囲の記号を`[]`へ戻す。ループ範囲への`mark-done`は周回数を据え置き、記号を`[x]`・状態を（完了）に
  する。二重管理にならないため、表とヘッダが食い違う経路が無い。
- 行の解析は先頭flow-id（`3-6`）と周回数（`3`）だけを取り出す。**ループ範囲は互いに素なので先頭
  flow-idが範囲の識別子になる。** ヘッダが別のループ範囲を指していれば、周回数は引き継がず1周目から
  数え直す（範囲が切り替わったということなので）。範囲の区切り文字`〜`は正規表現へ書かず`.*`で
  読み飛ばす（多バイト文字をパターンへ持ち込まない）。
- **旧`[x][x][]`表記からの移行は自動で行う。** ヘッダ行が無い（または別の範囲を指す）場合、周回数は
  進捗列の記号の個数から読み取る。`[x][x][]`に`mark-done`すれば「3周目（完了）」がヘッダへ移り、
  進捗列は`[x]`へ畳まれる。新表記では記号1つ=1周目なので、移行済みのファイルでは常に1が読まれる。
- 行が存在しない`HANDOFF.md`でも、次の`add-round`／`mark-done`で自動的に挿入される。挿入位置は、
  ヘッダブロック内のヘッダ項目（`- issue:`/`- ブランチ:`/`- PR:`/`- push回数:`）のうち最後の行の
  直後。ヘッダ項目が1つも無ければ`## フロー進捗状況`見出しの**直後**へ、前に空行を1つ添えて
  挿入する（issue #66以前は見出しの**直前**へ挿入していたが、実物のHANDOFF.mdはヘッダブロックを
  見出しの下に置くため、`- 現在のループ:`だけが他のヘッダ項目から切り離されていた）。
  `- 追従監視:`は挿入位置の基準にしない（`- 現在のループ:`より後ろに置く項目のため）。
- `mark-skip`は追従の対象にしない（ループ範囲を丸ごと`[-]`にした場合、周回数という概念が当てはまら
  ないため）。

### 制約・設計判断

- **ループ範囲は「1周（レビュー往復1回）が完全に完了して初めて`[x]`にする」という設計であり、
  範囲内の一部ステップだけを個別に完了扱いにすることはできない。** `mark-skip`で範囲内の一部を
  先に`[-]`にすると、その後の同じ範囲への`mark-done`/`add-round`は「末尾が`[]`でない」エラーで
  拒否される。これは実装のバグではなく、`.claude/rules/docs-workflow.md`の「同じループ範囲内の
  ステップは常に同じ記号を持つ」というルールを機械的に強制した結果であり、意図した挙動である
  （実機確認: issue #20対応中、前issue #13のHANDOFF.mdがこのルールに反する手作業更新をしていた
  ことがこの過程で判明した）。
  - ループ範囲の一部だけ実施し残りを省略する場合（非対話的実行環境でのレビュー省略等）は、進捗記号を
    `[]`のまま残し、実施した内容は「やったこと」等の文章セクションで補足する運用とする。
  - **ただしこの強制は、「不整合を作る操作」ではなく「その後の正当な操作」のほうを拒否する形で
    働いている。** `mark-skip`で範囲の一部を`[-]`にした時点では何も言わず、次に同じ範囲へ
    `mark-done`/`add-round`を実行して初めて表面化する。この点をどう改めるか（伝播させる／入口で
    エラーにする／現状維持）は**issue #140で扱う**。issue #66で入れた「書き換え対象が見つからなければ
    非0で終了する」方針の射程外であり、#66では`mark-skip`の挙動を一切変更していない
    （切り分けの理由: `.claude/docs/ddr/i0066-01-HANDOFFのヘッダ表記を1つに定めset-headerは見つからなければ失敗させる.md`）。
- ヘッダ各項目（issue/ブランチ/PR/push回数/現在のループ）は1行である前提で実装している。説明の
  補足等で2行目以降に折り返している場合、`set-header`は1行目のみを書き換え、2行目以降はそのまま残る。
- **進捗表から周回数を消したことで、過去の周が何回完了したかは表から追えなくなる。** `[x][x][]`は
  「2周完了して3周目が進行中」という履歴を持っていたが、新表記のヘッダは現在地だけを表す。履歴が
  必要な場合はブランチ上のcommit履歴（HANDOFF.mdの差分）を見る。読み取りの確実さを履歴性より優先した
  判断であり、issue #58のレビューで方針として確認した。
- 進捗表の書き換えは、Markdownテーブル行を正規表現でprefix（進捗列より前）・progress（進捗列の
  中身）・suffix（進捗列より後、flow-id列を含む）の3区画へ分解し、単純な文字列連結で再結合する
  方式を採る。bashのパターン置換（`${line/pattern/repl}`）は使わない。`[x]`のような進捗記号が
  globの文字クラスとして誤解釈される事故を避けるためである。
- **ヘッダ行の追従に失敗しても`mark-done`/`add-round`自体は成功させる**（警告を標準エラーへ出し、
  進捗表の更新はそのまま書き戻す）。挿入位置を持たない変則的な`HANDOFF.md`（テスト用の最小
  フィクスチャ等）で記号の更新まで巻き戻すより、書き戻せた分だけでも状態が前へ進むほうが正しいため。
  一方、`set-header --loop`はユーザーが明示的にその行を求めているので、書けなければエラーにする。
- HANDOFF.mdを直接テキスト処理で書き換える方式を採用し、進捗状態を別のJSON/YAML等の構造化
  データへ移行する設計は採らなかった。既存の`HANDOFF.md`の構成（見出し・表の列）を人間にも読み
  やすいMarkdownのまま壊さない、という要件を素直に満たせるため。

### issue #58（2026-08-19）周回数を進捗表からヘッダの1行へ移す

- 旧表記のHANDOFF.mdは、次の`add-round`／`mark-done`で自動的に移行する（記号の個数を周回数として

- `.claude/skills/issue-mr-flow/SKILL.md`: `add-round`／`mark-done`の説明を新しい意味へ更新した。

### issue #66（2026-08-20）ヘッダ行の表記を確定し、set-headerを無言で成功させない

- **`set-header`が、指定した項目のヘッダ行がちょうど1件見つからなければ、ファイルを書き戻さずに
  非0で終了するようにした。** 項目オプションを1つも指定しない呼び出しもエラーにした。
- **ヘッダ行の探索範囲を「ヘッダブロック」へ限定した。** 「やったこと」節の引用行を書き換えなくなる。
  周回数の読み取り（`resolve_loop_rounds_to_reply`）も同じ範囲に限った。
- **`- 現在のループ:`行の挿入位置を、見出しの直前から見出しの直後（ヘッダブロックの中）へ変えた。**
  実物のHANDOFF.mdはヘッダブロックを`## フロー進捗状況`の下に置くため、変更前はこの行だけが
