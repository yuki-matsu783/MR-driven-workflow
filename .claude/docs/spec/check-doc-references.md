# DDR参照切れ検出（check-doc-references.sh）

## 背景・目的

issue #171「`.gitignore`のコメントが存在しないDDRファイル名（`i36-01`）を指しているのを直し、
同種の参照切れを検出できるようにする」。

issue #133でDDRの識別子をissue番号ベース（`i0000-01`形式）へ一括改番した際、ファイル**名**は
改番されたが、ドキュメント本文に書かれた**参照文字列**（`.gitignore`のコメント等）は改番の
対象に含まれず、古い識別子のまま取り残された。この種の取りこぼしは、ファイル移動・改名・削除の
たびに再発しうるが、これまで機械的な検出手段が無く目視に頼っていた。

意思決定の背景・実装が2回の敵対的レビューを経て変遷した経緯は
[DDR i0171-01](../ddr/i0171-01-DDR参照切れ検出は絶対パス形式に限定しgrep一括抽出で実装する.md)
を参照する（本specは「現在の仕様」のみを記載し、変遷の経緯は繰り返さない）。

## 仕様

### 呼び出し

```bash
bash .claude/scripts/src/check-doc-references.sh
```

引数を取らない。スクリプト冒頭で`cd "$(git rev-parse --show-toplevel)"`しリポジトリルートを
起点に走査する。**実行タイミングは手動実行のみ**で、hook・CI等への自動組み込みは行わない
（DDR i0171-01「決定」3参照）。

### 検出対象

`git ls-files`（追跡ファイル全件からバイナリを除く）のうち、次の4ディレクトリ配下を除いた
すべてのファイルを走査する。

| 除外ディレクトリ | 理由 |
|---|---|
| `.claude/scripts/test/` | 単体テストのフィクスチャが検証用に架空のDDRパスを含むため |
| `plans/` | タスク単位（flow-id 5-4）で削除される短命ファイルのため |
| `reports/` | 同上 |
| `worklog/` | 同上 |

各ファイル中の、次の形式に一致する文字列を候補として抽出する。

```
.claude/docs/ddr/i<issue番号（桁数不問）>-<枝番（桁数不問）>-<任意の文字列>.md
```

- 終端は半角空白・実際のタブ文字・`)` `]` `"` `'` `` ` `` `(` のいずれかの直前、または文字列
  末尾までの**貪欲マッチ**。DDRファイル名自体に`.md`という文字列を含むケース
  （例: `i0032-01-…Default.mdを正とし….md`）でも、最後の`.md`まで正しく候補に含める。
- 正規表現の文字クラスには**ASCII文字のみ**を用いる（多バイト文字を含めない）。理由は
  「ロケール依存の罠」参照。

### 除外フィルタ

抽出した候補のうち、次のいずれかに該当するものは実在確認の対象から除外し、除外件数を
サマリへ計上する。

1. **コードフェンス内**: CommonMark方式のフェンス（`` ``` `` または`~~~`、3文字以上）で
   囲まれた行にある候補。開始行と**同じマーカー種別・同じ長さ以上**の行でのみ閉じたと
   みなす。ファイル末尾までフェンスが閉じなかった場合は、**そのフェンス内の行を除外しない**
   （安全側。フェンスの誤判定で実在の参照切れを見逃さないため）。
2. **省略記法を含む候補**: 候補の文字列中に`...`または`…`を含むもの（例示・省略を表す記述で
   あり、実在するパスを指す意図ではないため）。

### 連結候補の分割（ASCII構造による後処理）

全角の句読点等（例: `。`、`、`）で2つの参照が直接連結されている場合、貪欲マッチにより1つの
候補として抽出されることがある。この場合、候補文字列の中に`.claude/docs/ddr/`という接頭辞が
2回目以降も出現するかどうかだけを見て分割する（`split_concatenated_candidates_to_reply`）。
判定はASCII文字列の部分一致のみで行い、連結に使われた文字そのもの（全角か半角か、どの記号か）
は問わない。

### 実在確認と出力

除外を通過した候補について`[[ -f "$path" ]]`で実在確認する。存在しない場合は参照切れとして
`file:lineno:path`形式で標準出力へ1行ずつ出力する。

標準エラーへ、次の3行のサマリを出力する。

```
走査ファイル数=<N>（除外ディレクトリ配下=<N>、削除済み未ステージのためスキップ=<N>）
候補数=<N>（フェンス内除外=<N>、省略記法による除外=<N>）
参照切れ数=<N>
```

- 「削除済み未ステージのためスキップ」は、`git ls-files`が返すがワーキングツリーに実体の
  無いファイル（追跡済みファイルを削除したがまだステージしていない状態）の件数。
- **走査対象ファイルが0件の場合はエラーメッセージを出力し、終了コード1で終了する。** 除外
  フィルタの設定ミス等で対象が空になる異常を、「参照切れ0件」という正常終了と区別するため。

### 終了コード

| 終了コード | 意味 |
|---|---|
| `0` | 走査を実行し、参照切れが0件だった |
| `1` | 参照切れが1件以上あった、または走査対象ファイルが0件だった |

### 実装方式

候補抽出は、`git ls-files -z`で得たファイル一覧を`xargs -0 grep -nHoE`へ1回で渡す一括抽出
方式を採る（bashの`while read`ループで1行ずつ`[[ =~ ]]`判定する方式は採らない）。理由は
DDR i0171-01「理由」2参照（実測: リポジトリ全体約37,000行に対し5.2秒→0.96秒）。

`-H`（ファイル名を常に出力するオプション）は、GNU grepが単一ファイル引数の場合に既定で
ファイル名列を省略する挙動を避けるために必須。

## ロケール依存の罠

**この実行環境（`LANG`未設定のPOSIXロケール）では、POSIX ERE のブラケット式（`[...]`）へ
多バイト文字を直接含めると、`grep -E`・bashの`[[ =~ ]]`のいずれも、パターン全体がリポジトリ
全体に対して一致しなくなることがある**（実機確認: 全角句読点1文字を終端文字クラスへ追加した
ところ、候補抽出結果が121件から0件へ落ちた）。詳細・再発防止のための一般規約への反映は
`.claude/rules/shell-script-style.md`「文字コード」節を参照。

## 影響範囲

- 新規ファイル。既存スクリプト・既存フローへの変更は無い。
- 対象は`.claude/docs/ddr/`配下のDDRファイルパスへの**絶対パス参照のみ**。パスを伴わない
  裸の識別子表記、相対パス表記（`../docs/ddr/…`等）は検出しない（下記「未決定事項」）。

## 設定項目

無し（引数を取らない。除外ディレクトリ・正規表現はスクリプト内の定数）。
