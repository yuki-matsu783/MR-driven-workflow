# 対応工数を把握する

## どんな場面か

このissue対応に実際どれだけかかったのか——セッションのトークン使用量・作業の往復回数を、
pushの区切り（レビュー依頼の単位）ごとに振り返りたい場面。

## 使う機能と流れの概要

- **集計は自動で走る。** pushを検知するhook（post-push-usage-report.sh）が、pushのたびに
  セッションログの新規分を集計し、ブランチ別の状態（`usage/` 配下。Git管理外）へ累積する。
  人が起動する操作は無い。
- **push断面の振り返り**には show-push-log.sh を使う。push断面はログ全文のコピーではなく
  行番号インデックス（どのpushがログのどの範囲に対応するか）で表現されており、断面ごとの
  内容を後から取り出せる。
- **より細かい生データ**が要る場合は、OTelリスナー機構がClaude Code公式のテレメトリを
  `usage/` 配下へ日別に振り分け保存している（関連機能。工数レポートとは別系統）。

## 何が得られるか

- pushごと（＝レビュー依頼ごと）の工数が、作業を止めずに自動で記録される。
- 「このフェーズのレビュー往復に何回・どれだけ使ったか」を、ブランチ単位の状態ファイルから
  振り返れる。
