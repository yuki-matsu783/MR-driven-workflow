# レビューをAIに補助してもらう

## どんな場面か

pushされた計画や実装を自分でレビューする前に、機械的に見つかる欠陥（検証の空振り・md/htmlの
不整合・数の誤り・規約違反など）をAIに先へ拾わせて、人間のレビューを本質的な判断に集中させたい
場面。

## 使う機能と流れの概要

- 人間が `/adversarial-review` を呼ぶと、独立したコンテキストの専任サブエージェントが起動する。
  サブエージェントには差分・ファイルパス・マージ済みのレビュー観点表だけが渡され、「なぜそう
  実装したか」の経緯は渡されない（実装者の文脈に引きずられないため）。
- 見つかった指摘はfindingsとして重大度・確度つきで返り、基準を満たすものがPR/MRへインライン
  コメントとして投稿される（本文は「Claude Codeより（敵対的レビュー）:」で始まる）。
- レビュー観点はスキル本体ではなく各ディレクトリの `REVIEW-POINTS.md` に置かれ、`review-points`
  スキルが対象ファイルの祖先を遡って収集・マージする。観点を育てれば敵対的レビューも人間の
  レビューも同じ表で強くなる。
- 対話セッションではAIから自律起動しない（レビューの主体が人間であるという前提を崩さないため）。
  回数は各フェーズ最大3回に機械的に制限される。

## 何が得られるか

- 人間のレビュー前に、観点表ベースの欠陥探しが済んだ状態のPR/MRになる。
- 指摘はスレッドとして残り、通常のレビューコメントと同じ往復（対応・返信）に合流する。
