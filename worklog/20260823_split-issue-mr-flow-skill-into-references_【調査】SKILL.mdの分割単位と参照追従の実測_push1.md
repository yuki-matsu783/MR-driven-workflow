# worklog: 【調査】SKILL.mdの分割単位と参照追従の実測

対象: issue #160（`issue-mr-flow/SKILL.md` の `references/` 分割）のフェーズ2〈調査〉（2026-08-23）。
全体作業計画: `plans/split-issue-mr-flow-skill-into-references.md`
個別調査計画: `plans/【調査】SKILL.mdの分割単位と参照追従の実測.md`
push回数: 1

## 試したこと

- **A-1**: Pythonで見出し行の行番号から範囲を算出し、`len(body.encode())` でバイト数を出した。
  フェンス（```）内の `#` を見出しとして数えないよう、トグルで除外している。
- **A-2**: `下記「〜」` `上記「〜」` `](#anchor)` を正規表現で抽出。**改行をまたぐ表記があるため、
  一度 `\n` を `\x01` へ置換した全文に対して照合し、位置から行番号を逆算した**（行単位の
  `grep` では `層の番号は『…』であって、実行順では\n  ない` のような折り返しを取りこぼす）。
- **A-3/E**: 分割案（案1: いつ読むか／案2: サイズ4分割）を辞書で定義し、参照元・参照先の節を
  ファイルへ写像してファイルまたぎ件数を数えた。あわせて flow-idごとの読み込みバイト数を算出。
- **B**: `grep -rn` → `git grep` へ切り替え（下記「ダメだったこと」）。節名を伴う参照は、
  `issue-mr-flow/SKILL.md` の直後140文字以内に現れる `「…」` を拾う形で抽出した。
- **C-1/C-2**: 進捗表を解析する試作関数を書き、実データ（本ブランチの `HANDOFF.md`）と
  3種の合成フィクスチャ（表なし／全行未着手／`[-]` 混在）に対して実行した。
- **C-3**: ヘッダ行から `参照` を含む列の位置を求める awk を、サンプルの表に対して試した。
- **D-1**: `sed '584,606d'` で `describe` 節を落とした SKILL.md の写しを作り、テストの
  `describe_headings()` と同じ awk を両方に対して実行して 3行 → 0行 を確認した。
- **D-2**: `mktemp -d` ＋ `git init` した一時ディレクトリへ `sync-assets.sh` →
  `install-to-project.sh -f` を実行し、配布先の `.claude/skills/issue-mr-flow/` を `find` した。

## うまくいったこと

- **A-3 が「案を選べない指標」だと分かったこと。** 案1・案2ともファイルまたぎ39件で同数だった。
  数えてみるまでは「いつ読むかで切ればまたぎが減る」と見込んでいたが、またぎの過半が
  「全体フロー表 → 詳細節」で、**分割という操作そのものの帰結**だった。判断材料を
  E-2/E-3（flow-idごとの読み込みバイト数）へ移せたのは、この空振りのおかげである。
- **C-1 で、計画に書いた方式（最初の `[]`）がその場で否定できたこと。** 本ブランチの
  `HANDOFF.md` が既に反例（1-5 が `[]` のまま 1-6 が `[x]`）になっていた。
  「最後の `[x]`/`[-]` の次の `[]`」へ変えると正しく `2-1` を返す。
- **C-0（DDR i0113-01 との整合）で、非対称性という論点が見つかったこと。** 同じ材料でも、
  失敗したときに失うものが「手順まるごと」か「1行」かで判断が変わる。これはDDRへ残す。

## ダメだったこと

- **`grep -rn` の母集団が倍になっていた。** D-2 で `sync-assets.sh` を実行した直後に B を
  測り直したところ、209箇所が398箇所へ増えた。原因は
  `.claude/skills/apply-mr-workflow-to-project/assets/`（リポジトリ全体の複製・`.gitignore` 対象）。
  **`git grep` へ切り替えて解決。** 「調査の実行順で測定値が変わる」という形の事故で、
  順序が逆なら気づけなかった。
- **`install-to-project.sh` が最初に失敗した。** 配布先がgitリポジトリでないと
  `Target directory is not a Git repository` で拒否される。`git init` を足して解決。
- **`grep -o '下記「[^」]*」\|…'` が1件しか返さなかった。** シェル経由のエスケープと
  多バイト文字の組み合わせで壊れていた。Pythonへ移して54件を得た
  （`.claude/rules/shell-script-style.md`「AIエージェント向け注記: バックスラッシュが1つに潰れる」
  と同根）。
