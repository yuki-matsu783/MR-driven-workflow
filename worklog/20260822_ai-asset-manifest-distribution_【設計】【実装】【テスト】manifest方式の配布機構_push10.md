# worklog: 敵対的レビュー2回目の反映

対象: issue #26 フェーズ3（2026-08-23）。push回数: 10。
結果の正文: `reports/20260822_ai-asset-manifest-distribution_manifest方式の実装結果.md`

## 試したこと

- 指摘14件のうち、**先にユーザーへ判断を仰いだ2件**（`HANDOFF.md`/`index.md` の雛形、
  本家で削除されたファイルの追従）を除く**8件＋報告のみ4件のうち3件**を反映した。
- 反映の順序は「blocker → その原因である `set -e` → 残り」。原因が共通する指摘は、
  **深いほうから直すと浅いほうが自然に消える**（後述のとおり、消えすぎて検出できなくなった）。

## うまくいったこと

- **`|| return 1` を外すだけで `set -e` が正しく効いた。** `apply_pass` 等はグローバル変数へ
  結果を書くのでサブシェルで包めず、規約が挙げる2つの対処
  （明示サブシェル／各コマンドの終了コード検査）のどちらも重い。しかし `main` 自体が
  `if [ ... ]; then main "$@"; fi` の**then節**から呼ばれている（条件式ではない）ため、
  素で呼べば `set -e` が関数の内部まで正しく効く。**規約が禁じているのは「条件式の中で呼ぶこと」
  であって、`|| return 1` を別の何かへ置き換えることではない。**
- **`upstream` の印を落とす処理を、パスの直書きではなく定数 `DEF_REL` の比較にした。**
  `DEF_FILE` が既に `${UPSTREAM_ROOT}/${DEF_REL}` なので、定義ファイルの位置を変えても
  1箇所の変更で追随する。
- **`git` の `:(exclude)` pathspec** で、未追跡ファイルの件数から `exclude` 層の配下を
  除けた。自前で接頭辞判定を書かずに済む。

## ダメだったこと

- **自分で書いた回帰テストが、blockerを検出できていなかった。** `set -e` の修正だけで
  「中断する」「0バイトにしない」の両方が満たされてしまうため、blocker修正（jqの終了コード検査）
  を単体で戻してもテストが通る。**両方戻して初めて `actual: 0`（0バイト）で落ちた。**
  - 教訓は前回（push9）と同じで、**「検出できることを確かめる」検証は、検証自体が正しいかを
    もう一段確かめないと意味を持たない。** 今回は「戻して落ちるか」を実際に流して初めて分かった。
  - テストとしては**この形のままにした**。多重防御のどちらか一方が生きていれば通る、という
    表明で正しいためである（片方だけを戻して落ちないのは仕様）。ただし
    **「両方戻すと落ちる」ことまで確かめたという事実は残す**必要があり、それがこの節である。
- **フィクスチャの高速化は空振りだった。** 186ファイルの写しを `cp` ループ（370回以上のfork）
  から `tar` 1回へ変えたが、所要時間は66秒→65秒でほぼ変わらなかった。**支配的なのは
  インストーラ自身が毎回160ファイルを `cp` していること**で、テストが12回適用すれば
  約2000回のforkになる。規約に沿った変更ではあるので戻さないが、**測らずに「速くなった」と
  書かなくてよかった**。
- 検証コマンドの実行が2分のタイムアウトに当たった。テスト1本で65秒かかるようになっており、
  「戻して流す → 復元して流す」を1コマンドに繋ぐと超える。**復元は流す前に済ませる**。
