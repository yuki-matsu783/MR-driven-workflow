## 試したこと

### 敵対的レビューの実施と投稿

- `adversarial-review` スキルの手順に沿って `adversarial-reviewer` を起動した。渡したのは
  対象ファイル一覧・マージ済み観点表・フェーズ番号の3つだけで、**設計意図と経緯は渡していない**。
- プロンプトで1点だけ強く指示した:「**レポートが引用している行番号・定数値・スキーマ定義が実際に
  そのとおりか、原典に当たって確かめること**」。今回の成果物は「一次情報を読んだ」ことが価値の
  中心なので、引用が事実と違えば全体の信頼性が崩れるため。
- 結果は21件。**この指示が効いた**——21件中、行番号・定数・引用元の突き合わせから出た指摘が
  半数以上を占めた。
- 実施回数カウンタ（`adversarial-review-count.sh increment 2`）は投稿の前に加算した（戻り値1）。
- 投稿は `get_vcs_access_mode` が `mcp` を返す環境なので、MCPの3ステップ
  （`create` → `add_comment_to_pending_review` ×10 → `submit_pending` with `event="COMMENT"`）で
  行った。`delete_pending` は使わずに済んだ。

### 指摘の裏取り

投稿前に、最も重い blocker を原典で確認した。

```bash
grep -n 'commandRegex\|decision = ' docs/reference/policy-engine.md
#   33: decision = "deny"
#  325: commandRegex = "git (commit|push)"
```

**指摘は正しかった。** レポートは「Geminiにコマンド文字列パターンでの拒否に相当する設定は無い」と
書き、しかも根拠記号 **S（ソースコードで確定）** を名乗っていた。実際には policy engine に
そのままの機能がある。

反映前に残り6件（`CLAUDE_PROJECT_DIR` エイリアス／環境変数の解決タイミング／matcher の定義／
`write_todos`・`invoke_agent`／`PostToolUse` の2グループ／skills 9件の `description`）も
まとめて確認し、**すべて指摘のとおり**だった。

## うまくいったこと

- **置換スクリプトに「元の文字列がちょうど1回現れること」の検証を入れた。** 26件＋22件＋2件の
  置換を3本のスクリプトに分けて流したが、1件も取りこぼさずに済んだ。前提が崩れていれば
  **1文字も書き込まずに落ちる**ようにしてあるので、部分適用で壊れた状態が残らない。
- **撤回した数値・断定を、黙って書き換えずに「撤回する」と明記して残した。**
  「94箇所」「217箇所」「約190ms」「10項目すべて正しい」の4つが該当する。レポートは
  flow-id 5-5（繰り下げ後）で削除されるが、その前に読む人にとっては
  「なぜ数字が変わったか」が分かるほうが価値がある。
- **根拠記号に R（このリポジトリのソースを読んだ）を新設した。** M（実測）の定義は「コマンドを
  流して測った」なのに、実際には3箇所が「スクリプトを読んだだけ」で M を名乗っていた。
  記号を1つ足すだけで、この種の緩みが構造的に起きなくなる。
- **M に測定環境を紐づけた。** `0.603s` はこの環境（Linux / bash 5.2.21 / jq-1.7）の値で、
  同じ節で引用していた `95ms/回` は **Windows git bash** の値だった。異なる環境の数字が
  足し合わされていたので、両方に環境を明記した。

## ダメだったこと

- **HTMLの同期で1箇所取りこぼした。** Q6の表にある `L32–34` は置換リストに入れていたが、
  Q4の副作用表にも同じ文字列があり、そちらが残った。`grep` で撤回済みの文言を検索する
  検証を後から流して見つけた。**「md側で直した箇所」からHTML側の置換リストを作ると、
  HTML固有の重複を見落とす。** 反映後に**撤回した文言そのものを検索する**のが確実。
- **敵対的レビューの投稿上限（10件）で6件が溢れた。** 溢れたのはすべて `minor`×`high` で、
  内容としては投稿対象だったもの。会話へ報告したが、**PR画面には残らない**。
  レポート側には反映してあるので実害は無いが、上限の設計上こうなることは意識しておく。
