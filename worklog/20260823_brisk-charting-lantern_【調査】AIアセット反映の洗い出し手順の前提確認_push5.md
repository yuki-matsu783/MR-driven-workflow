# worklog: 【調査】AIアセット反映の洗い出し手順の前提確認（敵対的レビュー2回目への対応）

対象: issue #155 フェーズ2〈調査〉の作業実施に対する敵対的レビュー（2026-08-23）。
全体作業計画: `plans/brisk-charting-lantern.md`
個別作業計画: `plans/【調査】AIアセット反映の洗い出し手順の前提確認.md`
push回数: 5

## 試したこと

- `adversarial-reviewer` サブエージェントを調査結果レポート（md/html）へ実行し、**18件**の指摘を得た。
- **18件すべてを実ツリーに対して裏取りしてから**、投稿基準（確度×重大度）と1回10件の上限に従い
  10件をインライン投稿、8件（A〜H）はレビュー本文の表で報告のみに留めた。
- `bash .claude/scripts/src/adversarial-review-count.sh increment 2` → **2**（フェーズ2の残り1回）。
- 18件すべてを修正し、HTMLをmdから再生成した。

## うまくいったこと

- **裏取りの過程で、指摘そのものの誤りを2件見つけた。**
  - 除外規定の位置は指摘の「161-163行」ではなく **162-166行**（`対象に含めない` は164行）。
  - 広めのgrepのヒットは「11箇所」ではなく **7行**。
  返信・レポートには実測値を書いた。
- **`doc-search` の `matched=0` を単独の打ち切り条件にすると偽陰性になる**ことを実測で確かめられた。

  ```
  bash .claude/scripts/src/search-frontmatter.sh --text 'AIアセット反映' --format count  # matched=1
  grep -rl 'AIアセット反映' --include='*.md' . | wc -l                                     # 7
  ```

  frontmatterのキーしか見ないため、本文にある記述を拾えない。打ち切り条件を
  「`doc-search` で `matched=0` **かつ** `grep -rn` でも0件」の2段へ直した。
- **md→HTML変換のバグ（コードスパン内の `**` を強調として解釈する）を、変換側で直せた。**
  `` `**/REVIEW-POINTS.md` `` がHTMLでだけ崩れていた。コードスパンを先に退避してから
  `**bold**` を適用する順序にした。

## ダメだったこと

- **Q2のスキップ条件の書き直しが、そのままでは設計の後退になっていた。**
  「手順1〜2まで実施して分類結果が0件」とだけ言い直すと、**スキップ条件の主語がAIアセットだけへ
  狭まり**、spec/ddr・実装コードの反映有無が条件から抜け落ちる。3つの連言を保つ形
  （「spec/ddr・実装コード/テストコードに反映するものが無く、**かつ**AIアセット側は手順1〜2まで
  実施して分類結果が0件だったとき」）へ直した。**言い換えの対象が連言の一項だけでも、
  文全体の主語が変わっていないかを確認する必要がある。**
- **Q1(2)（4-6行の列挙へ項目を足す）とQ7（6形態を認める）が矛盾していた。** 列挙を行に残したまま
  項目を足すと、行内の列挙と新設する節とで反映先の一覧が二重管理になる。**列挙は節へ移す**方針へ
  変えた。
- **Q7の結論に対して、除外規定（164行）の書き換えを見落としていた。** `scripts`/`hooks` を反映先に
  含めると決めた以上、除外の主語も同時に直さないと片手落ちになる。編集対象は4箇所ではなく
  **5箇所**になった。
- **Q8の「版を上げれば打ち消せる」が実装で成り立たなかった。** `install-to-project.sh` は
  `.claude/VERSION` を `ALWAYS_OVERWRITE_RELPATHS` で上書きコピーするだけで、版の差分に応じて
  配布先を消す処理も通知する処理も持たない。**版上げは追跡可能性のためだけ**と書き直し、
  実害の解消は別issueの範囲として残課題へ移した。

## 学び（次回以降に効くもの）

- **レビューの指摘に含まれる行番号・件数は、必ず自分で数え直してから採用する。** 今回2件外れていた。
  数え直しのコストは `grep -n` 1回で、誤った数値をドキュメントへ固定する損失と非対称である。
- **自分が根拠として載せた実測出力の中に、自分の結論の反例が混ざっていることがある。**
  列挙漏れの指摘で `GEMINI.md` を落としていたが、その行はQ3で自分が貼った `doc-search` の出力に
  含まれていた。**出力を貼ったら、その出力を自分の結論に対して読み返す。**
