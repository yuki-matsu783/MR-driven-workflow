# worklog: 【実装】【テスト】コマンド位置判定ライブラリとhookへの適用

対象: コマンド位置判定ライブラリの実装と3つのhookへの適用（2026-08-20）。
全体作業計画: `plans/hook-command-position-detection.md`
個別作業計画: `plans/【実装】【テスト】コマンド位置判定ライブラリとhookへの適用.md`
push回数: 2

## 試したこと

- 正規化＋トークン走査の2段構えで `CommandPosition.sh` を書き、単体テスト54件を先に列挙してから
  合わせ込んだ。初回は 50/54 で、落ちた4件から4つの独立した不具合が出た。
- ライブラリを3つのhookから `${BASH_SOURCE[0]%/*}/lib/…` で `source` する形にした
  （`CLAUDE_PROJECT_DIR` はpush検知hookでは判定より後に解決されるため使えない）。
- CRの影響を、スタブ `jq` をPATHの先頭へ置いて20ケースで再実測した。

## うまくいったこと

- **期待値の表（20ケース）を先に固めてから実装した。** 「クォートを外す」だけの素朴な実装なら
  受け入れ条件は満たせるが、`bash -c` / `eval` / `$( )` / `xargs` / `find -exec` が素通りする。
  表があったので、実装のどの段階でも「いま何件落ちているか」で判断できた。
- **プレースホルダ方式が効いた。** クォート内の文字を残さず `_` へ潰したことで、
  「引用された文字がコマンド位置に来る」経路が構造的に無くなった。テキストを残す案も検討したが、
  `sudo` の sticky と組み合わせたときに `time echo "git commit"` が誤検知になることが分かって捨てた。
- **CRの吸収を `tr -d '\r'` ではなく判定側でやれた。** `IFS` に `\r` を含めるのと、区切り行の
  比較前に末尾の `\r` を落とすので足りた。forkが増えない。

## ダメだったこと

- **ブラケット式をダブルクォートの中へ直接書いて、バックスラッシュが文字集合から落ちた。**
  `"${rest%%[\'\"#\\\`<]*}"` の `\\` はシェルの段階で `\` になり、続く `` \` `` と合わせて
  「`` ` `` のエスケープ」として消費される。`$'...'` で組み立てた変数をクォートせず展開する形へ変更。
- **`<<<"str"` をヒアドキュメントと誤認した。** `<` を1文字ずつ返していたため、残った `<<` を
  次の走査が拾った。3文字まとめて消費する形へ変更。
- **`bash` を無条件のフォールバック対象にして、受け入れ条件のケースを落とした。**
  `bash .claude/scripts/src/create-commit.sh --message "…"` がフォールバック対象になり、
  常用の呼び出しがブロックされる。コード指定オプションと併用時のみに絞った。
- **透過的なラッパーの扱いが甘かった。** 直後1トークンだけをコマンド位置扱いにしていたので
  `sudo -u alice git commit` が素通りした。次のセパレータまで保つ形（sticky）へ変更。
- **`$( )` 突入時にセパレータを出していなかった。** 空白を1つ出すだけだったので、正規化結果は
  正しいのにトークン走査が `git` をコマンド位置と見なさなかった。`(` を出す形へ変更。
- **作業中に2回、自分でブロックを踏んだ。** どちらもパッチの説明コメントに該当語が入っていただけ。
  この変更が入れば同じ書き方は通るようになる。
