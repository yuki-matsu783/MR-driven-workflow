# worklog: 【実装】【テスト】.gitignoreのDDR参照修正と検出スクリプトの追加（push1）

## 個別作業計画への敵対的レビュー対応

フェーズ3の個別作業計画（`plans/【実装】【テスト】.gitignoreのDDR参照修正と検出スクリプトの
追加.md`・`.html`）に対する敵対的レビュー（1回目、12件のfindings）を受け、全件を実機で
再検証したうえで計画を全面改訂した（v2）。

### 実機再検証で確認した主な指摘（対応済み）

- **blocker: 終端文字集合の`\t`表記が機能しない**。POSIX ERE のブラケット式内では
  バックスラッシュはエスケープとして解釈されないため、`[^]\) "'\`(\t]`は「タブを除く」では
  なく「`\`と`t`の2文字を除く」集合になる。実機確認:
  ```
  $ grep -noE '\.claude/docs/ddr/i[0-9]+-[0-9]{2}-[^]\) "'"'"'`(\t]*\.md' .gitignore
  （マッチ0件、exit 1）
  $ 同じ式から \t を外すと28行目・40行目の2件がヒット
  ```
  ASCIIの`t`がDDRファイル名に高頻度で現れるため（`Git管理下`等）、`t`が終端文字になると
  `.md`まで到達できず候補が1件も抽出されない。検証コマンドは常に「0件＝合格」を返すため、
  **実装が正しくても壊れていても同じ結果になる、検出できない検証**だった。
  対応: 実際のタブ文字（`tab=$'\t'`で変数に格納し埋め込む）へ変更。実機で28行目・40行目の
  2件が正しく検出されることを確認済み。

- **major: `plans/` `reports/` `worklog/`を対象に含めていたため検証3が原理的に達成不能**。
  worklogの前回レビュー対応の記録（`ls .claude/docs/ddr/i0000-13-*.md`というコマンド断片）が
  glob文字`*`を含むDDRパス候補として抽出され、`[[ -f ]]`に失敗する。実機確認:
  ```
  $ grep -noE '...' "worklog/..._push1.md"
  69:.claude/docs/ddr/i0000-13-*.md
  ```
  対応: `plans/` `reports/` `worklog/`を除外対象へ追加（`.html`除外と同じ「短命ファイル」
  理由で整合）。除外後、`total=118 missing=2`（`.gitignore`の2件のみ）と実機確認した
  （プロトタイプスクリプトで検証。詳細は下記「プロトタイプでの検証」）。

- **major: テストから呼べる関数境界が計画に無かった**。`extract_ddr_candidates_to_reply` /
  `is_excluded_target_path` / `is_placeholder_candidate`の3関数と`main`ガードを明記した。

- **major: git bash実機再検証の要否がreportsと食い違ったまま放置されていた**。reportsは
  「git bash実機では未検証」と明記していたが、計画の検証節・やらないこと節のどちらにも
  この点への言及が無かった。対応: 「やらないこと」へ、手動実行のみとする方針を理由に
  git bash実機再検証を見送る旨を理由付きで明記した。

### プロトタイプでの検証

指摘の妥当性を確認するため、scratchpadで検出ロジックのプロトタイプを組んで実機実行した。

```bash
# フェンス除外はawkでトグルし、抽出は real tab + 枝番[0-9]+化した正規表現で行う
tab=$'\t'
total=0; missing=0
while IFS= read -r -d '' file; do
  case "$file" in .claude/scripts/test/*|plans/*|reports/*|worklog/*) continue ;; esac
  [[ -f "$file" ]] || continue
  content="$(awk '/^[[:space:]]*(```|~~~)/{infence=!infence;next} !infence{print}' "$file")"
  [[ -z "$content" ]] && continue
  while IFS=: read -r lineno match; do
    [[ -z "${match:-}" ]] && continue
    case "$match" in *"..."*|*"…"*) continue ;; esac
    total=$((total+1))
    [[ -f "$match" ]] || { missing=$((missing+1)); echo "MISSING $match"; }
  done < <(printf '%s\n' "$content" \
    | grep -noE "\\.claude/docs/ddr/i[0-9]+-[0-9]+-[^]) \"'\`($tab]*\\.md" || true)
done < <(git ls-files -z -- '*.md' '*.sh' '.gitignore')
echo "total=$total missing=$missing"
```

結果: `total=118 missing=2`（`.gitignore`の28行目・40行目のみ）。プロトタイプはあくまで
検証目的の使い捨てで、実装（flow-id 3-6）ではファイル1回読みのbash単独方式（`grep`を使わない）
へ書き直す（計画の「実装上の注意」節を参照）。

  判断し、`[0-9]+`へ変更した。ただし、この変更によって新たな偽陽性が増えないかは
  プロトタイプの`total=118`（変更前の`[0-9]{2}`版と同数の見込み——本リポジトリには枝番が
  1桁・3桁のDDRパス参照が実在しないため、今回のリポジトリでは実害が無いことを確認した）。
- 全角句読点（`、`）による2パス結合の指摘は、実例が本リポジトリに無いことを確認したうえで
  「やらないこと」に留めた（理由を「顕在化しても出力で気づける」に精緻化）。
- コードフェンスの奇数個問題（`.claude/skills/commit/SKILL.md`が11本のフェンス行を持つ）は

  無いが、将来の変更で表面化しうる潜在リスクとして、未閉鎖時は除外しない（安全側）という

### フェンス除外設計のバグと修正

当初、`main`関数の中でファイルを1行ずつ`while IFS= read -r line`で読みながら、同じループ内で
`in_fence`をリアルタイムに更新し、`in_fence`が1のときは`continue`で候補抽出をスキップする
実装（ストリーミング方式）を書いた。しかし、この実装では**フェンスが未閉鎖のままファイル末尾に
達した場合の「除外しない」という安全側の設計を満たせない**ことに気付いた。ストリーミング方式は
1行ずつ処理を確定させていくため、「フェンスが最後まで閉じなかった」と判明するのはファイルを
最後まで読み終えた後であり、その時点では既に`in_fence=1`だった行を`continue`でスキップして
しまった後——スキップした事実を取り消せない。

対応として、以下の2パス方式へ設計変更した。

1. ファイル全体を`content="$(<"$file")"`で一度に読み込む（bash内蔵の変数展開。
   `.claude/rules/shell-script-style.md`「外部プロセス起動のコスト」の対応表
   `cat file` → `$(<file)`のとおり、追加のフォークは発生しない）。
2. `strip_fenced_lines_to_reply`という新しい純粋関数を切り出し、渡された複数行テキストに
   対してフェンストグルの回数を数える。**トグル回数が偶数（正しく閉じている）ならフェンス内の
   行を除いたテキストを返し、奇数（未閉鎖）なら除外を一切行わず入力をそのまま返す**。

この変更により、計画段階のプロトタイプ実測値（`total=118`）から、実装後の実測値
（`候補数=121`）へ3件増加した。差分は`.claude/rules/markdown-frontmatter.md`
（フェンス行11本、奇数個で未閉鎖）に含まれる3件の実在DDRパス参照で、いずれも参照切れでは
ない（`test -f`で実在確認済み）。この3件は、計画段階のプロトタイプ（ストリーミング的な
awkトグル実装）では誤って除外されていた偽陰性であり、今回の設計変更で正しく候補に含まれる
ようになった。
