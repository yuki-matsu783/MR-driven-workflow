### 最も重かったもの: Q2の結論が誤りだった

初版は「マージ済みPRの `reports/*.html` は参照できない（対象ブランチが削除済みで断面を
取得できない）」と書いていたが、**これは確かめずに書いた推測で、実際には取得できた。**

- `mcp__github__pull_request_read` の `get_files` は **squash後の差分**しか返さないため、
  `reports/` の中身が現れない。これを「存在しない」と読み違えていた。
- 正しくは `get_commits` で **squash前の個別コミット**を一覧し、
  `mcp__github__get_file_contents` に `sha=<そのコミット>` を渡すと、
  **片付け（flow-id 5-4）の前の断面**が読める。ブランチが削除済みでも通る。
- 標本3件（PR #80 / #128 / #152）のうち2件にHTMLがあり、**2件とも全文を取得して読んだ**。
  どちらも `<script src="https://cdn.tailwindcss.com">` を使っていた（現行方式と一致）。

**教訓**: 「取得できない」は「取得を試みて失敗した」ときにだけ書ける。今回は
**別の取得経路（`get_files`）が空だったことを、対象の不在の証拠として使ってしまった**。

**副次的な収穫**: 実例2件の構造（ヘッダ帯／h1＋リード／結論カード／表主体の詳細／
次にやること／範囲外・未完了／正文mdへの参照）が取れたので、テンプレートの必須／任意の
根拠が「REVIEW-POINTS.md と SKILL.md の表」の2つから**3つ**に増えた。
また #128 は**1つのHTMLがフェーズをまたいで育っていた**（3-6・4-6 の節が後から追記されている）。
「3-6・4-6 でもHTMLを作る」は md が増えれば html も増える意味であって、
フェーズごとに別ファイルを作る意味ではない、と確かめられた。

### 他に直したもの

- **Q1の除外宣言と軸2が矛盾していた。** 「CDN到達性は主根拠にしない」と宣言しながら、
  軸2の「当てはまる」2件のうち1件がその到達性そのものだった。**閲覧可用性（除外）と
  検証可能性（軸2で使う）を分ける**形へ限定し直し、閾値（3件中1件以上で CDN不利）も明記。
  閲覧可用性由来を全部外しても結論が変わらないことも書いた。
- **軸1に循環論法があった。** 「`reports/REVIEW-POINTS.md` が求める自己完結を満たせない」と
  書いたが、同ファイル31行目は「TailwindCSS CDN**以外**の外部依存が無いか」で
  **CDNは明示的に許可されている**。観点自体が現行方式に合わせて書かれているので根拠にならない。
- **grepの件数が本作業自身のファイルを数え込んでいた。** `git grep` を HEAD 断面
  （`2a72016`）に対して実行する形へ変え、コマンド・SHA・単位（行数）を掲載。P4 は 40→18。
- **パターンに「テンプレート名そのもの」が無く、1箇所を取りこぼしていた。**
  P8 `reports\.template\.html|plans\.template\.html` を足して
  `spec/issue-mr-workflow.md:677` の暫定記述を発見（Q5-1 #11）。
  暫定記述の解除箇所は**2つ**だった。見出しの「（全数）」も外した。
- **改訂対象一覧に「新しく書き足す場所」が無かった。** Q4 で flow-id 1-4/2-1/3-1/4-1 の
  位置を確認しておきながら一覧へ引き継いでおらず、そのまま従うと
  **`plans.template.html` を作ったのに使えと書いてある場所が1つも無い**成果物になる。
  「Q5-1b. テンプレート参照を新設する箇所」を新設。
- **Q4 の 3-6・4-6 を「ずれなし」と判定していた。** 実際は 3-6 が「必要があれば作成する」
  （任意）、4-6 は**HTMLへの言及そのものが無い**。
