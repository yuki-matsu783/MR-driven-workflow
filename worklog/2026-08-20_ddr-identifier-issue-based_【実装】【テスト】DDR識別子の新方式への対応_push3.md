# worklog: 【実装】【テスト】DDR識別子の新方式への対応

対象: DDRの識別子を連番からissue番号ベースへ変更する（2026-08-20）。
全体作業計画: `plans/ddr-identifier-issue-based.md`
個別作業計画: `plans/【実装】【テスト】DDR識別子の新方式への対応.md` /
`plans/【設計反映】DDR識別子の新方式をspecとDDRへ記録する.md`
push回数: 3

## 試したこと

- `ddr_identifier_to_reply` の正規表現を `^(i[0-9]+-[0-9]{2})-` と `^([0-9]{4})-` の2本立てにし、
  新方式を先に判定する形にした。両者は先頭が数字かどうかで排他なので、実は判定順に依存しない。
  それでも順序を決めておいたのは、**今後増えるのは新方式だけ**だからである。
- 枝番の桁数を `{2}` に固定するか `+` にするかを検討した。`+` にすると `i133-1-…` も
  `i133-001-…` も通ってしまい、**同じDDRが表記の揺れで二重に採番されうる**。`{2}` に固定し、
  揺れたものは「DDRではない」として弾く方針にした（単体テストで5パターン確認）。
- 単体テストへ「4桁のissue番号を持つ新方式（`i1234-12`）」と「連番 `0133` と新方式 `i133-01` が
  同一視されないこと」のケースを入れた。issue番号が4桁に達したときに新旧の判別が壊れないかを
  真っ先に疑ったため。

## うまくいったこと

- 単体テストは 13 → 28 アサーションへ増え、全12テストスクリプト（合計664アサーション）が
  `failures=0` で通った。
- `extract-frontmatter.sh` / `search-frontmatter.sh` は**ファイル名の形式に依存していなかった**ため、
  新方式のDDRを何も変更せずに拾えた（`doc-search` から1件で引ける）。
- `resolve-conflict` の類型Aを A-1 / A-2 に分けたことで、「新方式でも残る唯一の衝突経路
  （同一issueの並行作業）」に、改番手順ではなく**並行作業自体を疑う**という別の対処を割り当てられた。

## ダメだったこと

- **追加した単体テストが無出力・終了コード1で落ちた。** 枝番3桁のケースを
  `ddr_identifier_to_reply "…i133-001-…"` と裸で呼んでいたため、関数が1を返した時点で
  `set -e` がテストスクリプト全体を止め、`passed=… failures=…` の行にすら到達しなかった。
  既存テストと同じ `if` の条件式で受ける形へ直した。
  **失敗が「アサーション失敗」ではなく「何も出ずに終わる」形になるのが厄介**で、
  `.claude/rules/shell-script-style.md`「テスト」に既に書かれている落とし穴だった。
- **`check-base-conflicts.sh --help` が壊れた。** ヘルプは `sed -n '2,30p'` で先頭コメントを
  出す実装だったため、今回コメントを増やした時点で説明の途中で切れるようになった。
  行番号直書きは、コメントを増減させたときに**エラーも警告も出さずに範囲がずれる**。
  `awk 'NR > 1 { if ($0 !~ /^#/) exit; print }'` で「最初の非コメント行の直前まで」を取る形へ
  変え、範囲指定ごと直した。
