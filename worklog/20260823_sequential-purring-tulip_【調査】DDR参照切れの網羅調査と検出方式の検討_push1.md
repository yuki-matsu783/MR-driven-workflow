## 試したこと

- issue #171を取得し、4見出し（目的・現状・期待する動作・受け入れ条件）の過不足を確認した
  （欠けている見出しなし）。
- `.gitignore`の内容を確認し、28行目・40行目にDDR参照コメントがあることを確認した。
- issue本文の「`i00-13`参照はissue #70で既に消えた」という記述の真偽を、実際の`.gitignore`と
  `.claude/docs/ddr/`配下のファイル一覧で確認した。
- リポジトリ全体を`i[0-9]{1,3}-[0-9]{2}[^0-9]`で走査し、ヒット箇所を1件ずつ確認した。

## うまくいったこと

- issue本文の前提が古いことを発見した。`.gitignore`28行目に`i00-13-gemini配下は…md`という
  参照がまだ残っている（実ファイルは`i0000-13-...md`）。40行目の`i36-01`（実ファイル
  `i0036-01-...md`）と合わせて、**修正対象は2箇所**と特定できた。
- `i[0-9]{1,3}-[0-9]{2}[^0-9]`の走査結果のうち、`.gitignore`の2箇所以外はすべて
  ゼロ埋め規約を説明するための例示的記述（`i0133-01-...md`本文、`.claude/docs/README.md`、
  `.claude/rules/markdown-frontmatter.md`、`test_check_base_conflicts.sh`）であることを
  確認した。これらはファイルパス形式ではなく裸の識別子として書かれているため、検出方式を
  「パス形式限定」にすれば誤検知しないという設計上の根拠になった。

- flow-id 2-1（個別調査計画・worklog作成）をcommit・push（push2）した後、正式な走査を実施した。
  `\.claude/docs/ddr/i[0-9]+-[0-9]{2}-[終端文字を除く任意文字]*\.md`という**パス形式**の
  正規表現でリポジトリ全体を走査したところ144件ヒットしたが、実在確認すると23件が
  「存在しない」と判定された。内訳を精査したところ、以下の3種の誤検知が含まれていた。
  - 省略記法（`...md`/`…md`）3件
  - `.claude/scripts/test/`配下のテストコード内の意図的な架空フィクスチャ18件
  - spec内のJSON出力例（コードフェンス内）2件
- 上記3種を除外するフィルタ（テストファイル除外・コードフェンス内除外・省略記法除外）を
  追加したところ、候補は123件へ絞られ、実在しない参照は`.gitignore`の2件（28行目・40行目）
  のみとなった。全体作業計画時点の見込み（「パス形式に限定すれば誤検知を避けられる」）は
  甘く、テストフィクスチャとコード例という2種の追加フィルタが必要だった。

## ダメだったこと

- 最初のbashループ実装で、出力形式を`file:lineno -> path`（矢印区切り）にしていたため、
  `while IFS=: read -r file line path`で`:`区切りすると`path`変数が空になり、全件が
  「missing」と誤判定される事故があった。出力形式を`file:lineno:path`（コロン区切り）へ
  修正して解消した。
