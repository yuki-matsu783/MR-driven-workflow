  - 1回目は前セッションでセッション上限に達して落ちており、findingsが0件・カウンタ未加算
    だったため、**やり直しを1回目として数えた**（`get 3` が `0` を返すことを確認してから再実行）。
- 投稿前に**17件すべての主張を自分で裏取りした**。すべて事実だった。
  - `collect-review-points.sh` の104〜106行目は `rel` への代入だけで、出力は108〜112行目。
  - `install-to-project.sh` のGo検知は151/193/199/319の4箇所に散っている。
  - `.claude/rules/go-applications.md` は**存在しない**（削除処理は既に空振り）。

  - `grep -rn` は `usage/state/*.json` を必ず拾う（`git grep` なら拾わない）。
  - `grep -c` はマッチ0件のときだけ終了コード1（`|| echo` が正常時に発火する）。
- 確度×重大度で振り分け、**10件をPR #154へインライン投稿**、7件を会話で報告。
  上限10件のため `major`/`medium` の3件と `minor`/`high` の1件が投稿から溢れた。

## うまくいったこと

- **計画へ書いた検証コマンドを、反映後に実際に流したところ2件が期待どおり動かなかった。**
  レビューが「検証がno-opになっていないか」を指摘した直後に、**自分が新しく書いた検証でも
  同じ種類の誤りを2つ作っていた**ことになる。書いただけで満足せず流したのが効いた。

  | 検証 | 症状 | 原因 |
  |---|---|---|
  | AI計画・検証7 | 3件のはずが**40件** | `git grep` が既定で非ASCIIパスをクォート＋8進エスケープして出すため、`^\.claude/docs/ddr/` の除外が1件も効かない |
  | 設計計画・検証5 | 1行のはずが**3行**落ちる | `grep -v 'sync-assets'` が11・23行目のコメントまで巻き込む |

  前者は `.claude/rules/shell-script-style.md` に**明記のある罠**（`-c core.quotepath=false`）で、
  規約を読んでいながら踏んだ。`git grep` を「`grep -rn` の追跡ファイル版」として書き換えた
  ときに、パス出力の形式が変わることまで考えていなかった。

- **`seed` を書き換える処理が受け入れ条件と衝突していることに、指摘経由で気づけた。**
  Go検知（193〜195行目）は `AGENTS.md` へ参照行を**追記**する。`AGENTS.md` は新設計で `seed`
  なので、受け入れ条件3（配布先が編集した seed を触らない）と正面から衝突する。
  「機能を引き継ぐか」ではなく「**そもそも新しい層分けと両立するか**」という問いに変わった。

## ダメだったこと

- **`.gitignore` の `/build/` 削除が、2つの計画のどちらにも指示として存在しなかった。**
  push7のworklogで「同じファイルを触る箇所を洗い出せた」と書いたのに、寄せた先（対の計画の
  項目10）が「マーカーの中に入れない」としか書いておらず、**削除の指示になっていなかった**。
  「対の計画へ寄せた」と書いた時点で確認を終えており、寄せた先の文面が指示として読めるかを
  読み返していない。**受け渡しは、渡した側ではなく受け取った側の文面で確認する。**
- **新規追加する4ファイル自身の層を決めていなかった。** 検査1が追跡ファイル全件を要求する
  設計にしたのは自分なのに、その検査を追加するファイル自身が分母に入ることを見落とした。
  さらに `check-dist-coverage.sh` を `core` で配ると、配布先で流したとき配布先の自前ソースが
  全件「未分類」になる（**本家でしか意味を持たない検査を配る**）ことにも気づいていなかった。
- **「二重の担保」と書いた箇所が、Claude Code 経路でしか成立していなかった。**
  Gemini CLI は `.claude/rules/` を読まないため、残るのは未確認の `@` import だけになる。
  担保が二重だと**書いた**ことで、未確認である前提5のリスクが小さく見える文になっていた。
