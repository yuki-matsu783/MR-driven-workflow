# worklog: レビュー返信漏れを機構で防ぐ（push15）

対象: issue #70 / PR #157 / flow-id 4-6

## 詰みかけた設計（`set-header` と `mark-done` を同じ扱いにすると復旧できない）

最初は「`--unreplied` も他のヘッダ項目と同じく、行が無ければエラー」で揃えようとした。
**揃えると詰む。**

1. `mark-done`（ループ範囲）が「行が無い」を理由に拒否する。
2. その復旧手段である `set-header --unreplied 0` も「行が無い」を理由に拒否する。
3. 手でファイルを編集するしか出口が無くなる。

**非対称にするのが正しい**——書く側（`set-header`）は寛容に挿入し、通す側（`mark-done`）は
厳格に拒否する。既に `--loop` が同じ非対称を持っていた（issue #66）ので、そこへ揃えた。

## 既存テストが一斉に落ちたことの読み方

フィクスチャへ `- 未返信スレッド:` を足すまで、ループ範囲への `mark-done` を含む既存ケースが
すべて落ちた。**「テストを直す作業」に見えるが、これは検査が本当に必須の前提条件になって
いることの表明である。** もし落ちなかったら、判定が働いていないことを疑うべきだった。

- 落ちたケースの内訳を見て、**単発ステップのケースが落ちていない**ことも確認した
  （検査をループ範囲に限る意図どおり）。
- そのうえで別途、`|| return 1` を `|| true` に置き換えて**5件落ちる**ことを確認した
  （こちらは「フィクスチャを直したから通っている」だけではないことの裏付け）。

## フィクスチャへの追記が、別のテストの意図を壊しかけた

`FIXTURE_NOHEADER`（ヘッダ項目が1つも無い場合の挿入位置を見るテスト）へ
`- 未返信スレッド: 0` を足すと、**「ヘッダ項目が無い」という前提が崩れるように見える。**
実際には崩れない——`- 未返信スレッド:` は `- 現在のループ:` の挿入 anchor に含めていないため、
`last_header` は -1 のままで、見出し直後への挿入という挙動が変わらない。

**これは偶然ではなく、anchor の設計がそう決めている。** 逆に `FIXTURE_WATCH`
（`- 追従監視:` を anchor にしないことを見るテスト）では行番号がずれるため、
アサーションを `sed -n '4,6p'` → `'4,7p'` へ広げ、**期待値に `- 未返信スレッド:` を含めた**。
広げたことで、この2項目がどちらも anchor でないことを1つのケースで表明できるようになった。

## `status_of` の期待値を取り違えた

`test_cleanup_task.sh` の `status_of` は「テストが真なら `0`」を返す。すぐ上の既存ケース
（「進捗表の記号を含まない」）の期待値が `1` だったのに引きずられ、こちらも `1` と書いて
1件落とした。**同じヘルパでも、肯定の検証と否定の検証で期待値が反転する。**
コメントで理由を書き添えて直した。
