## うまくいったこと

- **`-A` を採用しなかったため、SKILL.mdの絶対ルールに例外を持ち込まずに済んだ。** 全体作業計画の
  段階では「ラッパー内部のパス限定 `-A` は例外」という但し書きを入れる想定だったが、
  絶対ルールは文言どおりのまま成立し、注記は「削除済みパスも渡してよい」という**追加の許可**
  だけで済んだ。禁止に例外を足すより、読み手が誤解しにくい
- SKILL.mdへの注記は、最初「自動除外：」の直後に入れてしまい、見出しとリストの間を割っていた。
  除外リストの**後ろ**へ移動して、リストの流れを壊さないようにした
- issue #69 の起票時、最小再現（`jq -nc --args '<フィルタ>' 'a' '-A' 'b'`）と対策候補
  （`--args` の後ろに `--` を置く）まで実機確認してから本文へ入れた。調査フェーズの入口が短くなる

## ダメだったこと

- `shell-script-style.md` への1件目（NULバイト）は、計画では「既存の『文字コード』節または
  『JSON操作』節の近く」としていたが、**どちらにも収まらなかった**（文字コードの話でもJSONの話でも
  なく、コマンド置換の性質の話）。`## コマンド置換とNULバイト` という節を新設した。
  計画時点で「どの節に入れるか」を決め打ちすると、書く段になって噛み合わないことがある
- issueの4見出しを渡す際、`--current` の本文にシングルクォートを含むコード例
  （`jq ... 'def items: ...'`）があり、コマンド文字列へ直接書くとクォートが壊れる。
  **スクリプトファイルへ書き出してから実行する**形にして回避した
  （長文をコマンド文字列へ埋め込まない、という既存の教訓と同じ対処）
