  （インライン投稿13・サマリ報告のみ nit 2）を両計画の md/html へ反映した。
- 【設計反映】側の主な修正:
  - 前提へ「ベースブランチの遅れ」節を追加。`check-base-sync.sh` で behind 2 / ahead 13、
    `check-base-conflicts.sh` で textualConflictFiles 21件・DDR重複0件を**自分でも実測**して
    から書いた（指摘を鵜呑みにせず一次情報で検証）。取り込みは AskUserQuestion 承認必須の
    ため非対話セッションでは実施せず、flow-id 5-1 で扱う方針と、正史ドキュメントの書き方の
    制約（タスクディレクトリ名へ言及しない・directory-structure 変更は最小差分）を明記。
  - 洗い出し表を9行へ拡張（README の spec節・usecase節の手書き更新、SKILL.md 予告文の
    差し替え、HANDOFF 記録を明示的な行として追加）。
  - spec「影響範囲」を訂正: `.claude/` は core 層のため配下の追加・変更は exclude 2スキルを
    除きすべて配布対象になる（「配布対象外」という誤解を修正）。VERSION 適用の記録は spec の
    changelog と HANDOFF「判断を迷った内容」の両方へ（distribution-assets.md 規定）。
  - DDR `i0027-02` の文案を「原因は1つ」から**2機構の書き分け**へ全面修正（下記）。却下案
    3つ（inherit_errexit 常時オン・set -E + trap ERR・戻り値の個別検査）を追記。
  - 検証節を実行可能なコマンドへ全面書き換え（frontmatter 4件の jq -e・DDR一覧の
    「生成→ステージ→再生成→git diff --exit-code」・重複検知の jq -e・README の grep）。
- 【AIアセット反映】側の主な修正:
  - 洗い出し表へ「テスト」節の行を追加（類型b。`"$(func; echo $?)"` を使わないという結論は
    維持し、理由付けだけを訂正する。エラー方針と同時に直さないと同一ファイル内で
    「継承する／しない」が並立するため）。
  - errexit の診断を2機構へ書き分け: (1) 明示サブシェル `( f )` は -e を継承するが、条件文脈
    （`||`・`if`）では errexit の一時停止が内側へ伝播して途中失敗が素通りする。
    (2) コマンド置換 `$(...)` は `shopt inherit_errexit` が既定オフのため、条件文脈かどうかに
    関係なく -e を一切継承しない。
  - 推奨パターンへ出力受け取り形 `set +e; out="$(set -e; f)"; rc=$?; set -e` を追記
    （出力を受け取る用途を従来形のまま残すと訂正前と同じ欠陥が残るため）。
  - 検証を5ケースの実測コマンド＋期待値へ拡張（全ケース実行済み・期待どおりを確認）。
