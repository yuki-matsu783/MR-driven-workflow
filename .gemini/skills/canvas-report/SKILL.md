# canvas-report スキル

報告用HTML（`wip/reports/日付_<全体計画名>_<内容を簡潔に>.html`。調査結果に限らず設計・実装・AIアセット
反映等の報告に使う。運用は`.claude/rules/docs-workflow.md`参照）のうち、複数の要素同士の
「関連・依存関係」を主題とする内容を、**階層セマンティックズーム対応のCode Canvas形式**
（issue #141で全面刷新）で表現するためのスキル。

**結果の正文は同名の`.md`側であり、このHTMLはその視覚化である**（issue #87。詳細:
`.claude/skills/issue-mr-flow/references/deliverables.md`「計画と実施結果の分離」）。HTMLを書く前に、対応する
`wip/reports/…md` に結果が記録されていることを確認する。

## いつcanvasを選ぶか

調査結果の内容が次のような性質を持つ場合、canvas形式が適している。

- ファイル・モジュール・クラス・関数・ドキュメント等、**複数の「モノ」同士のつながり**が主題に
  なっている（例:「AがBを呼び、BはCの設定を必要とする」といった関係のネットワーク）
- **コードの依存関係と変更点を1枚で俯瞰し、気になった箇所をズームして該当コードまで辿りたい**
- 一覧・表で並べると関連性が読み取りにくい（矢印や補足説明を大量に書かないと伝わらない）

逆に、以下のような調査結果には向かない（一覧・表形式のテンプレート——既定は
`.claude/skills/issue-mr-flow/assets/reports-clean.template.html`。5本からの選び方は
`.claude/skills/issue-mr-flow/references/deliverables.md`「レポートテンプレートの選び方」——で十分）。

- 単純な比較（候補A/B/Cのメリット・デメリット比較等）
- 時系列の手順・チェックリスト
- 要素間のつながりが1〜2本程度しかない、または全要素がフラットに並列

迷う場合は、まず調査結果の要点を箇条書きにしてみて、「矢印を書きたくなるか」を基準に判断する。

## データモデル（レイヤ > クラス > メンバ の3層階層）

テンプレートは**データ定義とエンジンが分離**されており、生成側が書くのは `CANVAS_DATA` と
`EDGE_KINDS` の2つだけである。**座標・色クラス・HTML断片は一切書かない**（文字列はエンジンが
すべて `textContent` ベースで自動エスケープするため、`List<String>` のような `<` を含む値も
HTMLエスケープせずそのまま書いてよい）。

**ただしデータ部は `<script>` 内のJSリテラルなので、次の2点だけはJS/HTMLの構文として
生成側がエスケープする**（エンジンのエスケープはDOM挿入時のもので、パース段階には効かない）。

- 値のどこかに `</script`（大小無視）が現れる場合は `<\/script` と書く。素で書くと
  そこでスクリプト要素が終端し、**ページ全体が壊れる**。
- バックスラッシュ・クォート（囲みに使った引用符）はJS文字列としてエスケープする
  （例: シングルクォート文字列内の `'` は `\'`、`\` は `\\`）。

```js
const CANVAS_DATA = {
  meta: {
    title: 'レポートの題名', subtitle: 'issue #NN 調査結果',
    repoUrl: '',   // 任意。'https://github.com/o/r/blob/<ref>/' を設定するとpath表示がリンク化
  },
  layers: [        // 帯として縦に積まれる（配列順＝上から下）
    { id: 'hooks', label: 'Claude Code hooks', desc: '説明（任意）' },
  ],
  nodes: [
    // クラスノード: parentを持たない。layer必須。path/lines/desc/change/detail/mermaidは任意
    { id: 'Provider', layer: 'vcs', label: 'Provider.sh',
      path: '.claude/scripts/src/vcs/Provider.sh', desc: '短い説明',
      change: { status: 'modified', add: 12, del: 3 },
      detail: '詳細パネルに出す長文（プレーンテキスト。改行は保持される）',
      mermaid: 'graph LR\n  A --> B' },
    // メンバノード: parent=クラスid。lines/code/codeStart/changeは任意
    { id: 'Provider.get_issue', parent: 'Provider', label: 'get_issue <n>',
      lines: '120-145', code: '複数行の\nコード片', codeStart: 120 },
  ],
  edges: [
    // from/toはクラスidまたはメンバid。kindはEDGE_KINDSのキー。labelは任意（ホバーで表示）
    { from: 'Provider.get_issue', to: 'Github.github_get_issue', kind: 'call' },
  ],
};
```

決めごと:

- **「クラス」はJavaのclassに限らない**。bashならスクリプトファイル、mdならドキュメント、
  というように「メンバ（関数・見出し等）を束ねる単位」を割り当てる。メンバを持たないクラスが
  あってもよい。
- ノードは**フラットな配列に `parent` 参照で書く**（ネスト記法にしない）。階層は
  レイヤ > クラス > メンバ の3層まで。エンジンは未定義ID参照・親子の循環・階層の深さ超過・
  必須項目欠落・id重複を検出し、**画面上の赤字パネルへ列挙して該当要素だけをスキップする**
  （黙って壊れない）。生成後にブラウザで開いてこのパネルが出ていないことを確認する。
- `change.status` は `added` / `modified` / `deleted` の3値。`add` / `del` を添えると
  `+N −M` バッジになる。
- 関係種別 `EDGE_KINDS` の既定は `call`（呼び出し）/ `extend`（実装・継承）/ `di`（DI注入。
  bashなら `source` もここ）/ `data`（データアクセス）/ `other`。キー・色・線種・和名は
  対象に合わせて追加・変更してよい。
- 座標は自動レイアウト（レイヤ帯＋barycenter順序付け＋行折返し）が決める。**`x`/`y` は
  書かない**。どうしても位置を直したいノードに限り `x`/`y`（world座標）で上書きできる。

## 規模の指針

**1枚あたり〜40クラス程度**を上限の目安とする（issue #141の想定規模）。それを超える場合は、
調査対象を絞って複数枚に分けるか、レイヤ・サブシステム単位で別ファイルにする。メンバは
「関係の端点になるもの＋変更があったもの」だけを載せ、全関数を網羅しない。コード片も
「報告で見せたい箇所」だけでよい（1メンバ10行前後が読みやすい）。

## 依存関係の抽出手順（生成側の作業）

1. **クラス（ファイル）の列挙**: 対象ディレクトリのファイル一覧から、レポートの主題に関係する
   ものを選ぶ。レイヤは配置・役割から決める（例: `.claude/hooks/` → hooks層、
   `.claude/scripts/src/` → scripts層、`lib/` → 共有ライブラリ層。Javaならアノテーション
   `@Controller`/`@Service`/`@Repository` からレイヤを判定する）。
2. **メンバの抽出**: 関係の端点・変更点になる関数だけを選ぶ。bashなら
   `grep -n '^[a-z_]\+()' file.sh` で関数定義と行番号を取り、`lines` に記録する。
3. **エッジの抽出**:
   - `source` / import / DIフィールド型 → `di`（Javaならフィールド型・コンストラクタ引数の型
     からDI辺を張る）
   - 関数呼び出し → `call`（呼び出し元関数が特定できるならメンバ→メンバで張る。特定コストが
     高ければクラス→メンバでよい）
   - ファイル読み書き・状態ファイル → `data`
   - 継承・実装・テンプレート複製 → `extend`
4. **コード片**: 見せたい関数本体を `sed -n '120,145p'` 等で切り出して `code` へ入れる。
   HTMLエスケープは不要だが、**上記「データモデル」の2点（`</script` は `<\/script` と書く／
   `\` とクォートはJS文字列としてエスケープ）は生成側の責務**である。バッククォート・`${}` を
   含む場合はJS側のテンプレートリテラルと衝突しないよう通常の文字列リテラル＋`\n` 連結で書く。
5. テンプレート `assets/canvas-report.html` をコピーし、データ部（`// データ部:` の
   コメント枠から `// ENGINE BEGIN` のコメント枠の直前まで）を差し替える。エンジン部は
   変更しない。あわせて**成果物に雛形の痕跡を残さない**: ファイル冒頭の使い方コメントは
   このレポートの説明（何のデータか・出典）へ置き換え、mermaidを使わない場合は
   `<script src="…mermaid…">` タグを削除する。
6. ブラウザで開き、(a) 赤字のデータエラーパネルが出ていない、(b) FITで全体が見える、
   (c) ズームでコード片まで辿れる、の3点を目視確認する。

## 操作方法（テンプレートの既定動作）

- **連続セマンティックズーム**: ズーム率に連動して L0（レイヤ俯瞰。クラスはチップ表示）→
  L1（クラス箱＋メンバ一覧）→ L2（メンバ＋行番号つきコード片）へ自動で切り替わる。
  現在の段階とズーム率はヘッダーに表示される。
- **折りたたみ/展開**: クラス箱の ▾/▸ ボタンでズームと独立に切り替えられる。展開中のノードは
  最前面に出て他は減光する（周囲の再レイアウトはしない）。`Esc` で一括解除。
- **エッジ**: 端点はメンバ行（クラスがメンバ表示中のとき）またはクラス箱の境界。両端がクラス箱の
  エッジは（クラスペア, 種別）単位で1本へ集約され、**太さが本数**を表す。ホバーで種別・内訳
  ラベルを表示。選択ノードの**上流（呼び元）=アンバー／下流（呼び先）=シアン**で色分けされる。
- **パン/ズーム**: ドラッグでパン（ノードの上からでも可）。ホイールでズーム、Ctrl+ホイールで
  微調整ズーム、トラックパッドの2本指スクロールはパン（タッチ・ピンチは非対応）。
- **検索**: `/` でフォーカスし、クラス名・メンバ名・パスの部分一致でジャンプできる。
- **トグル**: 左パネルでレイヤ・関係種別ごとの表示/非表示を切り替えられる。
- **キー操作**: `f`=全体フィット、`/`=検索、`Esc`=選択・展開の解除／パネルを閉じる。
- **ミニマップ**: 右上。クリック/ドラッグで該当位置へジャンプ。

## mermaidの位置づけ（補足図への降格。issue #141）

関係の表現は**ネイティブのエッジが主役**であり、mermaidは**詳細パネル内の補足図**としてのみ
任意で使う（クラスノードの `mermaid` フィールド。クリックで開く右パネルに描画される）。
mermaid.jsは唯一の外部CDN依存で、読み込めないオフライン環境では自動でソース文字列表示に
退避する。mermaidを1つも使わない場合は `<script>` タグごと削除してよい。

## 外部依存・スタイルについて

エンジン・スタイルは**自己完結**（自前CSS）で、TailwindCSS CDNには依存しない（issue #141）。
旧版はTailwindの任意値クラス（`animate-[...]`）や存在しないクラス（`z-25`）に依存して
アニメーション・重なり順が壊れており、CDN遮断環境では検証もできなかったため、canvas形式に
限りTailwindを外した。

**issue #54 以降、一覧・表形式のHTMLも自己完結CSSになった**（`wip/reports/` `wip/plans/` のHTMLビューの
土台は `.claude/skills/issue-mr-flow/assets/` の2テンプレート）。したがって「CDN前提の一覧表形式に
対し、canvas形式だけが自己完結」という以前の対比は、もう成り立たない。ただし**両者が完全に同じに
なったわけではない**ので、次のように区別して扱う。

| 形式 | 外部を読みに行く記述 |
|---|---|
| 一覧・表形式（`reports-{clean,neobrutal,mono,paper}.template.html` / `reports.template.html` / `plans.template.html`） | **無い**（`<script src>` も `<link href>` も持たない） |
| canvas形式（本スキル） | **mermaidを使う場合に限り、CDNの `<script src>` を1本読む**。使わない場合はその `<script>` ごと削除すれば外部依存ゼロになる |

**「URLを1文字も含まない」という意味での自己完結ではない点に注意する。** canvas形式は
mermaidを外しても `http://www.w3.org/2000/svg`（`createElementNS` に渡すSVGの名前空間）を
**4箇所**持つ（`assets/canvas-report.html` の835・842・902・911行。`https?://` にヒットする
6行の残りは、mermaid CDN 1行とJSコメント内の例示URL 1行である）。これは外部を読みに行く記述
ではないため、`wip/reports/REVIEW-POINTS.md` の自己完結の検査も「実際に外部を読みに行く記述」
（`src`/`href`/`url()`/`@import` に `//` で始まる値が来る）だけを数える形にしてある。
