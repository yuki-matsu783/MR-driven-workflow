# i0054-01. 計画・レポートのHTMLビューはassets配下のテンプレートへ切り出す

## 背景

issue #54「計画・レポートの人間レビュー用HTMLビューをテンプレートファイルへ切り出す」。

`plans/` の計画と `reports/` のレポートには、mdと同じベース名の `.html`（人間レビュー用ビュー）を
併存させる運用がある。しかしその**記述の型**（どんな見出しを立て、何を必須とするか）は
`.claude/skills/issue-mr-flow/SKILL.md` の散文として各flow-idの説明に散っており、次の2つの問題が
あった。

1. **導入先プロジェクトが自分の型へ差し替えたいときに、手を入れる場所が定まらない。** この機構は
   `.claude/` 一式を他プロジェクトへ配布する前提であり、フローの手順書（SKILL.md）とレポートの
   様式は寿命も変更頻度も異なる。
2. **型が守られているかを機械的に確認できない。** テンプレートが実体として無いため、必須節の
   欠落や埋め忘れを検出する手がかりが無かった。

あわせて、既存の記述には次の3つのずれもあった。

- **テンプレート化そのものの保留**。DDR `i0000-11` は方式（CDN）を決めた項とは別に、
  「`reports/<plan名>.html` のテンプレート化（雛形ファイル・生成スクリプトの新設）は行わない。
  当面は個別issueごとにAIエージェントが都度執筆する運用とし、**複数件運用した実績を踏まえてから
  テンプレート化を判断する**」という項を持っており、却下案にも「毎回固定フォーマットの
  テンプレートから生成する」が挙がっていた。**本DDRの決定1は、この保留を明示的に覆すものである**
  （下記「1. 記述の型の正を〜」の冒頭を参照）。
- **`reports/` のHTMLの方式**。DDR `i0000-11` が「調査結果のhtml版はTailwindCSS CDN方式の
  自己完結HTMLで作る」と決めていたが、その後 DDR `i0141-01` が canvas形式テンプレートだけを
  Tailwind非依存の自前CSSへ移しており、**一覧・表形式だけがCDN方式のまま残っていた**。
- **バンドルリソースのディレクトリ名**。`.claude/rules/directory-structure.md` は
  「`templates/` のようなサブディレクトリを追加してよい」と書き、実体は
  `canvas-report/templates/` だけだった。一方 issue #54 本文は、Agent Skills の語彙
  （`scripts` / `references` / `assets`）に揃えることを求めていた。

## 決定

### 1. 記述の型の正を、`assets/` 配下のテンプレートファイル2本へ移す

**この決定は、DDR `i0000-11` の「テンプレート化は行わない（複数件の運用実績を踏まえてから判断
する）」という保留を上書きする。** 覆してよいと判断した根拠は次の3点である。

1. **`i0000-11` が待つと言っていた運用実績が溜まった。** `i0000-11`（issue #48 相当の対応）から
   本issueまでの間に、`reports/` のHTMLは複数のissueで繰り返し執筆されており、必須節と任意節の
   区別・埋め忘れの検査・自己完結の条件という**繰り返し現れる型**が具体的に分かっている。
   保留の理由は「型がまだ見えていない」ことであって、テンプレート化それ自体の否定ではなかった。
2. **`i0000-11` が想定していたのは「生成スクリプト」を含む重い仕組みだが、今回作るのは
   コピー元となるHTMLファイル2本だけである。** 生成スクリプトは作らない（コピーして書き換える
   運用のまま）ため、保留が避けようとしたコスト——仕組みの保守と、型が固まる前の早すぎる固定化
   ——のうち前者は発生しない。
3. **`i0000-11` の時点に無かった要求が加わった。** 配布先が自分の型へ差し替えられること
   （上記「背景」1）は、`i0000-11` の検討範囲に入っていない。

| テンプレート | 対象 |
|---|---|
| `.claude/skills/issue-mr-flow/assets/plans.template.html` | 全体作業計画（flow-id 1-4）と個別計画（2-1・3-1・4-1） |
| `.claude/skills/issue-mr-flow/assets/reports.template.html` | 調査結果（2-6）・作業結果（3-6）・反映結果（4-6）・最終統括レポート（5-3） |

SKILL.md 側は見出し構成を列挙せず、「テンプレートを読んでから書く」と参照するだけにする。
必須／任意の区別は各 `<section>` の直前のHTMLコメント（`[必須]` / `[任意]` /
`[全体作業計画のみ必須]`）で示し、プレースホルダはHTMLコメント（`<!-- ここに書く: … -->`）で
統一する。

**md側のテンプレートは作らない。** `plans/*.md` `reports/*.md` の見出し構成は規定せず自由記述の
ままとする。型を固定する価値があるのは、人間が繰り返し目を通すHTMLビューの側だけであるため
（issue #54 本文も明示的に除外している）。

### 2. HTMLの方式を TailwindCSS CDN から自己完結CSSへ変える

テンプレート2本のスタイルは自前CSS（CSSカスタムプロパティ＋`prefers-color-scheme`）で、
CDN・外部フォント・画像を1つも参照しない。**2本のCSSは同一内容を重複して持たせる。**

**issue #54 本文は `reports.template.html` を「TailwindCSS CDN通常版」と書いていた**が、
方式は受け入れ条件で固定されていない。字面と異なる選択になるため、**この決定はユーザーの承認を
得てから記録した**（2026-08-22、チャットで受領。「自己完結CSSで良い」。PR #156 のコメントに
記録がある）。

### 3. バンドルリソースの語彙を `assets/` に統一する

スキル配下のバンドルリソースは `assets/`（出力に使うもの）・`scripts/`（実行するもの）・
`references/`（AIが読むもの）の3語彙に統一し、**`templates/` は使わない**。
`canvas-report/templates/` を `assets/` へ改名した。

## 理由

### 決定2について

**核心は「`i0000-11` がCDNを選んだ根拠が、テンプレート化すると成り立たなくなる」ことである。**
`i0000-11` の根拠(b)は「出力トークン量と表現力の釣り合い」——毎回CSSを書き起こすより、CDNの
ユーティリティクラスを使うほうが少ないトークンで整った見た目になる、というものだった。
しかしテンプレート化すると、**CSSを書くのはテンプレート作成の1回だけ**になり、以降の各レポートは
どちらの方式でもクラス名を書くだけである。前提そのものが消えるので、根拠として使えない。

加えて、`i0141-01` が canvas形式をTailwindから外した3つの理由のうち2つ——「存在しないクラスが
黙って無視され、実行時まで誤りに気づけない」「CDNが遮断された環境では表示を1度も確認できない」
——は、一覧・表形式のテンプレートにも当てはまる。

**CDNへの到達性そのものは主根拠にしない。** `i0141-01` は到達不可を実測で記録したうえで
`reports/` の一覧・表形式をCDN方式に据え置いており、同じ事実から逆の結論を出すことはできない。
到達性のうち使ったのは「**書き手が成果物の表示を1度も確認できないまま納品することになる**」
という検証可能性の側面だけで、「レビュアーが開けるか」という閲覧可用性は根拠にしていない
（後者を外しても、上記の「実行時まで気づけない」だけで結論は変わらない）。

### 決定3について

`templates/` と `assets/` が並立すると、同じ役割に2つの語彙がリポジトリ内へ残る。issue #54 が
新設するテンプレートを `assets/` へ置く以上、既存の1件を改名して寄せるほうが、規約と実体の
両方が1つに揃う。

## 却下した案

### 決定1に対して

**(a) SKILL.md の散文のまま、記述を整理して集約する。** 差し替え可能なファイルにならないため、
問題1（導入先が手を入れる場所が定まらない）が解決しない。

**(b) md側のテンプレートも作る。** issue #54 本文が明示的に除外している。加えて、mdは正文であり
自由記述であることに価値がある（型を先に決めると、書くべきことより埋めることが優先される）。

**(c) 最終統括レポート（flow-id 5-3）専用のテンプレートを別に作る。** 同上（本文が除外）。
統括レポートは `reports.template.html` を土台にし、必須節の読み替えを冒頭コメントで示す形にした。

**(d) `i0000-11` の保留を維持し、テンプレート化をさらに見送る。** 保留の理由だった「型がまだ
見えていない」は、その後の複数issueでの執筆により解消している。加えて issue #54 は
テンプレート化そのものを求めており、維持するとissueの受け入れ条件を満たせない。**保留を
続けるなら、その判断こそをDDRとして記録する必要がある**（何も決めずに見送る形にはできない）。

### 決定2に対して

**(a) CDN方式を維持する（issue本文の字面どおり）。** 上記のとおり `i0000-11` の根拠が
テンプレート化後は成り立たない。維持すると、根拠を失った決定だけが残る。

**(b) 共有のCSSファイルへ切り出し、2本のテンプレートから読む。** 重複は消えるが、
**「自己完結」でなくなる**。**HTMLファイル単体をリポジトリ外へ持ち出して共有・保管した場合に
開けなくなる**（flow-id 5-4 は `reports/` のmdとhtmlをまとめて削除するので、「片方だけが残る」
状況は起きない。壊れるのは持ち出したときである）。CSSの重複（2ファイル）はこのコストと
引き換えに許容する。

### 決定3に対して

**(a) `templates/` を使い、新設テンプレートもそちらへ置く。** issue #54 本文が Agent Skills の
語彙を根拠として `assets` を示しており、外部の語彙に揃える利点を捨てることになる。

**(b) `resources/` 等の第3の語彙を作る。** 語彙が3つになり、統一という目的に反する。

## 補足: `apply-mr-workflow-to-project/assets/` とは別物である

同じ `assets` という名前だが、`.claude/skills/apply-mr-workflow-to-project/assets/` は
`sync-assets.sh` が配布前に生成する**ビルド用の一時ディレクトリ**で、`.gitignore` 対象である。
本DDRが定める `assets/` は**Git管理下に置く恒久のバンドルリソース**であり、性質が正反対である。

`.gitignore` の除外行は先頭スラッシュでパスを固定しているため現状は衝突しない（確認済み:
`git check-ignore -v .claude/skills/issue-mr-flow/assets/x.html` は何にも当たらない）。ただし
**この行を相対パターン（`assets/`）へ広げると、恒久のテンプレートが無言でGit管理から外れる。**
`.claude/rules/directory-structure.md` はこの2つを区別して書いている。
