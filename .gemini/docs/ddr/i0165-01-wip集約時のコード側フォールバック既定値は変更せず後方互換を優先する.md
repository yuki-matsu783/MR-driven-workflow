# i0165-01. wip集約時のコード側フォールバック既定値は変更せず後方互換を優先する

## 背景

issue #165で、タスク単位の作業ドキュメント置き場を `plans/` `worklog/` `reports/` から
`wip/plans/` `wip/worklogs/` `wip/reports/` へ集約・改名した。本リポジトリ自身の
`.mrworkflow.json` は `plansDir` / `worklogDir` / `reportsDir` を新しい値へ明示的に変更した。

一方、`.claude/scripts/src/vcs/Provider.sh`（`get_workflow_config`）と
`.claude/scripts/src/cleanup-task.sh` は、**`.mrworkflow.json` がこれらのキーを持たない場合の
フォールバック既定値**（`"plans"` / `"worklog"` / `"reports"`）を持っている。この既定値を
本リポジトリの新しい設定値に合わせて `"wip/plans"` 等へ変更するかどうかが論点になった。

## 決定

**フォールバック既定値は変更せず、`"plans"` / `"worklog"` / `"reports"` のまま据え置く。**

## 理由

- この機構（`.claude/` 一式）は複数プロジェクトへ配布されるテンプレートである
  （`.claude/skills/apply-mr-workflow-to-project/`）。既にこの機構を導入済みの配布先が
  `.mrworkflow.json` を持たない、または `plansDir`/`worklogDir`/`reportsDir` のいずれかを
  明示していない場合、そのフォールバック既定値を `wip/*` へ変更すると、**配布先のファイルシステム
  上の実際のディレクトリ（`plans/` 等）と、コードが探しに行く先（`wip/plans/` 等）が食い違う**。
  `get_branch_work_files`（作業ファイル列挙）や `cleanup-task.sh`（片付け対象の決定）が
  実在しないパスを見に行き、作業ファイルが1件も見つからない・片付け対象が0件になる、という
  形で無言に壊れる。
- 本リポジトリ自身は `.mrworkflow.json` に3キーを明示しているため、フォールバック既定値の
  変更有無は本リポジトリの動作には影響しない。据え置く実害は**配布先にのみ**及ぶため、
  「据え置く」が保守的で安全な選択である。

## 却下案

- **フォールバック既定値も `wip/*` へ変更する。** 新規に配布を受けるプロジェクトでは
  `apply-mr-workflow-to-project` スキルが `.mrworkflow.json` ごとテンプレートを配るため、
  この変更の恩恵は無い。恩恵があるのは「`.mrworkflow.json` を自分で書いたが3キーを省略した」
  という限定的なケースのみで、そのケースのために「既存配布先の実在パスとの食い違い」という
  実害を負うのは割に合わない。

## 影響範囲

- `.claude/scripts/src/vcs/Provider.sh`（`get_workflow_config` のheredoc既定値）: 変更しない。
- `.claude/scripts/src/cleanup-task.sh`（jqフォールバック `.plansDir // "plans"` 等）: 変更しない。
- `README.md`「セットアップ」節の設定項目表: 「デフォルト値」列は**本リポジトリの設定値**
  （`wip/plans` 等）を示すものであり、**コードのフォールバック既定値とは意味が異なる**ことを
  明記する。

## 未決定事項

- 配布先が旧ディレクトリ（`plans/` 等）を持ったまま `install-to-project.sh` で本機構を更新した
  場合の移行手順は、本DDRの対象外（`.claude/VERSION` の増分・移行案内の要否とあわせて別途検討）。
