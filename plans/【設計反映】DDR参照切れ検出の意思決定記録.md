# 【設計反映】DDR参照切れ検出の意思決定記録（issue #171）

## 前提（合意状況）

- 上位の計画: `plans/sequential-purring-tulip.md`（全体作業計画、flow-id 1-5で合意）。
  「フェーズ4〈反映〉」節で「検出の仕組みに関する意思決定をDDRとして記録し、
  `generate-ddr-list.sh`でREADMEの一覧を再生成する」ことが既定路線として合意済み。
- 直前の実装結果: `reports/20260823_sequential-purring-tulip_gitignore修正と検出スクリプト
  実装結果.md`（v2、敵対的レビュー対応済み）。

## この計画で何をするか

1. issue #171で行った意思決定（対象範囲の限定・検出方式・実装が2回の敵対的レビューを経て
   変遷した経緯）を1件のDDRとして記録する。
2. `bash .claude/scripts/src/generate-ddr-list.sh`を実行し、`.claude/docs/README.md`の
   DDR一覧を再生成する。
3. 新規specファイルは作成しない（フェーズ3の個別作業計画で「規模の小さいスクリプトであり、
   本計画＋テストコード＋フェーズ4のDDRでドキュメントとして十分」と決定済み）。
4. AIアセット反映: 作業中に気づいたルール・スキルの不備があれば反映する。

## 変更対象

- `.claude/docs/ddr/i0171-01-<タイトル>.md`（新規DDR）
- `.claude/docs/README.md`（`generate-ddr-list.sh`による自動再生成）

## 方針

### DDRに記録する内容

1. **対象範囲を「DDRファイルパスへの絶対パス参照」に限定した判断**（個別調査計画・
   個別作業計画の両方で合意済み）とその理由:
   - 裸の識別子表記（`i0159-01`等）は規約説明の例示として頻出し誤検知源になるため対象外
   - 相対パス表記（`../docs/ddr/…`、`ddr/…`）は今回のスコープ外（約79件が未検査のまま。
     将来の課題として明記）
   - 旧形式（4桁連番、`i`接頭辞なし）は本リポジトリに現存しないため対象外（配布先で必要に
     なった場合の拡張余地として記録）
2. **検出方式の実装が2回の敵対的レビューを経て変遷した経緯**（設計判断そのものが変わった
   点を中心に記録し、詳細な試行錯誤はworklog参照に留める）:
   - 対象ディレクトリからの除外（`.claude/scripts/test/` `plans/` `reports/` `worklog/`の
     4つ。当初3つと誤記していたものを訂正）
   - フェンス除外の方式変更（行削除の2パス→行番号集合による判定。行番号ずれの実バグを修正）
   - フェンス判定ロジックの変更（単純トグル→マーカー種別・長さの一致判定。false negativeの
     実バグを修正）
   - 全角句読点による連結対策で、正規表現へ直接埋め込む案がこの実行環境のロケール
     （POSIX/`LANG`未設定）で致命的に破綻することを実機で発見し、ASCII構造による後処理
     方式へ変更した経緯（**他プロジェクトへの配布時にも再現しうる罠として重要**）
   - 候補抽出方式の変更（bash単独ループ→grep一括抽出。実測5.2秒→0.96秒）
3. **実行タイミングを手動実行のみとし、hook等への自動組み込みを行わない判断**（全体作業計画
   で決定済み。頻度の低い整合性チェックを毎回自動実行する価値が無いという理由）。
4. **新規specファイルを作らない判断**とその理由（規模の小さいスクリプトのため、計画＋
   テストコード＋DDRで十分）。

### 却下案

- 検出の仕組みを作らず目視確認のみで済ませる案（全体作業計画で却下済み、DDRにも記録する）。
- 正規表現の文字クラスへ全角句読点を直接追加する案（ロケール依存の破綻により却下。
  代替のASCII構造による後処理方式を採用）。

## やらないこと（スコープ外）

- 相対パス表記への対応拡張（将来課題として記録するのみで、今回は実装しない）。
- 検出スクリプトのhook・CI等への自動組み込み。
- git bash実機での動作確認（個別作業計画で見送りと決定済み。DDRにも実施していない事実として
  記録する）。

  いることを`git diff`で確認できる。
