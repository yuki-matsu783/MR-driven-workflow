# 全体作業計画: チャットで受けたレビュー判断をMRコメントとして残す（issue #50）

## 対象issue

- #50 チャットで受けたレビュー判断をMRコメントとして残す
- ブランチ: `claude/mr-comment-review-decision-jljzxo`

## 課題

`.claude/skills/issue-mr-flow/SKILL.md` の `comments` サブコマンド手順3は
「ユーザがプロンプトにおいて指摘を行った場合は、MRにコメントすることを促す」とあり、
**人間に促すだけ**でAIエージェント自身は記録しない。

issue #48 のフェーズ4（PR #49）では、AIが判断を仰いだ3点すべてがチャットで回答され、
MR上には未解決スレッド0件のまま判断の記録が一切残らなかった。`plans/` 側へ書いても
flow-id 5-1で削除され、squash mergeによりmainにも残らないため、PR画面から経緯を追えない。

## 受け入れ条件（issueより）

1. `comments` 手順に、チャットで受けた判断をMRコメントとして残す手順が明記されている
2. 残す対象／残さない対象の基準が定義されている
3. 署名（`Claude Codeより:`）の付与ルールが `reply` サブコマンドと揃っている

## 進め方

フェーズ2（調査）は、対象が自リポジトリ内の既存記述（`SKILL.md` / spec / DDR 0004）に
閉じており、参照箇所も特定済みであるため実施しない。フェーズ3（作業）から入る。

| フェーズ | 内容 |
|---|---|
| 1 | issue取得・ブランチ確認・本計画作成 |
| 2 | （実施しない） |
| 3 | `SKILL.md` へ手順・基準・署名ルールを追加する |
| 4 | `.claude/docs/spec/issue-mr-workflow.md` へ仕様と影響範囲を反映し、DDR 0040を新規作成する |
| 5 | 片付け・push |

## 方針（比較検討）

記録先の候補を比較し、**PR/MRの通常コメント（`add_mr_comment`）**を採る。

| 候補 | 判定 |
|---|---|
| 通常コメント（`add_mr_comment`） | **採用**。時系列で追記され消えない。スレッドではないため未解決件数に影響しない |
| レビュースレッドへの `reply` | 却下。チャット由来の判断には紐づくスレッドが存在しないことがある |
| MR description（`describe`） | 却下。`describe` は最新スナップショットで上書きするため判断ログが消える |
| `plans/` への追記（現状） | 却下。flow-id 5-1で削除され、squash mergeでmainにも残らない（issueの問題そのもの） |

## 制約

- 非対話的な実行環境のため、人間のレビュー往復（flow-id 3-3/3-4, 3-8/3-9, 4-3/4-4, 4-8/4-9）は
  待てない。該当ループの進捗記号は `[]` のまま残し、実施内容は「やったこと」で補足する
  （`.claude/rules/docs-workflow.md` 末尾の規定に従う）。
- ハーネスがPR作成を制限するため、Draft PRは作成しない
  （`.claude/rules/git-workflow.md`「ハーネスがPR作成を制限する環境での扱い」の3番）。
