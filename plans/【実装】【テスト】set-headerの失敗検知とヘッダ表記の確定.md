# 【実装】【テスト】set-headerの失敗検知とヘッダ表記の確定

対象issue: [#66](https://github.com/yuki-matsu783/MR-driven-workflow/issues/66)（flow-id 3-1）
調査結果（実装方針の正）: `reports/2026-08-20_set-header-silent-failure_調査結果.md`

**この計画には結果を書かない。** 結果は
`reports/2026-08-20_set-header-silent-failure_実装結果.md` へ書く。

種別を併記しているのは、テストコードを実装と同時に書き、**まとめて1回で合意を取る**ため
（`.claude/skills/issue-mr-flow/SKILL.md`「種別を複数併記する場合／分ける場合」）。

## 前提（flow-id 2-6 で確定した事項）

- `set-header` の無言成功の原因は、`cmd_set_header` が**一致件数を数えていない**こと。
  `- Draft PR:` 表記は引き金であって原因ではない。
- `- 現在のループ:` 行の挿入位置判定が実物のHANDOFF.mdと噛み合っておらず、見出しの上へ入る。
- ヘッダブロックの位置は履歴上2通りある（見出しの後23件／見出しの前9件）。
- issue #140 は取り込まず、別issueのまま残す。

## 変更1: `cmd_set_header` の一致件数検査

`.claude/scripts/src/update-handoff-progress.sh`

- 指定された項目（`--issue` / `--branch` / `--pr` / `--push-count`）ごとに一致件数を数える。
- **1件でない項目が1つでもあれば、書き戻さずに `return 1`**。標準エラーへ、項目名・実際の件数・
  期待する行の書式（例: `- PR: <値>`）を出す。
  - 0件: ヘッダ行が無い／表記が違う（`- Draft PR:` 等）。
  - 2件以上: 「ヘッダ各項目は1行」という前提が崩れている。どちらを正とすべきか機械では
    決められないため、黙って両方書き換えない。
- `--loop` は従来どおり `set_loop_header_in_lines` へ委ね、失敗時はエラー終了する
  （既存の挙動。行が無ければ挿入するため、件数検査の対象にしない）。
- **`--loop` の書き込みも、他項目の検査に通ってから行う。** 検査に落ちる呼び出しで
  `- 現在のループ:` だけが更新される中途半端な状態を作らない。

## 変更2: ヘッダ行の探索範囲を「ヘッダブロック」へ限定

同ファイル。`cmd_set_header` と `set_loop_header_in_lines` が共通で使う。

- **ヘッダブロック** = ファイル先頭から `## フロー進捗状況` 節の終わり（その見出し以降で最初に
  現れる `## ` 見出しの直前）まで。`## フロー進捗状況` が無いファイルではファイル全体。
  - 履歴上の2通りの配置（見出しの前／後）をどちらも拾える。
  - 「やったこと」以降の本文で `- PR: …` のように引用されている行は拾わない
    （現状は拾って書き換えてしまう）。
- 範囲の算出は行走査1回で行い、外部コマンド・コマンド置換を増やさない
  （`.claude/rules/shell-script-style.md`「外部プロセス起動のコスト」）。

## 変更3: `- 現在のループ:` 行の挿入位置

同ファイル `set_loop_header_in_lines`。

| 状況 | 挿入位置 |
|---|---|
| 既に `- 現在のループ:` 行がある | その行を置換（現状のまま） |
| ヘッダブロック内にヘッダ項目がある | **最後のヘッダ項目の直後**（現状は「見出しより前」に限定されていた） |
| ヘッダ項目が無く `## フロー進捗状況` がある | **見出しの直後**（空行を挟む）。現状の「見出しの直前」から変更する |
| どちらも無い | 終了コード1（現状のまま。`mark-done` は警告止まり、`set-header --loop` はエラー） |

`- 追従監視:` は**挿入位置の基準にしない**（`- 現在のループ:` より後に置く項目のため）。

## 変更4: `HANDOFF_TEMPLATE` へヘッダ行の雛形

`.claude/scripts/src/cleanup-task.sh`

```
## フロー進捗状況

- issue: （未着手）
- ブランチ: （未着手）
- PR: （未着手）
- push回数: 0
- 現在のループ: なし
- 追従監視: なし

（進捗表は次タスク着手時に記入する）
```

- リポジトリにコミットされている `HANDOFF.md` も、flow-id 5-3 の `cleanup-task.sh` 実行で
  この内容へ揃う。
- `.claude/scripts/test/test_cleanup_task.sh` の `HANDOFF_TEMPLATE` 検査（見出しの有無・
  末尾改行・進捗記号を含まないこと）が引き続き通ることを確認する。

## テスト（`.claude/scripts/test/test_update_handoff_progress.sh`）

**実物どおりのフィクスチャ**（`## フロー進捗状況` 見出しの下にヘッダ行が並ぶ形）を追加し、
既存の `write_fixture`（見出し無し）と併存させる。既存ケースは1件も変更しない。

| # | 検証すること |
|---|---|
| 1 | `set-header --pr` が `- Draft PR:` 表記のファイルで**エラー終了**する |
| 2 | そのときファイルが1バイトも変わっていない（書き戻していない） |
| 3 | エラーメッセージに項目名と期待する書式が含まれる |
| 4 | 複数項目を指定し、片方だけ見つからない場合もエラーになり、**見つかった側も書き換わっていない** |
| 5 | 同じ項目が2行ある場合にエラーになる |
| 6 | 正常系（全項目が1行ずつある）は従来どおり成功する |
| 7 | 実物どおりの配置で `mark-done` すると `- 現在のループ:` が**最後のヘッダ項目の直後**へ入る |
| 8 | ヘッダ項目が無く見出しだけのファイルでは、見出しの**直後**へ空行付きで入る |
| 9 | 「やったこと」節に `- PR: …` の引用があっても、そちらを書き換えない |
| 10 | `- 追従監視:` 行があっても `- 現在のループ:` はその**前**へ入る |
| 11 | `--loop` と他項目を同時指定し、他項目が見つからないとき `- 現在のループ:` も書き換わらない |
