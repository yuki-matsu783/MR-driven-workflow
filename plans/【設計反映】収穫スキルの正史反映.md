### 3. DDR: `i0027-02-エラー隔離は条件文脈の外のサブシェルでset-eを掛け直して行う.md`

- **実測**（bash 5.2.21 / Claude Code on the web・Linux／2026-08-23）。原因は2つに
  分けて記録する（敵対的レビュー5回目の指摘）:
  1. 明示サブシェル `( f )` は `-e` を継承する（条件文脈の外なら単体で fail-fast する）が、
     **条件文脈（`||`・`if`）に置くと errexit の一時停止が内側まで伝播**し、途中失敗が
     素通りする（`( f ) || rc=$?` で `REACHED` が出力され rc=0）。
  2. コマンド置換 `$(...)` は **`shopt inherit_errexit` が既定オフ**のため、条件文脈か
     どうかに関係なく `-e` を継承しない（`out="$(f)"` は条件文脈の外でも関数本体が最後まで
     走る）。
- **採用**: フォークされる側の内側で `set -e` を掛け直す。出力を捨てる形
  `set +e; ( set -e; f ); rc=$?; set -e` と、出力を受け取る形
  `set +e; out="$(set -e; f)"; rc=$?; set -e` の2形（いずれも実測で途中失敗が rc=1 に
  現れることを確認済み）。
- **却下案**（いずれも理由付きで記録する）:
  - `shopt -s inherit_errexit`（bash 4.4+）: コマンド置換側の直接の対処で、立てると
    `out="$(f)"` が fail-fast することを実測確認済み。却下理由は (1) **bash 4.4 未満では
    使えない**（この機構は git bash 配布先で bash 版を制御できない前提。
    shell-script-style.md「hookの前置フィルタ」の `${var,,}` 却下と同根）、(2) スクリプト
    全体へ効く宣言のため、**既存コードの「継承しない」前提の箇所（`$(cmd)` の失敗を無視して
    続行する意図的な書き方）を一括で挙動変更してしまう**副作用の広さ、(3) サブシェル側の
    条件文脈問題（機構1）には効かず、単独では解決にならない。
  - `set -E` ＋ `trap ERR`: ERR トラップの発火条件も条件文脈で抑止されるため機構1を
    解決せず、トラップの継承規則がさらに難解になる（デバッグ困難）。
  - 各コマンドの終了コードを1つずつ `|| return 1` で検査する案: 漏れが出やすく、
    追加のたびに検査を書く負担が残る。採用形なら関数全体が既定で fail-fast になる。
- shell-script-style.md「エラー方針」「テスト」節の従来記述が成り立たない環境があることを
  記録する（規約本体の訂正は `【AIアセット反映】` 側）。
