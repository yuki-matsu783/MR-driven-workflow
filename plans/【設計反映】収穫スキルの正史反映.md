### 1. spec: `.claude/docs/spec/harvest-from-projects.md`

従い、次を記載する。

- **背景・目的**: 配布（apply-mr-workflow-to-project）の対向。配布先の改善を本家へ還流する
  起点を作る。出口は issue 起票まで（正史の直接変更はしない。issue #27 受け入れ条件）。
- **仕様**: scan の出力スキーマ（`{"schemaVersion":1,"targets":[...]}`・files レコードの
  キー）／分類規則（modified=層・strategy 別指紋、deleted / removedUpstream、added の
  3段除外）／縮退モードの条件と挙動（manifest 無し・壊れ・`files` 空／`git archive | tar`
  失敗時は error）／conflict 判定（base 解決・`-dirty` の baseApproximate）／merge3 の
  終了コード5値（0/1/2/3/4）と層判定のフェイルクローズ／読み取り専用の保証（git
  サブコマンド一覧）／git 起動の一括化と `core.quotepath=false`・`--no-renames`。
- **影響範囲**: 本家専用（exclude 層）。配布物への影響は markdown-frontmatter.md の
  追記節と dist-layers.json のエントリのみ。
- **未決定事項・懸念点**: Windows（git bash）実機未検証（`git archive | tar`・

### 2. DDR: `i0027-01-収穫スキルは読み取り専用分析とissue起票までを出口にする.md`

主な決定と却下案（詳細はレビュー往復の記録から転記する）:

- 出口は issue 起票（＋任意で草案）まで。**自動で本家の正史を変更する案・PR を自動作成する
  案は却下**（着手判断は人間が握る原則。issue #39 と同根）。
- 除外の正は配布先の dist-layers.json（del(.upstream) 済み）1つだけ。**`git check-ignore`
  併用案は「正が2つになる」ため却下**（敵対的レビュー2回目）。
- merge 層・seed 層・dist-layers.json は 3-way 対象外。層判定はフェイルクローズ。
- エラー隔離はサブシェル内での `set -e` 掛け直し（詳細は `i0027-02`）。

### 3. DDR: `i0027-02-エラー隔離は条件文脈の外のサブシェルでset-eを掛け直して行う.md`

- **実測**（bash 5.2.21 / Claude Code on the web・Linux／2026-08-23）:
  `( f ) || rc=$?` も `if out="$(f)"` も、errexit の一時停止がサブシェル・コマンド置換の
  内部へ伝播し、関数内の途中失敗が素通りする（`REACHED` が出力され rc=0）。
- **採用**: `set +e; ( set -e; f ); rc=$?; set -e`（条件文脈の外なら内側の `set -e` が
  効き、内部失敗で即座にサブシェルごと終了して rc に現れる。実測済み）。
- **却下案**: 各コマンドの終了コードを1つずつ `|| return 1` で検査する案（漏れが出やすく、
  追加のたびに検査を書く負担が残る。採用形なら関数全体が既定で fail-fast になる）。
- shell-script-style.md「エラー方針」の従来記述が成り立たない環境があることを記録する
  （規約本体の訂正は `【AIアセット反映】` 側）。
