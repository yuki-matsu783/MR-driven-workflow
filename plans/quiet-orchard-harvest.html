この計画で何をするか

配布先プロジェクトで加えられたAIアセットの改善のうち、汎用的で価値のあるものを本家へ取り込む「収穫（逆輸入）」スキルを新設する。issue #26 で整備済みの土台（.claude/dist-layers.json の5層定義・配布先の .claude/.asset-manifest.json（適用元コミットSHA・ファイル別のLF正規化sha256））を前提とする。

変更対象

領域何をするか
.claude/skills/<収穫スキル>/（新規）SKILL.md と収穫スクリプト（scripts/）。配布対象外（本家専用）とする想定
.claude/scripts/test/ またはスキル配下収穫スクリプトの純粋ロジックの単体テスト（置き場所はフェーズ2で確定）
.claude/rules/ または既存ルールファイル「配布先で機構に関するDDRを書かず本家へissue起票する」運用規約の明文化（配布物に含まれる場所へ置く）
.claude/dist-layers.json新スキルの層エントリ追加（exclude 想定。apply-mr-workflow-to-project と同じ理由）
.claude/docs/spec/ .claude/docs/ddr/フェーズ4で仕様書・意思決定記録を反映

方針

  • 読み取り専用の分析＋人間の選択＋既存フロー接続という構成にする。収穫スキル自身は本家の正史（.claude/rules/ .claude/skills/ .claude/docs/）を直接書き換えない。出口は issue 起票（issue-create スキル経由）または個別作業計画草案の作成まで。
  • 差分検出は配布先 manifest の記録sha256と現在内容の比較で行い、core / merge 層の modified / added / deleted を抽出する。
  • 3-way突き合わせ（base=git show <記録SHA>:<path>、ours=本家HEAD、theirs=配布先現在）で「衝突なし／衝突あり」へ仕分ける。
  • manifestが無い配布先では縮退モード（層分け定義に含まれる全ファイルを本家HEADと差分表示）で動く。
  • 複数の配布先ローカルパスを一度の実行で受け取れる。
  • 判断材料（ai-asset: prefix コミットの有無・変更回数・プロジェクト固有語の含有）を提示する。

フェーズ2〈調査〉

実施する。個別調査計画で次の問いに答える。

  1. manifest の正確な形式と merge 層の指紋の記録形（「読む側が無い」の確認）
  2. 収穫スクリプト・単体テストの置き場所の規約（install-to-project.sh のテストのされ方）
  3. 3-way突き合わせの実装手段（git merge-file / git show と、記録SHAが本家に無い場合の縮退）
  4. 縮退モード（manifest無し）で層分け定義から対象ファイルを列挙する方法
  5. 出口レベル2種（issue起票のみ／個別作業計画草案）の実装接続点
  6. DDR運用規約の明文化先（配布物に含まれ、二重管理にならない場所）
  7. 判断材料3種を配布先リポジトリから取得する方法と限界

フェーズ3〈作業〉・フェーズ5〈クローズ〉

フェーズ3: 調査結果をもとに個別作業計画（plans/【AIアセット作成】【実装】【テスト】〜.md）を立て、収穫スキル（SKILL.md＋スクリプト＋単体テスト）と運用規約の明文化を実装する。

フェーズ5: 通常どおり実施する（コンフリクト検知・関連issue通知・.gemini/ 変換同期・統括レポート・片付け・Draft解除）。マージは人間が行う。

やらないこと（スコープ外）

この計画では決めない・触らない
  • 収穫スキルによる本家正史（.claude/rules/ .claude/skills/ .claude/docs/）の直接書き換え（issueの受け入れ条件で明示的に禁止）
  • GitLab MCP 対応・リモート配布先（同一マシン上に無い配布先）の収穫（issueが「同一マシン上にある前提」と明示）
  • 配布側（install-to-project.sh）の機能変更（manifest形式の変更等はしない。読むだけ）

非対話セッションでの進め方（この回の特記）

  • ユーザー指示により、各フェーズの計画 commit/push 後と作業実施 commit/push 後に敵対的レビューを自動起動し、指摘を修正しながら進める（非対話モードのため自律起動が許可される。各フェーズ上限3回の範囲内＝計画1回＋実施1回）。
  • 人間レビューのステップは待てないため、該当ループの進捗記号は [] のまま残し、実施内容は HANDOFF.md「やったこと」へ文章で補足する。
  • 敵対的レビューの指摘へは、修正後に同スレッドへ返信し、未返信スレッド0を維持する。
