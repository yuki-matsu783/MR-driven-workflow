反映内容（反映先: .claude/rules/shell-script-style.md）

  • 誤りの訂正（原因は2つあり、混同せず書き分ける）: 「フォークされた側では set -e が正しく機能する」という理由付けは bash 5.2 では成り立たない。機構は2つに分かれる（いずれも bash 5.2.21 で実測済み）。
    1. 明示サブシェル ( f ): -e 自体は継承する（条件文脈の外なら単体で fail-fast。実測: exit=1）。壊れるのは条件文脈（||・if）に置いたときで、errexit の一時停止がサブシェルの内側まで伝播し途中失敗が素通りする。
    2. コマンド置換 $(...): shopt inherit_errexit が既定でオフのため、条件文脈かどうかに関係なく -e を一切継承しない（実測: out="$(f)" は条件文脈の外でも関数本体が最後まで走る）。「条件文脈の外へ出せばコマンド置換でも fail-fast する」と読める書き方をしない。
    実測の詳細・却下案は DDR i0027-02 を正とし、規約側は結論とパターンだけを書く。
  • 推奨パターンの差し替え: フォークされる側の内側で set -e を掛け直す。出力の要否で2形を併記する。
# 出力を捨ててよい場合（サブシェル。条件文脈に入れない）
set +e
( set -e; risky_func )
rc=$?
set -e
if [ "$rc" -ne 0 ]; then fallback; fi

# 出力を受け取る場合（コマンド置換の内側で set -e を掛け直す。
# 外側の set +e だけでは inherit_errexit 既定オフのため効かない）
set +e
out="$(set -e; risky_func)"
rc=$?
set -e
if [ "$rc" -ne 0 ]; then fallback; fi
  • 従来パターンの位置づけ: if result="$(risky_func)" は関数の最終コマンドの失敗しか検知できないことを明記（複数コマンドから成る関数の途中失敗の検知には使えない）。実例（session-start.sh 等）は見直し候補として注記（実装修正はスコープ外）。
  • 「テスト」節の理由付けの訂正: 「コマンド置換のサブシェルは -e を引き継ぐ」を「$(func; echo $?) の値は errexit・inherit_errexit の設定と bash の版で変わる」という趣旨へ差し替える（使わないという結論・if で受ける代替はそのまま）。
  • 実例参照として harvest-from-projects.sh の cmd_scan を追加。

検証

# (1) 条件文脈のサブシェル: 途中失敗が素通り（従来記述が成り立たない実証）
bash -c 'set -euo pipefail; f() { false; echo REACHED; }; rc=0; ( f ) || rc=$?; echo "rc=$rc"'
# (2) 条件文脈の外のサブシェル: fail-fast する（機構1の実証）
bash -c 'set -euo pipefail; f() { false; echo R1; }; ( f ); echo after'; echo "exit=$?"
# (3) コマンド置換: 条件文脈の外でも -e を継承しない（機構2の実証）
bash -c 'set -euo pipefail; f() { false; echo R2; }; out="$(f)"; echo "after out=$out"'; echo "exit=$?"
# (4) 推奨パターン（出力を捨てる形）
bash -c 'set -euo pipefail; f() { false; echo R3; }; set +e; ( set -e; f ); rc=$?; set -e; echo "rc=$rc"'
# (5) 推奨パターン（出力を受け取る形）
bash -c 'set -euo pipefail; f() { false; echo R4; }; set +e; out="$(set -e; f)"; rc=$?; set -e; echo "rc=$rc out=[$out]"'

合格条件: (1) は REACHED と rc=0、(2) は何も出力せず exit=1、(3) は R2 と after が出て exit=0、(4) は R3 を出力せず rc=1、(5) は rc=1 out=[]。訂正後の規約本文がこの5つの実測結果と矛盾しないこと（いずれも本計画作成時に実行済みで、期待どおりの値を確認している）。
