反映内容（反映先: .claude/rules/shell-script-style.md）

  • 誤りの訂正: 「フォークされた側では set -e が正しく機能する」という理由付けは bash 5.2 では成り立たない（実測の詳細は DDR i0027-02 を正とする）。
  • 推奨パターンの差し替え: 条件文脈の外でサブシェルを実行し、内側で set -e を掛け直す。
set +e
( set -e; risky_func )
rc=$?
set -e
if [ "$rc" -ne 0 ]; then fallback; fi
  • 従来パターンの位置づけ: if result="$(risky_func)" は関数の最終コマンドの失敗しか検知できないことを明記。実例（session-start.sh 等）は見直し候補として注記（実装修正はスコープ外）。
  • 実例参照として harvest-from-projects.sh の cmd_scan を追加。

検証

bash -c 'set -euo pipefail; f() { false; echo REACHED; }; rc=0; ( f ) || rc=$?; echo "rc=$rc"'
bash -c 'set -euo pipefail; f() { false; echo R2; }; set +e; ( set -e; f ); rc=$?; set -e; echo "rc=$rc"'

合格条件: 1つ目は REACHED と rc=0（従来記述が成り立たない実証）、2つ目は R2 を出力せず rc=1（推奨パターンの実証）。訂正後の規約本文がこの実測と矛盾しないこと。
