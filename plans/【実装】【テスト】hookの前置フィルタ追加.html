この計画で何をするか

block-direct-git-commit.sh と post-issue-create-notice.sh の main()冒頭へ前置フィルタを追加し、対象外ペイロードでjqを1回も 呼ばないようにする。あわせて、前置フィルタが精密判定の超集合であることを固定する単体テストを 追加する。

方針

前置フィルタの型

local raw
IFS= read -r -d '' raw || true
[ -n "$raw" ] || exit 0
case "<比較対象>" in
  <パターン>) ;;
  *) exit 0 ;;
esac

read・case・${raw,,}はいずれもbash組み込みで forkしない。判定本体は変更しない。

block-direct-git-commit.sh: 超集合の設計

精密判定は${s,,}で小文字化してから走査・比較するため、大文字混じり （git COMMIT）も検知対象になりうる。gitとcommitが 隣接している必要もない。よって${raw,,}で小文字化した上で*commit*を 含むかを見れば十分な超集合になる。

post-issue-create-notice.sh: 超集合の設計

精密判定は大文字小文字を区別する完全部分一致（CLI経路: create-issue.sh）と MCPツール名一致（mcp__github__issue_write）の2経路。前置フィルタはこの2つの 文字列いずれかを含むかで判定する（methodの値までは前置フィルタでは見ない。 後段のis_issue_create_callが絞り込む）。

issue #149との整合性 #149はis_issue_create_callのCLI経路判定を、部分一致からコマンド位置判定へ 差し替える計画（未着手）。コマンド位置判定は部分一致の対象を絞り込む方向の変更であり、 マッチする集合は現状の部分一致の部分集合になる。したがって前置フィルタ（部分一致での 超集合）は、#149適用後の狭められた判定に対しても引き続き超集合であり続ける。この関係は DDR（フェーズ4）に明記し、#149へも通知する（flow-id 5-2）。
