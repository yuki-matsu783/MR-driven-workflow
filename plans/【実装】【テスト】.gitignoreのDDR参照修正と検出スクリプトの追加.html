検出スクリプトの設計（reportsの「検出方式の設計」節を実装する。v2で全面改訂）

  1. 対象ファイル: git ls-files -z -- '*.md' '*.sh' '.gitignore'で取得 （バイナリを除く）。
  2. 次の3ディレクトリ配下は除外する:

    • plans/ reports/ worklog/ （v2で追加。理由は下記「対象範囲の除外理由」）。
  3. Markdownコードフェンス（行頭が```または~~~で始まる行。 インデントされたフェンスも対象、正規表現^[[:space:]]*(```|~~~)でトグル）で 囲まれた範囲内の行は除外する。フェンス行が奇数個で閉じずにファイル末尾へ達した場合は、 残りの行を除外しない（安全側＝偽陽性が出る方向へ倒す。偽陰性＝無言の見逃しにしない）。

  6. 残った候補について[[ -f "$path" ]]で実在確認する。存在しなければ 参照切れとしてfile:lineno:path形式で標準出力へ報告する。加えて、 標準エラーへ走査ファイル数 / 候補数 / 除外数（テスト・plans等/フェンス内/ 省略記法の内訳） / 参照切れ数のサマリを出す（v2で追加: 件数を出さないと 「正規表現が当たらず0件」と「本当に参照切れが無く0件」を区別できないため。issueの 受け入れ条件・全体作業計画が求める「件数付きの検索結果」の要件でもある）。
  7. スクリプトは引数を取らない。冒頭でcd "$(git rev-parse --show-toplevel)" しリポジトリルートを起点に走査する（v2で追加: 未定義だった呼び出し インターフェースを確定した）。
  8. 実行タイミングは手動実行のみとし、この個別作業計画で決定する （v2で訂正: 当初「全体作業計画の判断を踏襲」としていたが、全体作業計画が 留保していたのは「hookへ組み込まない」ことだけで、実行タイミングの具体案自体は フェーズ2の成果物として決めるとされていた。しかしreportsにはこの判断が記録されて いなかった（帰属の誤り）ため、ここで確定させる。.claude/rules/shell-script-style.md 「外部プロセス起動のコスト」に照らし、頻度の低い整合性チェックをhookへ組み込む価値は 無いと判断。将来resolve-conflictスキル等への合流が必要になれば別issueで 検討する）。新規specファイルは作らない（規模の小さいスクリプトであり、本計画＋ テストコード＋フェーズ4のDDRでドキュメントとして十分と判断。全体作業計画の 「過剰なドキュメント化は避ける」方針に沿う）。

実装上の注意（shell-script-style.mdへの適合）

  • git ls-files -z + while IFS= read -r -d ''でNULバイトを保持し、 日本語パスのクォート化を回避する。外部コマンドの起動はgit ls-filesの1回のみ （上記のとおりgrepは使わない）。
  • git ls-filesはindexの内容を返すため、削除済み未ステージファイルが 混ざりうる。読み込み前に[[ -f "$path" ]]のガードを挟む。
  • スクリプト冒頭でset -euo pipefailを宣言し、BOM無しUTF-8・LF改行で保存する。
  • テストから直接呼べるよう、次の関数境界を持たせる（v2で追加: 純粋関数への切り出しが 無いと、単体テストが実装の正規表現・フィルタ条件を書き写すだけになり、実装側の誤りを 検出できない。.claude/rules/shell-script-style.md「テスト」の指摘と同根）。
    • extract_ddr_candidates_to_reply <行>: 1行から候補パス配列を REPLY_CANDIDATES（配列）へ返す。
    • is_excluded_target_path <ファイルパス>: ディレクトリ除外 （テスト・plans/reports/worklog）の判定。
    • is_placeholder_candidate <候補文字列>: 省略記法（.../ …）を含むかの判定。
    • 本体はmain関数にまとめ、 if [ "${BASH_SOURCE[0]}" = "${0}" ]; then main; fiでガードする。 単体テストはこのファイルをsourceし、上記の関数を直接呼ぶ （正規表現やフィルタ条件をテスト側へ書き写さない）。

単体テストの設計（v2で改訂）

  • 対象は副作用の無い純粋ロジック（上記の3関数）。
  • 少なくとも次のケースを含める:
    • 通常のDDRパス参照が実在すれば検出されない
    • 存在しないDDRパス参照は検出される（.gitignoreの元の2箇所相当の 再現ケース）
    • .claude/scripts/test/ plans/ reports/ worklog/配下のパスはis_excluded_target_pathで除外される
    • コードフェンス内のパスは除外される（インデントされたフェンスも含む）
    • コードフェンスが奇数個で閉じない場合、残りの行は除外されない （安全側の挙動を確認する）
    • 省略記法（.../…）を含む候補は is_placeholder_candidateで除外される
    • ファイル名自体に.mdを含む実在DDR（ i0032-01-GitLab-issueテンプレートは予約名Default.mdを正とし文書側を合わせる.md。 v2で訂正: 省略記法を含む例示文字列をそのままフィクスチャにすると省略記法 フィルタに先に除外され貪欲マッチの検証にならないため、省略記法を含まない実名を 使う）について、extract_ddr_candidates_to_replyが抽出した候補文字列 そのものをassert_eqし、末尾の.mdまで正しく1本の フルパスとして一致することを確認する（検出結果の真偽ではなく抽出関数の戻り値を 直接検証する）
    • タブ区切りで2つのパスが同一行に並ぶ場合、2つの独立した候補として抽出される
    • 枝番が1桁・3桁のDDRパス（i0133-1-…md等）も候補として抽出される （枝番側[0-9]+化の検証）
  • bash -n構文チェックを行い、passed=N failures=N形式で出力、 失敗時は終了コード1。

検証

# 1. .gitignore側の参照切れが解消されたことを確認する（0件を期待）。
#    タブは \t ではなく実際のタブ文字を使う（変数経由で組み立てる）
tab=$'\t'
grep -noE "\.claude/docs/ddr/i[0-9]+-[0-9]+-[^]) \"'`($tab]*\.md" .gitignore \
  | while IFS=: read -r lineno path; do [[ -f "$path" ]] || echo "$lineno:$path"; done

# 2. 検出スクリプトの構文チェック
bash -n .claude/scripts/src/check-doc-references.sh

# 3. 検出スクリプトをリポジトリ全体に対して実行し、候補件数>0かつ参照切れ0件であることを
#    標準エラーのサマリで確認する（引数は取らない）
bash .claude/scripts/src/check-doc-references.sh

# 4. 単体テストが全件成功する
bash .claude/scripts/test/test_check_doc_references.sh

上記1〜4がすべて成功すること（1は0件、3は候補N件・N>0のうえで参照切れ0件、2と4は 非0の終了コードが出ないこと）をreports/へ、走査した候補の母数付きで記録する。
