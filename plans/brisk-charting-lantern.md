# 全体作業計画 — AIアセット反映の対象を洗い出す手順を定義する（issue #155）

- issue: #155
- ブランチ: `claude/ai-asset-reflection-scope-njqn95`
- 作成日: 2026-08-23
- フェーズ: 1〈起点〉 flow-id 1-4

## この計画で何をするか

`.claude/skills/issue-mr-flow/SKILL.md` に **「AIアセット反映の対象の洗い出し」節**を新設し、
flow-id 4-1・4-6 の行からそこを参照させる。節が持つのは次の6つである。

1. 洗い出しの**起点**（今回のMRで、既存アセットで対応できなかったもの）
2. **4類型**（(a) アセットが無かった／(b) あったが誤っていた／(c) あったが罠が書かれていなかった／
   (d) あったのに辿り着けなかった）
3. **再現性の証拠を要求する範囲**（(a) のみ。(b)(c)(d) は1回でも反映する）
4. **証拠集めの段階と打ち切り条件**（同一MR内 → `doc-search` → 直近のPR・DDR一覧、で打ち切る）
5. **反映先の形態の選び方**（「いつ効いてほしいか」×「守らせ方の強さ」の2軸）
6. **削除・統合も対象**であること

あわせて `plans/REVIEW-POINTS.md` へ `【AIアセット反映】` の計画に対するレビュー観点を足し、
判断の理由と却下案をDDRへ残す。`.claude/docs/spec/issue-mr-workflow.md` は入口のみとし、
手順そのものを二重に持たない。

## 方針

- **手順の正はSKILL.mdの1箇所に置く。** issueの受け入れ条件が明示的に「spec側は入口のみ」と
  求めており、このリポジトリが繰り返し問題にしてきた二重管理を避ける。
- **4類型は「アセットの有無」と「不足の性質」で切る。** (a) だけ再現性の証拠を要求するのは、
  新設は継続コスト（読む量・(d) の温床）を伴うのに対し、(b)(c)(d) は既存アセットの精度を上げる
  だけで、書かないコスト（次のセッションが同じ罠を踏む）と書くコストが非対称なためである。
- **証拠集めは安い側から見て打ち切る**（全MR横断の網羅探索はしない）。flow-id 5-4 で
  `plans/` `worklog/` `reports/` を消して squash merge するため、過去MRの一次資料は main に
  残らない。網羅を求めると原理的に達成できない要求になる。
- **反映先の2軸は「いつ効いてほしいか」×「守らせ方の強さ（読ませる → 手順化 → 検証で落とす）」。**
  形態（rules / skills / scripts / hooks / REVIEW-POINTS.md / agents）はこの2軸から決める。
- **削除・統合を対象に含める。** 追加だけを見ているとアセットが単調増加し、(d)（辿り着けない）を
  自ら量産する。

## issue分割の判定

**分割しない。** 受け入れ条件は「SKILL.mdの節」「表」「打ち切り条件」「2軸」「REVIEW-POINTS」
「DDR」「spec入口」と並ぶが、これらは**同型の成果物の並列列挙ではなく、1つの手順定義を成立させる
ための構成要素**である。「各項目が単独でマージされてもシステムが壊れないか」で判定すると、
たとえば4類型だけをマージしても証拠要求範囲が無く手順として機能しない。横断的変更に当たるため
分割の対象ではない。
