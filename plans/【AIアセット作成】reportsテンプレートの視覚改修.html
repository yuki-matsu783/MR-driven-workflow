新設: 重点レビュー依頼（id="review-focus"）

3段階の枠を色付きカードで用意し、各項目から該当章（#f1 等）へリンクする。

段階意味視覚（線色＋地色＋ラベル）
特に見てほしい判断に困っているborder: 2px solid var(--accent)＋background: var(--accent-soft)・「◆特に見てほしい」
承認が欲しい方針は決めたので確認してほしいborder: 1px solid var(--accent)＋background: var(--panel)・「◇承認が欲しい」
細かいレビューは不要ほぼ確実border: 1px solid var(--line)＋background: var(--panel)・文字 var(--muted)・「・細かいレビューは不要」

色相（青/黄/赤）は結論の性質専用に予約し、レビューの重みには使わない。重みはアクセント系1色相の中の濃度・枠の太さ＋記号（◆◇・）で表す。こうすることで、流し読みで「重点依頼の赤」を「問題の赤」と読み違える混線を避ける。第3段階は専用トークンを新設せず既存の --panel／--line／--muted で組む——--muted は文字色にのみ使い、背景には使わない。

サマリ（結論の一覧）の改修

  • 表を廃止し、結論カードのリストにする。1件＝「性質チップ（◎良／△注意／✕問題）＋短い結論（1行）＋根拠の性質（実測／推測 等。現行の表の4列目の情報を落とさず引き継ぐ）＋該当章へのアンカーリンク」の4要素。
  • 性質の色: 良＝青 --good（新設）／注意＝黄 --warn／問題＝赤 --stop。
  • ヘッダ帯に件数チップ（例: ◎3 △2 ✕1）を置く。
  • 記述量の目安をコメントで指示（結論は1行。詳細は章に書く）。

色トークン・チップ

  • :root へ --good: #1d4ed8; --good-soft: #e7edfd;、ダーク側へ --good: #8ab4f8; --good-soft: #17233a; を追加。
  • .tag.ok/.tag.warn/.tag.stop（既存・本体未使用）は削除し、結論性質チップ .chip.good/.chip.warn/.chip.stop へ置き換える（緑チップと青「良」チップの語彙併存を防ぐ）。

  • テンプレート冒頭コメントへリンク破断検査（下記「検証」のcommコマンド。出力0行が合格）を追記。

# 2. リンク破断（テンプレートの見本アンカー自身が整合していること。出力0行が合格）
comm -23 <(grep -oE 'href="#[A-Za-z0-9_-]+"' "$f" | sed 's/^href="#//;s/"$//' | sort -u) \
         <(grep -oE 'id="[A-Za-z0-9_-]+"'   "$f" | sed 's/^id="//;s/"$//'   | sort -u)

# 2b. 検査自体が壊れていないことの確認（存在しないIDへの参照を1件仕込んだ一時コピーで、
#     同じコマンドが「zzz-broken」1行を出力すること。異常が無ければ何も出ない検証の空振り対策）
tmp="$(mktemp)"
sed 's|</body>|<a href="#zzz-broken">x</a></body>|' "$f" > "$tmp"
comm -23 <(grep -oE 'href="#[A-Za-z0-9_-]+"' "$tmp" | sed 's/^href="#//;s/"$//' | sort -u) \
         <(grep -oE 'id="[A-Za-z0-9_-]+"'   "$tmp" | sed 's/^id="//;s/"$//'   | sort -u)
rm -f "$tmp"

# 3. プレースホルダ検査手順の維持（テンプレート自身には残っているのが正。0でないこと）
grep -c '<!-- ここに書く' "$f"

# 4. 受け入れ条件の構造確認（それぞれ1件以上ヒットすること）
grep -c 'id="review-focus"' "$f"

# 5. コメントの伝承内容が実在すること（左のコマンドが右の件数以上を返すこと）
grep -c '重点レビュー依頼' "$f"   # 2以上（本文の節と冒頭コメントの双方に現れる）
grep -c 'リンク破断' "$f"          # 1以上（冒頭コメントの検査手順）
grep -c '結論の性質' "$f"          # 1以上（色・記号の使い分けの説明）
