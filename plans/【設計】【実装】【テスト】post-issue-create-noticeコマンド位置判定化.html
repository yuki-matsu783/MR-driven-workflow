方針

既存の_cp_scan_tokens（git <サブコマンド>専用）と同じ骨格 （正規化済み文字列をトークン走査し、コマンド位置にあるトークンだけを見る）を再利用しつつ、 判定内容を「basenameが対象スクリプト名と一致するか」に置き換えた専用関数 _cp_scan_tokens_for_scriptを新設する。_cp_scan_tokens自体は 改変しない（gitのグローバルオプション読み飛ばしという固有ロジックを持ち、スクリプト名判定には 不要なため。局所性を優先する既存方針に合わせる）。

判定する2形態: (1) 単体実行 — コマンド位置のトークンのbasenameが対象スクリプト名と一致。 (2) インタプリタ経由 — コマンド位置のトークンがbash/sh等で、直後の 非オプショントークン（-c等のコード文字列オプションが無い場合に限る）のbasenameが 一致。cat/grepのような無関係なコマンドの引数に現れるだけでは、 そのコマンド自身がコマンド位置を消費した時点で判定対象外になる（既存の_cp_scan_tokens と同じ振る舞い）。

既存の記述を置き換える場合 置き換え前と置き換え後の形を両方書く。

置き換え前:

run_shell_command | Bash | PowerShell)
  [[ "$command" == *create-issue.sh* ]]
  ;;

置き換え後（イメージ。3段ガードはmain()側、is_issue_create_callの 引数3つのシグネチャは変えない）:

if ((BASH_VERSINFO[0] > 4 || (BASH_VERSINFO[0] == 4 && BASH_VERSINFO[1] >= 3))) &&
  [ -r "$lib" ] && source "$lib" 2>/dev/null &&
  declare -F command_invokes_script >/dev/null; then
  cli_match() { command_invokes_script "$1" 'create-issue.sh'; }
else
  cli_match() { [[ "$1" == *create-issue.sh* ]]; }
fi
