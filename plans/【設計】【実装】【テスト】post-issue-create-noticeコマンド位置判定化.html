方針

command_invokes_script の設計

既存の_cp_scan_tokens（git <サブコマンド>専用）と同じ骨格 （正規化済み文字列をトークン走査し、コマンド位置にあるトークンだけを見る）を再利用しつつ、 判定内容を「basenameが対象スクリプト名と一致するか」に置き換えた専用関数 _cp_scan_tokens_for_scriptを新設する。_cp_scan_tokens自体は 改変しない（gitのグローバルオプション読み飛ばしという固有ロジックを持ち、スクリプト名判定には 不要なため。局所性を優先する既存方針に合わせる）。

判定する2形態: (1) 単体実行 — コマンド位置のトークンのbasenameが対象スクリプト名と一致。 (2) インタプリタ経由 — コマンド位置のトークンがbash/sh等で、直後の 非オプショントークン（-c等のコード文字列オプションが無い場合に限る）のbasenameが 一致。

_cp_scan_tokens_for_script() {
  local norm="$1" target="$2"   # target は小文字化済みのbasename
  _CP_OPAQUE_FOUND=0
  # ループ: at_cmd の間だけ判定
  #   base == target -> 一致
  #   base が _CP_OPAQUE_WITH_OPT -> 直後の非オプショントークンを見る。コード文字列
  #     オプションがあれば _CP_OPAQUE_FOUND=1
  #   base が _CP_OPAQUE_WORDS（eval/xargs/find等）-> _CP_OPAQUE_FOUND=1
  #   base が _CP_PREFIX_WORDS（sudo/if/timeout等）-> 次の非オプショントークンを
  #     「実コマンド」として1回だけ判定し、sticky区間をそこで終える
  #     （_cp_scan_tokens とはこの点が異なる。下記「敵対的レビュー」1点目）
  #   それ以外 -> at_cmd=0
}

command_invokes_script() {
  local s="${1:-}" script="${2:?}"
  [[ -n $s ]] || return 1
  local script_lower="${script,,}"
  script_lower="${script_lower##*/}"; script_lower="${script_lower%.exe}"
  if _cp_has_overlong_line "$s"; then
    [[ "${s,,}" == *"$script_lower"* ]] && return 0
    return 1
  fi
  normalize_shell_command_to_reply "$s"
  if _cp_scan_tokens_for_script "$REPLY" "$script_lower"; then
    return 0
  fi
  # 保守的フォールバック（command_invokes_git_subcommand と同じ設計原則）
  ((_CP_OPAQUE_FOUND)) || return 1
  [[ "${s,,}" == *"$script_lower"* ]] || return 1
  return 0
}

post-issue-create-notice.sh の3段ガード（改訂）

既存の記述を置き換える場合 置き換え前と置き換え後の形を両方書く。

置き換え前:

run_shell_command | Bash | PowerShell)
  [[ "$command" == *create-issue.sh* ]]
  ;;

置き換え後（トップレベルで一度だけ確定させる。main()の中に置くと、 sourceしてmain()を実行せずis_issue_create_callを 直接呼ぶ既存テストが落ちるため）:

_pin_cli_match() { [[ "$1" == *create-issue.sh* ]]; }  # 既定値（フォールバック）
_pin_lib_dir="${BASH_SOURCE[0]%/*}"
[ "$_pin_lib_dir" = "${BASH_SOURCE[0]}" ] && _pin_lib_dir='.'
_pin_lib="${_pin_lib_dir}/lib/CommandPosition.sh"
if ((BASH_VERSINFO[0] > 4 || (BASH_VERSINFO[0] == 4 && BASH_VERSINFO[1] >= 3))) &&
  [ -r "$_pin_lib" ] && source "$_pin_lib" 2>/dev/null &&
  declare -F command_invokes_script >/dev/null; then
  _pin_cli_match() { command_invokes_script "$1" 'create-issue.sh'; }
fi

is_issue_create_callはCLI経路の分岐で_pin_cli_match "$command"を 呼ぶ形へ変更する（引数3つのシグネチャは変えない）。

前置フィルタ（raw_hints_at_issue_create）は変更しない

既存の前置フィルタは判定本体の超集合であり続ける（command_invokes_scriptは 部分一致の対象を絞り込むだけで、新しい語形を拾うようにはならないため）。実装後に 既存テスト（バックスラッシュ分割・大文字小文字混在）が新しい判定本体に対しても成立することを 確認する。
