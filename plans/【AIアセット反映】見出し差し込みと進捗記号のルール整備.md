# 【AIアセット反映】見出し差し込みと進捗記号のルール整備（issue #64）

全体作業計画: `plans/frolicking-doodling-meerkat.md`
対象フェーズ: フェーズ4（反映）の**2セット目**。1セット目の `【設計反映】` はレビュー合意済み
（flow-id 4-6〜4-10 完了）。

## ゴール

issue #64 の作業中に実際に踏んだ・回避した失敗を、次回以降のAIエージェントが**同じ手順で防げる形**
にして `.claude/rules/` `.claude/skills/` へ残す。issue #64 の受け入れ条件そのものではなく、
flow-id 4-6 の「作業中に気づいたルール・スキルの不備を反映する」に対応する。

反映候補は3件。いずれも**このタスクで実際に起きたこと**に限り、一般論は書かない。

## 作業1: 既存ドキュメントへ見出しを差し込む際の確認手順（`.claude/rules/docs-workflow.md`）

**何が起きたか**: `issue-mr-flow/SKILL.md` の新節を `### 計画の2階層構造（issue #9）` の直後へ入れる
計画だったが、同節の末尾に**節全体へかかる地の文**（囲み文字の注意・`plans/【*.md` での機械的列挙・
flow-id 1-4 の判定）が続いており、間に別の `###` 節を挟むと係り先が壊れることが分かった。
`## サブコマンド` の直前へ位置を変更して回避した。一方 `.claude/docs/spec/issue-mr-workflow.md` の
同名節では直後に地の文が無く、当初計画どおりの位置で問題なかった。

**反映内容**: 「ファイル移動に伴うパス参照の一括置換は〜」の段落の後ろへ、次の趣旨の段落を追記する。

- 既存ドキュメントへ新しい見出しを差し込むときは、**挿入位置の直前の節が、その節全体にかかる
  地の文で終わっていないか**を必ず確認する。終わっている場合、間に別節を挟むとその地の文が
  新しい節にかかって読めるため、末尾へ回すなど位置を変える。
- **同じ節名でもファイルごとに結論が変わる**（今回、SKILL.md では位置変更が必要で spec では不要
  だった）。「前に同じ位置へ入れたから安全」とは判断せず、ファイルごとに確認する。

## 作業2: 本文差し込み時の空行の扱い（`.claude/rules/shell-script-style.md`）

**何が起きたか**: 既存規約どおり「差し込む行はクォート済みヒアドキュメントで別ファイルへ書き出し、
`sed -n` で分割した前後と連結する」方法を使ったが、差し込むファイルの**先頭に空行**を入れていた
ため、連結後に空行が2つ連続し、後続の `## 設定項目` の直前の空行が消えた。`sed -i` で事後修正した。

**反映内容**: 「`awk`/`sed`の置換文字列で、`\r`を含むシェルコードを生成しない」の直後（同じ
`## パラメータ展開の既定値` より前のブロック内）に、差し込むファイル側の空行規約を1項目として追記する。

- 差し込むファイルは**先頭に空行を置かず、末尾に空行をちょうど1つ**持たせる。
- 連結後は差し込み位置の前後3行を目視で確認する（空行が2つ連続していないか、次の見出しの直前に
  空行が1つあるか）。

## 作業3: ループ範囲の`mark-done`を呼ぶタイミング（`.claude/skills/issue-mr-flow/SKILL.md`）

**何が起きたか**: flow-id 4-6 の作業を終えた時点で `update-handoff-progress.sh mark-done 4-6` を
実行したところ、4-6/4-7/4-8/4-9 が**まとめて `[x]`** になった。commit・push も人間のレビューも
まだだったため、`sed` で `[]` へ差し戻した。

**原因**: SKILL.md の「**flow-idが1つ進むごとに、必ず`HANDOFF.md`を更新する**」（156行目付近）が、
ループ範囲に属するflow-idについて**いつ**`mark-done`を呼ぶかを書いていない。
`.claude/docs/spec/update-handoff-progress.md` には「ループ範囲は1周が完全に完了して初めて`[x]`に
する」と書かれているが、**手順側のSKILL.mdだけを読むと踏む**。

**反映内容**: 該当段落へ次の趣旨を追記する（specの記述と重複させず、タイミングだけを書く）。

- ループ範囲（`2-3 2-4` / `2-6`〜`2-9` / `3-3 3-4` / `3-6`〜`3-9` / `4-3 4-4` / `4-6`〜`4-9`）に
  属するflow-idでは、**`mark-done` を呼ぶのはレビュー合意まで進んで1周が完了した時点のみ**。
  範囲内の途中のflow-id（作業完了・push直後など）では記号を動かさず、「やったこと」の文章だけを
  更新する。
- 2周目以降に入るときは `add-round <flow-id>` で `[]` を1つ足してから作業する。

## 作業4（判断が必要）: テキスト加工に `python` を使わない旨の注記

**何が起きたか**: 空行修正のため `python - <<'EOF'` を使おうとしたところ、
`SyntaxError: Non-ASCII character '\xe8' ... but no encoding declared` で失敗した。
この環境の `python` は **Python 2** で、日本語を含むスクリプトはエンコーディング宣言なしに書けない。

**反映内容（案）**: `.claude/rules/shell-script-style.md` の「前提・保存形式」へ1行、
「日本語を含むテキスト加工に `python` を使わない（この環境の `python` は Python 2）」を追記する。

- **この作業だけはレビューで要否を判断してほしい。** 本リポジトリのスクリプトはbash + jqで統一
  されており、そもそもpythonを使う前提が無い。「使わない」と書くこと自体が、選択肢として
  存在するかのような誤解を生む可能性がある。**不要と判断された場合は作業4を落とす**（作業1〜3は実施する）。
