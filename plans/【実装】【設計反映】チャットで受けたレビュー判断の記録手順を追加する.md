# 【実装】【設計反映】チャットで受けたレビュー判断の記録手順を追加する

実装と設計反映は同じ文書群（`SKILL.md` / spec / DDR）への追記であり、合意を分けて取る
意味が薄いため1つの個別計画にまとめる。

## 1. `.claude/skills/issue-mr-flow/SKILL.md`

- 全体フロー表の 2-4 / 2-9 / 3-4 / 3-9 / 4-4 / 4-9 の6行へ、チャットで受けた判断を記録する旨の
  短い参照を足す（AIエージェントが最初に読む位置のため）。
- `comments [all]` サブコマンド手順を書き換える。
  - 手順3を「促す」から「MRスレッド由来の指摘と同列のレビュー入力として洗い出す」へ変更。
  - 手順5を新設し、洗い出した判断のうち基準に該当するものを `add_mr_comment` で投稿する。
- 新節「チャットで受けたレビュー判断の記録」を追加する（`## レビュー完了合図の確認` の直前）。
  - 記録する単位とタイミング（往復1回につき1コメント／修正後に投稿／該当なしなら投稿しない）
  - 残す対象・残さない対象の表
  - 本文テンプレートと `Claude Codeより:` の署名ルール（`reply` 手順2と同一規約・DDR 0004）
  - 本文はコマンド文字列へ直接埋め込まず一時ファイル経由にする（push検知hookの誤発火回避）
- MCPフォールバック節「3. サブコマンドごとの読み替え」の `comments` 行へ、
  `add_mr_comment` → `mcp__github__add_issue_comment` の読み替えを追記する。
- frontmatterの `keywords` へ判断記録関連の語を追加する。

## 2. `.claude/docs/spec/issue-mr-workflow.md`

- 「### レビューコメントへの返信」の直後へ「### チャットで受けたレビュー判断の記録（issue #50）」を新設する。
- 「## 影響範囲」へ `### issue #50（...）` のchangelogエントリを追記する。

## 3. `.claude/docs/ddr/0040-*.md`

チャット由来のレビュー判断をMRの通常コメントへ記録する決定と、却下した案
（現状維持／全発言記録／`reply` 代用／description追記／`plans/` 追記）を残す。
