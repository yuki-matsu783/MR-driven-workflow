フェーズ2報告からの更新点

重要: .gemini/settings.jsonは手編集対象ではなくなった

フェーズ2報告5〜7節は「.gemini/settings.jsonを手で編集する」前提だったが、defaultブランチ追従で取り込んだPR #157（issue #70）により.gemini/は.claude/からの変換生成物になっている。手編集してもsync-gemini-assets.shの次回実行で失われる。

生成ロジック（convert_settings() / SETTINGS_JQ_FILTER）には、Claude Code側に存在しない設定（telemetry）を注入する仕組みが元々無いため、本計画で新設する。既存のSETTINGS_IGNORED_KEYSのenvキーには「Claude Code側OTelリスナー（.claude/hooks/otel/listener.pl）へGemini由来のテレメトリを流すと壊れるため変換しない」という既存判断があるが、本計画の注入（target: "local"固定・outfileへ直接書き込み、リスナーを経由しない）はこの判断と衝突しない。

この計画で何をするか

フェーズ2報告の8方針を、設定層（.gemini/settings.json生成へのtelemetry注入）・集計層（UsageTracking.shへのバイトオフセットカーソル集計関数群）・レポート層（post-push-usage-report.shへの別セクション追加）の3層で実装し、単体テストを追加する。あわせて配布先.gitignoreへの/usage/追記漏れを是正する。

方針

1. .gemini/settings.jsonへのtelemetry注入

sync-gemini-assets.shのSETTINGS_JQ_FILTERの出力へ、次の値を固定で追加する。

{
  "telemetry": {
    "enabled": true,
    "target": "local",
    "outfile": "usage/gemini-otel.log",
    "logPrompts": false
  }
}
enabledは既定falseから始める フェーズ2報告7.節の判断（既定ONは保留）と矛盾しないよう、enabledは当面falseのまま（変更なし）とし、他のキーだけを用意する。既定ONにするのは、配布gitignore是正とtool_call機微情報確認の2条件が揃ってから（別issueまたはフェーズ4以降）。

outfileは相対パスusage/gemini-otel.log。相対パス解決基準は実機未確認のため、問題が判明したら絶対パスへ変更することをspecの未決定事項として記録する（フェーズ4）。

2. バイトオフセットカーソル集計

フェーズ2報告4.節の設計をそのまま実装する。新規関数（案）:

  • _usage_read_otel_cursor / _usage_write_otel_cursor: usage/state/gemini-otel-cursor.jsonの読み書き。空・不正JSONへの自己回復は既存の_usage_read_gemini_totalsと同じパターン
  • _usage_otel_fold: outfileの新規バイトから、完全にパースできた末尾までを処理。metricsを除外し、同一イベントの2重emit（toLogRecord/toSemanticLogRecord）を重複排除する
  • ファイル縮小検知: DDR i0097-01のneedsResetと同じ考え方でカーソルを0へリセット
  • _sync_usage_state_otel: 上記を統合。既存のsync_usage_state（Claude Code経路・Gemini経路）とは完全に独立し、既存関数のシグネチャ・返り値は変更しない

3. post-push-usage-report.shへの統合

engine="gemini"のときに限り_sync_usage_state_otelを追加で呼び出す（既存呼び出しとは別）。結果があれば「### Gemini CLI公式テレメトリ（参考値）」セクションを追加し、既存のtokensByModelへは合算しない。

4. 配布gitignore是正

install-to-project.shのignore_rulesへ/usage/を追加する（既存の旧パス名2行は互換性のため残す）。

5. テストフィクスチャ

フェーズ2報告の方針（safeJsonStringify(data, 2) + '\n'形式）に沿ったヒアドキュメントを追加する。正常系・2重emit重複排除・metrics除外・カーソル継続・ファイル縮小・状態ファイル破損・途中書き込み・レポート本文（既存セクション不変）の8ケースを含める。
