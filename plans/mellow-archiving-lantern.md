# MR/PRテンプレートをアーカイブとして再設計する（全体作業計画）

issue #145 / PR #187 / ブランチ `claude/mr-pr-template-archive-0bo17a`

**合意状況: flow-id 1-5（全体作業計画への人間の合意）は未実施である。** このセッションは非対話
（人間のレビュー往復を待てない実行環境）で動いており、以降の「方針」「やらないこと」も
**AIエージェントの提案であって合意事項ではない**。人間のレビューを受けたら、その結果でこの計画を
更新する。

## この計画で何をするか

MR/PRのdescriptionを、レビュー時だけの作業メモではなく「**後からこのPRを開いた人が、何を・なぜ・
どうやったかを一望できるアーカイブ**」として機能させる。具体的には次の3つを行う。

1. `.github/pull_request_template.md` と `.gitlab/merge_request_templates/Default.md` の見出しを、
   issue #145「期待する動作」が定める10節構成へ改める（GitHub版・GitLab版で同一）。
2. `describe` サブコマンド（`.claude/skills/issue-mr-flow/references/review-loop.md`）が生成する
   descriptionを同じ構成に合わせ、各見出しに「計画段階では何を書くか」を定める。
3. テンプレートファイルと `describe` 節に同じ雛形が二重に存在している状態を解消する。

## 新しい見出し構成（issue #145「期待する動作」の転記）

**以降この計画・下位の個別計画は、この10節を「新テンプレートの見出し構成」の正として参照する。**
issue本文は後から編集されうるため、着手時点の前提をここへ固定しておく。

| # | 見出し | 何を書く節か |
|---|---|---|
| 1 | `## 概要` | 何を・なぜ変えたか3行以内。issueを開かずここだけで骨子が分かる。バグ修正なら原因を1行含める |
| 2 | `## 変更内容` | 先に挙動の before → after、そのあとに変更ファイルの表 |
| 3 | `## 設計判断・採らなかった案` | DDRを起こさない規模の判断はここにしか残らない |
| 4 | `## 検証` | 実行したテスト・実機確認とその結果。未実施なら「未実施」と明記 |
| 5 | `## レビューの結果` | 敵対的レビュー・人間レビューの指摘件数と、その結果**設計が変わった点**のサマリ |
| 6 | `## 意図的にやらなかったこと・スコープ外` | 理由と、派生issueがあれば番号 |
| 7 | `## 未解決・限界・確かめられなかったこと` | 後任が踏む地雷 |
| 8 | `## 受け入れ条件との対応` | issue本文の受け入れ条件を転記して突き合わせ |
| 9 | `## 反映先・関連` | spec/DDRの反映先、関連issue/PR、コメントのpermalink |
| 10 | `## 備考` | 上記に当てはまらない任意事項の受け皿 |

先頭には従来どおり `Closes #<issue番号>` 行を置く（見出しではない）。

## なぜやるか

- `plans/` `worklog/` `reports/` は flow-id 5-5 で削除され、squash mergeによりmainにも残らない。
  spec/DDRへ昇格しなかった経緯・却下案・検証結果の**唯一の恒久的な置き場がPR/MRのページ**である。
- ところが現行テンプレートは `Closes #N` / `## Plan` / `## 実装状況` の3点しか持たず、
  過去64件のPRのうち約3分の2が独自構成へ流れている（issue #145「現状」の集計）。
- さらに64件中52件が本文から `plans/` `worklog/` `reports/` を参照しており、削除後は参照先が無い。
  `.claude/rules/docs-workflow.md` はコード・スクリプト内のコメントからの参照を禁じているが、
  **MR本文には同じ歯止めが無い**。

## 方針

- **見出し構成はissue #145「期待する動作」の10節をそのまま採る。** 順序も含めて指定されており、
  この計画で組み替えない。
- **固定見出しは、該当が無ければ「特になし」と1行書いて残す。節ごと削除してよいのは `## 備考` のみ。**
  消すと「検討した結果無かった」のか「書き忘れ」なのかを後から読む人が区別できないため。
- **二重管理の解消方式は、フェーズ2の調査で決める。** issue本文が挙げる「`describe` の手順を
  テンプレートファイルの読み込みへ変えて一本化する案」を含めて比較し、DDRへ残す。
  この全体作業計画の時点では結論を書かない。
- **#111（最終統括レポートのサマリコメント）との役割分担も、フェーズ2で決める。** #111 は
  PR #144 で既にマージ済み（flow-id 5-4 として稼働している）ため、廃止ではなく棲み分けの定義になる。
- **既存仕様（`.claude/docs/spec/distribution-assets.md`「PR/MRテンプレート」節）との衝突を、
  実装と同じフェーズで解消する。** 同節は現在、次の2点を仕様として定めている。

  | 現行の記述 | 10節構成の下でどうするか（フェーズ3で確定させる） |
  |---|---|
  | 「両者の見出し構成は `describe` が生成するdescriptionと同一にする（`Closes #<issue番号>` → `## Plan` → `## 実装状況`）」 | **列挙をやめ、「同一にする」という制約だけを残す。** 見出し名の実体は1箇所（フェーズ2で決める正）だけが持ち、specは正の場所を指す |
  | 「**見出しを増やさない。** テンプレートにしか無い見出しは初回 `describe` で消える」 | **制約の趣旨は維持する。** `describe` 側も同じ10節を出す限り消えないため、「テンプレートと `describe` の見出し集合を一致させる」という形へ言い換える |

  **spec側を後回しにしない。** 実装だけ10節へ進めると、specが旧3節構成を正と主張したまま残り、
  「正が2つあり片方だけ古くなる」状態（ルート `REVIEW-POINTS.md`）を新たに作ってしまう。
- **既存テスト `.claude/scripts/test/test_install_to_project.sh` の期待値を、実装と同じコミットで
  更新する。** 同テストは `review-loop.md` の `describe` 節から `^(Closes|## )` の行を抜き出し、
  テンプレート2本と3者一致を表明したうえで、**抽出できた行数が `3` であること**も表明している
  （「抽出が空振りして空同士の一致で通る」ことを防ぐための表明）。10節構成にすると必ず落ちる。
  更新方針は**フェーズ2の問1の結論に従属する**ため、ここでは次の2点だけを決めておく。

  1. **行数の固定値 `3` は残さない。** 見出しの数は今後も変わりうるので、`10` へ置き換えるのでは
     なく「**抽出できた見出しの集合が、期待値として書き下した10節と一致すること**」を表明する
     （空振り防止の目的は、期待値が非空であることの表明で引き続き満たされる）。
  2. **抽出元は、問1で「正」と決めた場所に合わせる。** `describe` 節が雛形を持たなくなる案を
     採る場合、`awk` の抽出範囲を `### \`describe\`` 節のままにすると空振りする。

   テンプレートがどの層に属するか、(c) テンプレートが配布先で改変されている場合に何が起きるか。

検証2は、期待値を書き下した形で行う。

```bash
# 期待値（この計画の「新しい見出し構成」節の転記。順序込み）。
# ヒアドキュメント側は各行を `| ` で始め、sed で剥がしてから比べる。
# 行頭に `## ` を持つ行をこの計画ファイル自身へ増やさないための書き方である
# （増やすと、この計画のmd/HTMLの見出し突き合わせと、テンプレートの見出しを
#  `^## ` で数える検査の両方が、コードブロックの中身を拾ってしまう）。
expected="$(sed 's/^| //' <<'EXPECTED'
| Closes #<issue番号>
| ## 概要
| ## 変更内容
| ## 設計判断・採らなかった案
| ## 検証
| ## レビューの結果
| ## 意図的にやらなかったこと・スコープ外
| ## 未解決・限界・確かめられなかったこと
| ## 受け入れ条件との対応
| ## 反映先・関連
| ## 備考
EXPECTED
)"
for f in .github/pull_request_template.md .gitlab/merge_request_templates/Default.md; do
  diff <(printf '%s\n' "$expected") <(grep -E '^(Closes|## )' "$f") || echo "NG: $f"
done
```

**`bash .claude/scripts/src/extract-frontmatter.sh .` は、この節の検証には含めない。**
再生成が成功することしか見ておらず、本issueの変更に対する検出力を持たないため（実行自体は
SessionStart hookが毎回行っている）。
