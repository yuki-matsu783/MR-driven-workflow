# issue #106 全体作業計画

## Context

`adversarial-review` スキルは「非対話セッションでのみAIが自律的にレビューを起動してよい」という
方針を、環境変数 `AUTOMATION`（`AUTOMATION=1` なら非対話モード）で判定している。しかしこの
`AUTOMATION` を実際に設定する経路（CI環境変数の自動注入、起動スクリプトでの設定等）はリポジトリの
どこにも実装されておらず、`.claude/docs/spec/adversarial-review.md` の未決定事項にも「非対話環境で
`AUTOMATION=1` が実際に設定されるかは未検証」と記されたまま残っていた。結果として、この判定は
非対話セッションであっても常に「対話モード」と判定され続け、判定ロジックとして意味を成していない
（issue #106）。

このissueでは、効果のない環境変数判定を廃止し、「非対話セッションの場合にのみ自動起動を許可する」
という方針自体はそのまま残しつつ、判定手段を「AIエージェント自身が実行環境の性質（人間のレビュー
往復が成立するか）から判断する」方式へ置き換える。判断に迷う場合は既定を起動禁止（対話モード相当）
に倒す方針は維持する。DDR 0045の決定4のうち、起動可否の方針そのもの（対話セッションでは禁止・
非対話セッションのみ許す）は変更しないため、DDR 0045自体の`status`は変更せず、判定手段の変更のみを
新規DDRとして記録する。

## 対象ファイルと変更内容

### 1. `.claude/skills/adversarial-review/SKILL.md`

- frontmatterの `description`: 現在の「対話セッションでは...禁止...（非対話セッションでのみ自律
  起動を許す）」という否定形の書き方を、issueの指定どおり肯定形へ書き換える。
  「**非対話的なセッションの場合にのみ、敵対的レビューの自動起動を許可する**（対話セッションでは
  人間が `/adversarial-review` を明示的に呼んだときだけ実行する）」
- frontmatterの `keywords` から `AUTOMATION` を削除。
- **現行の「手順1: 実行モードを判定する」を丸ごと削除する**（`echo "AUTOMATION=${AUTOMATION:-unset}"`
  のbashコードと判定表）。
- 直後の「### 起動ポリシー（絶対ルール）」節は、番号なしの独立した節として手順1の位置に残し、
  判定手段の説明を「環境変数ではなくAIエージェントが実行環境の性質（人間のレビュー往復が成立
  するか）から判断する。判断に迷う場合は対話モード（起動禁止）を既定とする」という趣旨へ書き換える
  （起動を許可／禁止する方針そのものの文言は変更しない）。
- **旧「手順2」〜「手順9」を「手順1」〜「手順8」へ繰り上げる。** 本文中の相互参照
  （旧「手順4で確認する」→新「手順3で確認する」、旧「手順6（レビュー実行の直後）」→新「手順5」、
  「してはいけないこと」内の手順番号）もすべて追随させる。
- 「してはいけないこと」の「手順1（実行モードの判定）・手順2（実施回数の確認）を飛ばすこと。」は、
  実行モード判定が数字付きの手順で無くなるため「手順1（実施回数の確認）を飛ばすこと。」へ整理する
  （対話セッションでの無断起動禁止は既存の別項目でカバー済み）。

### 2. `.claude/docs/spec/adversarial-review.md`

- 「全体像（責務分離）」の図から `├ 手順1 実行モード判定（AUTOMATION）` の行を削除し、以降の
  手順番号（2〜9→1〜8）を繰り上げる。
- 「起動ポリシー」節（68-84行目）の表・説明文から `AUTOMATION=1` という環境変数表記を除去し、

  書き換える。対話セッションで自律起動を禁じる理由の説明文（81-84行目）はそのまま維持する。
- 「設定項目」表の1行目 `| 実行モード | 対話モード | 環境変数 AUTOMATION=1 で非対話モード |` を、
  環境変数を使わない判定方式の説明へ書き換える。
- 「未決定事項・懸念点」から「非対話環境で `AUTOMATION=1` が実際に設定されるかは未検証」の

- 「影響範囲」表（issue #77時点のpoint-in-time記録）は書き換えず、その下へ本issue分の変更を

### 3. `.claude/skills/issue-mr-flow/SKILL.md`

「敵対的レビューの位置づけ（issue #77）」節（344-366行目）の表の「例外」行から `AUTOMATION=1` の
記述を除去し、「非対話セッション（人間のレビュー往復を待てない実行環境）でのみ、AIエージェントが
自律的に起動してよい」という、環境変数に触れない表現へ書き換える。

### 4. 新規DDR `.claude/docs/ddr/0055-敵対的レビューの非対話判定は環境変数ではなくAIエージェントの判断に委ねる.md`

DDR 0045の決定4のうち「判定手段」の部分だけを置き換える新規DDR。DDR 0045は他の決定
（サブエージェント切り出し・投稿の責務分離・承認モデル・実施回数上限・全体フロー表への非包含）が
引き続き有効なため、`status`は変更しない。

- 背景: issue #106。`AUTOMATION`を実際に設定する経路が存在せず判定が機能していなかった事実。
- 決定: 環境変数判定を廃止し、AIエージェント自身の判断（実行環境の性質、判断に迷えば対話モード
  既定）へ委ねる。起動可否の方針自体（対話セッション禁止・非対話セッションのみ許可）は変更しない
  ため、DDR 0045の`status`はそのまま。
- 却下案: (1) `AUTOMATION`を実際に設定する経路を新設する（実行基盤依存になり未検証懸念が形を変えて
  残るだけ）、(2) 非対話セッションでの自律起動自体を諦める（DDR 0045決定4の目的を放棄することになり
  issueの期待する動作と異なる）。

`.claude/docs/README.md` のDDR一覧（`.claude/docs/ddr/0054-...`の次の行）に本DDRへのリンクを追記する。

## 作業の進め方

本issueはドキュメント（SKILL.md・spec・DDR・issue-mr-flow）のみの変更であり、コード実装を伴わない。
issue-mr-flowの全体フローに沿って、個別作業計画（`plans/【設計反映】〜.md`ではなく通常の
`plans/【実装】〜.md`相当、内容はドキュメント編集）を1つ作成し、上記1〜4のファイルをまとめて
1回の実装フェーズで編集する。設計ドキュメント自体の変更が主目的のため、通常のflow-id 4系
（設計反映）に近い性質を持つが、issueの受け入れ条件がSKILL.md/spec/DDR/issue-mr-flowへの直接編集を
求めているため、flow-id 3系（実装）としてこれらのファイルを直接編集し、flow-id 4（設計反映）は
「今回の変更自体が設計ドキュメントの変更そのもの」であるため簡略化してよいか、実装時に判断する。
