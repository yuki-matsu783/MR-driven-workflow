hookの空振り起動コストを前置フィルタで削減する

前提

  • 対象は block-direct-git-commit.sh（PreToolUse）と post-issue-create-notice.sh（PostToolUse）。どちらも if フィールドを 持たず、Bash/PowerShell（後者はさらにmcp__github__issue_write）の全呼び出しで起動する。
  • issue #159実測（2026-08-22, strace）: 空振り1回で block-direct-git-commit.sh = execve 5 / clone 10、 post-issue-create-notice.sh = execve 7 / clone 17。原因は判定材料の取り出し （raw="$(cat)" と printf | jq の連鎖）。
  • issue #70（PR #157、未マージ）が push系hook2本で同じ問題を解決済み。 IFS= read -r -d '' raw || true + case による足切りパターンを 本issueで残り2本へ適用する（PR #157 diffで実装内容を確認済み）。
  • issue #149（未着手）は post-issue-create-notice.sh の判定本体を コマンド位置判定へ差し替える別issue。前置フィルタはその新判定に対しても超集合であること が受け入れ条件。

この計画で何をするか

2本のhookのmain()冒頭に、判定本体（jq呼び出しを含む）へ入る前の前置フィルタを 追加し、対象外のペイロードでjqが1回も呼ばれないようにする。判定本体 （command_invokes_git_subcommand / is_issue_create_call）は変更しない。 前置フィルタのパターンが精密判定の超集合であることをテストで固定する。
