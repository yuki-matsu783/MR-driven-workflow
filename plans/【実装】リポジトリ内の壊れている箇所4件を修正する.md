# 【実装】リポジトリ内の壊れている箇所4件を修正する（issue #32）

非対話的実行環境（Claude Code on the webのリモート実行環境）のため、人間のレビュー往復を
待つステップ（flow-id 3-3/3-4, 3-8/3-9 等）は省略し、調査〜実装〜設計反映を一括で行う。

## 対象と方針

| # | 事象 | 方針 |
|---|---|---|
| 1 | `.claude/docs/spec/extract-frontmatter.md` へのNULバイト混入 | **issue #69（PR #78）で解消済み**。再発が無いことを走査で確認するのみ |
| 2 | `.gitignore` 1行目 `参考ディレクトリ` が裸のignoreパターン | コメント化する（削除ではなく、何が在ったかの痕跡を残す） |
| 3 | リンク切れ | issueの2件に加え実測で計5件。すべて解消する |
| 4 | GitLabテンプレート名の不整合 | **実体（`Default.md`）を正とし、文書側を統一する** |

### 3の内訳（実測5件。issue記載は2件）

- `.claude/docs/spec/issue-mr-workflow.md:31` → `../ddr/0002-...`
- `.claude/docs/spec/issue-mr-workflow.md:170` → `../ddr/0002-...`
- `.claude/docs/ddr/0019-...md:79` → `0002-...`（issue未記載）
- `index.md:37` → `./plans/`（issue未記載）
- `index.md:41` → `./build/`

`0002` は移植時に持ち込んでいないDDR（`.claude/docs/README.md` に既に明記あり）。実体を作らず、
リンク記法を外して「未同梱」の注記と README への誘導へ置き換える。
`./plans/` `./build/` はGit管理下に実体を持たないため、リンクを外し理由を併記する。

### 4で「文書側を直す」と決めた理由

`Default.md` はGitLabの**予約名**で、新規issueの説明欄へ自動適用される。`task.md` へ改名すると
テンプレート選択が手動になり、テンプレート標準化という当初目的が損なわれる。よってDDRへ記録する。
