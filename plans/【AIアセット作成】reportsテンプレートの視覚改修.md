## 方針

調査結果の結論を転記した次の設計で実装する。

### 節の並び順（節名は全維持）

ヘッダ帯（結論件数チップ追加）→ 目次 → **重点レビュー依頼（新設・必須）** →
サマリ（結論の一覧）（色分け結論カードへ改修・必須）→ **確かめられなかったこと（前半へ移動・必須。
一覧は全項目を保持し、詳細は各章のcalloutへ）** → 実施条件（任意）→ 実施した内容と結果（必須。
章ID・性質チップ・未確認詳細callout）→ 設計への反映（必須）→ 想定と異なった点（任意）→
残課題（任意）→ フッタ。

### 新設: 重点レビュー依頼（`id="review-focus"`）

3段階の枠を色付きカードで用意し、各項目から該当章（`#f1` 等）へリンクする。

| 段階 | 意味 | 視覚 |
|---|---|---|
| 特に見てほしい | 判断に困っている | 赤系（`--stop`）の枠・「◆重点」ラベル |
| 承認が欲しい | 方針は決めたので確認してほしい | 黄系（`--warn`）の枠・「◇承認」ラベル |
| 細かいレビューは不要 | ほぼ確実 | 低彩度（`--muted`系）の枠・「・確認不要」ラベル |

（レビューの重み＝注意の量を表す軸なので、結論の性質（良/注意/問題）とは別の視覚語彙にする。
段階ラベルは記号＋文字で色に依存させない。）

### サマリ（結論の一覧）の改修

- 表を廃止し、**結論カードのリスト**にする。1件＝「性質チップ（◎良／△注意／✕問題）＋
  短い結論（1行）＋該当章へのアンカーリンク」。
- 性質の色: 良＝青 `--good`（新設）／注意＝黄 `--warn`／問題＝赤 `--stop`。
- ヘッダ帯に件数チップ（例: ◎3 △2 ✕1）を置く。
- 記述量の目安をコメントで指示（結論は1行。詳細は章に書く）。

### 色トークン・チップ

- `:root` へ `--good: #1d4ed8; --good-soft: #e7edfd;`、ダーク側へ
  `--good: #8ab4f8; --good-soft: #17233a;` を追加。
- `.tag.ok/.tag.warn/.tag.stop`（既存・本体未使用）は削除し、結論性質チップ
  `.chip.good/.chip.warn/.chip.stop` へ置き換える（緑チップと青「良」チップの語彙併存を防ぐ）。
- `--ok`（緑）と `.box.ok` は「決めたこと・手順の成功」専用として存続。役割の違いを
  コメントに明記する（結論の性質には使わない）。

### 確かめられなかったこと（前半移動）

- サマリ直後に置き、**1行1件の一覧**（各行に関連章へのリンク）。節名・警告色（`--warn`）は維持。
- 詳細は各章内の専用callout `.box.warn.unverified-detail`（ラベル「確かめられなかったこと（詳細）」）
  で語る。一覧側を空にしない・詳細だけを前半に書かない、という分担をコメントで指示。

### 実施した内容と結果

- 各h3章に `id="f1"` `id="f2"` …の連番IDを振る（結論カード・未確認一覧・重点レビュー依頼の
  3箇所から参照される）。
- 章見出しの隣に性質チップを置き、サマリの色と対応させる。

### アンカーの位置ずれ対策・検査

- `section[id], h3[id] { scroll-margin-top: 16px; }` を追加。
- テンプレート冒頭コメントへ**リンク破断検査**を追記する（下記「検証」のcommコマンド。
  出力0行が合格）。コード例で `href` 断片を引用するときは `#` を `&#35;` と書く流儀も明記。

### テンプレートコメント（次の書き手への伝承）

冒頭コメントを更新する: (1) 節の並び順とその理由（未確認事項が前半にある理由＝結論の
確からしさを先に把握させる） (2) 色・記号の使い分け（性質3色＋緑boxの役割分担） (3) 重点
レビュー依頼の3段階の書き方 (4) リンク破断検査 (5) 既存の「フェーズごとの読み替え」を更新
（統括5-4: 重点レビュー依頼は「マージ判断で最後に見てほしい点」、未確認一覧は残存分のみ。
反映4-6: 設計への反映は「次のissueへ回したもの」——従来どおり） (6) プレースホルダ検査・
自己完結性・md/html併存の既存指示は維持。

## 検証

```bash
f=.claude/skills/issue-mr-flow/assets/reports.template.html

# 1. 自己完結性（いずれも0件が合格）
grep -nE "(src|href)=['\"]?(https?:)?//" "$f"
grep -nE "(url\(|@import[[:space:]]+)['\"]?(https?:)?//" "$f"

# 2. リンク破断（テンプレートの見本アンカー自身が整合していること。出力0行が合格）
comm -23 <(grep -oE 'href="#[A-Za-z0-9_-]+"' "$f" | sed 's/^href="#//;s/"$//' | sort -u) \
         <(grep -oE 'id="[A-Za-z0-9_-]+"'   "$f" | sed 's/^id="//;s/"$//'   | sort -u)

# 3. プレースホルダ検査手順が維持されていること（テンプレート自身には残っているのが正。0でないこと）
grep -c '<!-- ここに書く' "$f"

# 4. 受け入れ条件の構造確認（それぞれ1件以上ヒットすること）
grep -c 'id="review-focus"' "$f"
grep -c -- '--good' "$f"
grep -c 'scroll-margin-top' "$f"
```

- 空振りの排除: 検証4の3語は**現テンプレートでは0件**であることを実測済み（2026-08-23。
  改修後に1件以上へ変わることが変更の検出になる）。検証3は現テンプレートで18件（残っているのが
  テンプレートとして正。誤って全て埋めた場合に0となり検出できる）。
- 節順の確認: `grep -oE '<h2>[^<]*</h2>' "$f"` の出力が上記「節の並び順」と一致すること。
- 実ブラウザ確認は行えない環境のため、HTML構文の機械確認（タグ対応）と上記grepで代替し、
  その旨をレポートの「確かめられなかったこと」へ残す。
