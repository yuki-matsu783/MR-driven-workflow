# 【実装】フェーズ5のステップ順の並べ替え（issue #112）

全体作業計画: `plans/tidy-closing-cascade.md`

## 前提（確定済み）

- 動くのは 5-1〜5-3 の3ステップのみ。5-4（Draft解除）・5-5（マージ）は番号・内容とも変えない。
- **DDR本文は書き換えない**（`.claude/rules/docs-workflow.md`）。DDR 0044・0048 の本文にある
  旧番号は残したまま、新DDR側で「現在の番号」を対応づける。
- **specの過去issueごとのchangelog（`## 影響範囲` 配下の `### issue #NN` 節）も書き換えない**。
  現在の状態を説明する節（`## 仕様` 配下）だけを更新する。

## 手順

### 1. `.claude/skills/issue-mr-flow/SKILL.md`

- フェーズ一覧（`| 5 | 5-1〜5-5 |` の行）の内容欄を新しい順序の語順へ直す。
- 全体フロー表の 5-1〜5-3 の行を、新しい順序で並べ替える（行の中身は原則そのまま移し、
  「次にどのflow-idへ進むか」を書いている箇所だけ書き換える）。
- 節見出しと本文の flow-id 参照を更新する。
  - `## defaultブランチとのコンフリクト検知・解消（flow-id 5-2）` → `（flow-id 5-1）`。
    分岐先の「5-3（関連issue通知）へ進む」→「5-2（関連issue通知）へ進む」。
  - `## マージ前の関連issue通知（flow-id 5-3）` → `（flow-id 5-2）`。次に進む先を 5-3（片付け）へ。
    **「影響先なし」の記録先が `HANDOFF.md` のままで成立する**ことを本文で示す。
  - `## PRがflow-id 5-1実施前にマージされてしまった場合の対処` → `flow-id 5-3`。
  - 監視節の「最終ゲート」表と、`AskUserQuestion` の例外列挙（レビュー依頼節）の番号。
  - 「計画と実施結果の分離」等にある「flow-id 5-1で削除され」→ `5-3`。
- 新5-2の手順2（キーワード抽出）へ、**差分から `plans/` `worklog/` `reports/` を除外する**旨を
  追記する（新順序ではこれらがまだ削除されておらず差分に含まれるため）。

### 2. `.claude/rules/`

| ファイル | 変更 |
|---|---|
| `docs-workflow.md` | ライフサイクル表・注記の「flow-id 5-1で削除／リセット」→ `5-3` |
| `directory-structure.md` | 同上（3箇所） |
| `markdown-frontmatter.md` | 同上（1箇所） |
| `git-workflow.md` | 関連issue通知 `5-3`→`5-2`、片付け `5-1`→`5-3`、追従監視の `5-2`→`5-1` |

### 3. `.claude/skills/` ほか

- `resolve-conflict/SKILL.md`: description・本文の `flow-id 5-2` → `5-1`、次に進む先 `5-3` → `5-2`。
- `canvas-report/SKILL.md` `doc-search/SKILL.md`: 削除タイミングの `5-1` → `5-3`。
- `index.md`: `plans/` `worklog/` の説明にある `5-1` → `5-3`。

### 4. `.claude/scripts/src/`（コメントのみ。ロジックは変更しない）

- `cleanup-task.sh`: 冒頭コメントの `flow-id 5-1` → `5-3`。
- `check-base-conflicts.sh`: `flow-id 5-2` → `5-1`。
- `vcs/Provider.sh` `vcs/Github.sh` `vcs/Gitlab.sh`: `flow-id 5-3: マージ前の関連issue通知` → `5-2`。
- `update-handoff-progress.sh`: `flow-id 5-1でリセットした直後` → `5-3`。
  **`LOOP_RANGES` はフェーズ2〜4の6範囲のみでフェーズ5を含まないため、テーブル自体は変更しない。**
