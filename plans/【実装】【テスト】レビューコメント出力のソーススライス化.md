# 個別作業計画: レビューコメント出力のソーススライス化

全体作業計画: `plans/issue43-review-comment-source-slice.md`（issue #43）
調査結果: `reports/2026-08-20_issue43-review-comment-source-slice_レビューコメント出力仕様の調査.md`

**種別を併記する理由**: 追加する関数の大半が純粋関数で、テストは実装と同時に書かないと
「テストできる形になっているか」を確かめられない。合意の単位が実装とテストで分かれないため
1ファイルにまとめる（`.claude/skills/issue-mr-flow/SKILL.md`「種別を複数併記する場合／分ける場合」）。

## 目的

`get_mr_unresolved_comments` の出力から `diffHunk` を除去し、`(path, line, sha)` から共通ロジックが
切り出した**行番号付きソーススライス**を、**スレッドにつき1回**出力する。行数とバイト数の
両方で上限制御する。

## 変更対象と役割

| ファイル | 変更内容 |
|---|---|
| `.claude/scripts/src/vcs/Github.sh` | `github_get_mr_review_threads` を新設（正規化JSONを返す）。GraphQLから `diffHunk` を外し `originalLine` / `isOutdated` / commit oid を足す。`github_get_mr_unresolved_comments` は**削除**する |
| `.claude/scripts/src/vcs/Gitlab.sh` | `gitlab_get_mr_review_threads` を新設（正規化JSONを返す）。`gitlab_format_discussion_notes` は**削除**し、正規化を担う純粋関数 `gitlab_normalize_discussions` へ置き換える。`gitlab_get_mr_unresolved_comments` も削除 |
| `.claude/scripts/src/vcs/Provider.sh` | 共通の後段ロジックを追加し、`get_mr_unresolved_comments` をその合成へ置き換える |
| `.claude/scripts/test/test_vcs_provider.sh` | 追加した純粋関数の単体テストを足す |

## Provider.sh へ追加する関数

| 関数 | 種別 | 内容 |
|---|---|---|
| `read_file_at_ref <sha> <path>` | git依存 | 断面のファイル内容を標準出力へ返す。取れなければ終了コード1。`git cat-file -e` で事前判定する |
| `slice_source_lines <line> <before> <after> <maxBytes>` | **純粋**（stdin→stdout） | 標準入力のファイル内容から、指摘行の前後を行番号付きで切り出す。バイト上限を超えたら指摘行を中心に両側から均等に削る |
| `build_review_source_slices <正規化JSON>` | git/CLI依存 | スレッドごとに断面ソースを取得してスライスを作り、`{threadId: {text, note}}` のJSONを返す |
| `format_review_comments <正規化JSON> <スライスJSON>` | **純粋**（jqのみ） | 最終的なテキストを組み立てる |
| `get_mr_unresolved_comments <n> [true]` | 合成 | 上記3つを順に呼ぶ |

**純粋関数を2つ切り出すのが本作業の要**である。GitHub側の整形は現状テストが1件も無く
（`gh` 依存のため）、issue #43 へのマージ前通知コメントで指摘されたCR混入もテストでは
検知できなかった。

## 出力書式

```
[review unresolved threadId=PRRT_... <path>:<line> url=<permalink>] <author>: <body>

--- source <path> @ <sha短縮> ---
    81 | ...
>>> 91 | ...
   101 | ...
```

- **行頭の `[review unresolved threadId=...]` は現行のまま**。`.claude/hooks/session-start.sh:169`
  が `^\[review unresolved threadId=` で未解決件数を数えており、変えると集計が壊れる。
- **GitLab側の行頭も `[review ...]` へ揃える**（現状 `[unresolved ...]` で、GitLabリポジトリでは
  上記の集計が常に0件になっていた。調査で判明した副次的な不具合）。
- ソースブロックはスレッドの全コメントを出力した**後**に1回だけ置く。
- 断面が現HEADへ落ちたときは見出しへ `(断面 <sha> を取得できず現HEADを表示)` を添える。
  バイト上限で切り詰めたときは `(バイト上限により切り詰め)` を添える。

## 上限の既定値

- `REVIEW_SOURCE_CONTEXT_LINES`（既定 `10`）
- `REVIEW_SOURCE_MAX_BYTES`（既定 `2000`）

いずれも環境変数で上書きできる。`.mrworkflow.json` へは置かない（移植時に書き換えたい値ではなく、
その場の事情で一時的に変えたい値であるため）。

## 実装上の注意（既存ルールから）

- **ループ内で `jq` を呼ばない**（`.claude/rules/shell-script-style.md`「外部プロセス起動のコスト」）。
  スレッドの位置情報は `jq -r ... | @tsv` で**1回**取り出し、bash側のループでは `git` 呼び出しのみに
  留める。スライスの組み立ては bash の `while read` と算術で行い、jq を呼ばない。
- **同じ `(sha, path)` は1回しか読まない**（メモ化）。同一ファイルに複数の指摘が付くのは普通にある。
- **`jq --args` へ可変長の値を渡すときはフィルタの直後に `--` を置く**（同ルール）。スライス本文は
  `-` で始まる行を含みうる。
- **複数行を返す `jq -r` には `tr -d '\r'` を付ける**（同ルール「文字コード」。issue #94 / PR #126）。
- **大きなJSONを `--argjson` でコマンドライン引数として渡さない**（同ルール「JSON操作」）。
  スライス群は**一時ファイル**へ書き出し、jq へは `--slurpfile` でパスを渡す。
- `set -e` 配下でコマンド置換に頼った終了コード検査をしない（同ルール「テスト」）。

## テスト（`.claude/scripts/test/test_vcs_provider.sh` へ追加）

| 対象 | ケース |
|---|---|
| `slice_source_lines` | 中央・ファイル先頭付近（前が足りない）・末尾付近（後ろが足りない）・1行ファイル・行番号の桁揃え・バイト上限で切り詰め・上限が緩ければ切り詰めない・`line` が範囲外 |
| `format_review_comments` | 未解決のみ／全件・スレッド内の複数コメントでソースが1回だけ・`path` が無いスレッドの `(場所不明)`・`url` の有無・通常コメントの混在・**出力にCRが混入しない** |
| `gitlab_normalize_discussions` | `system: true` の除外・`resolvable` でないnoteの扱い・`new_line` / `old_line` の使い分け・`head_sha` の採用 |
| `github_normalize_review_threads` | `line` が null なら `originalLine` へフォールバック・`isOutdated`・commit oid の選択 |
