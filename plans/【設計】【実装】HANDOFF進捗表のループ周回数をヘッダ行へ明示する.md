# 【設計】【実装】HANDOFF進捗表のループ周回数をヘッダ行へ明示する（issue #58）

設計と実装を1回の合意で進める（表の記号仕様は変更せず、ヘッダ1行の追加とスクリプトの追従処理に
閉じるため、フェーズを分けるほどの分岐点が無い）。

## 目的

`HANDOFF.md` の進捗表で、レビュー往復のループが何周目かを、`[x][x][]` の反復記号を数えずに
読み取れるようにする。同一トークンのカウントはLLMが最も誤りやすい処理のため、周回数を数字として
ヘッダへ直接書く。

## 方針

- 進捗表（行構成・進捗記号・ループ範囲の定義）は**一切変更しない**。既存の `HANDOFF.md` は
  そのまま有効とする。追加するのはヘッダの1行だけにする。
- ヘッダ行の書式は `- 現在のループ: <開始flow-id>〜<終了flow-id> の<N>周目（<状態>）` とする。
  状態は「進行中」（進捗列の末尾が `[]`）か「完了」（末尾が `[x]`）の2値。
  ループ範囲の外にいる間は `- 現在のループ: なし` を人手（または `set-header --loop`）で入れる。
- 周回数・状態は**進捗表から導出する**（別途カウンタを持たない）。表とヘッダが食い違う状態を
  構造的に作らないため。

## 実装内容

### 1. `.claude/scripts/src/update-handoff-progress.sh`

| 追加・変更 | 内容 |
|---|---|
| `count_rounds_to_reply` | 進捗列（例 `[x][x][]`）の `[` の個数を数えて周回数を返す。forkを避けるため文字単位のループで実装する |
| `format_loop_status_to_reply` | ループ範囲と進捗列から `3-6〜3-9 の3周目（進行中）` を組み立てる |
| `set_loop_header_in_lines` | `LINES` 配列中の `- 現在のループ:` 行を置換する。行が無ければ既存ヘッダ項目（issue/ブランチ/PR/push回数）の最後の行の直後へ挿入し、ヘッダ項目が1つも無ければ `## フロー進捗状況` 見出しの直前へ空行付きで挿入する |
| `cmd_add_round` | 更新後の進捗列からヘッダ行を組み立てて自動追従させる |
| `cmd_mark_done` | 対象がループ範囲に属する場合のみ、同様に自動追従させる（単発ステップでは触らない） |
| `cmd_set_header` | `--loop <text>` を追加し、指定文字列をそのままヘッダ行へ書く |

`mark-skip` は追従の対象にしない（issueの「期待する動作」が `add-round` と該当ループ範囲への
`mark-done` のみを対象としているため）。ループ範囲を丸ごとスキップした場合は
`set-header --loop なし` で明示する。

### 2. テスト（`.claude/scripts/test/test_update_handoff_progress.sh`）

- `add-round` 実行後にヘッダの周回数が1つ進むこと（`1周目（完了）` → `2周目（進行中）`）。
- ループ範囲への `mark-done` でヘッダが `（進行中）` → `（完了）` になること。
- 単発ステップへの `mark-done` ではヘッダ行が変わらないこと。
- `- 現在のループ:` 行が無い既存 `HANDOFF.md` でも、`push回数` 行の直後へ挿入されること。
- `set-header --loop` が任意文字列を書けること／未指定時は現状維持であること。
- 既存の記号系テストの期待値が変わらないこと（進捗表に差分が出ないことの確認）。

### 3. ドキュメント

- `.claude/rules/docs-workflow.md`: ループ記号の説明の直後へ、ヘッダ行の運用を追記する。
  `HANDOFF.md` 行の「ヘッダ情報（issue/ブランチ/PR/push回数）」へ「現在のループ」を加える。
- `.claude/docs/spec/update-handoff-progress.md`: 実行方法・サブコマンド表・仕様・影響範囲を更新する。
- `.claude/skills/issue-mr-flow/SKILL.md`: `add-round` / `mark-done` の説明へ、ヘッダが自動追従する
  ことを1文添える。

## 受け入れ条件（issue #58より）

- ヘッダを見るだけで、表の記号を数えずに現在の周回数と進行状態が分かる。
- `add-round` 実行後、ヘッダの周回数が自動で1つ進む。
- 進捗表の記号・行構成に差分が出ない（既存 `mark-done`/`mark-skip`/`add-round` の挙動は不変）。
- `bash .claude/scripts/test/test_update_handoff_progress.sh` が `failures=0` で通り、ヘッダ追従の
  テストが追加されている。
- ルール・仕様の記述が実装と一致している。

## 触ってはいけない範囲

- 進捗表の行構成・進捗記号（`[x]`/`[]`/`[-]`）・`LOOP_RANGES` の定義。
- `- 追従監視:` 行（issue #88で追加されたヘッダ行。`set-header` の対象外という扱いを維持する）。

## 方針変更（PR #93 のレビュー、2026-08-19）

PR #93 のレビューで、`.claude/scripts/src/update-handoff-progress.sh` の「往復1回につき `[]`/`[x]` を
連結して持つ」という記述に対し、**「この記述が冗長なのでやめて、今なんループ目かを記録するように
したいと言うのがissueの目的」** という指摘を受けた。上記の当初方針（進捗表は据え置き、ヘッダ行を
追加するだけ）は指摘と方向が異なるため、ユーザーの判断を仰いだうえで次のとおり変更した。

### 変更後の方針

- **`[x][x][]` の連結表記を廃止する。** 進捗表はループ範囲の行も含めて**どの行も記号1つ**
  （`[]` / `[x]` / `[-]`）になる。
- **周回数の記録場所はヘッダの `- 現在のループ:` 行だけ**にする（進捗表には持たせない）。
  - `add-round` = ヘッダの周回数を+1し、範囲の記号を `[]` へ戻す
  - ループ範囲への `mark-done` = 周回数は据え置き、記号を `[x]` にして状態を（完了）へ
- ヘッダが**別の**ループ範囲を指していれば、周回数は引き継がず1周目から数え直す（範囲は互いに素
  なので、先頭flow-idが範囲の識別子になる）。
- **旧表記のHANDOFF.mdは自動移行する。** ヘッダ行が無い（または別範囲を指す）場合は、進捗列の記号の
  個数を周回数として読み取り、ヘッダへ移したうえで進捗列を記号1つへ畳む。手作業の書き換えは不要。

### 当初方針からの差分

| 項目 | 当初 | 変更後 |
|---|---|---|
| 進捗表のループ範囲行 | `[x][x][]`（据え置き） | 記号1つ |
| 周回数の正 | 進捗表（ヘッダは導出値） | **ヘッダ行のみ** |
| `add-round` | 記号を1つ追記 | 周回数+1・記号を `[]` へ戻す |
| 既存HANDOFF.md | そのまま有効 | 次回操作時に自動移行 |
| issue #58 本文 | そのまま | 「期待する動作」「受け入れ条件」を更新 |

### 更新が必要になった範囲（当初計画からの追加）

- `.claude/rules/docs-workflow.md`: ループ記号ルールの**全面書き換え**（追記ではなく置き換え）。
  廃止した表記とその理由は残す。
- `.claude/docs/spec/update-handoff-progress.md`: 「進捗記号とループ範囲」節・サブコマンド表・
  制約の書き換え。「表を正とする」という設計判断は取り下げ、代わりに「履歴が表から追えなくなる」
  トレードオフを明記する。
- `.claude/scripts/test/test_update_handoff_progress.sh`: 既存の `add-round` 期待値
  （`[x][]`）を書き換え、旧表記からの自動移行・別範囲での数え直しのテストを追加する。
- issue #58 本文の「期待する動作」「受け入れ条件」。
