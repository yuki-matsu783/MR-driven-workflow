# 【実装】【テスト】.gitignoreのDDR参照修正と検出スクリプトの追加（issue #171）

## 前提（合意状況）

- 上位の計画: `plans/sequential-purring-tulip.md`（全体作業計画、flow-id 1-5で合意）
- 直前の調査結果: `reports/20260823_sequential-purring-tulip_DDR参照切れの網羅調査結果.md`
  （フェーズ2、v2。敵対的レビュー対応済み）「検出方式の設計」節を実装の正とする。

## この計画で何をするか

1. `.gitignore`の2箇所のDDR参照切れを実在するファイル名へ修正する。
2. リポジトリ全体を対象にDDRパス形式の参照切れを検出するスクリプト
   `.claude/scripts/src/check-doc-references.sh`を新規作成する。
3. 副作用の無い純粋ロジック（正規表現によるパス抽出・フィルタ判定）の単体テスト
   `.claude/scripts/test/test_check_doc_references.sh`を作成する。

## 変更対象

- `.gitignore`（28行目・40行目のDDR参照コメント修正）
- `.claude/scripts/src/check-doc-references.sh`（新規）
- `.claude/scripts/test/test_check_doc_references.sh`（新規）

## 方針

**本節は敵対的レビュー（1回目、フェーズ3計画）で12件のfindingsを受け、全件を実機で再検証の
うえ全面改訂した。** 検証手順・訂正内容は下記「v1からの訂正点」節を参照。

### `.gitignore`の修正

| 行 | 修正前 | 修正後 |
|---|---|---|
| 28行目 | `i00-13-gemini配下は…md` | `i0000-13-gemini配下は…md` |
| 40行目 | `i36-01-frontmatterのindex.jsonlを…md` | `i0036-01-frontmatterのindex.jsonlを…md` |

コメント文字列の書き換えのみを行い、ignoreパターン自体（`/.gemini/docs`等）は変更しない。

### 検出スクリプトの設計（reportsの「検出方式の設計」節を実装する。v2で全面改訂）

1. 対象ファイル: `git ls-files -z -- '*.md' '*.sh' '.gitignore'`で取得（バイナリを除く）。
2. 次の3ディレクトリ配下は除外する:
   - `.claude/scripts/test/`（フィクスチャに架空パスを含むため。偽陰性のトレードオフは
     reportsに記録済み・設計判断として許容する）。
   - `plans/` `reports/` `worklog/`（**v2で追加**。理由は下記「対象範囲の除外理由」）。
3. Markdownコードフェンス（行頭が`` ``` ``または`~~~`で始まる行。インデントされたフェンスも
   対象、正規表現`^[[:space:]]*(\`\`\`|~~~)`でトグル）で囲まれた範囲内の行は除外する。
   **フェンス行が奇数個で閉じずにファイル末尾へ達した場合は、残りの行を除外しない**
   （安全側＝偽陽性が出る方向へ倒す。偽陰性＝無言の見逃しにしない）。
4. 抽出は**1ファイル1回、bash内蔵の`while read`＋`[[ =~ ]]`のみで行い、`grep`は使わない**
   （外部コマンド`git ls-files`の1回起動のみに留める。**v2で訂正**: 当初「`xargs -0 grep`と
   フェンス除外のbashループを両方使う」という両立しない案を書いていたため、bash単独方式へ
   一本化した）。正規表現は
   `\.claude/docs/ddr/i[0-9]+-[0-9]+-[終端文字を除く任意文字]*\.md`で、
   **issue番号側だけでなく枝番側も`[0-9]+`（桁数不問）にする**（**v2で訂正**: `[0-9]{2}`固定では
   枝番のゼロ埋め漏れ自体を検出できなかったため）。終端文字は空白・**実際のタブ文字**・
   `)` `]` `"` `'` `` ` `` `(`とする。**タブは`\t`というエスケープ表記ではなく、
   `tab=$'\t'`のようにシェル変数で組み立てた生のタブ文字を使う**（**v2で訂正・blocker対応**:
   POSIX ERE のブラケット式内では`\t`はバックスラッシュと`t`の2文字として解釈され、
   「タブを除く」ではなく「ASCIIの`t`を終端文字にする」誤りになる。DDRファイル名には`t`が
   高頻度で現れるため、この誤りがあると`.md`まで到達できず**候補が1件も抽出されなくなり、
   検証コマンドが常に「0件＝合格」を返す**。実機で確認済み——詳細は「v1からの訂正点」）。
   `.md`で終わることを要求し、貪欲マッチ（bashの`[[ =~ ]]`は既定で貪欲）で最後まで一致させる。
5. 抽出したパスに`...`または`…`（省略記法）が含まれる場合は除外する。
6. 残った候補について`[[ -f "$path" ]]`で実在確認する。存在しなければ参照切れとして
   `file:lineno:path`形式で標準出力へ報告する。**加えて、標準エラーへ
   `走査ファイル数 / 候補数 / 除外数（テスト・plans等/フェンス内/省略記法の内訳） / 参照切れ数`
   のサマリを出す**（**v2で追加**: 件数を出さないと「正規表現が当たらず0件」と「本当に
   参照切れが無く0件」を区別できないため。issueの受け入れ条件・全体作業計画が求める
   「件数付きの検索結果」の要件でもある）。
7. スクリプトは**引数を取らない**。冒頭で`cd "$(git rev-parse --show-toplevel)"`しリポジトリ
   ルートを起点に走査する（**v2で追加**: 未定義だった呼び出しインターフェースを確定した）。
8. 実行タイミングは**手動実行のみ**とし、**この個別作業計画で決定する**（**v2で訂正**:
   当初「全体作業計画の判断を踏襲」としていたが、全体作業計画が留保していたのは
   「hookへ組み込まない」ことだけで、実行タイミングの具体案自体はフェーズ2の成果物として
   決めるとされていた。しかしreportsにはこの判断が記録されていなかった（帰属の誤り）ため、
   ここで確定させる。`.claude/rules/shell-script-style.md`「外部プロセス起動のコスト」に
   照らし、頻度の低い整合性チェックをhookへ組み込む価値は無いと判断。将来
   `resolve-conflict`スキル等への合流が必要になれば別issueで検討する）。新規specファイルは
   作らない（規模の小さいスクリプトであり、本計画＋テストコード＋フェーズ4のDDRで
   ドキュメントとして十分と判断。全体作業計画の「過剰なドキュメント化は避ける」方針に沿う）。

### 対象範囲の除外理由（v2で追加）

- **`plans/` `reports/` `worklog/`を除外する**: これらはflow-id 5-4でタスク単位に削除される
  寿命の短いファイル群であり、`.html`を対象外にした理由（reportsの「対象範囲の限定理由」節）と
  同じ理由で除外するのが整合的である。加えて、除外しない場合は**実際に偽陽性が発生する**ことを
  実機で確認した:
  `worklog/20260823_sequential-purring-tulip_【調査】…_push1.md:69`に、前回レビュー対応の
  記録として書いた`ls .claude/docs/ddr/i0000-13-*.md`というコマンド断片があり、glob文字
  `*`を含む文字列がDDRパス候補として抽出され`[[ -f ]]`に失敗する（**v1では対象に含めていた
  ため、この偽陽性のせいで検証3の「参照切れ0件」が達成できなかった**）。

### 実装上の注意（`.claude/rules/shell-script-style.md`への適合）

- `git ls-files -z` + `while IFS= read -r -d ''`でNULバイトを保持し、日本語パスの
  クォート化を回避する。外部コマンドの起動は`git ls-files`の1回のみ（上記のとおり`grep`は
  使わない）。
- `git ls-files`はindexの内容を返すため、削除済み未ステージファイルが混ざりうる。
  読み込み前に`[[ -f "$path" ]]`のガードを挟む。
- スクリプト冒頭で`set -euo pipefail`を宣言し、BOM無しUTF-8・LF改行で保存する。
- テストから直接呼べるよう、次の関数境界を持たせる（**v2で追加**: 純粋関数への切り出しが
  無いと、単体テストが実装の正規表現・フィルタ条件を書き写すだけになり、実装側の誤りを
  検出できない。`.claude/rules/shell-script-style.md`「テスト」の指摘と同根）。
  - `extract_ddr_candidates_to_reply <行>`: 1行から候補パス配列を`REPLY_CANDIDATES`
    （配列）へ返す。
  - `is_excluded_target_path <ファイルパス>`: ディレクトリ除外（テスト・plans/reports/worklog）
    の判定。
  - `is_placeholder_candidate <候補文字列>`: 省略記法（`...`/`…`）を含むかの判定。
  - 本体は`main`関数にまとめ、`if [ "${BASH_SOURCE[0]}" = "${0}" ]; then main; fi`で
    ガードする。単体テストはこのファイルを`source`し、**上記の関数を直接呼ぶ**
    （正規表現やフィルタ条件をテスト側へ書き写さない）。

### 単体テストの設計（v2で改訂）

- 対象は副作用の無い純粋ロジック（上記の3関数）。
- 少なくとも次のケースを含める:
  - 通常のDDRパス参照が実在すれば検出されない
  - 存在しないDDRパス参照は検出される（`.gitignore`の元の2箇所相当の再現ケース）
  - `.claude/scripts/test/` `plans/` `reports/` `worklog/`配下のパスは`is_excluded_target_path`
    で除外される
  - コードフェンス内のパスは除外される（インデントされたフェンスも含む）
  - コードフェンスが奇数個で閉じない場合、残りの行は除外され**ない**（安全側の挙動を確認する）
  - 省略記法（`...`/`…`）を含む候補は`is_placeholder_candidate`で除外される
  - ファイル名自体に`.md`を含む実在DDR（`i0032-01-GitLab-issueテンプレートは予約名Default.md
    を正とし文書側を合わせる.md`。**v2で訂正**: 省略記法を含む例示文字列をそのままフィクスチャに
    すると省略記法フィルタに先に除外され貪欲マッチの検証にならないため、省略記法を含まない
    実名を使う）について、`extract_ddr_candidates_to_reply`が**抽出した候補文字列そのもの**を
    `assert_eq`し、末尾の`.md`まで正しく1本のフルパスとして一致することを確認する
    （検出結果の真偽ではなく抽出関数の戻り値を直接検証する）
  - タブ区切りで2つのパスが同一行に並ぶ場合、2つの独立した候補として抽出される
  - 枝番が1桁・3桁のDDRパス（`i0133-1-…md`等）も候補として抽出される（枝番側`[0-9]+`化の
    検証）
- `bash -n`構文チェックを行い、`passed=N failures=N`形式で出力、失敗時は終了コード1。

## やらないこと（スコープ外）

- 相対パス表記（`../docs/ddr/…`）への対応（reportsの「確かめられなかったこと」で見送りと
  記録済み）。
- 旧形式（4桁連番、`i`接頭辞なし）DDRパスの検出（本リポジトリに現存しないため。将来配布先で
  必要になった場合の課題として reports に記録済み）。
- パスを伴わない裸のDDR識別子表記の検出（全体作業計画・個別調査計画でスコープ外と合意済み）。
- 検出スクリプトのSessionStart/PostToolUse hookへの自動組み込み（全体作業計画で「作らない」と
  明記済み）。
- **終端文字集合への全角読点（`、`）・全角括弧（`（）「」`）追加**（**v2で理由を精緻化**:
  「実例が無いため」だけでなく、実例が出た場合に**検出器の出力（誤って結合された1本の
  存在しないパス）を見れば気づける**ため——無言の見逃しにはならない、という理由を明記する。
  タブと違い、これらの文字は本リポジトリのドキュメントで多用される書式
  （「（詳細: X.md、経緯: Y.md）」）と衝突しうるため、対応するなら別途正規表現の再設計が必要
  になる。今回は見送る）。
- **git bash（MSYS/Windows）実機での再検証**（**v2で追加**: reportsの「実施条件」節は
  今回の走査がLinux/GNU grep 3.11で行われ「git bash実機では未検証」と明記している。
  本issueのスコープでは、この検出スクリプトはCIやhookに組み込まず手動実行のみとするため、
  git bash実機での動作確認は本issueでは行わず、実際にgit bash環境で使う際の課題として
  残す。実機が用意できないことの代替（PATH先頭のスタブ等）では、マルチバイト文字を含む
  ブラケット式のロケール依存の挙動は代替できないため、代替検証も行わない）。

## 検証（この作業が完了したと言える条件）

```bash
# 1. .gitignore側の参照切れが解消されたことを確認する（0件を期待）。
#    タブは \t ではなく実際のタブ文字を使う（変数経由で組み立てる）
tab=$'\t'
grep -noE "\\.claude/docs/ddr/i[0-9]+-[0-9]+-[^]) \"'\`($tab]*\\.md" .gitignore \
  | while IFS=: read -r lineno path; do [[ -f "$path" ]] || echo "$lineno:$path"; done

# 2. 検出スクリプトの構文チェック
bash -n .claude/scripts/src/check-doc-references.sh

# 3. 検出スクリプトをリポジトリ全体に対して実行し、候補件数>0かつ参照切れ0件であることを
#    標準エラーのサマリで確認する（引数は取らない）
bash .claude/scripts/src/check-doc-references.sh

# 4. 単体テストが全件成功する
bash .claude/scripts/test/test_check_doc_references.sh
```

- 上記1〜4がすべて成功すること（1は0件、3は候補N件・N>0のうえで参照切れ0件、2と4は
  非0の終了コードが出ないこと）を`reports/`へ、走査した候補の母数付きで記録する。
