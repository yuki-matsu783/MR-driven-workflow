## 1. `split_remote_url` を新設する

`parse_repo_slug`（`sed`×2）の直前に置く。

```bash
# remote URLを「ホスト部」と「パス部」へ分解する純粋関数（issue #55）。
# 外部コマンド・コマンド置換を伴わないため、呼び出しあたりのプロセス起動はゼロ。
# 結果は標準出力ではなくグローバル変数へ返す（.claude/rules/shell-script-style.md
# 「ホットパスの小さなヘルパー関数は…`REPLY`へ返す」。値が2つあるため `REPLY` ではなく
# `REPLY_HOST` / `REPLY_PATH` を使う）。
#
#   REPLY_HOST … 小文字化したホスト名（scheme・認証情報・ポートを除く）
#   REPLY_PATH … `owner/repo` 形式のパス（先頭スラッシュ・末尾の `.git`・末尾スラッシュを除く。
#                 大文字小文字はそのまま保つ）
#
# scp形式（`git@host:o/r.git`）とポート付きURL（`host:2222/o/r.git`）は、`:` の後ろが
# **数字だけかどうか**で区別する。これがパラメータ展開だけで書ける唯一の分岐点である。
#
# ホスト名が取れない場合も失敗させず `REPLY_HOST` を空にして返す。エラーにするかは呼び出し側の
# 判断に委ねることで、`provider_from_remote_url`（終了コード1）と `parse_repo_slug`（空のまま
# JSONを返す）それぞれの従来の振る舞いを変えずに済む。
split_remote_url() {
  local url="$1" rest first tail

  # scheme:// を除去（無ければそのまま）
  rest="${url#*://}"

  # 認証情報 user@ を除去する。最初の `/` より前に `@` がある場合だけ落とすことで、
  # パスに `@` を含むURL（https://gitlab.com/foo/b@r.git）で誤爆しない
  first="${rest%%/*}"
  if [ "$first" != "${first#*@}" ]; then
    rest="${rest#*@}"
    first="${rest%%/*}"
  fi

  if [ "$first" = "${first%%:*}" ]; then
    # `:` を含まない → ホストのみ
    REPLY_HOST="$first"
    if [ "$rest" = "${rest#*/}" ]; then REPLY_PATH=""; else REPLY_PATH="${rest#*/}"; fi
  else
    REPLY_HOST="${first%%:*}"
    tail="${first#*:}"
    case "$tail" in
      ''|*[!0-9]*)
        # 数字以外を含む → scp形式のパス区切り
        REPLY_PATH="${rest#*:}"
        ;;
      *)
        # 数字のみ → ポート
        if [ "$rest" = "${rest#*/}" ]; then REPLY_PATH=""; else REPLY_PATH="${rest#*/}"; fi
        ;;
    esac
  fi

  REPLY_HOST="${REPLY_HOST,,}"
  REPLY_PATH="${REPLY_PATH%.git}"
  while [ "$REPLY_PATH" != "${REPLY_PATH%/}" ]; do REPLY_PATH="${REPLY_PATH%/}"; done
}
```

### 分解の追跡（代表4例）

| 入力 | scheme除去後 | 認証情報除去後 | `first` | 判定 | HOST / PATH |
|---|---|---|---|---|---|
| `https://github.com/o/r.git` | `github.com/o/r.git` | 同左 | `github.com` | `:`無し | `github.com` / `o/r` |
| `git@github.com:o/r.git` | 同左（`://`無し） | `github.com:o/r.git` | `github.com:o` | `:`後が`o`＝非数字→scp | `github.com` / `o/r` |
| `ssh://git@ghe.example.com:2222/o/r.git` | `git@ghe...:2222/o/r.git` | `ghe...:2222/o/r.git` | `ghe.example.com:2222` | `:`後が数字→ポート | `ghe.example.com` / `o/r` |
| `https://user@gitlab.com:8080/foo/b@r.git` | `user@gitlab.com:8080/foo/b@r.git` | `gitlab.com:8080/foo/b@r.git` | `gitlab.com:8080` | ポート | `gitlab.com` / `foo/b@r` |

`.git`除去と末尾スラッシュ除去の順序は既存の`sed`（`s#\.git$##` → `s#/+$##`）と同じにする。
`o/r.git/` のように両方が付く場合の結果（`o/r.git`）も現状と一致する。

## 2. `provider_from_remote_url` を載せ替える

**判定規則・エラーメッセージ・終了コードは一切変更しない。** ホスト抽出だけを差し替える。

```bash
provider_from_remote_url() {
  local host
  split_remote_url "$1"
  host="$REPLY_HOST"

  if [ -z "$host" ]; then
    echo "remote URLからホスト名を取得できませんでした: $1" >&2
    return 1
  fi

  case "$host" in
    # 社内GitLab（Aslead）を明示的に先に判定する。（既存コメントをそのまま維持）
    *aslead*) printf 'gitlab\n' ;;
    *github*) printf 'github\n' ;;
    *) printf 'gitlab\n' ;;
  esac
}
```

関数上部の長いコメント（判定規則・受け入れたトレードオフ・DDR 0028への参照）は**そのまま残す**。
ホスト抽出手順を説明している箇所だけ、`split_remote_url` を参照する形へ書き換える。

**プロセス起動は引き続きゼロ**（`split_remote_url` は関数呼び出しであってコマンド置換ではない）。

## 3. `parse_repo_slug` を載せ替える

`sed` 2回が消え、外部プロセス起動は **3回 → 1回**（`jq` のみ）になる。

```bash
parse_repo_slug() {
  local host path owner repo
  split_remote_url "$1"
  host="$REPLY_HOST"
  path="$REPLY_PATH"
  owner="${path%/*}"
  repo="${path##*/}"
  jq -nc --arg host "$host" --arg owner "$owner" --arg repo "$repo" --arg path "$path" \
    '{host: $host, owner: $owner, repo: $repo, path: $path, url: ("https://" + $host + "/" + $path)}'
}
```

`owner` / `repo` の切り出しと `jq` の組み立ては**現状のまま**。返すJSONのキー・構造は変えない
（`session-start.sh`・`get_repo_url`・両SKILL.mdが依存している）。

**唯一の振る舞い変更はホストの小文字化**（`https://GitHub.COM/O/R.git` の `.host` と `.url`）。
`owner` / `repo` は `REPLY_PATH` 由来で小文字化されないため、リポジトリ名の大文字は保たれる。

## 4. テストを追加する

`tests/test_vcs_provider.sh` の**末尾**（`provider_from_remote_url` のテスト群の後ろ）へ追加する。
`split_remote_url` は `get_provider` に依存しないため、issue #34の上書き箇所より後ろでも問題ない
（ファイル冒頭の注意書きの対象外）。

`REPLY_HOST`/`REPLY_PATH` はグローバル変数へ返るので、**パイプではなく直接呼ぶ**
（`.claude/rules/shell-script-style.md`「`REPLY`へ返す関数はパイプではなくヒアストリングで呼ぶ」と
同じ理由。パイプの右辺はサブシェルになり代入が呼び出し元へ伝わらない）。
