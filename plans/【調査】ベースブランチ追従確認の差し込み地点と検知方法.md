# 【調査】ベースブランチ追従確認の差し込み地点と検知方法（issue #67）

- 全体作業計画: `plans/base-branch-sync-check.md`
- 対象issue: [#67](https://github.com/yuki-matsu783/MR-driven-workflow/issues/67)

## 目的

「作業開始・再開時にベースブランチの最新を取り込めているか」を確認するステップを追加するにあたり、
**どこへ差し込むか**と**何をもって『遅れている』と判定するか**を、実物のコード・実際のgitの
挙動で確定させる。issue本文の「現状」に書かれた内容（`sync_branch()` が fetch と ff-only pull
しかしていない等）を鵜呑みにせず、自分で確かめる。

## 調べること

### 調査1: 既存機構の守備範囲（この空白は本当に空いているか）

- `.claude/scripts/src/vcs/Provider.sh` の `sync_branch()` が何をしているか（行番号つきで確認）
- `.claude/scripts/src/check-base-conflicts.sh` の出力JSONに、遅れ（behind）を表すキーがあるか
- `.claude/agents/issue-mr-resume.md` の現在地サマリの項目に、ベースブランチとの差分があるか
- `.claude/hooks/session-start.sh` がセッション開始時に注入する情報に含まれていないか
  （issue本文は触れていないが、「作業開始時」という点で重複しうるため確認する）

**確認の観点**: 「コンフリクトは無いが遅れている」状態を、既存のどれかが検知できてしまわないか。
できるなら本issueの前提が崩れるので、その旨を報告して方針を見直す。

### 調査2: 差し込み地点

`.claude/skills/issue-mr-flow/SKILL.md` のどこへ手順を足すかを確定する。候補は次の3つ。

| 地点 | 状況 |
|---|---|
| `start` 手順2「見つかった場合（セッション再開）」 | 既存ブランチを検出して `sync_branch` するだけの経路 |
| `resume` | セッションを跨いだ引き継ぎ |
| `sync` | 「ブランチを最新化したいだけ」の経路 |

- 新規ブランチ作成時（`start` の「見つからない場合」）は、`main` から切るため定義上追従済み。
  確認が不要であることを確かめる。
- flow-id 5-2（`check-base-conflicts.sh`）・「PR作成後のdefaultブランチ追従（監視）」との
  **役割の違いを1つの表で説明できるか**を確認する（受け入れ条件の最後の項目）。

### 調査3: 検知に使うgitコマンドと境界条件

- behindコミット数: `git rev-list --count HEAD..origin/<base>`
- 未取り込みの変更ファイル: `git diff --name-only HEAD...origin/<base>`（3点リーダ）
  - **2点（`..`）との違い**を実際に確かめる。3点は「merge-base から見た base 側の変更」であり、
    作業ブランチ自身の変更を含まない。ここを取り違えると「自分が変えたファイル」を
    「取り込めていないファイル」として提示してしまう。
- 境界条件として次を確認する。
  1. `origin/<base>` のリモート追跡参照が存在しない場合に何が起きるか
  2. `--no-fetch` を付けた場合と付けない場合で結果が変わるか（fetch前は古い `origin/<base>` を見る）
  3. merge-base が取れない場合（無関係な履歴）
  4. behind が 0 でも ahead がある通常の状態を「遅れ」と誤判定しないか

### 調査4: 出力形式と既存スクリプトとの整合

- `check-base-conflicts.sh` の引数（`--base` / `--head` / `--no-fetch`）・出力JSON・終了コードの
  規約を確認し、新スクリプトを**同じ規約に揃えられるか**を判断する。
- 変更ファイルが多いときにJSONが肥大化しないよう、件数上限と切り詰めの表現を決める。

## 検証手順（このリポジトリ上で実際に実行する）

```bash
# 調査1
sed -n '690,705p' .claude/scripts/src/vcs/Provider.sh
grep -n 'hasConflict\|behind' .claude/scripts/src/check-base-conflicts.sh

# 調査3（実際の値を見る。テスト用の一時ブランチで、既知の差を作って確認する）
git rev-list --count HEAD..origin/main
git diff --name-only HEAD...origin/main
git diff --name-only HEAD..origin/main
```

一時ブランチを作って確認する場合は、**作業ブランチの状態を変えないこと**（`git worktree` か、
確認後に元のブランチへ戻す）。

## この調査で決めないこと（スコープ外）

- 新スクリプトの実装そのもの（フェーズ3で行う）
- 取り込み（merge）を実行するロジック。本issueは**検知と確認まで**が範囲で、実際の取り込みは
  ユーザーの承認後に通常のgit操作で行う
- `resolve-conflict` スキルの類型A〜Eの見直し（issue #88 の担当範囲）
