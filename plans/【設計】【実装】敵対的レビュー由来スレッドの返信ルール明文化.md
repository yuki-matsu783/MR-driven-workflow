# 【設計】【実装】敵対的レビュー由来スレッドの返信ルール明文化

issue #109 の個別作業計画。合意を1回で取るため設計と実装を併記する（変更対象がドキュメント
4ファイル＋DDR1件に限られ、設計と実装を分けても間に挟むレビュー内容が変わらないため）。

## これから何をするか

### 1. `.claude/skills/issue-mr-flow/SKILL.md`

#### 1-a. 「敵対的レビューの位置づけ」表へ「返信」行を追加

表の最後（進捗記号の行の後）へ1行足す。この節を読んだ人が「投稿したあとどうなるのか」を
その場で辿れるようにするため。

#### 1-b. `comments` サブコマンドへ手順を追加

手順3（チャット由来の指摘）の直後へ新しい手順を挿し込み、以降の手順番号を1つずつ繰り下げる。
盛り込む内容は次の4点。

- 敵対的レビュー由来のスレッド（`Claude Codeより（敵対的レビュー）:` で始まるもの）も、人間の
  指摘と同列のレビュー入力として扱う。**AI自身が投稿した指摘であることは、返信を省いてよい
  理由にならない。**
- 対応した場合も、対応しないと判断した場合（指摘が誤り・意図した設計である等）も返信する。
  返信を省略してよい類型を作らない。
- 返信のタイミングはこのループ（2-4・2-9・3-4・3-9・4-4・4-9）に揃える。敵対的レビューの直後
  には返信しない。
- 理由（返信が無いと人間のレビュアーから未対応と区別が付かないこと・実例）。

#### 1-c. 「レビュー完了合図の確認」節のゲートへ未返信の確認を追加

現在は `unresolved` が残っていないかだけを見ている。ここへ「返信が1件も付いていないスレッドが
残っていないか」を足す。判定基準は出力から機械的に読める形にする（同じ `threadId=` を持つ
`[review ...]` 行が1本しか無いスレッド＝返信ゼロ）。

### 2. `.claude/skills/adversarial-review/SKILL.md`

- 手順8（結果を報告する）の末尾へ、返信の担当が `issue-mr-flow` の `comments`/`reply` ループで
  あることを示す**参照の1文**を置く。返信手順は書かない。
- 「してはいけないこと」へ「投稿した自分の指摘へその場で返信すること」を追加する（タイミングの
  規定であって返信手順ではないため、上の「手順を書かない」方針と両立する）。

### 3. `.claude/docs/spec/adversarial-review.md`

- 「投稿されたスレッドの取得」節の末尾（解決に関する1文の前）へ、返信の扱いを追記する。
- 「影響範囲」節の末尾へ `変更（issue #109）:` / `新規（issue #109）:` を追記する。

### 4. DDR

新規DDRを起こすか既存への追記で足りるかを判断し、結論を記録する。判断の観点は「既存DDRの本文は
変更できない（追記のみ）」「返信を必須とする判断は、既存のどのDDRの主題とも別である」の2点。

### 5. 機械的検出手段

未返信スレッドを機械的に検出するスクリプト・Provider関数を追加するかを判断する。判断の観点は
「CLI経路とMCP経路の両方で同じ基準が使えるか」「新しい外部依存・テストの追加に見合うか」。
