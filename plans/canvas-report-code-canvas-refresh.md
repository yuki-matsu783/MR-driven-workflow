# 全体作業計画: canvas-reportテンプレートのCode Canvas全面刷新

- issue: #141「canvas-reportテンプレートを階層セマンティックズーム対応のCode Canvas形式へ全面刷新する」
- ブランチ: `claude/canvas-report-template-refresh-cd7bn5`（ハーネス指定ブランチ。リポジトリ規約の
  `feature-141-*` ではなく、実行環境の指定を優先する）
- 実行環境: Claude Code on the web（非対話セッション）。人間のレビュー往復（flow-id 2-3等）は
  待てないため、敵対的レビュー（`adversarial-review` スキル）の自律起動で代替し、人間担当の
  ステップは省略した事実をHANDOFF.mdへ明記する。

## ゴール（issueの受け入れ条件の要約）

1. 現行テンプレートの不具合1〜12（無エスケープ・固定worldサイズ・矢印の隠れ・単色マーカー・
   動かないアニメーション・`z-25`・FIT・ミニマップずれ・エッジラベル未描画・ノード上パン不可・
   mermaid多重描画・トラックパッド）を解消する。
2. `レイヤ > クラス > メンバ` の階層データを、ズーム操作だけでレイヤ俯瞰→クラス箱＋メソッド
   一覧→コード片まで連続的に辿れる。
3. エッジはメソッド行を端点にでき、折りたたみ時はクラス単位へ集約（太さ＝本数）される。
4. 変更状態（追加/変更/削除）の色分けと `+N / -M` バッジ。
5. 検索（クラス名・メソッド名・パス）とヒットへのジャンプ、レイヤ・関係種別トグル。
6. `x`/`y` 手打ちなしの自動レイアウト（40ノード規模で重なりなし）。
7. 不正データ（未定義ID参照・循環parent・必須項目欠落）を画面上に赤字表示する。
8. SKILL.mdを新モデル（データモデル・抽出手順・規模指針・mermaidの降格）へ更新する。
9. 実データ（`.claude/scripts/` 配下の依存関係）でサンプルを1件生成し、ブラウザ目視確認の
   結果を記録する。

## フェーズ2〈調査〉

- 現行テンプレート468行の静的読解は**issue本文（不具合表1〜12）で完了済み**とみなし、
  独立した調査フェーズは実施しない（flow-id 2-1時点の判断）。
- 残る調査は「サンプルデータの元になる `.claude/scripts/`・`.claude/hooks/` の依存関係の把握」で、
  これはフェーズ3のサンプル生成作業と不可分なため、フェーズ3の中で行う。

## フェーズ3〈作業〉

個別作業計画 `plans/【設計】【実装】【テスト】canvas-reportテンプレート全面刷新.md` に詳細を書く。
概要:

1. `.claude/skills/canvas-report/templates/canvas-report.html` を全面刷新
   （データ定義とエンジンの分離・上記ゴール1〜7）。
2. `.claude/skills/canvas-report/SKILL.md` を新モデルへ書き換え。
3. `.claude/scripts/`・`.claude/hooks/` の依存関係を抽出し、
   `reports/` へサンプルHTML＋結果md（正文）を生成。
4. Playwright + 同梱Chromiumで受け入れ条件をブラウザ実機検証し、結果をreports/のmdへ記録。

## フェーズ4〈反映〉

反映対象はflow-id 4-1相当の時点で洗い出す。現時点の候補:

- spec: `.claude/docs/spec/` にcanvas-reportテンプレートの仕様書は現存しないため、新設は
  「テンプレート自体がSKILL.mdと同居して自己記述的である」ことを踏まえ、洗い出し時に判断する。
- DDR: レイアウト方式・エスケープ方式など「検討したが却下した案」があれば `i0141-XX` として記録。

## フェーズ5〈クローズ〉

- 非対話セッションのため、Draft PRの作成まで行い（ユーザーから明示指示あり）、
  マージ（flow-id 5-5）には進まない。5-3の片付け（plans/worklog/reports削除）は
  レビュー往復が終わってから行うため、本セッションでは実施しない。

## やらないこと（issue「初版に含めない」）

タッチ・ピンチ操作／ビュー状態のURL保存／描画カリング／展開時の周囲再レイアウト／パンくず／
フォーカス分離表示／シンタックスハイライト／コード内シンボルのクリック追跡／循環依存の自動検出／
影響範囲の自動塗り／before-afterトグル／重なり回避の物理演算／画像書き出し／アクセシビリティ対応。

## issue分割の判定

受け入れ条件は「1つのテンプレート刷新」に収束しており、並列列挙構造（独立してマージ可能な
同型成果物の並び）ではないため、分割は提案しない。
