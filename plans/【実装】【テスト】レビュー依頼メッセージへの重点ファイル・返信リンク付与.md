# 【実装】【テスト】レビュー依頼メッセージへの重点ファイル・返信リンク付与（issue #42）

## 前提

このセッションは Claude Code on the web のリモート実行環境（非対話）で動作しており、
`gh`/`glab` CLI が存在しない。人間のレビュー往復を待てないため、`.claude/rules/docs-workflow.md`
「非対話的実行環境」の注記に従い、全体作業計画（planツール）とレビュー待ちステップは省略し、
本ファイル（個別作業計画）から着手する。

## やること

### (1) 重点レビュー対象ファイルへのリンク

- `Provider.sh` / `Github.sh` / `Gitlab.sh` へ純粋関数を追加する。
  - `get_blob_url <repoUrl> <ref> <path>` … GitHub `<repoUrl>/blob/<ref>/<path>` /
    GitLab `<repoUrl>/-/blob/<ref>/<path>`
  - `get_diff_anchor_url <compareUrl> <pathHash>` … GitHub `<compareUrl>#diff-<hash>` /
    GitLab `<compareUrl>#<hash>`
  - `get_diff_anchor_algo` … GitHub `sha256` / GitLab `sha1`
  - `url_encode_path_to_reply <path>` … パス中の非unreserved文字をUTF-8バイト単位で
    percent-encodeする（`/`は保持）。ホットパス規約に合わせ `REPLY` へ返す
  - `hash_paths <algo> <path>...` … 複数パスのハッシュを**1回**の `sha256sum`/`sha1sum`
    呼び出しでまとめて計算する（ループ内で外部コマンドを呼ばない規約への対応）
- `post-push-compact-prompt.sh` が、今回pushの差分ファイル一覧を
  `git diff --numstat <from>...HEAD` で取得し、変更行数の多い順に最大N件（既定20件）だけ
  blobリンク・差分アンカーリンクを組み立てて `additionalContext` へ渡す。
  - 差分範囲は既存の差分リンクと同じ意味論（初回push: `origin/<base>...HEAD`、
    2回目以降: `<前回pushSHA>...HEAD`）。
  - 上限超過分は「他N件は省略」と明示する。
  - **どれを載せるか／blobと差分アンカーのどちらを載せるかはエージェントが判断する**旨を
    指示文に明記する（hookは候補の供給のみ）。

### (2) 返信コメントへのリンク

- `github_get_mr_unresolved_comments` のGraphQLへ `url` を追加し、出力の各行の角括弧内へ
  `url=<パーマリンク>` を含める。
- `github_add_mr_thread_reply` のmutation戻り値を `comment { url }` にし、返信URLをstdoutへ返す。
- GitLab側は note `id` から `<mrUrl>#note_<id>` を組み立てる（`gitlab_get_mr_url` /
  `gitlab_get_note_url` を純粋関数として追加）。**GitLab remoteが無いため【未検証】**。
- `post-push-compact-prompt.sh` の指示文へ「このpushでレビュー指摘へ返信した場合は
  その返信コメントのURLも含める」を追加する。

### (3) テスト・ドキュメント

- `.claude/scripts/test/test_vcs_provider.sh` へ、追加した純粋関数の単体テストを足す。
- `.claude/docs/spec/issue-mr-workflow.md`「提供関数」表・「/compact実施の呼びかけ」節、
  `.claude/skills/issue-mr-flow/SKILL.md` の `comments`/`reply` 定義とMCP対応表を更新する。

## 実機確認の方針（受け入れ条件対応）

- 差分アンカーのハッシュ算出方法は**実機確認済み**: GitHubのCompareページは差分本体を
  `include-fragment src="/<owner>/<repo>/compare/file-list?range=<from>...<to>"` で遅延読込する。
  この断片HTMLを取得したところ、変更3ファイルに対し `id="diff-<sha256(パス)>"` が出力されており、
  ローカルで計算した `sha256sum` の値と完全一致した（詳細はworklog）。
- ブラウザでのスクロール挙動の確認は、この実行環境のChromiumがegress proxyのCA証明書を
  信頼しない（`ERR_CERT_AUTHORITY_INVALID`）ため実施できなかった。人間による1クリック確認を
  HANDOFF.mdの「未解決の内容」へ残す。

## やらないこと

- 既存4リンク（MR・defaultブランチとの差分・前回pushとの差分・コメント一覧）の挙動変更。
- テキストフラグメント（`#:~:text=`）の採用（issue #42で不採用と決定済み）。
