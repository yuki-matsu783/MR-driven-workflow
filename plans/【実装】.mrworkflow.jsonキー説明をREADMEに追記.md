# 【実装】.mrworkflow.jsonの各キー説明をREADMEに追記

全体作業計画: `plans/playful-napping-finch.md`（issue #21）

## 対象

`README.md` の「セットアップ」節（3.の行）。

## 変更内容

現在の3.の記述:

```markdown
3. リポジトリ固有のブランチ命名規則・`plans/`等の場所は [.mrworkflow.json](.mrworkflow.json) を
   参照・編集する。
```

これを維持しつつ、直後に各キーの一覧テーブルを追加する。

| キー | デフォルト値 | 用途 |
|---|---|---|
| `branchPrefixTemplate` | `"feature-{issue}-{slug}"` | issueブランチの命名規則テンプレート。`{issue}`はissue番号、`{slug}`はタイトル等をスラッグ化した文字列に置換される（`new_issue_branch`でのブランチ名生成、`get_issue_number_from_branch`でのブランチ名からのissue番号逆抽出に使用） |
| `defaultBaseBranch` | `"main"` | Draft PR/MR作成・ブランチ作成・差分検出のデフォルトベースブランチ |
| `plansDir` | `"plans"` | 計画ファイル（全体作業計画・個別計画）の格納ディレクトリ |
| `worklogDir` | `"worklog"` | 実装中の試行錯誤ログの格納ディレクトリ |
| `reportsDir` | `"reports"` | 報告用自己完結HTMLの格納ディレクトリ |
| `specDirs` | `[".claude/docs/spec"]` | 正史仕様ドキュメントの格納ディレクトリ一覧（アプリ本体追加時の拡張ポイント。現状スクリプトからは未消費で、ドキュメント上の配置場所指定として使う） |
| `ddrDirs` | `[".claude/docs/ddr"]` | 意思決定ログ（DDR）の格納ディレクトリ一覧（同上） |

`specDirs`/`ddrDirs`については「現状`Provider.sh`のどの関数からも読み出されていない」旨を注記し、
実態との齟齬を避ける。

## 確認方法

- README.mdを読むだけで各キーの意味・デフォルト値・用途が分かることを目視確認する。
- 記載する値が`.mrworkflow.json`の実値・`Provider.sh`の実装と一致していることを確認する
  （`cat .mrworkflow.json`、`grep -n "branchPrefixTemplate\|defaultBaseBranch\|plansDir\|worklogDir\|reportsDir\|specDirs\|ddrDirs" .claude/scripts/src/vcs/Provider.sh`）。
