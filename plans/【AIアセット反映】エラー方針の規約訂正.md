## 反映内容（手順4: 反映先は `.claude/rules/shell-script-style.md`）

「エラー方針」節の「bashでのtry/catch相当の書き方」を次の方針で訂正する。

- **誤りの訂正**: 「コマンド置換・明示サブシェルはフォークされるため、フォークされた側では
  set -e が正しく機能する」という理由付けは、少なくとも bash 5.2 では成り立たない
  （`( func ) || rc=$?`・`if result="$(func)"` のいずれも、errexit の一時停止が
  フォークされた側の内部へ伝播し、関数内の途中失敗が素通りする。実測の詳細は DDR
  `i0027-02` を正とし、規約側は結論とパターンだけを書く）。
- **推奨パターンの差し替え**: 「失敗を検知しつつ処理を継続したい」箇所は
  **条件文脈の外でサブシェルを実行し、内側で `set -e` を掛け直す**。

  ```bash
  set +e
  ( set -e; risky_func )
  rc=$?
  set -e
  if [ "$rc" -ne 0 ]; then fallback; fi
  ```

- **既存の `if result="$(risky_func)"` パターンの位置づけ**: 「関数の最終コマンドの失敗」は
  従来どおり検知できるため全否定はしないが、**複数コマンドから成る関数の途中失敗を検知する
  目的には使えない**ことを明記する。実例として挙がっている `session-start.sh` の
  `build_context` 等は、この制約に照らした見直し候補として注記する（実装の修正自体は
  本計画のスコープ外。必要なら別 issue）。
- 実例参照として `harvest-from-projects.sh` の `cmd_scan` を追加する。

## 検証

```bash
# 訂正後の記述が実測と一致することを、その場で再実行して確かめる
bash -c 'set -euo pipefail; f() { false; echo REACHED; }; rc=0; ( f ) || rc=$?; echo "rc=$rc"'
bash -c 'set -euo pipefail; f() { false; echo R2; }; set +e; ( set -e; f ); rc=$?; set -e; echo "rc=$rc"'
```

合格条件: 1つ目は `REACHED` と `rc=0`（従来記述が成り立たない実証）、2つ目は `R2` を
出力**せず** `rc=1`（推奨パターンの実証）。訂正後の規約本文が、この2つの実測結果と
矛盾しないこと。
