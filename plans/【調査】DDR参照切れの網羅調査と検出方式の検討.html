前提（合意状況）

  • 上位の計画: plans/sequential-purring-tulip.md（全体作業計画、flow-id 1-5で合意）

この計画で何をするか

  1. .gitignoreの2箇所（28行目・40行目）以外に、DDRファイルパス形式の参照切れが 無いことを件数付きの検索結果で確認する。
  2. 同種の参照切れを検出する仕組みの実装方式（置き場所・判定ロジック・実行タイミング）を決める。

変更対象

本計画は調査であり、ファイルの変更は行わない。調査結果はreports/へ記録する。

方針

  • リポジトリ全体（git ls-files、バイナリ除く）を対象に、 .claude/docs/ddr/i<番号>-<枝番>-というパス形式の文字列を 正規表現で抽出し、対応する実ファイルが存在するかを1件ずつ確認する。パス形式に限定するのは、 裸の識別子（i133-01等）がゼロ埋め規約の説明文中の例示に多用されており、 単純な識別子検索では大量の誤検知を生むため（事前調査で確認済み）。この限定により 裸の識別子表記は見逃す（issueの受け入れ条件(2)の文言上はパス形式に限定していないが、 本issueのスコープでは許容する。詳細は下記「やらないこと」）。
  • 参照文字列の終端規則: 一部のDDRファイル名自体が.mdを含む （例: i0032-01-...Default.mdを正とし...md）。非貪欲マッチで最初の .mdを終端にすると誤って途中で切れるため、貪欲マッチ（bashの [[ =~ ]]は既定で貪欲）で終端記号（空白・) ] " ' ` (）の直前までを候補とし、 .mdで終わることを要求する。
  • 既存のddr_identifier_to_reply（check-base-conflicts.sh）・ generate-ddr-list.shの実装を読み、識別子の正規表現・ファイル一覧の取得方法を 流用できるか確認する。
  • 検出方式（新規スクリプト独立／既存スクリプトへの追記）と実行タイミング（手動実行のみ／ flow-id 5-1に合流／generate-ddr-list.sh実行時に自動）を比較し、採用案を決める。
事前調査からの引き継ぎ .gitignoreの28行目はi00-13、40行目はi36-01を参照しており、 実ファイルはそれぞれi0000-13-...md、i0036-01-...md。issue本文は 「i00-13参照は既に消えた」としているが、これは誤りで現に残っている。

やらないこと（スコープ外）

この計画では決めない・触らない
  • パスを伴わない裸のDDR識別子表記（例:「DDR i0159-01参照」）の参照切れ検出 （上記「方針」の理由参照。判断はフェーズ2の合意事項として全体作業計画へも反映する）
  • 実際の.gitignore修正・検出スクリプトの実装（フェーズ3へ送る）
  • DDR以外のドキュメントへの参照切れ検出（全体作業計画でスコープ外と合意済み）

検証

# リポジトリ全体からDDRパス形式の参照候補を抽出する（コードフェンス内・テストファイルは
# 別途除外ロジックで扱う。ここでは素朴な抽出コマンドの例を示す）
git ls-files -z -- '*.md' '*.sh' '.gitignore' \
  | xargs -0 grep -noE '\.claude/docs/ddr/i[0-9]+-[0-9]{2}-[^]) "'"'"'`(]*\.md' \
  | wc -l

合格条件: 上記のようなコマンドで得た候補について、3フィルタ（テストファイル除外・ コードフェンス内除外・省略記法除外）適用後の総数と、そのうち実ファイルが存在しない件数が reports/へ件数付きで記録され、検出方式の採用案とその理由が記録されていること。
