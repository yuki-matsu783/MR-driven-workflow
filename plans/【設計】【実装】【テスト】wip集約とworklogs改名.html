方針

1. KEEP_PATHSの動的化（最優先の既知の欠陥）

cleanup-task.shのKEEP_PATHS=("worklog/TEMPLATE.md")はハードコード されており、worklogDirをwip/worklogsに変えると TEMPLATE.mdが誤削除される。設定値から動的に組み立てる形へ修正する。

置き換え前後（コード上の対応箇所） 
# 置換前（50-52行目）
readonly -a KEEP_PATHS=(
  "worklog/TEMPLATE.md"
)

# 置換後（readonlyを外し空配列で初期化。declareは使わない — main内でdeclareすると
# ローカル変数になり、main経由の呼び出しではたまたま見えるがテストの直接呼び出しでは壊れる）
KEEP_PATHS=()

# main() 内、dirs_tsv -> target_dirs 読み込み直後に追加
# target_dirs[1] は worklogDir（224行目のjq配列の並び順に対応）
KEEP_PATHS=("${target_dirs[1]}/TEMPLATE.md")

test_cleanup_task.sh側の修正が必須。同スクリプトはmainを呼ばず is_keep_pathを直接呼ぶため、呼び出し直前にKEEP_PATHS=("worklog/TEMPLATE.md") を明示的にセットする行を追加する。加えて.mrworkflow.jsonで worklogDir: "wip/worklogs"を指定したフィクスチャによる新規結合テストケースを追加し、 main経由の配線自体を検証する（既存フィクスチャは.mrworkflow.jsonを 持たずこの配線を一度も通らないため）。

Provider.sh・cleanup-task.sh:224のjqフォールバック既定値は変更しない。 .mrworkflow.jsonを持たない配布先（旧レイアウトのまま）で、フォールバックが wip/*を指すと実際のplans/等が片付け対象から漏れるため。この決定により .claude/docs/spec/cleanup-task.mdの「未決定事項」節が事実と食い違うが、本計画では 変更せずフェーズ4へ送る。

2. ディレクトリ移動

チェックとgit mvを同じ条件式で繋ぎ、チェックが偽なら実行しないようにする （別行に分けるとBashツールにはset -eが無いため、チェックが偽でもgit mvが そのまま走ってしまう）。

mkdir -p wip
if [ ! -e wip/plans ] && [ ! -e wip/worklogs ] && [ ! -e wip/reports ]; then
  git mv plans wip/plans && git mv worklog wip/worklogs && git mv reports wip/reports
else
  echo 'error: 移動先が既に存在します' >&2
fi

移動後、wip/plans/REVIEW-POINTS.md wip/reports/REVIEW-POINTS.md wip/worklogs/TEMPLATE.mdが存在することを確認する（検証節に手順あり）。

上記「変更対象」表のとおり。install-to-project.shは162-163行目の mkdir -pと187-188行目の.gitkeepをwip/1つ＋配下3構成へ 変更し、reportsにも.gitkeepを新設する（受け入れ条件4）。
