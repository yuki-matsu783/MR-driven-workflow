# 【調査】収穫スキルの前提調査 — issue #27

## 前提（合意状況）

- 依拠する上位計画: `plans/quiet-orchard-harvest.md`（flow-id 1-4 でAIエージェントが作成）。
- **flow-id 1-5（全体作業計画への人間の合意）は未実施である。** 非対話セッションのため
  保留したまま進めている（進め方の特記は全体作業計画「非対話セッションでの進め方」節）。
  1-5 で全体作業計画の方針が変わった場合、本計画の調査項目（Q1〜Q8）も変わりうる。

## 目的

収穫スキルの個別作業計画（flow-id 3-1）を確度高く書けるだけの材料を揃える。

## 方針

- **読解が先、実行検証は判断が割れる箇所だけ**: Q1・Q2・Q4・Q6・Q8 は実装・規約の読解で
  確定できる。Q3（`git merge-file` の衝突挙動・CRLF入力）と Q5（`create-issue.sh` の
  引数検証）は実行して確かめる。Q7 の git コマンドは既知の挙動のため机上でよいが、
  縮退条件（非gitリポジトリ・浅い履歴）の整理までを答えに含める。
- **答えが出ない問いは「出なかった」として記録し、フェーズ3の計画で仮説として扱う**
  （調査を延長しない。8問に答えるか「答えられない理由」を書いた時点で打ち切る）。
- 進め方: Q1→Q4→Q8（manifest まわりを連続で読解）→Q3（実行検証）→Q2・Q5・Q6（規約・
  接続先）→Q7 の順。

## 検証（何が分かれば次へ進めるか）

Q1〜Q8 すべてに「実装に使える具体的な答え」（形式・置き場所・コマンド・縮退条件）が付き、
`reports/2026-08-23_quiet-orchard-harvest_調査結果.md`（＋同名.html）に**実行検証の
コマンドと出力を貼った形で**記録されていること。実行検証は最低限次を含む。

```bash
# Q3: git merge-file の衝突判定（終了コード=衝突数、-p は入力を変更しない）を確かめる
printf 'l1\nl2\nl3\n' > base; printf 'l1\nL2\nl3\n' > ours; printf 'l1\nl2x\nl3\n' > theirs
git merge-file -p ours base theirs; echo "exit=$?"
# 合格条件: 衝突マーカーが出力され exit=1（衝突1件）になること

# Q3: CRLF入力（LF正規化なし）で全行が不一致になることを確かめる
sed 's/$/\r/' base > theirs_crlf
git merge-file -p ours base theirs_crlf | grep -c '^<<<<<<<'
# 合格条件: 正規化しない場合に衝突が出ること（→3入力への正規化が必要という答えの根拠）

# Q4/Q8: 層分け定義から core の対象ファイルを列挙できることを確かめる
jq -r '.entries[] | select(.layer=="core") | .path // empty' .claude/dist-layers.json | head
git ls-files -- .claude | head
# 合格条件: pathspec 展開で対象一覧が得られること（0件でないこと）

# Q5: create-issue.sh が5引数必須であることを確かめる（引数不足で非0＋使い方表示）
bash .claude/scripts/src/create-issue.sh --title t 2>&1 | head -3; echo "exit=$?"
# 合格条件: 必須引数エラーの文言が出ること
```

コマンドの出力（またはその要約と実測値）を `reports/` のmdへ貼ることを合格条件とする。
