この計画で何をするか

フェーズ2の調査で決めた案B（.github/pull_request_template.md を唯一の正とし、describe 節は雛形を持たない）を実装する。作業は7項目で、うち3項目（1・2・4）は互いに依存するためまとめて行う。

種別を2つ併記している理由

テンプレート・スキル定義（AIアセット作成）と、それを固定するテスト（テスト）は同じコミットで揃っていないと意味が無い。テンプレートだけ変えるとテストが落ち、テストだけ変えると何も検査していない状態になる。合意も1回で取る。

案B採用の合意状況

合意はまだ取れていない

案Bは人間の合意をまだ得ていない。 このセッションは非対話（人間のレビュー往復を待てない）で実行されており、フェーズ2のレビュー往復は敵対的レビューによる自動レビューで代替している（ユーザーからの明示指示による）。したがって案Bは、現時点ではAI側の結論である。

  • 判断の根拠と却下案（案A・案C）は調査結果レポートの §1 にある。ただしその置き場は flow-id 5-5 で削除されるため、マージ後に辿れる場所へ残す必要がある。
  • 恒久的な記録先はフェーズ4のDDR i0145-01 である（flow-id 4-6）。この計画・レポートはそこへ昇格させるための材料であり、それ自体は合意の記録ではない。
  • 人間のレビューで案Bが否認された場合、この計画の作業項目1〜5はすべて作り直しになる。

1・2. テンプレート2本

先頭のHTMLコメントへ書くこと（現行から差し替える内容）。

  • このファイルが見出し構成の唯一の正であること。describe はこのファイルを読んで見出しを決めるので、ここを変えれば describe の出力も変わる（逆は無い）。
  • flow-id 2-5/2-10/3-5/3-10/4-5/4-10 で describe が本文を全文置換すること。
  • Draft PR/MRの初期本文（new_draft_merge_request のハードコード）はこの10節に合わせない。 初回の describe で全文置換されるため実害が無く、合わせると「まだ何も無い状態の10節」が一時的に残るだけで読みにくいため。この判断そのものを1行残す（後から見た人が「初期本文が古いテンプレートのままだ」と誤解しないため）。
  • GitLab版のみ: Default.md が予約名であること（DDR i0032-01）。この差分がGitHub版との唯一の相違である。

「見出しを増やさない」という現行の制約をどう書き換えるか。 現行の先頭コメントは「見出しを増やさないこと（増やしても最初の describe で消える）」と書いている。案Bでは describe がこのファイルを読むため、増やした見出しは消えない——理由が成り立たなくなる。しかし「増やしてよい」と単純に書き換えると、配布先に対して守れない約束になる。

配布元（このリポジトリ）配布先
テンプレートの扱い見出し構成の正。ここを変えれば describe の出力も変わるcore 層＝再適用のたびに上流の内容で上書きされる（改変は .bak へ退避のうえ一覧で通知）
見出しを増やせるか増やせる（消えない）増やせるが、次の install-to-project.sh 適用で上流の内容へ戻る
採る方針

テンプレートを core 層のまま据え置き、コメントの文言を配布元に限定する。「このリポジトリでは見出しを増やしてよい。配布先では core 層として再適用のたびに上書きされるため、増やした見出しは次の再適用で失われる」と両方を書く。

seed へ層を変える案は採らない。 dist-layers.json の note が「見出しが start・describe と機能的に結合」と書いているとおり、テンプレートの見出しは describe の出力そのものであり、配布先ごとに分岐すると describe の挙動も分岐する。層の変更は dist-layers.json・check-dist-coverage.sh・distribution-assets.md の3箇所に波及し、本issueの目的（正を1つにする）と逆方向でもある。

4. テスト

現在の describe_headings()（review-loop.md から awk で抽出）は、案Bで describe 節が雛形を失うため抽出が0行になり、assert_eq "3" が失敗する（「空振りして通る」のではなく「落ちる」。既存ガードは正しく機能している）。次の3種類へ差し替える。

検査内容
(a) 見出し期待値の10節をテスト内へ書き下し、テンプレート2本の ^(Closes|## ) が順序込みで一致すること
(b) 全文先頭のHTMLコメントブロックだけを除外した2本の全文差分が空であること
(c) 参照review-loop.md の describe 節が、テンプレート2本のパスを両方とも参照していること（各1件以上）
(c) を足す理由

現行テストは「describe 節 ⇔ GitHub版 ⇔ GitLab版」の3者を突き合わせており、テストのコメント自身が「2つのテンプレート同士を比べるだけでは足りない」と書いている。(a)(b) だけにするとテンプレート側しか見なくなり、案Bの成立条件である「describe 節がテンプレートファイルを読むと書いてあること」が誰かの編集で無言で失われてもどのテストも落ちない。一本化の効果はこの1点に全面的に依存しているので、そこだけ無検査にはできない。

空振り防止の表明を「期待値が非空」にしない。 期待値はテスト内のリテラルなので、非空は編集ミスでない限り常に真であり、落ちる入力が存在しない表明になる（ルート REVIEW-POINTS.md「異常が無ければ何も出ない形の検証は…常に成功する」）。代わりに次の2つを行う。

  1. 実データ側（テンプレートから抽出した見出し行・除外後の全文の行数）が非空であることを表明する。とくに (b) は、除外後の行数が 0でも1でもないことを併せて表明する（下記の空振り経路への対策）。
  2. 着手時に意図的に片方だけ1文字変えて (a)(b)(c) が落ちることを確かめ、worklog へ記録する。
  • 抽出行数の固定値 3 は残さない。
  • 期待値を持つことは「二重管理」に数えない。 期待値は正ではなく検査であり、これが無いと「2本を比べるだけでは足りない（両方が同時にずれると通ってしまう）」という既存コメントの趣旨が守れない。その旨をテスト側のコメントへ明記する（次に読む人が「二重管理では」と消しに来ないため）。

空振りしている検証

検証3は変更前から成功する不変条件である。「2本が食い違っていないこと」は今も真であり、この作業の成否を判定しない。判定に効くのは検証2・3'・4の3つで、検証3はそれらと組にして「10節へ移したあとも2本が食い違っていない」ことを守る役割にとどまる。

除外の実装（strip_lead）が空振りする2つの経路

素朴な sed '1{/^<!--$/!q}; 1,/^-->$/d' は、次の2つの入力で本文が食い違っているのに差分なしになる（いずれも実測で確認済み）。

経路何が起きるか
先頭コメントの終端が行末に付く（ 説明 --> のように --> が単独行でない）^-->$ に一致せず、削除範囲が最初の節の記入ガイドの --> まで伸びる。Closes 行・## 概要・その記入ガイドが両ファイルで丸ごと消える。「特になし／未実施」の定義を置く唯一の場所が検査の穴になる
先頭に <!-- が無い1{/^<!--$/!q} の q はパターン空間を出力して終了するため、出力が1行目だけになる。1行目が同じなら本文がどれだけ違っても差分なし

対策: (1) 除外を「1行目が <!-- で始まり、その後最初に現れる --> を含む行まで」へ広げる。ただし sed の範囲指定（1,/-->/d）では両方とも塞げない——範囲は1行目で開始してしまうと --> が現れるまで伸び続け、先頭にコメントが無い場合はEOFまで削る（実測で確認）。状態を持つ awk で書く（下記の実装）。(2) 除外後の行数が0でも1でもないことを併せて表明する（検証3'）。(3) 意図的に片方だけ1文字変えて diff が落ちることを着手時に確認する。

実測（2026-08-23、変更前のツリー）: 下記の awk 版は4ケースすべてで期待どおりだった。

検証2・3・3' の実行コマンド

期待値のヒアドキュメントは各行を | で始めて sed で剥がす（行頭に ## を持つ行をこの計画ファイル自身へ増やすと、計画のmd/HTML見出し突き合わせとテンプレートの見出しを数える検査の両方がコードブロックの中身を拾うため）。

| ## 変更内容

| ## 検証

EXPECTED

# 検証2: 見出しが期待値と順序込みで一致する
for f in "$gh_t" "$gl_t"; do
  diff <(printf '%s\n' "$expected") <(grep -E '^(Closes|## )' "$f") || echo "NG(見出し): $f"
done

# 先頭のHTMLコメントブロックだけを除く（終端が行末に付く形・先頭にコメントが無い形の両方へ対応）。
# sedの範囲指定（`1,/-->/d`）では両方とも塞げないことを実測したため awk で状態を持つ。
strip_lead() {
  awk 'NR==1 && /^[[:space:]]*<!--/ { lead = 1 }
       lead { if (/-->/) lead = 0; next }
       { print }' "$1"
}

# 検証3': 除外後が 0行でも1行でもない（除外が伸びすぎ／効かなすぎを検出する）
for f in "$gh_t" "$gl_t"; do
  n="$(strip_lead "$f" | grep -c '')"
  [ "$n" -gt 1 ] || echo "NG(除外後が${n}行): $f"
done

# 検証3: 先頭のHTMLコメントブロックだけを除いた全文が一致する
diff <(strip_lead "$gh_t") <(strip_lead "$gl_t") || echo 'NG(全文差分)'
