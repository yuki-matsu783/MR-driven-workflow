# 【全体作業計画】残置テキストの係り先ルールを構造変更全般へ広げる

issue #142 / PR #188。

## この作業で何をするか

`.claude/rules/docs-workflow.md` にある「既存ドキュメントへ新しい見出しを差し込むときは、挿入位置の
直前の節が『その節全体にかかる地の文』で終わっていないかを必ず確認する」というルール（issue #64 で
追加）を、**見出しの挿入に限定された書き方から、「残置したテキストの係り先が変わっていないか」という
観点の書き方へ一般化する**。

同型の事故が既に4件確認されている（issue #64 / #109 / PR #139 / issue #155）。現行の文言は
そのうち #64 の形しか拾えない。

## 背景（issueと通知コメントから確定している事実）

| # | 何を変えたか | 壊れたテキストの位置 | 現行ルールで拾えるか |
|---|---|---|---|
| issue #64 | 新しい見出しを差し込んだ | 挿入位置の**直前** | 拾える（このルールの元ネタ） |
| issue #109 | 既存の節を (1)(2) に**分割**した | (1) の**直後**（分割前は正しかった行） | 拾えない（見出しの挿入ではない） |
| PR #139（issue #135） | 新しい見出しを差し込んだ | 挿入位置の**直後**（見出しを持たない段落群） | **拾えない**（射程内の操作なのに「直前を見よ」という手順では検出できない） |
| issue #155 | 既存の箇条書きへ**項を1つ足した** | 直前の項の末尾にあった補足 | 拾えない（見出しも節も階層も動いていない） |

4件とも**自己確認では見つからず、敵対的レビューが検出**している。書いた本人は「新しく書いた部分が
正しいか」を見ており、「既にあった行の係り先が変わったか」を見ていない。

## 進め方（フェーズ構成）

### フェーズ2〈調査〉

**実施する。** 次の問いに答える。

1. 現行ルール（`.claude/rules/docs-workflow.md` の該当段落と実例2件）は、どの範囲を射程にしているか。
   一般化したとき、既存の実例2件はそのまま残せるか。
2. 同じ趣旨のルールが**他のファイルにも重複していないか**（ルート `REVIEW-POINTS.md`「ドキュメントの
   構造」に同型の観点がある。正を1箇所にするのか、観点表と規約で役割を分けるのかを決める）。
3. 4件の実例のうち、ルール本文へ載せるのはどれか。**「分割前は正しかった行が分割によって誤りになる」
   （#109）と「挿入位置の後ろが壊れる」（PR #139）は方向が逆**で、2つ並べると観点が立体的になる、と
   issue #142 のコメントが示している。何件までなら読み手の負担にならないか。
4. 受け入れ条件が求める「拡張の判断をDDRへ残すか、既存DDRへの追記で足りるか」の材料。issue #64 由来の
   DDRが存在するか、`.claude/docs/ddr/` を検索して確定する。
5. このルールを**実際に守らせる場所**はどこか（`.claude/rules/docs-workflow.md` だけでよいか、
   `REVIEW-POINTS.md`・敵対的レビューの観点にも要るか）。

### フェーズ3〈作業〉

調査結果をもとに、`.claude/rules/docs-workflow.md` の該当ルールを書き換える。想定する形は次のとおり
（確定はフェーズ3の個別計画で行う）。

- 適用対象を「見出しの差し込み」から**構造変更全般**へ広げる。ただし**操作の種類を列挙する形にしない**
  （issue #155 の3例目が、列挙した4操作のどれにも入らなかったため）。
- 確認の観点を「**残置した地の文・箇条書きが、変更前と同じものに係っているか**」という形で書く。
- 「**前後どちらの残置テキストも見る**」ことを明示する（PR #139 のコメントの指摘）。
- issue #64 の既存の実例（`計画の2階層構造` の位置、ファイルごとに結論が変わる話）は**消さない**。
- 「分割前は正しかった行が、分割によって誤りになる」形を明示した実例を足す。

種別は `【AIアセット作成】` を想定する（ルール文書そのものが今回の主たる成果物であるため）。

### フェーズ4〈反映〉

flow-id 4-1 で反映対象を洗い出す。現時点の見込みは次のとおり（確定した反映内容ではない）。

- **DDR**: 「なぜ操作の列挙ではなく観点で書くのか」の判断を残すか、既存DDRへの追記で足りるか。
  issue #142 の受け入れ条件が明示的に求めているため、**結論の記録は必須**。
- **`REVIEW-POINTS.md`**: ルート `REVIEW-POINTS.md`「ドキュメントの構造」の同型の観点を、
  一般化後の記述と揃えるか。
- **`.claude/docs/usecase/`**: 影響の有無を確認する。

## この計画で決めないこと（スコープ外）

- **過去に書かれたドキュメントの遡及点検**。今回はルールの文言を直すところまでで、既存文書に同型の
  破損が残っていないかの棚卸しは行わない（判断は別issueへ送る）。
- **敵対的レビューのプロンプト・サブエージェント定義（`.claude/agents/adversarial-reviewer.md`）の改修**。
  観点表へ書けば足りるかをフェーズ2の問い5で判定し、足りないと分かった場合のみフェーズ4で扱う。
- 4件以外の事例の発掘（判断は flow-id 2-1 の個別調査計画へ送る）。

## issueの受け入れ条件との対応

| 受け入れ条件 | この計画での対応 |
|---|---|
| `.claude/rules/docs-workflow.md` の該当ルールが、節の分割・再構成を含む形に更新されている | フェーズ3 |
| issue #64 の既存の実例を消さずに、issue #109 の実例が追加されている | フェーズ3（調査の問い3で載せる実例を確定） |
| 拡張後の記述が、issue #64 由来の既存の記述と矛盾していない | フェーズ2の問い1・フェーズ3 |
| 拡張の判断を新規DDRへ残すか既存への追記で足りるかが検討され、結論が記録されている | フェーズ2の問い4 → フェーズ4 |

## 検証

issue全体として、次がすべて満たせたら完了とする。

- `.claude/rules/docs-workflow.md` の該当ルールが、**4件の実例すべてを説明できる**文言になっている
  （4件それぞれについて、ルールの文言を読んで「見るべきだった」と分かるか机上で突き合わせる）。
- issue #64 由来の既存2実例が残っている（差分の削除行で確認する）。
- DDRの要否について結論が記録されている。
- 各フェーズで敵対的レビューを実施し、投稿された指摘へ対応・返信している。

## 進め方の前提（このセッション固有）

- **非対話的セッション**のため、人間のレビュー往復（flow-id 2-3/2-8・3-3/3-8・4-3/4-8）は成立しない。
  ユーザーの指示により、**各フェーズの計画時に1回・作業実施ごとに1回、敵対的レビューを自動起動し**、
  その指摘への修正・返信をもってレビュー往復の代替とする。
- ブランチ名はハーネス指定の `claude/docs-workflow-heading-rule-mi3krb` を使う
  （`.mrworkflow.json` の `feature-<issue番号>-<slug>` 規則とは異なるが、ハーネスの指定が優先する）。
