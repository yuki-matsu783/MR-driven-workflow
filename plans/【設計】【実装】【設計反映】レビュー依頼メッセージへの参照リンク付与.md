# 【設計】【実装】【設計反映】レビュー依頼メッセージへの参照リンク付与

対象issue: #13 レビュー依頼にMRへのリンクをつける

## 背景

`.claude/hooks/post-push-compact-prompt.sh`（`git push`検知でレビュー依頼メッセージをAIエージェントに
促すhook）が固定文のみを注入しており、レビュアーがMRを見に行くまでに1段階ハードルがあった。

## 実行環境に関する注記

このタスクはClaude Code on the webのissue駆動自動実行セッション（対話的なレビュー往復ができない
一発実行）で対応した。そのため、通常の `.claude/skills/issue-mr-flow/SKILL.md` が定める
「計画→レビュー→実施→レビュー」の複数ラウンド構成ではなく、設計・実装・設計反映を1回のpushに
まとめて実施している（種別を複数併記する基準どおり、合意を1回で取る前提のためファイルも分けない）。
全体作業計画（planツール利用）も、対話的な承認ステップが無いため作成していない。

## 受け入れ条件（issueより）

- レビュー依頼メッセージに参照リンクが含まれる
- defaultブランチとの差分を見れるリンク
- レビュー指摘対応の時は下記も記載する
  - 前回push時との差分を見れるリンク
  - コメント一覧(MR画面)が見れるリンク

## 設計

- `Provider.sh`に`get_mr_diff_url` / `get_mr_diff_since_url`を追加し、GitHub/GitLab双方の
  実装（`github_get_mr_diff_url`等、`gh`/`glab`呼び出しを伴わない純粋関数）へディスパッチする。
- `post-push-compact-prompt.sh`が`.claude/state/review-links/<safeBranch>.txt`へ前回pushの
  HEAD SHAを保存し、次回push時に読み出すことで「前回pushとの差分」を判定する。ファイルが
  無ければ初回pushとみなし、前回pushとの差分・コメント一覧の2リンクは省略する。
- 詳細な設計判断・却下案は
  [0022-レビュー依頼メッセージの参照リンクは前回pushSHAをローカル状態で保持して組み立てる.md](../.claude/docs/ddr/0022-レビュー依頼メッセージの参照リンクは前回pushSHAをローカル状態で保持して組み立てる.md)
  参照。

## 実装

- `.claude/scripts/src/vcs/Github.sh` / `Gitlab.sh`: URL組み立て純粋関数を追加
- `.claude/scripts/src/vcs/Provider.sh`: ディスパッチャを追加
- `.claude/hooks/post-push-compact-prompt.sh`: 参照リンクの計算・状態保存・メッセージ組み立てを追加
- `.gitignore`: `/.claude/state/`を追加
- `tests/test_vcs_provider.sh`: 新規URL組み立て関数の単体テスト
