# 【設計】`.gemini/` の hooks/ scripts/ docs/ の採否を決める

全体作業計画: `wip/plans/mellow-drifting-lantern.md`
調査結果: `wip/reports/20260823_mellow-drifting-lantern_gemini生成対象の参照実態.md`（issue #172 / PR #193）

## この計画で何をするか

3ディレクトリそれぞれについて **「生成対象に含める／外す」を1つずつ決め、決め方（判定基準）と
結論の根拠を `wip/reports/` へ記録する**。実装（`sync-gemini-assets.sh` の変更）を伴うかは
結論次第であり、**この計画では実装を前提にしない**。

**種別を `【設計】` 単独にした理由**: このフェーズの成果物は「判断とその理由」であって、コード
ではない。外す結論になった場合の実装（`is_copy_excluded` の接頭辞一致化とテスト追加）は
**同じフェーズ3の中で続けて行う**が、実装するかどうかがこの設計の結論に依存するため、
`【実装】` を先に併記すると「実装することが決まっている」と読めてしまう。**結論が「外す」に
なった時点で、この計画へ `【実装】` の節を追記する**（種別の併記は合意の単位で決める、という
`references/planning.md` の規定に従う）。

## 判定基準（これで決める）

3ディレクトリを**同じ物差しで**測る。物差しをディレクトリごとに変えると、issue本文の見立て
（hooks/scripts は不要・docs は要る）をなぞるだけになる。

| 軸 | 問い | 「外す」へ倒れる条件 |
|---|---|---|
| 1. 読まれるか | そのパスを指す経路が生成物・設定の中にあるか | 0件 |
| 2. 自己完結が壊れないか | 外したとき、**残るファイルから**切れる相対リンクが出るか | 0件、または切れても許容できる理由がある |
| 3. 外すコスト | 実装・テスト・ドキュメント追随に何が要るか | 追随箇所が特定でき、いずれも機械的に直せる |
| 4. 外す利得 | 何がどれだけ減るか | 利得が軸1〜3のコストを上回る |

**軸1で「0件」を根拠に外すなら、同じ根拠が当たる `.gemini/rules/` `.gemini/skills/` を外さない
理由も同時に説明できなければならない**（事実D）。説明できないなら、その根拠は3ディレクトリの
採否を決める根拠として使えない。**この整合性チェックを判定基準の一部として明示的に置く**のが、
この計画の要点である。

## 比較する案

| 案 | 内容 | 主な論拠 | 主な難点 |
|---|---|---|---|
| 案1 | 3つとも**残す**（現状維持） | 部分的に外すと自己完結が壊れる。配布物は減らない。外す根拠（軸1の0件）は未観測の推論で、同じ根拠が rules/ skills/ にも当たる | 176ファイル・2.49MBの複製が残る。調査中に実際に踏んだ「二重計上」のノイズも残る |
| 案2 | hooks/ と scripts/ だけ**外す** | 軸1で最も明確に0件。追随箇所が少ない（scripts/ で2ファイル3行） | **残る `.gemini/docs/` から切れリンクが2件出る**。「読まれないから外す」を rules/ へ適用しない理由を説明できない |
| 案3 | 3つとも**外す** | 削減が最大。切れリンクも18件で頭打ち（docs/ 内で完結する282件はリンク元ごと消える） | 未観測の推論だけを根拠に、`.gemini/` の8割を落とす。**`.gemini/rules/` に18件の壊れたリンクが残る** |

**現時点の暫定は案1**（事実D・F・Hの重なりによる）だが、**結論は flow-id 3-6 で確定させ、
`wip/reports/` へ書く**。この計画では案の比較軸までを固定する。

## この計画で決めないこと（スコープ外）

- **`.gemini/rules/` `.gemini/skills/` `.gemini/agents/` の採否**。issue #172 が対象にするのは
  3ディレクトリであり、事実Dはそれらを**外す根拠**としてではなく、**3ディレクトリを外す根拠の
  整合性を検査する材料**として使う。`.gemini/` 全体に何を置くかの再設計は、Gemini CLI 実機で
  読み込み経路を観測できるようになった時点で別issueとして扱う（この線引き自体を結論へ記録する）。
- **`.claude/docs/ddr/i0127-01-….md:132` の切れリンク**（issue #133 の改番で旧ファイル名が残った
  既存の欠陥）。本issueのスコープ外なので、扱いはフェーズ4（flow-id 4-1）で決める。
- **`check-doc-references.sh` の検出範囲**（絶対パス形式に限る、というDDR `i0171-01` の限定）。
  相対リンクの切れを検出できないことは調査で確認したが、その限定を見直すかは本issueの対象外。
- **Gemini CLI 実機での動作確認**（実行環境に CLI が無い。全体作業計画のスコープ外に既出）。

## 進め方（flow-id 3-6 で行うこと）

1. 判定基準の4軸を3ディレクトリへ**それぞれ独立に**当て、表として書き出す。
2. 軸1の整合性チェック（事実D）を通す。通らない案は、その旨を明記して落とす。
3. 案1〜案3から1つを選び、**選ばなかった案を却下した理由**まで書く（フェーズ4でDDRの
   「却下した案」節へそのまま移せる粒度で書く）。
4. **結論に「未観測のまま判断した」ことを明記する**（事実H）。どの結論を選んでも、根拠は
   実機観測ではなく生成物と設定からの推論である。
5. **再検討の条件を書く**（何が観測できたら、この判断を見直すのか）。
6. 「外す」を選んだ場合に限り、続けて実装する。
   - `is_copy_excluded` を接頭辞一致（または `case` パターン）へ拡張する。
   - `test_sync_gemini_assets.sh` の T8 へ「除外したディレクトリが出力に無いこと」と
     **「除外していないディレクトリは残ること」の対**を追加する（後者が無いと、判定が全件除外へ
     壊れても気づけない）。
   - `bash .claude/scripts/src/sync-gemini-assets.sh` を実行して `.gemini/` を再生成する。
7. 結果を `wip/reports/日付_mellow-drifting-lantern_gemini生成対象の採否.md`（＋同名 `.html`）へ
   記録する。**この計画ファイルへ結果を書かない。**

## 検証

**結論が「残す」の場合。**

```bash
bash .claude/scripts/src/sync-gemini-assets.sh --check ; echo "exit=$?"   # → 0
bash .claude/scripts/test/test_sync_gemini_assets.sh | tail -1            # → passed=91 failures=0
```

- 上の2つは**変更前から通る**（調査で実測済み）。したがって**これだけでは検証にならない**。
  「残す」を選んだ場合の検証は、**判定基準の4軸すべてに3ディレクトリ分の答えが書かれていること**
  と、**却下した案2・案3の理由が書かれていること**をレポートで確かめることである。

**結論が「外す」の場合**（上記に加えて）。

```bash
# 除外したディレクトリが生成物に無いこと（0件）と、残すディレクトリが在ること（非0）の対で見る
ls .gemini/ ; git -C . status --porcelain .gemini | head
bash .claude/scripts/test/test_sync_gemini_assets.sh | tail -1   # → passed=N failures=0（Nは91より増える）
bash .claude/scripts/src/sync-gemini-assets.sh --check ; echo "exit=$?"   # → 0
bash .claude/scripts/src/check-dist-coverage.sh ; echo "exit=$?"          # → 0
```

- **T8 の追加が空振りしないことを確かめる。** 追加したアサーションが、`is_copy_excluded` を
  完全一致へ戻した状態で**実際に落ちる**ことを一度確認する（落ちなければ、そのテストは
  除外の実装を固定していない）。
- 切れる相対リンクの件数を、調査と同じ手順（リンク解決）で**再測して記録する**。事前の見込みは
  hooks/scripts のみなら2件、3つすべてなら18件。
