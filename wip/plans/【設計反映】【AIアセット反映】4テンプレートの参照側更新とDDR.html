方針

1. 選択基準（受け入れ条件(4)の実体）

deliverables.md の1箇所に置き、他所からはそこを参照させる。 5本ぶんの説明が複数のファイルへ散ると、次に増やしたとき全部が古くなる。全行に同じ軸を揃える（テーマ／印刷／向く内容）。軸が抜けた行があると、その行と他の行のどちらを選ぶかが決まらない。

テンプレートテーマ@media print向く場面
reports-cleanライト／ダーク無し既定。迷ったらこれ。 サイドバー常時表示で章数が多くても迷子にならない
reports-neobrutalライト単一無し結論を強く押し出したいとき（太い黒枠＋ハードシャドウ）
reports-monoライト／ダーク無し色が付いている＝意味があるを徹底したいとき。白黒での閲覧・スクリーンショットでの色の誤読を避けたい場合
reports-paperライト単一有り印刷・PDF化して配るとき
reports.template.html（現行）ライト／ダーク無し移行期のみ。 このブランチ以前に作られ、まだ片付いていないレポートを更新する場合に限る
  • 既定を1つ決めるのが要点である。 5本並べて「好みで選ぶ」と書くと、レポートごとに見た目が変わり、読み手が毎回レイアウトを学び直すことになる。選ぶのは、右列に当てはまる理由があるときだけとする。
  • 競合したら paper を優先する。「白黒で読む」は mono と paper の両方に当てはまるが、実際に印刷するなら @media print を持つのは paper だけである（実測: 4本中 paper のみ）。
  • 現行を選ぶ場面は、移行が終われば消える。 wip/reports/ の成果物は flow-id 5-5 で削除されmainに残らないため、「既存の成果物を更新する」に該当するのは同一ブランチ内だけである。いつ現行を廃止するかはDDRの未確認事項へ入れる（install-to-project.sh は上流で消えたファイルを配布先から削除しないため、廃止時に配布先へ旧テンプレートが残る）。

2. 「土台は reports.template.html」という記述の直し方

パスを5つ並べる形にしない。 flow-id 2-6・3-6・4-6・5-4 の4箇所すべてに5本の一覧を書くと、テンプレートが増減するたび4箇所を直すことになる（今回まさにそれをやっている）。

変更前: 土台は `.claude/skills/issue-mr-flow/assets/reports.template.html`
変更後: 土台は `.claude/skills/issue-mr-flow/assets/reports-clean.template.html`（既定）。
        他の3案・現行との使い分けは `references/deliverables.md`「計画・レポートのHTMLビュー」

既定のパスは書く。「deliverables.md を見よ」だけにすると、フロー定義だけを読んで作業する場面で1回余分に開くことになる。既定＋参照の形にして、迷ったときだけ開けば済むようにする。

Eの348行だけは、この形にしない あの表は「テンプレート → どのflow-idの成果物か」の対応表なので、4本を足すと同じ対象を持つ5行が並び、区別する情報を持たない一覧がもう1つできる（方針1が避けようとしている二重管理そのもの）。reports系を1行へ畳み、直後にある「何の正か → どこ」の表へ「どれを選ぶか → deliverables.md」の行を足す。

3. 検査手順の「正」をどこに置くか（新規の論点）

フェーズ3で、検査手順の実体が1つから5つに増えた。 新4本は使い方コメントごとバイト単位で同一なので、プレースホルダ検査・リンク破断検査・重複ID検査の説明が4本すべてに複製されている。一方、「検査コマンドの正は reports.template.html 冒頭コメント」と名指しする箇所が3つある。

名指ししている場所扱い

DDR i0186-02 25行触らない（DDR本文は変更しない）。向け先の変更は spec の changelog（E）へ記録する

4. 検査を5種から6種へ増やす（AIアセット反映 (c)）

この計画のHTMLビュー自身が、<style> の二重出力という壊れ方をした 敵対的レビュー3回目で検出。既存の5種はどれも捕まえなかった——アンカー・ID・外部依存しか見ないためである。 
# 6. 構造の妥当性（1でなければ不合格）
grep -c '^<style>' "$f"; grep -c '^</style>' "$f"

この壊れ方は、ライト環境でだけ表示が崩れる。 <style> の直後にもう1つ <style> があると、2つ目はCSSのテキストとして扱われ、続く :root { … } ブロックごと破棄される。ダーク環境ではメディアクエリ内で :root を再定義しているため正常に見え、確認する環境によって結果が変わる。

反映先は J（plans.template.html）・K（wip/plans/REVIEW-POINTS.md）と、新4本＋現行テンプレートの冒頭コメントである。

DDRへ「一般則」を残すのは、同じ失敗を2回踏んだため

(3) 「触らない」と決めたものが本当に触られていないか

当初この計画は、次の2つを検証手順として書いていた。どちらも機能しない（敵対的レビュー3回目）。

書いていたものなぜ機能しないか
git diff … | grep -nE '^[-+].*(3132|3216|3275|3651)'diff本文に文字列「3132」が現れる行を探しており、行番号を見ていない。何をしても「該当なし」を返す空振りである
grep -c -e 'reports.template.html' <spec> の件数突き合わせ実測は6（348・758・3132・3216・3275・3651行）で、計画が書いた「4件」と合わない。しかも更新対象の348・758行を母数に含むため、増減が「触らない側が無傷か」を示さない

正しくは、触らないと決めた4行の原文そのものを固定文字列で1件ずつ確かめる。

cd /home/user/MR-driven-workflow
git fetch origin main
base=$(git merge-base origin/main HEAD)   # 分岐点は実行時に求める（固定SHAを書き写さない）

# 触らないと決めた4行の原文を、分岐点の版から取り出しておく
git show "$base:.claude/docs/spec/issue-mr-workflow.md" \
  | sed -n '3132p;3216p;3275p;3651p' > /tmp/frozen.txt

# 4行とも、現在のファイルに1件ずつ残っていること
while IFS= read -r line; do
  printf '%s -> %s\n' "$(grep -c -F -e "$line" .claude/docs/spec/issue-mr-workflow.md)" "${line:0:40}"
done < /tmp/frozen.txt
  • 合格条件は「4行すべてが 1」である。 0 なら書き換えてしまっている。
  • grep -F で固定文字列として渡す（原文には正規表現のメタ文字が含まれうる）。
  • -e を使う（原文がハイフンで始まる場合に grep: unknown option で落ちるため。.claude/rules/shell-script-style.md）。

負のコントロールを取る。「4行とも1」は、検査が壊れていても同じく出る。

cp .claude/docs/spec/issue-mr-workflow.md /tmp/broken.md
sed -i '3132s/.*/意図的に壊した行/' /tmp/broken.md
# 上のループを /tmp/broken.md に対して流し、1行目だけが 0 になることを確かめる

git diff "$base" --stat -- .claude/docs/ddr/   # 新規1本以外の変更が無いこと

(5) 4テンプレート自身が回帰していないこと

参照側と冒頭コメントを直す計画なので、バイト一致が保たれているかを必ず確かめる（方針3・4で4本の冒頭コメントへ同じ1行を足すため、書き漏らすと一致が壊れる）。

cd .claude/skills/issue-mr-flow/assets
tmp=$(mktemp -d)
for F in reports-clean reports-neobrutal reports-mono reports-paper; do
  sed '/^<style>$/,/^<\/style>$/d' "$F.template.html" > "$tmp/$F.nostyle"
  n=$(wc -l < "$tmp/$F.nostyle")
  [ "$n" -lt 100 ] && { echo "FAIL $F: 抽出が $n 行"; exit 1; }   # 空振りガード
done
md5sum "$tmp"/*.nostyle | awk '{print $1}' | sort -u | wc -l   # 1 なら4本一致

ハッシュの種類数が 1 であることを合格条件にする（行数・バイト数を目で見比べるより確実で、出力も1行で済む）。
