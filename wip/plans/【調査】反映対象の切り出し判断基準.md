# 【調査】反映対象の切り出し判断基準（issue #176・flow-id 2-1）

## 前提（合意状況）

- 上位の計画: `wip/plans/reflection-split-criteria.md`（flow-id 1-4 で作成。**非対話セッションのため
  flow-id 1-5 の人間による合意は経ていない**）。
- issue #176 の本文と、issue #155（PR #175・マージ済み）からの前提変更通知コメント。

## この計画で何をするか

フェーズ3で「切り出し判断」の節を書くために必要な事実を、既存のリポジトリ内ドキュメントから
集める。**基準そのものをこの計画で決めない**（決めるのはフェーズ3）。この調査で埋めるのは、
基準を書くときに参照する既存の記述・数字・記録先である。

**Q4 は「フェーズ3で検討する主判定の候補」を過去事例へ当てる妥当性検証だが、その候補の文言を
この計画では確定させない。** 候補一覧そのものがフェーズ3の成果物であり、ここで文言を固定すると
フェーズ3が「Q4 で確かめた基準」として自分の書いた文言を追認することになる。

## 調べ方

- **ドキュメントを探す問いは `doc-search`（frontmatterインデックス）を先に使う**
  （`AGENTS.md` のルール）。本文中の特定の語（「別issue」「切り出し」等）を探すときだけ
  `grep`/`rg` を使う。
- Q2・Q5 は該当ファイルを直接読む（`references/planning.md`・`SKILL.md`）。
- **Q4 の母数は「機械的に洗い出した集合」とする。** issue本文が挙げる3件をそのまま使わない
  （うち `i0014-01` は「別issueの規模」を理由とした見送りではないことを上位計画で確認済み）。
  `grep -rln -- '別issue' .claude/docs/ddr/` で候補を出し、各本文で**見送りの理由が規模か
  価値か**を読み分けてから母数を確定する。
- Q4 で **DDR を証拠に使うときは `status` を確認する**（後続のDDRに置き換えられた決定を現役の
  根拠として引かないため。`.claude/rules/markdown-frontmatter.md`「DDRのstatus」）。

## やらないこと（スコープ外）

- **基準の文面を書くこと**。フェーズ3（flow-id 3-1 以降）で行う。**主判定の候補を挙げることも
  含む**（この計画で候補を固定すると、Q4 の妥当性検証が自己追認になる）。
- **MRのレビュー往復まで遡って過去の切り出し判断を集めること**。理由は**この調査自身のコスト
  判断**である（探索コストが件数に比例して増える一方、Q4 に必要な「判断とその理由」は決定として
  書き起こされたDDRに残っている）。**`references/planning.md`「手順1」の『過去のMRを遡らない』を
  根拠にしない**——あちらは flow-id 4-1 でAIアセット反映の対象を洗い出すときに固有の規則であり、
  フェーズ2の調査一般には適用されない。**この除外によって母数に偏りが入る**（レビュー往復で
  下された判断は拾えず、DDRとして書き起こされた分だけが見える）ことを、結果へ明記する。
- **`.claude/scripts/` の実装調査**。今回の成果物は判断基準であって機械化ではない。

## 検証（この調査が完了したと言える条件）

```bash
# Q5 の実数（全体フロー表の行数）。references/planning.md:224 の記述と一致するか
grep -cE '^\| [0-9]+-[0-9]+ \|' .claude/skills/issue-mr-flow/SKILL.md

# Q5 の複製箇所の洗い出し
grep -rn -- '5フェーズ' .claude/skills .claude/rules .claude/docs/spec .claude/docs/usecase

# Q4 の母数の候補
grep -rln -- '別issue' .claude/docs/ddr/

# Q4 の DDR の status 確認（superseded を現役の根拠に使わない）
#   --format jsonl の1レコードは concept_id / directory / frontmatter / mtime の形で、
#   status も title も frontmatter の下にある（トップレベルの .status は常に null）
bash .claude/scripts/src/search-frontmatter.sh --type ddr --format jsonl \
  | jq -r 'select(.frontmatter.status) | [.concept_id, .frontmatter.status] | @tsv'
```

**最後の1本は、superseded のDDRが2件（`i0000-06` / `i0000-13`）出ることを確かめてから使う。**
0件しか返らないなら、フィルタが実データに合っていない（＝ガードとして機能していない）。

合格条件:

- 6問すべてに、**根拠となるファイルパス・行の引用つきで**答えが書けている。
- Q4 で、母数の取り方（何件をどう選んだか）と、候補が過去事例と食い違う件がある場合はその
  件数と原因が書けている。**食い違いゼロを目標にしない**（基準の限界が分かることも成果）。
- 結果は `wip/reports/2026-08-23_reflection-split-criteria_調査結果.md`（＋同名 `.html`）へ書く。
  **この個別調査計画には結果を書かない**（`references/deliverables.md`「計画と実施結果の分離」）。
