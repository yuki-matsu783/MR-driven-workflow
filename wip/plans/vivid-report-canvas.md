# 全体作業計画 — HTMLレポートをもっとビジュアル的にわかりやすい形にする（issue #186）

- issue: #186
- ブランチ: `claude/html-report-visual-improvement-chu89d`
- PR: #191（Draft）
- 実行環境: Claude Code on the web（非対話セッション）。人間のレビュー往復が成立しないため、
  各フェーズの計画時と作業実施後に敵対的レビュー（`adversarial-review` スキル）を1回ずつ自動起動し、
  指摘への修正・返信を行いながら進める（ユーザー指示による）。

## 目的（何を作る・変えるか）

`.claude/skills/issue-mr-flow/assets/reports.template.html` を、レビュアーが限られた時間で
重要な箇所へ集中できるフォーマットへ改修する。具体的には次の4点。

1. **サマリの視覚化**: 結論を性質（良かった＝青／気になる＝黄／悪かった＝赤）で色分けし、
   短いポイント＋該当章へのアンカーリンクを持つ形にする。
2. **重点レビュー依頼の新設**: レポート冒頭に「特に見てほしい（判断に困っている）／承認が欲しい
   （方針は決めた）／細かいレビューは不要（ほぼ確実）」の3段階を明示する節を置く。
3. **「確かめられなかったこと」の前半移動**: 前半では一覧として示し、詳細は各章で語る構成にする。
4. **書き手への伝承**: 色・記号の使い分けと節の並び順を、テンプレート内コメントとして
   次の書き手（AI）へ伝わる形で記述する。

issueに書かれたこと以外でも、より良い表現（例: 各章見出しへのレビュー重みバッジ、サマリの
件数チップ、アンカー移動時の位置ずれ防止）があれば採用してよい（ユーザー指示）。

## フェーズ2〈調査〉

実施する。調べる問いは次のとおり。

1. テンプレートの節構成・運用に言及するドキュメントはどこにあるか（変更時に矛盾が生じる箇所の
   全列挙）。`references/deliverables.md`「計画・レポートのHTMLビュー」、`.claude/rules/docs-workflow.md`、
   `reports/REVIEW-POINTS.md`、spec/DDR、hook等を横断確認する。
2. 現テンプレートの構造（必須／任意節・スタイルトークン・ダークモード対応）はどうなっているか。
   何を残し何を変えるべきか。
3. 色の設計判断: 「良かった＝青」の指定と既存の `--ok`（緑系）の関係をどう整理するか。
   ダークモード・アクセシビリティ（色だけに依存しない記号併用）をどう担保するか。
4. 「フェーズごとの読み替え」（統括5-4等での節の意味変化）は新構成でどう引き継ぐか。

分かれば次へ進める基準: フェーズ3で作る新テンプレートの節順・色トークン・コメント方針が
一意に決まること。

## やらないこと（スコープ外）

- `plans.template.html`（計画側テンプレート）の同等改修。issue #186 はレポート側のみを対象と
  している（計画側は結論・レビュー重みという概念が薄く、同じ問題が確認されていない）。
  必要なら別issueとする。
- `canvas-report`（canvas形式テンプレート）の改修。関連・依存関係が主題のレポート向けで、
  本issueの対象外。
- 既存レポートmdの見出し構成の規定（md側テンプレートは無い、という現行方針は変えない）。
