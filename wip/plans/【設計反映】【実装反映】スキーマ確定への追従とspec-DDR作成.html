変更対象と作業項目

1.【実装反映】スキーマ確定への追従

  • 入力検証（jq）: cover のみ title 任意／two-column は columns（長さ2・各要素は heading＋items 1件以上）／table は columns（1件以上）＋rows（各行は配列）／comparison は sides（2〜3件・各要素は name＋points 1件以上）／diagram は nodes（2件以上・各要素は label を持つオブジェクト）／bullets・summary は items（1件以上）。違反はキー名を挙げた明示エラー。
  • 写像（レコード形式と受け側 json-to-pptx.sh の対応を対で定める。jq冒頭のレコード種別コメントも更新）: cover は title/subtitle のmetaフォールバック（jq側で解決・SUB行構成は維持）。section は chapter を見出し上の小さめ段落（新レコード CHAP。受け側は CUR_CHAP バッファ新設＋reset_slide_buffers 追加＋flush_slide の section 分岐で描画）。two-column は heading（太字段落。新レコード COLH<US>L|R<US>テキスト。columns[0]→L・columns[1]→R 固定）＋items。comparison は表（1行目=name（tone があれば「（採用寄り）（却下寄り）（中立）」後置）、データ行=points の転置・不足セル空埋め。既存TROWを流用）。diagram は label の「 → 」連結1段落＋「label: note」行を箇条書き記号の付かない新レコード PARA で出す（BUL流用だと「•」が付き不自然なため。edges/caption 処理・.id フォールバック・文字列ノード対応は削除）。summary は items の後に takeaway を太字段落。comparison の別名（.label 等）は sides への全面置換で自然に消える。
  • 条件7突合の対象外リストへ slides[].sides[].tone を追加（5つへ）。tone は見た目の色分け指示子で本文でなく、値そのもの（pro/con/neutral）は日本語注記へ写像され本文へ現れないため（slides[].type と同じ扱い）。
  • SKILL.md: 必須キー表・型別表現表を確定スキーマの語彙へ書き換え。
  • 単体テスト: サンプルJSONをスキーマ適合形へ書き換え（8種type・chapter・tone・takeaway・note を含む）。cover は2枚置く: 1枚目は title/subtitle 省略でmetaフォールバック、2枚目は自前の title/subtitle で上書き側を検証（meta.title／meta.subtitle は1枚目に現れるため条件7の突合対象のままで通るサンプル設計）。meta.issue の integer 化に伴い verify_pptx.py の issue 参照を norm(str(...)) 相当へ修正（文字列前提の .replace が AttributeError になるため）。個別アサーション追加: tone注記3種が生成物に現れること・cover省略側に meta.title/meta.subtitle が現れること。境界値テストを新語彙へ追従。既存テストの扱い——維持: jq途中失敗・制御文字・改行入りmeta.title／書き換え: 不揃いな表（headers→columns）・空headers・空options・options要素型（文言ごと columns/sides へ）／削除: edges要素型・入れ子bullets（スキーマが持たず検証・分岐ごと削除するため。理由を結果レポートへ残す）。スキーマ適合の機械検証は jq による決定的チェックをテストへ組み込む（jsonschema はこの環境に無いことを実測済み。required／余剰キー／型／minItems・maxItems／enum を検査。目視は完了条件に置かない）。

背景・目的／仕様／影響範囲／設定項目／未決定事項・懸念点の型。内容: 入力仕様（確定スキーマとの対応表）／type別写像／rId採番規則・連動5箇所／zip経路試行／自己検証の範囲／jq終了コードの検知／制御文字の空白化／表の列数決定／条件7突合の手順（対象外5つ。meta.issue は integer のため文字列の葉として現れず対象外指定が実質効かない点も明記）／PowerPoint製雛形への差し替え前処理条件／実機確認の依頼事項。新規spec作成の人間承認は得られないため◆としてPRレビューへ依頼し、HANDOFFの未解決事項へ含める。
