# 【調査】Gemini CLI の読み込み経路と .gemini/ の自立性

issue #172（スコープ拡大後）／PR #193／フェーズ2〈調査〉の**2回目**。
全体作業計画は `wip/plans/mellow-drifting-lantern.md`「スコープ拡大後の追加の問い」。

## この計画で何をするか

**Q7〜Q11 に答える。** 目的は「`.gemini/` を自立させるか、`.claude/` への依存を明示するか」を
フェーズ3で決めるための材料を揃えることであり、**この計画では決めない・実装しない**。

## 1回目の調査から引き継ぐこと

**Q1〜Q6 は実施済み**（`wip/reports/20260823_mellow-drifting-lantern_gemini生成対象の参照実態.md`）。
再測定しない。ただし**次の1件は訂正済みとして扱う**。

- フェーズ3レポートの結論5-2「軸1の0件根拠は `.gemini/rules/` `.gemini/skills/` にも
  同じ強さで当たる」は**誤り**。`.gemini/skills/` は Gemini CLI が読む。

## 前提として確定していること

| # | 事実 | 出典 |
|---|---|---|
| A | `.claude/` 単体は動く（`.gemini/` を実行時に必要としない） | 実測（スコープ拡大時） |
| B | `.gemini/` 単体は動かない（hook 6本・GEMINI.mdのimport・agentsのsource がすべて `.claude/` を指す） | 同上 |
| C | Gemini CLI が読むのは `settings.json` `skills/` `agents/` `commands/*.toml` `sandbox-*` | 公式ドキュメント |
| D | `rules/` `docs/` `hooks/` `scripts/` は公式ドキュメントに記載が無い | 同上 |
| E | `.gemini/skills/` 内の `.claude/…` 参照は366件、`.gemini/agents/` 内は8件 | 実測 |
| F | `.gemini` は `dist-layers.json` で `layer: exclude`（配られず、配布先で生成される） | 実測（1回目） |
| G | Gemini CLI 実機はこの実行環境に無い | 既知（spec の未決定事項） |

**Gは調査手段の制約であり、この調査でも解消しない。** すべての結論に
「公式ドキュメントの読解であって実機の観測ではない」を併記する。

## 調べること

### Q7: Gemini CLI の読み込み経路（ドキュメントの精読）

- `skills/` の探索規則・優先順位・**SKILL.md の形式要件**（必須 frontmatter キー）
- `agents/` の探索規則・**ファイル形式の要件**
- **`.agents/skills/` エイリアス**: 探索されるか／`.gemini/skills/` との優先順位／
  Claude Code 側も同じパスを見るか（**見ないなら第3の道は成立しない**ので、ここは要確認）
- `context.fileName` で `AGENTS.md` を読ませられるか（`GEMINI.md` を介さない経路の有無）
- **答え方**: 該当ドキュメントのパスと引用を添える。「たぶんそう」は書かない。

### Q8: 現在の `.gemini/skills/` `.gemini/agents/` はそのまま使えるか

- 9つの `SKILL.md` の frontmatter が、Agent Skills 標準の必須キーを満たすか（**件数で**）
- `agents/*.md` 2本が Gemini CLI の localAgentSchema を満たすか
- 満たさない場合、`sync-gemini-assets.sh` の変換で埋まるか、追加の変換が要るか

### Q9: 自立させる場合に必要な変更の全量

- 374件の内訳を**書き換えてよいもの／いけないもの**へ分類する。分類の軸は次の4つ。
  1. **実行パス**（`bash .claude/scripts/…`・`source …`）— 書き換え対象
  2. **ドキュメント参照**（`.claude/docs/spec/…` へのリンク）— 書き換え対象（ただし
     リンク先が `.gemini/` にも複製されている場合に限る）
  3. **事実の記述**（`git ls-files -- .claude`・`.claude/VERSION`・生成の仕組みの説明）
     — **書き換えると嘘になる**
  4. **編集先の指示**（「編集は常に `.claude/` 側へ行い」）— **書き換えると有害**
- **各分類の件数を出す。** 分類が機械的に判定できるか（できないなら自立化の実装コストは
  「374件の一括置換」では済まない）も答える。
- hooks の実体・scripts の実体・rules の import 元をどうする必要があるか。
- **DDR本文・過去changelog の一括置換は `.claude/rules/docs-workflow.md` が禁止している。**
  `.gemini/docs/ddr/` が対象に含まれるかを確認する（含まれるなら自立化と既存ルールが衝突する）。

### Q10: 依存を明示する場合に必要な変更

- 「Gemini CLI 利用時も `.claude/` は必須」をどこへ書くか（spec・README・`.gemini/` 側の
  案内ファイル）。**候補と、それぞれが読まれる経路**を出す。
- 読まれない複製（`rules/` `docs/` `hooks/` `scripts/`）をやめると何が壊れるか。
  **Q3・Q4 の実測値をそのまま使う**（再測定しない）。
- `.gemini/` に残るのが `settings.json` `skills/` `agents/` だけになった場合の
  ファイル数・バイト数（1回目の実測から算出）。

### Q11: 配布への影響

- `install-to-project.sh` 手順7・`dist-layers.json` は2つの方向それぞれでどう変わるか。
- **配布先が片方のCLIしか使わない場合の手順**が成立するか。
  - Claude Code のみ: `.gemini/` を生成しない選択肢はあるか
  - Gemini CLI のみ: `.claude/` を消せるか（自立化しない限り消せないはず。**確認する**）
