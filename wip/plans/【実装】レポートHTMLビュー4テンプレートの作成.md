### 3. 色と記号の意味論（issue #186。変えない）

- 結論の性質は**3色＋記号＋文字**（◎良=青／△注意=黄／✕問題=赤）。色だけに意味を持たせない。
- 緑（`--ok` / `.box.ok`）は**決めたこと・手順の成功専用**。結論の性質には使わない。
- 重点レビュー依頼の3段階（◆◇・）は**色相を使わない**。
- **案12だけは `.box.ok` に色を与えず、太い左罫＋「決定」ラベルで表す**（Q7。12は緑系を持たない。
  12の「色が見えたら結論の性質」という方針とはむしろ整合する）。
  **このラベルはCSSの `::after` で足し、HTML本文は他の3本と1バイトも変えない**

### 6. 検査（5種。**3種→5種へ増やす**）

**プレースホルダ検査は、対象によって合格条件が逆になる。** 表を分けて書く
（同じ検査に相反する条件を書かないため。敵対的レビュー2回目の指摘）。

| 検査 | 対象 | 合格条件 |
|---|---|---|
| プレースホルダ | **テンプレート自身**（雛形） | **非0**。かつ**4本で件数が同一**（下記） |
| プレースホルダ | **テンプレートから作った成果物** | **0** |

現行テンプレートは、この取り違えを避けるために冒頭コメントで
「確認: `grep -c '<!-- ここに書く' <出力ファイル>` が 0 であること」と**対象を明示している**。
新テンプレートでもこの明示を保つ（受け入れ条件(3)の実質はここにある）。

| 検査 | 合格条件 |
|---|---|
| リンク破断 | `comm -23`（href集合 − id集合）が0行 |
| 重複ID | `sort \| uniq -d` が出力なし |
| **外部依存1** | `grep -nE "(src\|href)=['\"]?(https?:)?//"` |
| **外部依存2** | `grep -nE "(url\(\|@import[[:space:]]+)['\"]?(https?:)?//"` |

**外部依存検査は0件を機械的な合格条件にしない。** エスケープ済みの地の文（`<code>` 内の引用等）
にも当たるため、ヒットしたら中身を見て判断する——この注意を使い方コメントへ書く
（現行がプレースホルダ検査について書いている注意と同じ性質）。

## 検証

**「出力が無ければ合格」の検査は、そのままでは何も証明しない。** 検査コマンド自体が壊れていても
同じく無出力になるためである（フェーズ2 Q4で実際に空振りしていた）。以下では
(a) 空振りガード（拾えている件数を先に出す）と (b) 負のコントロール（意図的に壊して検出できることを
確かめる）を、検査そのものと同じ手順の中に置く。

### (1) 5種の検査

**プレースホルダ検査の合格条件は、テンプレート本体と成果物で逆になる。** テンプレートは
埋める前の雛形なので「意図した数だけ存在する」ことを見る（0件なら、むしろプレースホルダを
書き忘れている）。

```bash
cd .claude/skills/issue-mr-flow/assets
for F in reports-clean reports-neobrutal reports-mono reports-paper; do
  f="$F.template.html"
  echo "--- $f ---"

  # 1. プレースホルダ: テンプレートなので0ではなく「存在する」ことを見る（4本で同数が期待）
  grep -c '<!-- ここに書く' "$f"

  # 2〜3. 空振りガード: href/id を1件も拾えていないなら検査が壊れている
  hrefs=$(grep -oE 'href="#[A-Za-z0-9_-]+"' "$f" | sed 's/^href="#//;s/"$//' | sort -u)
  ids=$(grep -oE '<[a-z][^>]*[[:space:]]id="[A-Za-z0-9_-]+"' "$f" | sed 's/.*id="//;s/"$//' | sort)
  printf '拾えたhref=%s id=%s\n' "$(printf '%s\n' "$hrefs" | grep -c .)" "$(printf '%s\n' "$ids" | grep -c .)"

  # 2. リンク破断（0行が合格）
  comm -23 <(printf '%s\n' "$hrefs") <(printf '%s\n' "$ids" | sort -u)
  # 3. 重複ID（出力なしが合格）
  printf '%s\n' "$ids" | uniq -d

  # 4〜5. 外部依存（ヒットしたら中身を見る。0を機械的な合格条件にしない）
  grep -nE "(src|href)=['\"]?(https?:)?//" "$f"
  grep -nE "(url\(|@import[[:space:]]+)['\"]?(https?:)?//" "$f"
done
```

**外部依存検査の「0件」を合格条件に固定しない。** 冒頭コメントの地の文がCDNの例
（`&lt;script src="https://…"&gt;`）に言及するとヒットする。**ヒットしたら中身を見て、
実際の読み込みか地の文かを判断する**（フェーズ2で実際にこの誤検知を踏んだ）。

### (2) 負のコントロール（検査が本当に働くことの確認）

**1本（clean）のコピーを意図的に壊し、検査が反応することを確かめる。** 反応しなければ、
上の「出力なし」は検査が壊れている可能性がある。

```bash
tmp=$(mktemp -d)
cp reports-clean.template.html "$tmp/broken.html"
# 存在しないIDへのリンクを作る → リンク破断検査が f99 を出すはず
sed -i 's|href="#f1"|href="#f99"|' "$tmp/broken.html"
# 既存IDと重複させる → 重複ID検査が overview を出し、同時に f1 のリンクが破断するはず
sed -i 's|<h3 id="f1">|<h3 id="overview">|' "$tmp/broken.html"
```

**期待する結果**（フェーズ2 Q4で確認済みの性質）:

| 壊し方 | リンク破断 | 重複ID |
|---|---|---|
| `href="#f1"` → `#f99` | `f99` を出す | 反応しない |
| `<h3 id="f1">` → `id="overview"` | `f1` を出す | `overview` を出す |

後者の1操作で**両方が反応する**ことが、2つの検査を持つ理由をそのまま示す。

### (3) 4本のDOM共通性（この計画の中心的な主張）

**タグ名の並びの比較では弱い。** 属性・テキストの違いを一切見ないため、
「タグ構成は同じだが中身が違う」状態を見逃す。**`<style>` ブロックを除いた残り全体を
バイト単位で比較する。**

```bash
cd .claude/skills/issue-mr-flow/assets
tmp=$(mktemp -d)
for F in reports-clean reports-neobrutal reports-mono reports-paper; do
  sed '/^<style>$/,/^<\/style>$/d' "$F.template.html" > "$tmp/$F.nostyle"
  n=$(wc -l < "$tmp/$F.nostyle")
  # 空振りガード: <style> の除去が効きすぎて中身が消えていないか
  [ "$n" -lt 100 ] && { echo "FAIL $F: 抽出が $n 行"; exit 1; }
done
# 基準を clean に固定し、残り3本と総当たりで比較する（3組すべて0行が合格）
for v in reports-neobrutal reports-mono reports-paper; do
  echo "--- clean vs $v ---"
  diff "$tmp/reports-clean.nostyle" "$tmp/$v.nostyle"
done
```

**この形にするために、デザイン固有の説明文は冒頭コメントではなく `<style>` の先頭の
CSSコメントへ置く**（方針5）。冒頭コメントに置くと、そこだけが4本で異なりバイト比較が使えない。

### 合格条件

- 5種の検査が上の基準を満たす（外部依存はヒット0件、またはヒットの中身が地の文の引用だと確認済み）
- **負のコントロールで、リンク破断・重複IDの両検査が期待どおり反応する**
- **`<style>` を除いた残り全体が、clean と残り3本の3組すべてでバイト単位で一致する**（差分0行）
- 4本すべてに、現行と同等の冒頭コメント（使い方・節順・意味論・検査手順・フェーズ読み替え）がある
- **表の8節がすべて存在し、任意の3節には `[任意]` の印がある**（必須5節・任意3節。方針1の表）
- プレースホルダ件数が4本で同数である（DOMと使い方コメントを共有できている傍証）

### ブラウザでの実表示は、この計画では確認しない

**明示してスコープ外にする**（無言で落とさない）。次の6項目はいずれも静的検査では確かめられない。

| 未確認になる項目 | 対象 |
|---|---|
| `position: sticky` のサイドバーが実際に追従するか | 4本すべて |
| `prefers-color-scheme` の切り替えが破綻しないか | clean / mono |
| `color-scheme: light` が強制ダーク化を防ぐか | neobrutal / paper |
| ハードシャドウ（`box-shadow: 3px 3px 0`）の見え方 | neobrutal |
