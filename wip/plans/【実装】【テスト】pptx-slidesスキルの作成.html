目的

作業項目

1.【実装】雛形 assets/pptx-template/（展開ディレクトリ）

静的パーツ7ファイル（_rels/.rels・docProps/core.xml・slideMaster+rels・slideLayout+rels・theme）を .claude/skills/pptx-slides/assets/pptx-template/ へ置く。生成スクリプトが丸ごと所有するパーツ（Content_Types・presentation.xml・presentation.xml.rels・app.xml・ppt/slides/**）は雛形に含めない（調査レポートQ3の連動5箇所＋rId採番規則）。スライドサイズは16:9（12192000×6858000）。テーマは調査で機械検証済みのフルセット（clrScheme・fontScheme・fmtScheme）を使う。

2.【実装】生成スクリプト scripts/json-to-pptx.sh

処理順: (1) 入力検証（jq empty でのJSON構文検査→不正JSONはパスとjqのエラー付き明示エラー／必須キー検査／speakerNotes入りなら件数付き警告）→ (2) mktemp -d の作業ディレクトリへ雛形をコピー（Git管理下の実体に触れない。trap ... EXIT で正常・異常とも後始末）→ (3) slideN.xml 生成（type別写像）→ (4) 連動5箇所の生成（rId1/rId2予約・スライドはrId3から連番）→ (5) zip梱包の経路試行: 経路1 zip -X -D -r→自己検証、失敗なら出力を削除して経路2へ（python3→python→py -3 の import zipfile 成否で候補選択）→自己検証。全経路失敗（または使える経路なし）で明示エラー・非0終了、出力は残さない（途中経路の失敗=フォールバック、全経路の失敗=非0終了、を混同しない）。

  • CLI: bash json-to-pptx.sh <入力.json> [出力.pptx]。省略時は入力と同じディレクトリの <ベース名>.pptx（入力名が <ベース名>.slides.json なら .slides も落とす。拡張子なしは <入力名>.pptx）。既存出力は上書き。出力先がディレクトリ・親不在は明示エラー。
  • XMLエスケープ5種（& < > " '）は自前の純粋関数（単体テスト対象）。テキスト中の改行は段落分割で表現。
  • プレースホルダ置換はbashのパラメータ展開で行い、sed/awk を使わない（& の再解釈の罠。エスケープ済み値は必ず & を含みうる）。
  • metaの写像: meta.subtitle・meta.date・meta.author は cover スライドのサブタイトル行群として <a:t> へ出す（author は dc:creator へも併記）。meta.title→dc:title のみ、meta.issue→cp:keywords（いずれもdocProps行き）。
  • 条件7突合の対象外リスト = meta.title・meta.issue・speakerNotes の3つ（写像から機械的に決まる。この分だけ条件7の担保範囲は狭まる）。
  • 経路間の一致条件はエントリ集合の一致＋先頭が [Content_Types].xml＋ディレクトリエントリ0件（順序全体は比較しない。先頭はスクリプトが明示制御）。
  • シェル規約（shell-script-style.md）遵守: set -euo pipefail・jq呼び出しの集約・BOM無しUTF-8/LF・大きなJSONはファイルパス渡し。
