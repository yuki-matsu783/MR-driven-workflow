目的

構成案JSON（issue #168 / PR #194 と同じ入力）から、テキスト・表が編集可能な .pptx を生成するスキル一式を作成する。結果は本ファイルへは書かず wip/reports/2026-08-23_json-to-pptx-export-plan_実装.md（+同名.html）へ記録する。

作業項目

1.【実装】雛形 assets/pptx-template/（展開ディレクトリ）

静的パーツ7ファイル（_rels/.rels・docProps/core.xml・slideMaster+rels・slideLayout+rels・theme）を .claude/skills/pptx-slides/assets/pptx-template/ へ置く。生成スクリプトが丸ごと所有するパーツ（Content_Types・presentation.xml・presentation.xml.rels・app.xml・ppt/slides/**）は雛形に含めない（調査レポートQ3の連動5箇所＋rId採番規則）。スライドサイズは16:9（12192000×6858000）。

2.【実装】生成スクリプト scripts/json-to-pptx.sh

構造: 入力検証（jq必須キー検査・違反はキー名を挙げて明示エラー）→ slideN.xml 生成（type別写像）→ 連動5箇所の生成（rId1/rId2予約・スライドはrId3から連番）→ zip梱包（能力ベース検出: zip -X -D -r → python3/python/py -3 の import zipfile 成否 → 明示エラー）→ 自己検証（失敗したら出力を削除して非0終了）。

  • CLI: bash json-to-pptx.sh <入力.json> [出力.pptx]。省略時は入力と同じディレクトリの <ベース名>.pptx。
  • XMLエスケープ5種（& < > " '）は自前の純粋関数（単体テスト対象）。テキスト中の改行は段落分割で表現。
  • metaの写像: title→dc:title、author→dc:creator、date→coverのサブタイトル行、issue→cp:keywords（docProps行き）。core.xmlは固定トークンのプレースホルダ置換。
  • シェル規約（shell-script-style.md）遵守: set -euo pipefail・jq呼び出しの集約・BOM無しUTF-8/LF・大きなJSONはファイルパス渡し。

3. SKILL.md

.claude/skills/pptx-slides/SKILL.md。入力・実行方法・出力・speakerNotesは出力されない旨・制約（PowerPoint実機確認の依頼・Windows git bashでの検出経路）・PR #194 スキーマ確定時の突合への参照。

4.【テスト】単体テスト test_json_to_pptx.sh

  • 正常系: 8種type全部入り・スライド3枚以上のサンプルJSONで生成し、機械検証10種（検証8種＋a:tbl存在＋条件7突合=葉テキスト値ごとの部分一致、対象外= meta.issue・speakerNotes）を検査。
  • 異常系: type不正／必須キー欠落／空slides／入力ファイル無し／zip・python3両不在の明示エラー（PATHスタブ）／生成失敗時に出力ファイルが残らないこと。
  • 純粋関数: XMLエスケープ（5種・改行・日本語）。python3経路はzipをPATHから隠して縮退を確認。
  • 規約: passed=N failures=N 出力・失敗時終了コード1。置き場所は .claude/scripts/test/。
