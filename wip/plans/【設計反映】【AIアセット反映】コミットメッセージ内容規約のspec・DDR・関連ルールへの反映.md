# 【設計反映】【AIアセット反映】コミットメッセージ内容規約のspec・DDR・関連ルールへの反映

**種別を2つ併記した理由**: 反映先が `.claude/docs/`（設計文書）と `.claude/rules/` `.claude/skills/`
（AIアセット）にまたがるが、**どちらも同じ1つの決定（コミットメッセージ内容規約）を各所へ行き渡らせる
作業**であり、合意を分けて取る意味が無いため（`references/planning.md`「種別を複数併記する場合」）。

## この計画で何をするか

フェーズ3で `commit/SKILL.md` へ新設した内容規約を、**恒久的に残る場所**（DDR・spec・rules）へ
反映し、参照関係の食い違いを無くす。`wip/plans/` `wip/worklogs/` `wip/reports/` はflow-id 5-5で
削除されるため、それらにしか無い判断は失われる。

## やること

| # | 対象 | 何をするか |
|---|---|---|
| 1 | `.claude/docs/ddr/i0185-01-….md`（新規） | **本文を許容する判断**と却下案、**判定を2段階にした経緯**、**現行規約が既に6回破られていた事実**、**git bash実機では未計測**であることを記録する |
| 2 | `.claude/docs/spec/create-commit.md` | `## 影響範囲` へ issue #185 のエントリを追加する（`--message` の記述変更と、実装を変更していない事実） |

| 4 | `.claude/skills/resolve-conflict/SKILL.md:376` | 「『何を』『どう』解消したかを書く」を**新設節の具体化として位置づける**参照を張る |

## 決めること

### 決定A: DDR `i0185-01` に何を書くか

**1件（枝番01）にまとめる。** 「1行のみを維持するか本文を許容するか」（受け入れ条件2）と
「判定を2段階にした」は、**同じ「規約をどう書くか」という1つの決定の表と裏**であり、分けると
どちらのDDRを読んでも片方が欠ける。

書く内容（案）:

| 節 | 内容 |
|---|---|
| 決定 | 件名1行を必須、**本文は任意で許容**。追跡用フッター（`Refs #NNN`）も許容 |
| 背景 | `main` の1行ログに出るのは**PRタイトル**であり、個別の件名は squash 本文の `* 件名` として残る（実測） |
| 却下案1 | **1行のみを維持する** — 却下。現行規約は**既に破られており**、本文6件・`Refs` フッター6件がマージ済み。守られていない規約を維持しても実態が変わらない |
| 却下案2 | **本文を必須にする** — 却下。事務的な作業記録（母数の15%）にまで本文を強いると、書く手間に見合わない |
| 却下案3 | **6語で終わる件名を一律に不合格とする** — 却下。**規約自身の模範例4件を不合格にする**自己矛盾を起こした。判定と合否を同一視したのが原因 |
| 未計測 | **git bash（Windows）実機での複数行メッセージは未計測**。Linux実機でのみ確認している |

### 決定B: `.claude/VERSION` をどこまで上げるか

**`0.3.0` → `0.4.0`（MINOR）とする案。** 判断根拠は
`.claude/docs/spec/distribution-assets.md` の更新規則に従う（**着手前に読み直して確認する**）。

- 既存の呼び出し方（`create-commit.sh --message`）は変わらず、**配布先の既存コミットが壊れることは無い**
  → MAJOR ではない。
- **規約が増え、AIエージェントの振る舞いが変わる**（本文を書くようになる）→ PATCH では小さすぎる。

### 決定C: 4・5の参照をどちらの向きで張るか

新設節の冒頭には既に「本節が正であり、他スキルの記述はその場面への具体化である」と書いた
（フェーズ3、敵対的レビュー4回目の指摘への対応）。**これで片方向は張れている。**

- **案C-1（採用予定）**: 呼ばれる側（`resolve-conflict` / `issue-mr-flow`）からも1行で参照を張り、
  **双方向**にする。片方向だと、`resolve-conflict/SKILL.md` だけを読んだAIが新設節の存在を知らない。
- 案C-2: 片方向のままにする。追記行が増えないが、上記の見落としが残る。

## やらないこと

- **過去コミットの書き換え**（上位計画のスコープ外）。
- **`commit/SKILL.md` の `## 備考` 以下の孤立ブロックの修正**。本issueの受け入れ条件のどれにも
  該当しないため、**別issueへの切り出しを提案する**方針を維持する（無言で削除しない）。
- **prefix一覧の見直し**（スコープ外）。実例#6でprefixの誤りを1件直したが、これは既存規約の
  適用漏れであって、prefix一覧そのものは変えていない。

## 検証

| # | 検証項目 | 合格条件 |
|---|---|---|
| 1 | DDRの識別子がフォーマットに沿うか | ファイル名 `i0185-01-<タイトル>.md`、frontmatter `title: i0185-01. <タイトル>`、本文見出し `# i0185-01. <タイトル>` の3箇所が一致 |
| 2 | DDR一覧が再生成されているか | `generate-ddr-list.sh` 実行後の `git diff .claude/docs/README.md` に `i0185-01` の行が現れる |
| 3 | 参照切れが無いか | `check-doc-references.sh` の終了コードが0 |
| 4 | 4・5の参照が新設節を指しているか | 両ファイルに `commit/SKILL.md` と「コミットメッセージの内容規約」を含む行がある |
| 5 | VERSIONが上がっているか | `.claude/VERSION` が `0.4.0` |
| 6 | 却下案が3件そろっているか | DDRに「1行のみ維持」「本文必須」「6語一律」の3案がある |
| 7 | 未計測の明記 | DDRに「git bash実機では未計測」が含まれる |
| 8 | specの影響範囲 | `create-commit.md` の `## 影響範囲` に `### issue #185` の節がある |

## この計画の後

flow-id 4-2でcommit・push、続けて**敵対的レビュー5回目**（フェーズ4の計画に対して。実施回数 0/3）を
実施する。
