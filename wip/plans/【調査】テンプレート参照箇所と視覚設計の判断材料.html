前提（合意状況）

この計画で何をするか

次の4つの問いに答える。

Q1. テンプレートの節構成・運用に言及するドキュメントはどこにあるか

  • 対象は「変更対象（調査で読む範囲）」のとおり。
  • 方法: doc-search（frontmatterインデックス）を第一手段とし、本文中の固有文字列は grep で補完する（検索語は「検証」のコマンドに固定する）。
  • 判定: 各箇所を「節構成が変わると矛盾するか（＝フェーズ3で直す対象か）」で仕分けし、全件を「直す／直さない（理由付き）」の表としてreports側に残す。
  • .gemini/ 配下は列挙はするが直す対象ではない（変換生成物で直接編集禁止。flow-id 5-3 の sync-gemini-assets.sh 再生成で追随する側）。この扱いを調査結果にも明記する。

Q2. 現テンプレートの構造のうち、何を残し何を変えるか

  • 対象: 必須／任意節・スタイルトークン・「フェーズごとの読み替え」コメント・プレースホルダ検査手順。
  • 判定: issue #186 の期待する動作と突き合わせ、節ごとに「維持／移動／改修／新設」を決める。
  • 受け入れ条件のうち現テンプレートで既に部分的に満たされている項目（例: サマリ節の「各行から本文の該当節へリンクする」コメント指示）を洗い出し、新設指示と二重化しない形を決める。
  • 章IDの命名規則とアンカー設計: 既存の節ID（#summary 等）との整合、結論→章リンクのID命名規則、アンカー移動時の位置ずれ対策（scroll-margin-top 等）の要否。

Q3. 色の設計をどうするか

  • 「良かった＝青系統」の指定と、既存 --ok（緑系）・アクセント色（青）との衝突の整理。
  • ダークモード（prefers-color-scheme）対応を維持したまま色を増やす方法。
  • 色だけに依存しない表現（記号・ラベル併用。色覚多様性への配慮）。

Q4. 「フェーズごとの読み替え」を新構成へどう引き継ぐか

  • 「確かめられなかったこと」前半移動後の統括レポート（5-4）での扱い。
  • 「設計への反映」節の位置と反映結果レポート（4-6）での読み替え。
  • 新設「重点レビュー依頼」が全フェーズで意味が通るか。

変更対象（調査で読む範囲）

このフェーズではファイルを変更しない（読むだけ）。読む範囲は次のとおり。

範囲読み方
.claude/ 配下のrules・skills（references・assets含む）・docs（spec/ddr/usecase）・hooks「検証」の検索コマンドでヒットした箇所を精読
各 REVIEW-POINTS.md（ルート・.claude/・plans/・reports/）全文（テンプレート・HTMLへの観点を持つため）
ルート直下のガイド類（index.md AGENTS.md 等）検索コマンドでヒットした場合のみ
.gemini/ 配下検索コマンドで件数のみ列挙（生成物のため精読しない）
reports.template.html 本体全文（Q2の対象）

方針

  1. まず検索（「検証」のコマンド）で参照元を機械的に列挙し、目視の精読はヒット箇所に限定する（打ち切り条件: 検索コマンド2系統の全ヒットを仕分けし終えた時点）。
  2. 各ヒットを「現在の状態の記述」か「point-in-time記録（DDR本文・specの過去changelog）」かで仕分ける。後者はフェーズ3で書き換えない（.claude/rules/docs-workflow.md）。
  3. Q2〜Q4は、Q1で確定した「直す対象」との整合が取れる形で結論を出す。

やらないこと（スコープ外）

この計画では決めない・触らない
  • テンプレートの実改修（フェーズ3へ送る）
  • plans.template.html / canvas-report の調査（全体作業計画のスコープ外）
  • .gemini/ 配下の精読・修正（生成物。flow-id 5-3 の再生成で追随）

検証（この調査が完了したと言える条件）

次のコマンドを実行し、全ヒットが調査結果の仕分け表（直す／直さない＋理由）に載っていること。

# 参照元の列挙（パス言及）。.gemini/ は件数のみ扱う
grep -rln --include='*.md' --include='*.sh' --include='*.html' -e 'reports\.template\.html' \
  .claude/ .gemini/ *.md

# 節名への言及（構成が変わると矛盾しうる箇所）
grep -rn --include='*.md' --include='*.sh' \
  -e 'サマリ（結論の一覧）' -e '確かめられなかったこと' -e '設計への反映' \
  -e '想定と異なった点' -e '実施条件（測った対象・環境）' \
  .claude/ *.md reports/REVIEW-POINTS.md

# frontmatterインデックス側（grepの取りこぼし確認）
bash .claude/scripts/src/search-frontmatter.sh --text 'reports.template' --format count
bash .claude/scripts/src/search-frontmatter.sh --text 'HTMLビュー' --format count
