## 作業項目

### 1. DDR `i0145-01`（案Bの判断）を作る

`.claude/docs/ddr/i0145-01-MR_PRテンプレートを見出し構成の唯一の正としdescribeが読む.md`

- **決めたこと**: `.github/pull_request_template.md` を見出し構成の唯一の正とし、
  `describe` はそれを読む。GitLab版は複製で、先頭コメントを除いた全文差分が空であることを
  テストで固定する。
- **却下案**: 案A（`describe` 節を正としテンプレートを生成する）／案C（両方に書いて一致検査）。
  それぞれの却下理由を書く。
- **あわせて記録すること**:
  - `.github` / `.gitlab` の配布層を `core` のまま変えなかった理由（`seed` にすると
    上流の改善が配布先へ届かなくなる）。
  - Draft PR初期本文を10節に合わせない理由。
  - **記入ガイドを両側から同時に消しても検査を素通りした**という実測（検査 (a2) の存在理由）。
    これは「テストは書けば効く」わけではないという一般的な教訓なので残す。

### 2. DDR `i0145-02`（#111 との役割分担）を作る

`.claude/docs/ddr/i0145-02-MR_descriptionと統括レポートのサマリコメントは併存させる.md`

- **決めたこと**: 併存させる。分ける軸は内容の粒度ではなく、**自動処理が繰り返し上書きするか
  （description）／1回きりか（サマリコメント）**という非対称である。
- **限界を必ず書く**: 根拠は**このリポジトリの自動化経路**（`Provider.sh` に投稿済みコメントを
  編集する関数が無い）であって、**GitHub/GitLab の外部APIの性質ではない**。人間はWeb UI・API
  から編集できる。正しくは「フローの自動処理が繰り返し上書きするのは description だけ」。
- **却下案**: サマリコメントを廃止して description へ一本化する／サマリコメントを description
  へのリンク1行にする。
- **1件にまとめるか2件に分けるか**: **分ける**。`i0145-01` は「テンプレートの正をどこに置くか」、
  `i0145-02` は「description と統括レポートの役割分担」で、**後から片方だけが supersede されうる**
  独立した判断だから。1つのDDRにまとめると、片方が無効になったときに `status` を付けられない。
