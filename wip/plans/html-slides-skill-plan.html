この計画で何をするか

調査結果・設計内容・issue対応の報告を投影して発表するスライドの形で残せるように、次の4点を追加する（issue #168「期待する動作」）。

  1. スライドテンプレート1本: .claude/skills/<スキル名>/assets/slides.template.html。自己完結（CDN・外部フォント・外部画像なし）で、スライド型8種（表紙／章扉／箇条書き／2カラム／図解／表／比較／まとめ）、キーボード（←→／Space／Home／End）とクリックのページ送り、進行表示、@media print による1スライド1ページのPDF化を持つ。
  2. スキル1本: SKILL.md が「テンプレートをコピー → 型を選ぶ → 穴を埋める → プレースホルダ残存チェック」の手順を定義する。見出し構成の正はテンプレート側に置き、再掲しない。
  3. サブエージェント2本: ①構成設計（読み取り専用。構成案をJSONで返す。HTML生成はしない）／②HTML生成（渡された構成に忠実に埋める。構成の再設計はしない。食い違いは差し戻す）。
  4. 構成案JSONのスキーマ定義: 将来の .pptx 書き出し（別issue）の入力にできる機械可読な形。

進め方（非対話セッションでの運用）

本セッションは Claude Code on the web のリモート実行環境で、人間のレビュー往復を待てない非対話セッションである。ユーザーの明示指示により、次の運用で進める。

  • 各フェーズの計画をpushした直後に敵対的レビューを1回、作業実施をpushした直後に1回、自動起動する（adversarial-review スキル。非対話セッションの自律起動は同スキルが許可している。各フェーズ上限3回の範囲内）。
  • 指摘への対応・修正を行い、対応内容を各スレッドへ返信してから次のステップへ進む。
  • 人間担当のレビューステップ（2-3/2-8/3-3/3-8/4-3/4-8等）は実施できないため、該当ループ範囲の進捗記号は [] のまま残し、実施した内容は HANDOFF.md「やったこと」の文章で補足する。
  • 全体作業計画の人間合意（flow-id 1-5）も待てないため、ユーザーの当初指示を包括的な承認として進め、計画自体もPR上でレビュー可能な形で残す。
