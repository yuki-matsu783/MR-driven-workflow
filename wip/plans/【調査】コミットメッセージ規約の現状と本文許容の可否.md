# 【調査】コミットメッセージ規約の現状と本文許容の可否

## 前提（合意状況）

- 上位の計画: `wip/plans/keen-charting-lantern.md`（全体作業計画。flow-id 1-4 で作成。
  **非対話セッションのため人間の合意（1-5）は得ていない**。代替として敵対的レビューを行う）
- issue #185 の受け入れ条件のうち「方針が決まりDDRに記録されている」は、この調査の結果を
  判断材料にする。

## この調査で何を明らかにするか

**「1行のみ」を維持するか本文を許容するかを決めるための材料**と、**書き換えが必要な
ドキュメントの全件リスト**を得る。

## 調べること（問い）

### Q1. 「1行のみ」はどこで・何回述べられているか

- 対象: `.claude/` 配下すべて（skills / docs/spec / docs/ddr / rules）、`AGENTS.md`、`CLAUDE.md`、
  `GEMINI.md`、`.gemini/`（変換生成物なので**書き換え対象ではない**が、同期漏れの検出には使う）。
- 手段: `grep -rn` で「1行のみ」「1行」「本文・フッター」「フッター」を機械的に洗う。
  `.claude/scripts/src/search-frontmatter.sh`（doc-searchスキル）は**ドキュメントそのもの**を探す
  用途なので、本文中の言い回しを探すこの問いには `grep` を使う（`AGENTS.md` の使い分け）。
- 出力: ファイル・行番号・その行が「規約として述べている」のか「他所を参照しているだけ」なのかの区別。

### Q2. 実際のコミットログの欠落パターン

- 対象: `main` の直近のsquashコミット（`git log --oneline` と、squash本文に畳まれた個別コミット行）。
- issue本文が挙げた4類型（(a) 対象しか分からない／(b) どう直したか分からない／(c) 事務的作業記録／
  (d) mainに残らない対象）で分類し、**4類型に収まらない例があるか**を確認する。
- 併せて、**1行が長くなりすぎている例**・**列挙で中身が削れている例**の実数を数える。
- 出力: 類型ごとの件数と代表例。**件数は自分で数え直す**（`wip/reports/REVIEW-POINTS.md`「内容の妥当性」）。

### Q3. `create-commit.sh` は複数行メッセージを受け付けるか

- `--message` の受け取り方（`getopts`か手書きか）、`git commit -m "$message"` への渡し方を読む。
- **実際に改行を含むメッセージで一時リポジトリへコミットして確認する**（読解だけで済ませない）。
- 出力: 本文を許容する方針を採った場合に実装変更が要るか／要らないか。

### Q4. squash merge時に本文はどう畳まれるか

- GitHubのsquash mergeが、PR内の各コミットのメッセージをsquashコミット本文へどう並べるか。
  **本文（2行目以降）を持つコミットがあるとき、squash本文がどうなるか**。
- `main` の既存のsquashコミット（`git log --format=%B`）を実物として読む。
- 出力: 本文を許容した場合に `main` の1行目・本文に何が残るか。**1行目の情報量は改善するのか**。

### Q5. コミットメッセージの文言に依存している処理はあるか

- `.claude/scripts/` `.claude/hooks/` を対象に、コミットメッセージを検索・パースしている箇所を探す
  （`git log --grep`、prefixでの分岐等）。
- 出力: 規約を変えたときに壊れる処理の有無。

## 調べないこと（スコープ外）

| 項目 | 理由 |
|---|---|
| Conventional Commits仕様そのものの調査 | prefix一覧は本issueのスコープ外（全体作業計画） |
| 他リポジトリ・OSSのコミット規約の比較 | 判断に必要なのは本リポジトリの制約であり、一般論ではない |
| 過去コミットの書き換え可否 | スコープ外（全体作業計画） |

## 検証（この調査が完了したと言える条件）

- Q1〜Q5すべてに、根拠（ファイル・行番号・実行したコマンドと出力）付きで答えが書けている。
- Q3・Q4は**実際に実行した結果**が根拠になっている（読解のみの答えを「確認済み」と書かない）。
- 結果は `wip/reports/2026-08-23_keen-charting-lantern_コミットメッセージ規約の現状調査.md`
  と同名の `.html` に記録する（**この計画ファイルには結果を書かない**）。

## 手順

1. Q1: `grep -rn` で該当箇所を洗い、表にする。
2. Q2: `git log` を読み、類型ごとに分類・計数する。
3. Q3: `create-commit.sh` を読んだうえで、一時リポジトリで複数行メッセージを実際にコミットする。
4. Q4: 既存のsquashコミット本文を読む。
5. Q5: `grep -rn 'git log\|--grep\|%s\|%B' .claude/scripts .claude/hooks` 等で洗う。
6. 結果を `wip/reports/` のmd・htmlへ記録し、`wip/worklogs/` に試行錯誤を残す。
