#項目類型痕跡の確認（段階2）
1IFS=$'\t' read -r -a はタブ区切りの分割に使えない（タブはIFS空白文字。連続タブを畳み、行末タブを捨てる）(d).claude/docs/spec/generate-ddr-list.md と DDR i0135-01 に既にある。.claude/rules/shell-script-style.md には無い（該当語の grep -c = 0）
2hookの前置フィルタを、ブロック判定の縮退時フォールバックへ流用してはいけない(c)shell-script-style.md「hookの前置フィルタ」に「過剰検知は許容してよい」はあるが、ブロック判定では逆になるという記述が無い
3テストのフィクスチャで ${N:-既定} を使うと、空文字列を渡した検証が空振りする(c)「パラメータ展開の既定値」節はバックスラッシュの話だけ。「テスト」節に「フィクスチャを意図的に壊して落ちるか」はあるが、:- そのものの罠は無い
4訂正した数値を訂正の直前に測り直していない／数え方（行数か出現数か）が書こうとしている単位と一致していない(d)wip/reports/REVIEW-POINTS.md に「書いた数値と事実を、書く直前に実測したか」が既にあるのに、issue #17 で3回続けて踏んだ（(1) 合計を取らずに 1,699 と書く → (2) 訂正値 1,631 を測り直さない → (3) grep -c の行数を出現数として「8箇所」と書く。実測は 1,630 / 9箇所）
5get_review_comments に page を渡すと黙って1ページ目が返る(c)mcp-fallback.md に「誤ったパラメータ名を渡すと無視されて1ページ目が返る」がある。ただし page はツール定義に実在する正当なパラメータなので、「誤った名前」として読み取れない
判定の根拠
  • (a)（該当するアセットが無かった）は0件である。したがって再現性の証拠を要求する項目は無い
  • 1と4は (d)——記述はあったのに辿り着けなかった。どちらも「近いファイルがある」ではなく「その罠を扱った記述がある」ことを確認したうえで (d) と判定した（記述単位で見る）
  • 段階3（マージ済みPRの遡り）へは進んでいない。段階2で全件が確定したためである

ファイル操作項目何を書くか

wip/reports/REVIEW-POINTS.md強化4既存の「書いた数値と事実を、書く直前に実測したか」の bullet へ、(i) 訂正値も訂正の直前に測り直す、(ii) 数え方が単位と一致しているか（grep -c は行数を返すので、件数を書くなら grep -o … | wc -l）の2点を足す。新しい bullet を作らない
.claude/skills/issue-mr-flow/references/mcp-fallback.md追記5既存のページネーションの bullet へ、page を名指しで1文

方針

  • 5件すべて、既存の記述の近傍へ足す。 新しいファイル・新しい節を作らない（常時読込のアセットを増やすコストを払わずに済み、(d) を自分で作らない）
  • (d) の2件は、書き足すのではなく導線を直す。 項目1は罠の説明を写経するのではなく .claude/rules/ から既存の記述を指す形にする（本文が2箇所に増えると、次に直すときに片方だけが直る）。項目4は既存 bullet の強化であって新設ではない
  • 項目2はDDR i0017-01 の却下案とも重なる。 DDR側は「issue #17 でこの方式を却下した」という決定の記録、shell-script-style.md 側は「今後こう書け」という規約であり、役割が違うので両方に置いてよい。ただし理由の詳述はDDR側に置き、規約側は結論と参照に留める
分量に注意する shell-script-style.md は既に大きく、追記が3件集中する。それぞれ数行に収める。 書いたあとに読み返し、分量に見合う効果があるかを確かめる。
