調べること（問い）

問い手段得たい出力
Q1. 「1行のみ」はどこで・何回述べられているか grep -rn で .claude/ 配下・AGENTS.md・CLAUDE.md・GEMINI.md・.gemini/ を洗う。本文中の言い回しを探す問いなのでfrontmatter検索ではなく grep を使う（AGENTS.md の使い分け） ファイル・行番号と、「規約として述べている」のか「他所を参照しているだけ」なのかの区別
Q2. 実際のコミットログの欠落パターン main の直近のsquashコミットと、その本文に畳まれた個別コミット行を読む issue本文の4類型で分類した件数と代表例。4類型に収まらない例の有無。1行が長すぎる例・列挙で中身が削れている例の実数
Q3. create-commit.sh は複数行メッセージを受け付けるか --message の受け取り方と git commit -m への渡し方を読み、一時リポジトリで実際に改行入りメッセージをコミットする 本文を許容する方針を採った場合に実装変更が要るか／要らないか
Q4. squash merge時に本文はどう畳まれるか main の既存squashコミット本文（git log --format=%B）を実物として読む 本文を許容した場合に main の1行目・本文へ何が残るか。1行目の情報量は改善するのか
Q5. コミットメッセージの文言に依存している処理はあるか .claude/scripts/ .claude/hooks/ でコミットメッセージを検索・パースしている箇所を探す 規約を変えたときに壊れる処理の有無

手順

  1. Q1: grep -rn で該当箇所を洗い、表にする。
  2. Q2: git log を読み、類型ごとに分類・計数する。件数は自分で数え直す（wip/reports/REVIEW-POINTS.md「内容の妥当性」）。
  3. Q3: create-commit.sh を読んだうえで、一時リポジトリで複数行メッセージを実際にコミットする。
  4. Q4: 既存のsquashコミット本文を読む。
  5. Q5: grep -rn でコミットメッセージを扱う処理を洗う。
  6. 結果を wip/reports/ のmd・htmlへ記録し、wip/worklogs/ に試行錯誤を残す。

  • 過去コミットの書き換え可否 — スコープ外（全体作業計画）。
