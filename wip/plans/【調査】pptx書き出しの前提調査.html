調査項目

#問い何を確定するか
Q1zip相当の可用性と代替戦略（受け入れ条件1）この環境の実測記録＋Windows git bash向け代替手段の優先順位（zip / python3 zipfile / Compress-Archive / その他）と検出ロジック。OOXMLのzip制約（エントリ順・区切り・圧縮方式）の実測
Q2構成案JSONスキーマの依存範囲（受け入れ条件7）依存を「type enum 8種＋各型の必須キー」へ限定できるか。入力検証に使う必須キー集合と、PR #194 スキーマ確定時の突合手順
Q3最小OOXML構造（受け入れ条件3）警告なく開く .pptx の必須パーツ一覧と、スライド枚数可変時の連動書き換え箇所。最小構成の実生成と構造検査
Q4雛形の形態展開ディレクトリ vs バイナリ .pptx の比較と、PowerPoint製雛形へ後から差し替え可能な構造の設計
Q58種のtype → スライドXML表現の写像（受け入れ条件6）6型必須（テキストボックス・表）＋2型代替（図解→箇条書き、比較→表）の対応。speakerNotesの扱い
Q6検証手段の切り分け（受け入れ条件3・4・5）この環境で機械検証できる範囲と、人間の実機確認（PowerPoint）に残す範囲・PRレビューへの依頼文面の要点
