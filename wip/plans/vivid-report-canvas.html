この計画で何をするか

.claude/skills/issue-mr-flow/assets/reports.template.html を、レビュアーが重要箇所へ集中できるフォーマットへ改修する。具体的には次の4点。

  1. サマリの視覚化: 結論を性質（良かった＝青／気になる＝黄／悪かった＝赤）で色分けし、短いポイント＋該当章へのアンカーリンクを持つ形にする。
  2. 重点レビュー依頼の新設: 冒頭に「特に見てほしい／承認が欲しい／細かいレビューは不要」の3段階を明示する節を置く。
  3. 「確かめられなかったこと」の前半移動: 前半で一覧として示し、詳細は各章で語る構成にする。
  4. 書き手への伝承: 色・記号の使い分けと節の並び順を、テンプレート内コメントとして次の書き手へ伝わる形で記述する。
実行環境 非対話セッション（Claude Code on the web）。各フェーズの計画時と作業実施後に敵対的レビューを1回ずつ自動起動し、指摘への修正・返信を行いながら進める（ユーザー指示）。issueに無い改善（レビュー重みバッジ・件数チップ等）も、より良い表現であれば採用してよい（同）。

方針

issue #186 の「期待する動作」をそのまま設計の骨子とし、色・節順・コメントの具体設計はフェーズ2の調査で確定させる。テンプレートの自己完結性（外部依存なし）・md/html併存運用・プレースホルダ検査手順という既存の枠組みは変えない。

フェーズ2〈調査〉

実施する。調べる問い:

  • テンプレートの節構成・運用に言及するドキュメントはどこにあるか（変更時に矛盾が生じる箇所の全列挙）。
  • 現テンプレートの構造（必須／任意節・スタイルトークン・ダークモード対応）はどうなっているか。何を残し何を変えるべきか。
  • 色の設計判断:「良かった＝青」の指定と既存の --ok（緑系）の関係の整理。ダークモード・色だけに依存しない記号併用の担保。
  • 「フェーズごとの読み替え」（統括5-4等での節の意味変化）を新構成へどう引き継ぐか。

次へ進める基準: 新テンプレートの節順・色トークン・コメント方針が一意に決まること。

フェーズ4〈反映〉

反映対象は flow-id 4-1 で洗い出す。見込みの候補（確定ではない）:

  • 設計反映: 色・節順の設計判断のDDR記録の要否を検討する。
  • AIアセット反映: 作業中に気づいたアセット不備があれば反映する。
