# worklog: 【調査】反映対象の切り出し判断基準（push5）

対象: フェーズ4の反映対象に対する「このMRで対応するか別issueへ切り出すか」の判断基準を書くための調査（2026-08-23）。
全体作業計画: `wip/plans/reflection-split-criteria.md`
個別作業計画: `wip/plans/【調査】反映対象の切り出し判断基準.md`

**このファイルが記録している範囲: push 5。** push 2〜4 は `_push2.md`（同名・末尾のみ違う）にある。

## 試したこと

- 敵対的レビュー（フェーズ2・2/3回目）を `adversarial-review` スキルの手順どおり実施した。
  対象は flow-id 2-6 の調査結果（md＋html）と worklog。findings 11件を確度×重大度の表で
  1次振り分け（投稿候補8件／報告3件）し、`select-adversarial-findings.sh` で選別したところ
  major 7件＋minor 1件＝8件すべてが投稿対象になった（層追加のしきい値10件に達しないため
  minor層まで追加された）。
- **投稿の前に、11件すべてを自分のコマンドで裏取りした。** 結果は**全件が正しい指摘**だった。
- Q4 の母数を作り直した。`grep -rln -- '別issue' .claude/docs/ddr/` の13件に対し、除外を
  3段階（E1 部分一致の偽陽性／E2 語の用法／E3 判断の性質）へ分けて 13→7件とした。
- 対案（issue本文の骨子である規模基準）を同じ7件へ当て、3/7 という結果を得た。
- 母数7件の `status` / `note` を実測し、レポートへ表として記録した。

## うまくいったこと

- **`grep` の部分一致による偽陽性の検出。** `grep -o -- '別issue'` と
  `grep -o -- '個別issue'` の件数を並べるだけで、`i0000-11`・`i0054-01` の2件が
  `個別issue` だけでヒットしていたことが1コマンドで分かった。

  ```bash
  for f in i0000-11 i0054-01; do p=$(ls .claude/docs/ddr/${f}-*.md); \
    echo "$f: 別issue=$(grep -o -- '別issue' "$p" | wc -l) 個別issue=$(grep -o -- '個別issue' "$p" | wc -l)"; done
  ```

- **除外を「E1/E2/E3」と名前を付けて段階化したこと。** 前版は「13件→11件→9件」と2回絞って
  いたが、各段階の理由が地の文に埋もれており、あとから「なぜこの件を外したか」を辿れなかった。
  段階に名前と件数と識別子を付けると、レビュアーが段階ごとに賛否を言える。
- **対案比較を1本入れたこと。** 「7/7 で一致した」だけでは基準の良さを示せないという指摘は
  そのとおりで、規模基準を同じ母数へ当てると 3/7 になり、しかも誤り方に規則性
  （極小を流す／やらない出口が無い／必須を切り出す）が出た。**この規則性こそが、
  出口を3つ持つべき理由の直接の根拠になった。**

## ダメだったこと

- **`grep` の部分一致で母数を作り、語単体で数え直さなかった。** これが最大の失敗である。
  `別issue` は `個別issue` の部分文字列であり、このリポジトリでは `個別issue` が
  「個別計画」まわりの語として普通に出てくる。**偽陽性2件がそのまま「時期尚早」という
  存在しない類型を作り**、しかもその類型が「出口は3つ要る」という結論の根拠の1/4を
  占めていた。結論自体は生き残ったが、根拠は作り直しになった。
  - 教訓: **母数を `grep` で作ったら、必ず「その語を含む別の語」を1つは疑って数え直す。**
    `.claude/rules/shell-script-style.md` は `--` の付け忘れ（先頭ハイフン）を扱っているが、
    **部分一致そのものの罠は書かれていない**。フェーズ4の `【AIアセット反映】` 候補として拾う。
- **同じ意思決定を2行に分けて数えていた。** `i0054-01` と `i0000-11` を「テンプレート化の
  保留」として2件と数えたが、`i0140-01` は「過去の決定の踏襲だから」として0件にしていた。
  **同じ形のものに違う扱いをしていた**のに、表を見ているだけでは気づかなかった。
  しかも `i0054-01:32` は「本DDRの決定1は、この保留を明示的に覆すものである」と書いており、
  当時の結論欄（「保留」）が事実と逆だった。**DDRの本文を「見送りの理由」だけ拾い読みして
  判定欄を埋めると、その決定がどちら側だったかを取り違える。**
- **計画が要求した確認（`status`）を実施したのに記録へ残していなかった。** 読み手からは
  「やっていない」と区別が付かない。**計画の「調べ方」に書いた項目は、結果が空でも
  「0件だった」と書く。**
- **同じ数字（複製箇所）がレポート内で 4 と 6 に割れていた。** md の見出し・要約は4、
  本文の追記は「計6箇所」、HTMLは6。**「加えて〜」で数を後から足す書き方をすると、
  前の方に書いた数が置き去りになる。** 最初から全件を1つの表に入れる。
