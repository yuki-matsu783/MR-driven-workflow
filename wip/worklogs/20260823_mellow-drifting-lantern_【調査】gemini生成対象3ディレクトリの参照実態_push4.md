## 最も重い指摘: Q3-b の新設

**「docs/ を外すと18件切れる」の18件のリンク元（`.gemini/rules/`）自体が読まれるかを測っていない**
という非対称の指摘。hooks/scripts には「設定が `.claude/` を指しているから読まれない」という検査を
当てたのに、リンク元には当てていなかった。

実測すると、`.gemini/rules/` にも読み込まれる経路が見つからない。

```
GEMINI.md:11:@./AGENTS.md
AGENTS.md:11:@./.claude/rules/agent-common.md
.gemini/*.md            → REVIEW-POINTS.md のみ（GEMINI.md / AGENTS.md 相当は無い）
.gemini/settings.json   → トップレベルは general / hooks のみ、general は plan.directory だけ
```

**これは調査の結論を変えた。** 「hooks/scripts と docs/ は性質がはっきり分かれている」という
「設計への反映」1 を、「切れるリンク18件を、読まれるファイルの中の18件と読むか、読まれない
ファイルの中の18件と読むかで結論が変わる——ここがフェーズ3の争点である」へ書き直した。

## ダメだったこと

- **「grep 系はすべて本文中にコマンドを併記している」と、確かめずに書いていた。** 実際に
  コマンドがあったのはQ1の1ブロックだけ。**再現性を要求する節そのものが再現できない**という
  形になっていた。
- **「0件と書いた測定にはすべて対照を付けてあり」も同じく確かめていなかった。** 数え直すと
  対照を付けていない0件が2件あった。表にして、それぞれ「対照なし」と明記した。
- **同じ表の2つの数字を、行数と出現数という別の単位で並べていた**（hooks 22 は行数＝出現数で
  一致していたため気づけなかった。scripts は行数96・出現数97）。両方を出現数へ揃えた。
- **サマリの主語が「Gemini CLI から読まれない」になっていた。** 「確かめられなかったこと」節では
  正しく限定していたのに、**同じ文書の中で食い違っていた**。観点表が「区別して書くだけでは
  防げない」と名指ししている型そのもの。
