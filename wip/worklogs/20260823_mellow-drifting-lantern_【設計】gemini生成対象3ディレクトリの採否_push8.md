## 学び1: 自分の返信を1件撤回した

指摘3への最初の返信で、サマリ表6行目の「無言の移行失敗」を**据え置く**と書いた。理由として
「案3を却下した当時の判断材料が読めなくなる」を挙げたが、これは成り立たない。

- レポートは**現在の記録**であって経過ログではない。当時の判断材料は worklog が持つ。
- 本文（結論7）で「無言ではない」と訂正した語を、サマリに残すのは**指摘されたのと同じ内部矛盾**。

同じスレッドへ撤回の返信を出し、サマリ表6行目と「想定と異なった点」表を直した。
`grep -n 無言` で残るのは否定形の記述だけになった。

**教訓: 指摘への返信で「据え置く」と書くときは、その理由がレポートの性格（正史か経過ログか）と
噛み合っているかを確かめる。** 部分的に直して部分的に残すのが最も危うい形で、指摘された矛盾を
別の場所へ移しただけになる。

## 学び2: md と HTML の同期は「追加のみ」では足りない

指摘7が効いたのは1箇所だけではなかった。7件のうち6件が本文の**書き換え**を伴い、HTML側にも
同じ書き換えが要る。判断基準を次に固定した。

> md側の差分が「追加のみ」でないなら、HTML側も「追加のみ」では同期していない。

反映後の検証（プレースホルダ0／外部参照0／見出し一致／表のセル数）を全件通した。h2 だけ
テンプレート由来の「目次」1件が md に無いが、これは想定どおり。

## 学び3: MCPの `get_review_comments` は出力が大きすぎて直接読めない

30スレッド分で 60,555 文字あり、ツール結果がトークン上限を超えてファイルへ退避された。
`python3` で JSON をパースし、`comments` の要素数が1のスレッド（＝未返信）だけを抽出した。

```bash
python3 -c '...json.loads(...)["review_threads"]...'  # n=1 のものが未返信
```

**返信先の comment id は、推測せず必ずこの経路で取る。** push7 の時点で HANDOFF へ推測の
URLを1件だけ書いていたが、実際の7件とは無関係な値だった（今回の作業で実IDへ差し替えた）。
