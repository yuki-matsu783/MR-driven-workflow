# worklog: 係り先ルールの設計反映 push7（敵対的レビュー13件への対応）

flow-id 4-9。反映結果（DDR `i0142-01`・spec の changelog・レポート）に対する敵対的レビューで
**13件**（blocker 1／major 5／minor 7）の指摘が出た。**全件が実測で再現し、全件を修正した。**

## この回でいちばん重い発見

**フェーズ2の調査が明示的に否定した主張を、フェーズ4の恒久記録で復活させていた。**

- 全体作業計画（`wip/plans/brisk-weaving-lantern.md`）は、着手時の見立てとして
  「4件とも自己確認では見つからず、敵対的レビューが検出している」と書いていた。
- フェーズ2の調査でこれは**否定された**。敵対的レビュー機構は issue #77 で新設されたので、
  それより前の #64 を検出することは**原理的に不可能**である
  （`.claude/docs/spec/adversarial-review.md`「背景・目的」が根拠）。
  調査結果には「**正しくは4件のうち3件**」と明記してある。
- ところが**DDRとspecの両方に、訂正前の文言をそのまま書いていた。** 計画から転記し、
  訂正後の調査結果と突き合わせなかったためである。

**なぜこれが重いか。** DDRは本文をマージ後に変更できず、specのchangelogも point-in-time の記録
として残る。一方、訂正を保持していた調査結果は **flow-id 5-5 で削除される**。マージ後は
**「誤った記述だけが永続し、訂正が消える」**状態になっていた。しかも `.claude/` は配布対象
（`dist-layers.json` の `core` 層）なので、配布先にも誤記のまま渡る。

**教訓: 恒久記録（DDR・spec）へ書く前に、その主張が調査で訂正されていないかを調査結果側で
確かめる。** 全体作業計画は着手時の見立てであって、転記元にしてよい正ではない。

## 副次的に見つかったこと

**#8 の調査中に、規約と観点表で対処の書き方が既に食い違っていた。** 規約は「**まず**位置を選ぶ／
**位置で解けないなら**明示する」と優先順位付きなのに、観点表は「位置を選ぶ**か**明示する」と
並列だった。DDR自身が却下案の中で危惧した「同じルールが2ファイルで別物になる」状態の芽である。
観点表を規約へ揃えた。

**#12 は `AGENTS.md` のルール（ドキュメント探索は frontmatter インデックスを第一手段にする）と
噛み合っていなかった。** 「係り先」で引くと15件出るが、`wip/` 配下の12件は flow-id 5-5 で消える。
残るのは新規DDRだけで、**正である規約へ辿り着けない**状態だった。修正後は規約・観点表の両方が
ヒットする。
