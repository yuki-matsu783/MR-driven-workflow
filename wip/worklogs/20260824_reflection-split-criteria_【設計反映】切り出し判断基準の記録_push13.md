## VERSION が「競合しないまま」消えた

**これが今回の主題である。**

| | `.claude/VERSION` |
|---|---|
| 分岐点 | `0.4.0` |
| `main`（issue #185） | `0.5.0` |
| 本ブランチ | `0.5.0` |
| **マージ結果** | **`0.5.0`** |

**両側が同じ値へ変えたので、gitは競合と見なさない。** `git status` にも `git merge` の出力にも
何も現れず、**本issueの増分だけが無言で消える**。

これは `resolve-conflict` スキルの**類型A（DDR識別子の衝突）と同型**である。あちらも
「ファイル名が異なるため `git status` には何も出ない」ため、`check-base-conflicts.sh` という
専用の検知を持っている。**VERSION には同じ検知が無い。**

気づけたのは、マージ後に**分岐点・main・自分の3点を並べて確認した**からである。

```bash
MB="$(git merge-base HEAD origin/main)"
echo "分岐点: $(git show "$MB":.claude/VERSION)"
echo "main:   $(git show origin/main:.claude/VERSION)"
echo "自分:   $(cat .claude/VERSION)"
```

片側だけ見ると `0.5.0` は正しい値に見える。取り込み後の `0.5.0` を起点に **`0.6.0`** へ
上げ直し、経緯を spec の changelog・`HANDOFF.md`・反映結果レポートへ残した。

**これは `【AIアセット反映】` の候補になりうる**（`check-base-conflicts.sh` へ VERSION の
「両側が同じ値へ上げた」検知を足す）。ただし**本issueの反映対象としては扱わない**——
規模が「検知スクリプトへの機能追加＋単体テスト」で1issueに収まらず、スコープも issue #176
（反映対象の切り出し判断基準）の外である。**新節の出口(1) の AND 条件が成立する初めての例**である
（4-1 の10件はすべて規模が小さく AND が成立しなかった）。**新節の定めに従い、AIは起票せず
提示して止まる。** 反映結果レポートの検算も `洗い出し10件 + 4-6追加1件 = 11件` へ更新した。

## 反11 はマージをコミットしたあとでなければ意味を持たない

マージが**未コミットの状態**で反11（`git diff --stat "$(git merge-base origin/main HEAD)" -- .claude/`）
を流したところ、**42ファイル・4805行**が並んだ。

`git merge-base origin/main HEAD` は **HEAD が指すコミット**から計算される。マージが
未コミットのうちは HEAD がマージ前のままなので、分岐点も古いままになり、**`main` 側の変更が
まるごと自分の変更として並ぶ。**

マージをコミットしたあとは分岐点が `origin/main` の先端になり、期待どおり**自分の8ファイルだけ**
になった。

**「変えていないことの確認」に使う検査は、いつ流すかで意味が変わりうる。** 反3（DDR一覧）で
一度この罠を踏んで `git status` 依存をやめたばかりだったが、反11 は別の形で同じ性質を持って
いた（あちらは「コミット前か後か」、こちらは「マージをコミットしたか」）。
