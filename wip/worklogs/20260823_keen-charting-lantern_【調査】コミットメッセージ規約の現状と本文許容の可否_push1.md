## 調査実施（flow-id 2-6）での試行錯誤

- **一時リポジトリでの検証も `create-commit.sh` 経由でしか行えない。** 最初 `git commit -qm` で
  フィクスチャを作ろうとしたところ、`block-direct-git-commit.sh` がブロックした
  （hookは作業ディレクトリを問わないため、スクラッチパッド内の一時リポジトリでも効く）。
  ラッパー経由へ書き換えて解決した。**この制約自体は正しく働いている**（回避策を探さない）。
- **`git merge --squash` の既定メッセージは `.git/SQUASH_MSG` に置かれ、HEADは更新されない。**
  「Squash commit -- not updating HEAD」というメッセージが出るので、コミットせずに中身を読める。
  GitHubのsquashとは形式が違う（gitは `commit <sha>` ヘッダ付き、GitHubは `* <件名>`）ので、
  **これをGitHubの挙動の根拠にしてはいけない**。
- **`grep -c` の結果を鵜呑みにしない。** 敵対的レビュー反映系17件のうち「中身に触れている」件数を
  正規表現で数えたら8件と出たが、1件ずつ読み直すと6件だった（`修正する$` が
  「〜の指摘を修正する」という中身の無い行にも当たっていた）。**目視判断を含む分類は、
  その旨をレポートへ明記する。**

## 敵対的レビュー2回目（調査結果に対して）で踏んだこと

### 自分が根拠として貼った出力の中に、自分の結論の反例が混ざっていた

初版のレポートは「`main` の履歴に本文を持つコミットが1件も無い」を前提に、Q4の1項目を
「実測不能」としていた。実際には母数（直近5件のsquash）の内側に本文6件があり、しかも
**レポート自身が「良い例」として引用した行が、19行の本文を持つ当のコミットだった**。

原因は母数の作り方にある。`git log origin/main -5 --format='%B' | grep '^\* '` で件名だけを
抜き出したため、**本文は最初の1回のフィルタで消えており、以後どれだけ数え直しても現れない**。
「本文が無い」という観測は、履歴の性質ではなく自分のフィルタの性質だった。

- **教訓**: 「Xが1件も無い」という否定形の結論は、**Xを落とす前処理をしていないか**を先に疑う。
  数え直しても同じ数が出ることは、正しさの証拠にならない（同じフィルタを通しているため）。
- 確認は元データへ戻って行う: `for i in 0 1 2 3 4; do git log origin/main --skip=$i -1 --format='%B' | grep -vcE '^\* |^$'; done` → `3 3 3 63 3`。

### `awk` の `length()` はバイトを返す

`awk 'BEGIN{print length("あいう")}'` → **9**。`LC_ALL=C.UTF-8` を付けても 9 のままだった。
日本語の件名の長さを「文字数」として報告していたが、実際はバイト数で約2倍に膨らんでいた。

- 文字数が要るなら `perl -CSD -ne 'chomp; print length($_),"\n"'` か `wc -m` を使う。
- **バイトのまま示すなら「バイト」と明記する。** 単位を書かずに数だけ出すと、読み手は文字数だと
  解釈する（gitの慣習が「件名50〜72文字」で語られるため）。

### 散文で要約した grep 条件は、実行した正規表現とずれる

レポートに「上表のgrep条件は再現できる」と書いたが、除外語を散文で要約する際に
`ルール|フィクスチャ|\.sh|command-position|移設|改名|集約` が抜け落ち、読み手が再現すると
46件ではなく48件になった。

- **教訓**: 件数を根拠として書くなら、**実行したコマンドをそのまま貼る**。要約して書き直した
  時点で、それは別のコマンドである。

### `grep` の `--` を前に置きすぎるとフィルタが無効になる

`grep -rn -- '--message "' --include='*.md' .claude` は、`--` 以降が非オプション扱いになるため
`--include` が**検索対象ファイル名**として渡り、`grep: --include=*.md: No such file or directory`
を出しながらフィルタ無しで走る。**件数が偶然一致していたため見過ごした。**

正しい形: `grep -rn --include='*.md' --include='*.sh' -e '--message "' .claude`

- `.claude/rules/shell-script-style.md`「JSON操作」が扱う `--` の罠（置かないとハイフン始まりの
  値がオプション扱いになる）の**裏返し**にあたる。解はどちらも `-e` を使うこと。
- **エラーメッセージが自分の実行出力に出ていたのに、件数だけを見て通した。** 出力の
  標準エラー側を読まずに件数だけ拾うと、この形の失敗は必ず素通りする。
