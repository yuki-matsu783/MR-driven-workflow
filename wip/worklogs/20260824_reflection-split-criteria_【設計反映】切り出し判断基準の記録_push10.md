# worklog: 20260824 切り出し判断基準の記録 push10

対応: flow-id 4-1（個別反映計画の作成）。計画は
`wip/plans/【設計反映】切り出し判断基準の記録.md`。

## やったこと

1. `references/planning.md`「AIアセット反映の対象の洗い出し」手順1〜3 を実施し、反映対象を
   **10件**列挙・分類した。
2. **フェーズ3で作った新節の主判定を、このMR自身の10件へ適用した**（新節の初回適用）。
   結果は **Yes 2件 / No 8件**。
3. No の8件を判定順に通したところ、**8件すべてが出口(1)「別issueへ切り出す」**に当たった。
4. 非対話セッションのため起票できないので、**新節が定めた退避経路**（(2) へ落として DDR へ書く）
   に従うことにした。
5. 個別反映計画（md＋html）を作成し、検証コマンド6本の**変更前の基準値を実測**した。

## 新節を自分に適用してみて分かったこと

### 判定順の固定は、意図どおりに効いた

**8件すべてが (1) になった**のは偶然ではない。判定順を「(1) 別issue → (2) やらない →
(3) このMRでやる」と固定した結果、**スコープ外という条件が先に当たる**ためである。

適用前は「規模が小さいものは (3) でこのMRに入るだろう」と予想していたが、実際には
**(3) へ到達する前に (1) で止まった**。規模は (3) の条件であって、判定順の上位ではない。

**これは望ましい挙動である。** 規模が小さいという理由でスコープ外のものを流し込み始めると、
issue #176 のスコープが際限なく膨らむ（#64 節が問題にした状態）。フェーズ3の敵対的レビューで
指摘され判定順を固定したが、**その指摘が無ければ、8件のうち何件かは「小さいから」で
このMRへ入っていた**はずである。

### 退避経路が実際に必要になった

新節へ「起票されなかった場合は (2) へ落とす」「非対話セッションでは `main` に残る形で書き、
次セッションで確認する」を書いたのは敵対的レビューの指摘（出口(3) の行き先が無い）への対応
だったが、**その経路が初回適用でいきなり必要になった**。

- このセッションは非対話で `AskUserQuestion` を使えない。
- 8件を `wip/reports/` の1行だけで済ませると、5-5 と squash merge で `main` から消える。
- よって DDR `i0176-02` へ退避し、`HANDOFF.md` へ「次セッションで起票の可否を確認する」を残す。

**経路が無ければ、8件の判定結果はこのMRのマージとともに失われていた。**

### 「該当するアセット」を記述単位で見る、の判定が効いた

`grep` の部分一致の罠（#3）について、`shell-script-style.md` には `grep` の節があり
`--` の付け忘れも書かれている。**ファイル単位で見れば「アセットはある」ので (c) になる**が、
記述単位で見ると「数えたい対象そのものの語で数えているか」という罠は書かれておらず **(a)** である。

手順2の注記（「ファイル単位で見ると近いファイルが必ず1つは見つかるため、(a) が原理的に発生
しなくなり、手順3が恒久的に迂回される」）が、そのまま当てはまる場面だった。

## 詰まった点

### 手順3の段階3をどこまでやるか

段階2（`doc-search` + `grep`）で痕跡なしを確定したので、規定上は段階3（直近10件のマージ済みPR）
へ進むことになる。**しかし #3〜#5 は主判定で No になり、このMRでは反映しない。**

段階3は「(a) として反映してよいか」を確かめる手続きなので、**反映しないと決まった項目に対して
実施する意味が無い**。計画には「段階2で痕跡なしを確定したが、主判定で No になり反映しないため
段階3は不要」と明記した。

**これは手順の順序に関する気づきでもある。** 現状は「洗い出し（手順1〜4）→ 主判定」の順だが、
手順3は探索コストが最も高い段階である。**主判定を先に通せば、No の項目について段階3を省ける。**
ただし手順4（反映先の形態の決定）は切り出し先を決めるのに要るため、単純な入れ替えはできない。
これ自体が反映対象の候補になりうるので、4-6 で判断する。

### 計画の見出しをテンプレートの必須5節へ揃える

最初に書いたときは 前提／反映対象の洗い出し／主判定／出口／判定の記録／変更対象／やらないこと／
検証／受け入れ条件 という構成にしていたが、`plans.template.html` の必須5節（この計画で何をするか／
変更対象／方針／やらないこと（スコープ外）／検証）と食い違っていた。

**フェーズ3の敵対的レビューで「HTMLの必須節を落とした」と指摘されたばかりである。** 同じ轍を
踏まないよう、md 側の見出しを先にテンプレート構成へ揃え、洗い出し〜判定の記録は `方針` の下へ
`###`／`####` として入れ子にした。md と HTML の `##`／`h2` が一致することも `diff` で確認済み。
