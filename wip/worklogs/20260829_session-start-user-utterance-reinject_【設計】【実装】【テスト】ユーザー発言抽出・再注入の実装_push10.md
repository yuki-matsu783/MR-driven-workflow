# worklog: 【設計】【実装】【テスト】ユーザー発言抽出・再注入の実装（push10）

対象: issue #151 フェーズ3〈作業〉 flow-id 3-2〜（2026-08-29）。
結果の正文: `wip/plans/【設計】【実装】【テスト】ユーザー発言抽出・再注入の実装.md`
push回数: 10

## 試したこと

- push9で個別作業計画をコミット・pushした後、ユーザー指示
  「各フェーズでの計画時に一度敵対的レビュー」に従い、計画段階の敵対的レビュー
  （フェーズ3・1回目）を実施した。
- `adversarial-review` スキルの手順どおり、`collect-review-points.sh` でレビュー観点を集約し、
  `adversarial-reviewer` サブエージェントへ計画ファイル1本＋レビュー観点表のみを渡して
  16件の指摘を得た（実装の経緯・意図は渡さない設計どおり）。
- `select-adversarial-findings.sh` による決定的な振り分けで、10件（major/high 3件・
  major/medium 5件・minor/high 2件）をインラインコメントとして投稿、残り6件
  （すべてminor/medium）をレビュー本文で報告のみとした。
- 投稿した10スレッドすべてに、計画への反映内容を要約して返信した
  （`add_reply_to_pull_request_comment`）。

## うまくいったこと

- **transcript_pathの受け渡し・再注入バイト数の返し方（major/high最大の指摘）を、既存の
  bashパターンの組み合わせで解けた。** 下方向（transcript_path）は素朴に関数引数で渡せば
  サブシェル境界の影響を受けない（issue #43の問題は上方向の話であり無関係）。上方向
  （再注入バイト数）は、グローバル変数では伝わらないが**標準出力の中身自体はコマンド置換が
  何段ネストしても親へ伝わる**ことを利用し、本文末尾へセンチネル行
  （`__USER_UTTERANCE_BYTES__:<N>`）を1行追加する形にした。新しいインフラは不要。
- **`append_size_warning`の引数追加を「末尾へ追加・省略可・既定0」にしたことで、
  「既存6箇所のテスト呼び出しが無言で意味を変える」という指摘そのものを解消できた。**
  当初案（第2引数へ差し込む）は指摘のとおり危険だったが、末尾追加＋既定値という設計に
  変えるだけで「既存呼び出しは変更不要」という、より良い解になった。
- **累積カウントの重複計上対策（`countedUuids`）が、H-3の「発言本文を保存しない」という
  既存の秘密情報方針と自然に両立した。** 重複除去に必要なのは`uuid`（transcript上の識別子）
  だけで、本文を持ち歐る必要が無いため、既存方針を一切崩さずに済んだ。

## ダメだったこと

- 大きな指摘は無かったが、**H-3の例が辞書から外したはずの`ok`を使っていた**（H-1決定後の
  見直し漏れ）。1ファイル内の決定同士の整合性チェックを、書いた直後ではなく最後にまとめて
  行っていたため見落とした。次回は各決定を書いた直後に、既存の決定と矛盾しないかを
  その場で確認する。
