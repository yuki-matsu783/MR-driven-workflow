# worklog: 【調査】transcriptからのユーザー発言抽出と選定パラメータの実測（push7）

対象: issue #151 フェーズ2〈調査〉 flow-id 2-6〜2-7（2026-08-24）。
結果の正文: `wip/reports/20260824_session-start-user-utterance-reinject_transcript実測の調査結果.md`
push回数: 7

## 試したこと

- **敵対的レビュー（フェーズ2・2回目）**の findings 14件（投稿10・報告のみ4）を全件反映した。
- 指摘の数値を**自分で検算**したうえで反映した（レビュー観点「指摘に含まれる数値は、対応する前に
  自分で数え直す」）。
- **測定断面を1つ固定**（1,668行 / 4,929,555バイト）し、件数・バイト数・性能をすべて測り直した。
- 一時 SessionStart hook が `source=resume` で発火し、**問い1のペイロードを捕捉できた**。
- 後片付けとして `.claude/settings.local.json` を削除した。

## うまくいったこと

- **問い1と、指摘された問い9の `resume` が同時に埋まった。** 一時hookが `resume` で2回発火し、
  stdin JSON のキー5つ・`transcript_path` が POSIX絶対パスで実ファイルとして開けることを
  直接確認できた。**しかも hook が報告した inode が compact 時と同じ `475799`** だったため、
  「resume をまたいでも同一ファイル」という問い9の欠けていた部分がそのまま埋まった。
  - **敵対的レビューの指摘が、結果的に測定の設計を良くした。** 指摘が無ければ resume を
    「無言で省略」したままだった。
- **指摘の検算が、より大きな誤りを掘り当てた。** 「+4.6MB」の指摘を検算する過程で、
  **20回計測の 50.7ms 自体がぶれた値**だと分かり、100回×3試行で測り直したところ約70msだった。
  結果、**問い11の結論が「合格」から「不合格」へ反転**した。
  - 指摘は「増分の計算が10倍甘い」だったが、**実際にはその前提の実測値も甘かった**。
    **指摘された箇所だけを直していたら、反転に気づかなかった。**
- **断面を固定したことで、合計の不一致が消えた。** 問い12の内訳が
  314＋11＋7＋6 = 338 で `type=="user"` と一致した。

## ダメだったこと

- **集計に使った jq が `A | B, C` の優先順位を誤っていた。** `map([.[0].message.content|type, length])`
  と書いたところ、`[ .[0].message.content | (type, length) ]` と解釈され、**2要素目がグループの
  件数ではなく content 自体の長さ**になっていた。結果、content 型の内訳が「array 1 / string 220」
  という別物の集計になった。
  - **気づけたのは、同じ実行の別の集計と合計が合わなかったから。** 単独で見ていれば
    「そういう分布なのだろう」と通していた。**集計を出すときは、合計が既知の値と一致するかを
    必ず確かめる。**
  - 正しくは `map([(.[0].origin.kind), (.[0].message.content|type), length])` のように
    **パイプを括弧で閉じる**。
- **性能計測を20回で済ませていた。** ルール（`.claude/rules/shell-script-style.md`「起動回数が
  ゼロであることを計測で確かめるとき」）は「試行回数を十分に取る」と明記しており、
  20回では判別できなかった実例まで載っている。**それを読んでいながら20回で結論を書いた。**
  - 100回×3試行では 68.85 / 70.35 / 70.60ms と安定した。20回の 50.7ms とは**約4割の差**。
  - **「ルールを知っている」ことと「その場で適用する」ことは別である。**
- **走査対象が生きたファイルであることを意識していなかった。** transcript は自分が走査している
  間にも伸び続ける。問い2（1,403行時点）と問い12（別実行）で断面が違い、合計が合わなくなった。
  - **対処は単純で、最初に `cp` して断面を固定するだけだった。**
- **レポートの md と HTML で内容が乖離した。** 「設計への反映」「想定と異なった点」を HTML にだけ
  書いていた。**HTML を先に書いて md を薄くする**という、フェーズ2・1回目でも指摘された同じ形を
  繰り返した。
  - 今回は md を先に確定させてから HTML を生成し直した。
