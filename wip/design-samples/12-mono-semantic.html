  1. 0. 実施条件（測った対象・環境）

    Claude Code on the web（Linux）/ bash 5.2.21 / jq 1.7.1 / 対象43ファイル / 実施日 2026-08-23。1環境の観測であり、全環境の事実としては扱わない。

  2. 1. mtimeキャッシュの効果

    ◎良 根拠: 実測

    mtimeが変わっていないファイルの結果を前回出力から再利用する方式で比較。差分が無いときの再生成は136秒→約10秒。キャッシュキーはmtime＋スクリプト自身のハッシュとする。

    根拠を見る（実行コマンドと出力） 
    $ time bash extract-frontmatter.sh .   # キャッシュ無し
real  2m16.4s
$ time bash extract-frontmatter.sh .   # キャッシュ有り（差分なし）
real  0m9.8s

  3. 2. jq起動の集約可否

    ◎良 根拠: 実装の確認

    キー・配列要素ごとのjq呼び出し（1ファイル約30回）は、シェル配列へ中間表現を溜めて1ファイル1回へ集約できる。ハイフン始まりの値対策として --args の後ろへ -- を置く。

  4. 3. git bash実機は未計測

    △注意 根拠: 実測（Linuxのみ）

    計測はすべてLinux。git bashのfork単価（約95ms/回）とは桁が違う。起動回数の削減比（30回→1回）は環境に依らないが、「約10秒」という絶対値はgit bash実機で測り直すまで結論にしない。

  5. 4. 削除ファイルで走査中断

    ✕問題 根拠: 実測

    追跡ファイルを削除して未ステージのまま走査すると、git ls-files の列挙に実体の無いパスが混ざり走査全体が中断する。列挙とファイル操作の間に [[ -f ]] の実体判定を挟む修正が必要（スキップ件数は必ず出力する）。

    根拠を見る（エラー出力） 
    stat: cannot statx 'wip/reports/old.md': No such file or directory
