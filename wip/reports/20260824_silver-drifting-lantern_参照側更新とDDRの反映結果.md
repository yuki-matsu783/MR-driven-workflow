## 実施した内容と結果

### g1. 選択基準を `deliverables.md` の1箇所へ置いた ◎良

**受け入れ条件(4)「選択基準（既定はどれか）がドキュメント化されている」の実体である。**

`deliverables.md` へ「レポートテンプレートの選び方」節を新設し、5本を**同じ軸**
（テーマ／`@media print`／向く場面）で並べた。当初の草案は `mono` の行だけテーマの記載が
抜けており、`mono` と `paper` のどちらを選ぶかが表から決まらなかった（敵対的レビュー3回目）。

**競合したときの優先順を1行添えた。**「白黒で読む」は `mono` と `paper` の両方に当てはまるが、
実測では **`@media print` を持つのは `paper` だけ**（4本中1本）なので、印刷が絡むなら `paper` を採る。

**現行テンプレートの行には有効期限を書いた。** `wip/reports/` の成果物は flow-id 5-5 で削除され
mainに残らないため、「既存の成果物を更新する」に該当するのは**同一ブランチ内だけ**である。
移行が終われば、現行を選ぶ場面は消える。

### g2. 検査手順の「正」を `deliverables.md` へ移した ◎良

**フェーズ3で、同じ検査手順の実体が1つから5つに増えていた。** 新4本は使い方コメントごと
バイト単位で同一なので、検査の説明も4本すべてに複製されている。一方で「検査コマンドの正は
`reports.template.html` 冒頭コメント」と名指しする箇所が3つあった。

| 名指ししていた場所 | 対応 |
|---|---|
| `plans.template.html` 20行 | `deliverables.md` へ向け直した |
| `wip/plans/REVIEW-POINTS.md` 108行 | 同上 |
| DDR `i0186-02` 25行 | **触らない**（DDR本文は変更しない）。向け先の変更はspecのchangelogへ記録した |

**テンプレート側のコメントは残した。** あれは**読む場所にあることに意味がある使い方の説明**で
あり、正ではない。`deliverables.md` を正と決め、テンプレートには「正は `deliverables.md`」と
書き足した。**同じ1行を4本へ同じように足したので、バイト一致は保たれている**（下記 g4 の検証）。

### g3. 検査を5種から6種へ増やした ◎良

**6種目は「構造の妥当性」（`<style>` がちょうど1つ）である。**

```bash
printf 'open=%s close=%s\n' "$(grep -c '^<style>' "$f")" "$(grep -c '^</style>' "$f")"
```

**この検査は、この作業中に実際に踏んだ不具合から足した。** フェーズ4の計画HTMLで `<style>` が
二重に出力されており、**2つ目はCSSのテキストとして扱われて、続く `:root { … }` ブロックごと
破棄される**状態だった。ダーク環境ではメディアクエリ内で `:root` を再定義しているため正常に見え、
**ライト環境でだけ配色・枠線・強調色が初期値へ落ちる**。

**既存の5種はどれも捕まえなかった**（アンカー・IDと外部依存しか見ないため）。
プレースホルダ0件・リンク破断0行・重複IDなし・外部依存0件で、**全検査に合格していた**。

配った先は `deliverables.md`（正）・`plans.template.html`・`wip/plans/REVIEW-POINTS.md` である。

### g5. 「触らない」と決めた4行を凍結行照合で守った ◎良

**当初の計画が書いていた検証は、2つとも機能しなかった**（敵対的レビュー3回目）。

| 書いていたもの | なぜ機能しないか |
|---|---|
| `git diff … \| grep -nE '^[-+].*(3132\|3216\|3275\|3651)'` | diff本文に**文字列「3132」が現れる行**を探しており、行番号を見ていない。**何をしても「該当なし」を返す空振り** |
| `grep -c` の件数突き合わせ（期待値4件） | **実測6件**。しかも更新対象の348・758行を母数に含む |

**凍結行の原文を固定文字列で照合する形へ置き換えた。**

```bash
base=$(git merge-base origin/main HEAD)
git show "$base:.claude/docs/spec/issue-mr-workflow.md" | sed -n '3132p;3216p;3275p;3651p' > /tmp/frozen.txt
while IFS= read -r line; do
  printf '%s\n' "$(grep -c -F -e "$line" .claude/docs/spec/issue-mr-workflow.md)"
done < /tmp/frozen.txt
```

**結果は4行とも `1`。** 負のコントロール（3132行目を意図的に壊したコピー）では**1行目だけが `0`**
になり、検査が働いていることを確かめた。

**編集で行番号は動いた**（3132→3135 等）が、**原文で照合しているので影響しない**。
行番号ベースの検査だったら、この時点で当たらなくなっていた。

### g6. DDR `i0203-01` を書いた ◎良

却下案は**2つ**（4本独立／現行の置き換え）。**当初の計画にあった3つ目「1本にテーマ切り替えを
持たせる」は削除した**——フェーズ2・3のどこにも検討した痕跡が無かったためである
（敵対的レビュー3回目）。**DDRは本文を変更できない永続文書であり、検討していない案を書くと
後から読む人は「比較検討済み」と受け取る。**

あわせて計画の合格条件も「却下案が3つ」という**件数条件から内容の条件へ改めた**
（件数で縛ると、数を満たすための水増しを招く）。

未確認事項として3つ残した: ブラウザでの実表示6項目／**現行テンプレートをいつ廃止するか**／
`.claude/VERSION` の増分。

**「機械的に検査するときの一般則」3つもDDRへ残した。**（コメントを先に除く／負のコントロールを
取る／バイト単位で比べる）。いずれも**この作業で実際に踏んだうえで得たもの**である。

### g7. `.claude/VERSION` を据え置いた △注意

**当初の計画にはVERSIONの判断が1文字も無かった**（敵対的レビュー3回目）。
`distribution-assets.md` は flow-id 4-6 での判断を義務づけており、フェーズ3で配布対象アセットを
4本追加しているので、**判断そのものが必要な作業だった**。

| 選択肢 | 採否 |
|---|---|
| `MINOR`（0.5.0）へ上げる | **採らなかった** |
| **据え置く（0.4.0）** | **採った** |
| 何もしない | **採らなかった**（specが記録を義務づけている） |

目安表では「資産の追加」＝`MINOR` に当たる。しかし**非対話セッションでの増分適用の例外を
`.claude/VERSION` へ適用してよいかは未決定**であり（issue #185）、issue #165 の changelog に
「今後 `.claude/VERSION` を上げる場合は、改めて人間の指示を起点に増分を検討する」という
**人間の判断**が入っている。**この未決定をAIの独断で埋めない。**

**据え置きには実害がある。** 配布先は同じ 0.4.0 のまま中身の違う `.claude/` を受け取り、
**版から資産の差を判別できない**。承知のうえで選んだ。

据え置いた事実と根拠は、**specの `### issue #203` changelog と `HANDOFF.md`「判断を迷った内容」の
両方**へ残した（「判断したうえで据え置いた」のか「忘れた」のかを後から区別できるようにするため）。
**人間の指示があれば 0.5.0 へ上げる。**
