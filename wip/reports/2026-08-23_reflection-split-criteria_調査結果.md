## Q1: 節の配置先

**結論: `references/planning.md` へ置き、SKILL.md からは参照だけを張る。**

   「全体フロー表・PR/MR担当・詳細ルールへのポインタ・前提・旧節名の対応表」の5つに限定し、
   詳細は `references/` 配下の7ファイルへ移すと決めている。判断基準はこの5つのどれでもない。
2. **SKILL.md:131-132** —「このファイルは順序立ったフローの定義に専念し、内容の重複は避ける」。

   `references/planning.md:192` にあり、SKILL.md:174 の旧節名対応表が
   「→ `references/planning.md`」と明記している。判断基準を SKILL.md 本体へ書くと、
   **同じ種類の節が2つのファイルに分かれる。**

**受け入れ条件の「SKILL.md に節がある」は、issue #160 以前の構造を前提にした文言と読み替える。**

## Q3: issue #155 の4類型 (a)〜(d) との接続

**両者は入力と出力で接続し、重複しない。**

| | issue #155（手順2） | issue #176（本節） |
|---|---|---|
| 問い | **何が反映対象か** | その対象を**このMRでやるか** |
| 出力 | 4類型 (a)〜(d) への分類、またはどれにも当たらない | このMR／別issue／やらない |

**類型ごとに判断は変わらない。同じ一問で足りる。** ただし類型は無関係ではなく、
**「別issue候補」となった後の規模の見積り**に効く。

| 類型 | 反映の向き | 規模の傾向 |
|---|---|---|
| (a) 新規作成 | アセットを新設 | **大きい**（別issue候補になりやすい） |
| (b) 訂正 | 誤った記述を直す | **小さい**（1行で済むことが多い） |
| (c) 追記 | 罠を書き足す | 中 |
| (d) 導線の改善 | 参照・キーワード・配置 | 小〜中 |

また、**`main` の整合性の観点では (b) が Yes に倒れやすい。** 今回の変更で既存の記述が誤りに
なった場合、見送ると `main` に誤った記述が残るためである。ただしこれは傾向であって規則ではなく、
**類型を見て判定を分岐させるべきではない**（今回の変更と無関係な既存の誤りを (b) として拾った
場合は No になる）。

### 手順4の判別規則との関係

`references/planning.md:402-405` は、`【実装反映】` と `【AIアセット反映】` の判別を

## Q4: 過去事例での妥当性検証

### 母数の取り方（3段階の除外規則）

`grep -rln -- '別issue' .claude/docs/ddr/` で**13件**がヒットする。ただしこの grep はそのままでは
使えない。**除外を3段階に分け、各段階で落とした件を識別子で明示する。**

| 段階 | 除外の理由 | 件数 | 落とした識別子 |
|---|---|---|---|
| **E1** | **`個別issue` の部分一致による偽陽性。** `grep` の `別issue` は `個別issue` にも一致する | -2 | `i0000-11`・`i0054-01` |
| **E2** | `別issue` を**単に別のissueを指す語**として使っているだけで、見送り・切り出しの判断を記録していない | -2 | `i0039-01`・`i0068-01` |
| **E3** | **そのissueの作業中に見つけた項目への判断ではない。** `i0140-01` は過去の決定（`i0066-01` 却下3）の踏襲、`i0110-01` は計画レビューで検討した却下案 | -2 | `i0140-01`・`i0110-01` |
| | **残った母数** | **7** | |

E1 の実測:

```
$ for f in i0000-11 i0054-01; do p=$(ls .claude/docs/ddr/${f}-*.md); \
    echo "$f: 別issue=$(grep -o -- '別issue' "$p" | wc -l) 個別issue=$(grep -o -- '個別issue' "$p" | wc -l)"; done
i0000-11: 別issue=1 個別issue=1
i0054-01: 別issue=1 個別issue=1
```

どちらも `別issue` 単体としては0件で、`個別issue` の部分一致だけでヒットしていた。

**この2件は、前版が「時期尚早」類型としていたちょうど2件そのものである。** つまり
**「時期尚早」という類型は、母数の取り方の誤りから生まれていた**（前版はこの2件を

ある**」と書いており、保留した側ではなく解除した側だった）。E1 で両方が落ちるため、この矛盾は

### 対案との比較: 規模基準を同じ7件へ当てる

**候補を1つしか当てないと、「この基準が優れている」のか「この母数ならどんな素朴な基準でも
当たる」のかを区別できない。** issue #176 本文の骨子である規模基準
（「1issueに収まらない規模か → Yes なら別issueへ切り出す」）を同じ7件へ当てた。

| DDR | 主判定（`main` の整合性） | 規模基準 | 当時の結論 | 規模基準の可否 |
|---|---|---|---|---|
| `i0000-02` | No → 切り出す | 規模超過 → 切り出す | 見送り | ○ |
| `i0023-01` | No → 切り出す | 規模超過 → 切り出す | 見送り | ○ |
| `i0088-01` | No → 切り出す | 構造変更で規模超過 → 切り出す | 見送り | ○ |
| `i0053-01` | No → 切り出す | **極小**（同じ適用をもう1本）→ このMRでやる | 見送り | **✕** |
| `i0000-07` | No → やらないと決める | **極小**（1フィールド削除）→ このMRでやる | 現状維持 | **✕** |
| `i0171-01` | No → やらないと決める | 中規模 → 切り出す | 手動実行のみ（起票せず） | **✕** |
| `i0077-02` | Yes → このMRでやる | 規模超過 → 切り出す | issue #77 に含める | **✕** |

**主判定 7/7 に対し、規模基準は 3/7（4件で誤る）。** 差は偶然ではなく、誤り方に規則性がある。

- **極小の修正を「このMRでやる」へ流してしまう**（`i0053-01`・`i0000-07`）。規模だけを見ると、
  スコープ外・価値なしという理由が消える。
- **やらないと決めるべきものを起票してしまう**（`i0171-01`）。規模基準には「やらない」という
  出口が無い。
- **必須の反映を切り出してしまう**（`i0077-02`）。規模が大きいという理由だけで、
  見送ると `main` が成立しないものまで送り出す。

### 見つかった基準の欠落: No のときの出口が「規模」だけでは足りない

**No と判定された6件の理由は3種に分かれ、「規模」はそのうち2件だけだった。**

| 理由の類型 | 件数 | 該当 | 妥当な出口 |
|---|---|---|---|
| **規模**（別issueの規模になる） | 2 | `i0000-02`・`i0023-01` | 別issueへ切り出す |
| **スコープ**（このissueが名指ししていない／期待する動作を代替しない） | 2 | `i0053-01`・`i0088-01` | 別issueへ切り出す |
| **価値**（実害がない／自動化する価値が無い） | 2 | `i0000-07`・`i0171-01` | **やらないと決める**（起票しない） |

issue #176 の本文が骨子として挙げる「切り出さない条件（誤爆防止）」は
**「修正が極小で、別issue化の固定費が本体を上回る場合」**、すなわち**規模の話だけ**である。
この形の基準だと、**「価値」の2件が行き先を失う**（別issue候補として起票すると、着手されない
まま残る）。上の対案比較でも、この2件が実際に誤って流れている。

**したがって、No のときの出口は最低3つ要る**（このMRでやる／やらないと決める／別issueへ
切り出す）。出口(1)「このMRでやる（極小）」はこの母数からは直接裏付けられておらず、
issue #64 節の「分割コストが本体を上回る」からの引き継ぎである（下記「確かめられなかったこと」）。

**この欠落は、issue本文の骨子をそのまま実装していたら見つからなかった。** Q4 を「基準の妥当性
検証」として置いた効果である。
