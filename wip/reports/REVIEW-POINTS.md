# レビュー観点（reports配下）

## 内容の妥当性

- 結論の一つひとつに**実機で確かめた根拠**（実行したコマンド・返ってきたレスポンス・
  ステータスコード）が添えられているか。公式ドキュメントの記述だけを根拠にしていないか。
- 「確かめられなかったこと」が、確かめたことと**区別して**書かれているか。
- 調査の結論が、後続フェーズの設計に**どう効くのか**（「設計への反映」）まで書かれているか。
- 制約が「外部APIの制約」なのか「このリポジトリの実装の欠陥」なのかを取り違えていないか。
  後者なら修正対象であり、制約として受け入れてはいけない。
- **結論の主語が、実際に測った対象と一致しているか。** `deny` を測ったなら結論の主語は `deny`
  である。名前の似た別の仕組み（`hooks[].if` と `permissions`）や、同じ設定の別のキー
  （`deny` と `allow`）へそのまま広げていないか。**「区別して書く」だけでは防げない**
  （本人は区別したつもりで書くため）。issue #47 では、この隙間で同じclassの誤りを繰り返した。
- **測った件数の内訳が、結論を支える件数と一致しているか。** 「4ケース測って発火しなかった」の
  4件のうち、結論を支えるのが2件なら、根拠の重みが倍に膨らむ。内訳を表で出す。
- **測った環境が結論に添えられているか。** 1環境・1バージョンの観測を、全環境の事実として
  書いていないか。**`wip/reports/` はflow-id 5-5で削除されるため、`.claude/docs/` や
  `.claude/rules/` へ転記するときに限定が落ちやすい。**
- **書いた数値と事実を、書く直前に実測したか。** 行番号・件数・「据え置いた」「変更していない」の
  ような主張は、いずれも実行すれば確かめられる。**判断理由を事実の主張へ言い換えない**
  （「詳細を書く場所ではないから据え置く」は書けるが、「条件を含まないから据え置く」は別途
  確かめないと書けない）。受け取ったレビュー指摘に含まれる行番号・件数も、採用する前に数え直す。
  自分が根拠として貼った実測出力の中に、自分の結論の反例が混ざっていることもある
  （issue #155 で3件とも実際に起きた）。

## HTML版

- **自己完結**しているか（**外部依存・ローカル参照が1つも無い**。issue #54 以降、土台にする
  `.claude/skills/issue-mr-flow/assets/reports.template.html` が外部依存を持たない自己完結CSSに
  なったため、**CDNも例外ではなくなった**）。検査は「実際に外部を読みに行く記述」に限り、
  次の2つがいずれも **0件**であること。

  ```bash
  grep -nE "(src|href)=['\"]?(https?:)?//" <ファイル>          # 属性からの外部読み込み
  grep -nE "(url\(|@import[[:space:]]+)['\"]?(https?:)?//" <ファイル>  # CSSからの外部読み込み
  ```

  **`https://` を含む行を数える検査にしないこと**（`<code>` の中でURLを引用しただけの
  レポート——調査結果はURLを引用しがちである——と、`http://www.w3.org/2000/svg`
  （`createElementNS` の名前空間。外部を読みに行かない）を必ず誤検知する）。
  逆に、`src="https://` だけを見る形へ狭めるのも不足で、**シングルクォート
  （`src='https://…'`）とプロトコル相対（`src="//cdn…"`）、CSSの `@import` が素通りする**
  （issue #54 の敵対的レビューで判明）。上の形はこの3つを拾う。
  - **拾えないものが2つある。** (1) 相対パスのローカル参照（`src="./x.png"`）。
    `grep -oE '(src|href)="[^"]*"' <ファイル>` で値を一覧して目視で確かめる。
    (2) `<code>` 内でHTMLの属性ごとURLを引用した箇所（`&lt;script src="https://…"&gt;`）は、
    外部依存ではないのにヒットする。**引用の書き方で避けられる**ので0件に保つこと——
    URLのスラッシュを `&#47;&#47;` と書けば表示は変わらず検査に当たらない
    （issue #54 で実際に1件ヒットし、この方法で0件へ戻した）。**「ヒットするが問題ない」を
    許すと、次の人が本物の外部依存を見落とす。**
  URLを本文で引用する場合は `<code>` の中でエスケープして書き、`src`/`href` にしない。
  **canvas形式（`.claude/skills/canvas-report/SKILL.md`）でmermaidを使う場合は、CDNの
  `<script src>` が1本入るため、この検査の対象外とする**（採否はレポートごとに判断する）。
- **テンプレートの埋め忘れが無いか。** `grep -c '<!-- ここに書く' <ファイル>` が 0 であること
  （`<!--` まで含めて数える。**地の文で「ここに書く」という語に触れる成果物**——テンプレート自身を
  説明する計画・レポート——を誤検知しないため）。使わなかった `[任意]` の `section` は、
  プレースホルダを残さず**節ごと削除**する。
- markdown版とHTML版の**内容が同期**しているか（片方だけ更新されていないか）。
- **同期を「追記」だけで済ませていないか。既存記述の更新まで含める。** md側で書き換えた記述が
  HTML側に古いまま残ると、**視覚版だけを見た読み手が、md側では既に否定された結論を読む**。
  実例（issue #127）: md側で3箇所（サマリ・検証表・未完了節）を更新したのにHTMLへは末尾へ節を
  追記しただけで（削除0行）、HTMLだけを見ると「受け入れ条件1は未達」と読める状態のまま公開して
  いた。
  - 判定の目安: **md側の差分が「追加のみ」でないなら、HTML側も「追加のみ」では同期していない
    可能性が高い。** HTML側の差分に削除・変更行が1行も無いときは、md側の差分を見直す。
- 要素間の関連・依存関係が主題なら、canvas形式（`.claude/skills/canvas-report/SKILL.md`）の
  利用を検討したか。
