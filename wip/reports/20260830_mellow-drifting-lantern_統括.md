## なぜそうしたか（3論点の決着）

| 論点 | 結論 | 決め手 |
|---|---|---|
| **論点1**: `.gemini/` を `.claude/` から自立させるか | **取り下げ**（`.claude/` への依存を明示する） | `AGENTS.md` が `layer: seed` でどのCLI向け配布先にも常に配られ、`@./.claude/rules/agent-common.md` を import しているため、`.gemini/` 側だけを書き換えても依存はルート側に残る（ユーザー判断） |
| **論点2**: 読まれない4ディレクトリ（`rules/` `hooks/` `scripts/` `docs/`）を外すか | **現状維持**（4つとも残す） | (1) 配布物は1バイトも減らない (2) 部分的に外すと壊れたリンクを抱えた中間状態になる (3) 「読まれない」の根拠は未観測の推論であり、同じ根拠が除外しない`rules/`にも当たるため対象を選べない |
| **論点3**: `.agents/skills/` へのエイリアス化 | **不成立** | Claude Code の公式ドキュメントに `.agents` への言及が0件 |

判断は静的資産（生成物・設定ファイル）の解析と公式ドキュメントの読解に基づく。**Gemini CLI
実機での読み込み経路の確認は行っていない**（後述「残課題」）。
