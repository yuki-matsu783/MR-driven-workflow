6. 問い5: 除外規則で過剰除去が1件発生した ✕問題

確定済みの除外規則（正規化後の完全一致＋スラッシュコマンド正規表現）を母集団7件へ当てた。

残る            : 6

落としたのは辞書語 ok で、1件。これは flow-id 1-5 の合意（全体作業計画の4論点すべてへの承認）そのもので、このタスクで最も重要な意思決定の1つである。

結論 全体作業計画で確定済みの方針「過剰除去が1件でもあれば、その語を辞書から外す」に従い、ok と OK を辞書から外す。同じ理屈が辞書の他の語にも及ぶ — このワークフローでは、レビュー合意・着手承認・方針同意が はい・了解・お願いします のような短い肯定語で表明される。辞書そのものが、このリポジトリの運用と噛み合っていない。 落としたい「意味の無い相槌」と、落としてはいけない「短い承認」を文字列だけで区別する手段が無いというのが実データの示すところである。除去漏れは0件。
確かめられなかったこと（詳細） スラッシュコマンド正規表現は1件も当たらなかったが、これは /compact が <command-name> 形式で記録され origin を持たないため母集団に到達する前に落ちている（章12）ことによる。1事例のみを根拠に「不要」と断じない。 安全網として残すか外すかはフェーズ3の判断とする。

8. 問い8: ロケール非依存に文字単位で切れるのは jq だけ ◎良

日本語10文字の先頭5文字を切り出し、LANG/LC_ALL を空にした環境と LC_ALL=C.UTF-8 の両方で比較した（期待値は5文字ぶんが正しく出ること）。

手段LANG 空LC_ALL=C.UTF-8判定
jq の .[0:5]正しい正しい両方で正しい → 採用
awk の substr（mawk）壊れる（バイト単位）壊れる（バイト単位）不可
${s:0:5}壊れる（バイト単位）正しいロケール依存 → 不可
perl -CSDA正しい正しい可（外部プロセスが増える）
結論 ${var:0:N} がロケール依存で落ちることを再現した（.claude/rules/shell-script-style.md の記載どおり）。awk は同ルールのとおり mawk ではバイト単位で、gawk では文字単位になる — 環境によって結果が変わる手段は採らない。perl は当初 -CSD で試して壊れたが、これは呼び方の誤り（@ARGV のデコードには -CA が要る）で、perl 自体の欠陥ではない。切り出しは既に jq の中で行うため、.[0:N] を使えば外部プロセスは増えない。
