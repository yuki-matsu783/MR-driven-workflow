問い5: 除外規則で過剰除去が1件発生した（修正後の再測まで実施） ✕問題

辞書辞書で除外スラッシュコマンドで除外残る
修正前（ok/OK を含む）106
修正後（ok/OK を外した）007

落としたのは辞書語 ok で、1件。これは flow-id 1-5 の合意そのもので、このタスクで最も重要な意思決定の1つである。

結論 方針「過剰除去が1件でもあれば、その語を辞書から外す」に従い ok/OK を外した。停止条件が求める「外した後の測り直し」も実施し、除外0件・残7件を確認した（問い6 の 1,239B はこの修正後の母集団を通した値）。同じ理屈が辞書の他の語にも及ぶ — レビュー合意・着手承認・方針同意が はい・了解・お願いします のような短い肯定語で表明されるため、落としたい「意味の無い相槌」と落としてはいけない「短い承認」を文字列だけで区別する手段が無い。除去漏れは0件。
flow-id 2-8 の判断: 辞書は継続し、育てる 上の論点を人間の判断へ上げ、「辞書はオッケー」との回答を得た（辞書方式を継続し、辞書を空にする案・別方式へ置き換える案は採らない）。 さらに「辞書は毎回のユーザの入力を見ながら育てて行きたい」との方針が示された — 辞書を設計時に完成させる固定リストとして扱わず、実運用の入力を見ながら1語単位で足し引きしていく。
項目確定内容

実データはこの方針を支持している。辞書12語のうち実際に何かを落としたのは ok の1語だけで、残る11語はこの断面で一度も働かなかった。落とすべきノイズは origin.kind の1条件で構造的に消えており、辞書が担う残余はごく小さい。机上の網羅が実運用に当たる保証は無い。

flow-id 3-1 が決めること（本調査からの申し送り）:

#決めることなぜ必要か
1初期辞書の中身「育てる」の出発点。網羅から始めるか、観測実績から始めるか
2辞書の置き場所（定数か、編集しやすい外部ファイルか）育てるには人間が1語単位で足し引きできる必要がある
