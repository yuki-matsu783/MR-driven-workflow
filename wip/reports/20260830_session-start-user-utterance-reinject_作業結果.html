実施した内容と結果

1. UserUtteranceSelect.jqの出力スキーマ変更 △注意

計画の「抽出パイプライン」節は出力を {"selected": [...], "excludedCounts": {語: 件数}, "populationCount": N} とし、セクションテキストのレンダリングはbash側が担う設計だった。実装では、バイト予算内での テール間引き・見出し組み立て・除外内訳行の組み立てをすべてjq側へ集約し、出力を {"sectionText": "整形済み文字列", "excludedEvents": [{"uuid","word"}], "populationCount": N} へ変更した。

理由は2つ。(1) バイト予算超過時のテール間引き（`clip`後の文字列を都度連結してバイト数を 測り、収まるまで1件ずつ削る）は、jqの`reduce`で1回のプロセス起動内に収めるほうが確実・高速 （外部プロセス起動のコスト規約に沿う）。(2) 累積カウントの重複計上対策（H-3）にuuidが 必要なため、集計済みの`excludedCounts`ではなく、除外イベントを`{uuid, word}`のペア配列 （`excludedEvents`）として返す設計にした。

出力例:
{"sectionText":"## 直近のユーザー発言（SessionStart hook）\n- 「…」",
 "excludedEvents":[{"uuid":"c1a2...","word":"はい"}],
 "populationCount":7}
結論 計画からの設計変更だが、H-3の要件（uuid単位の重複計上対策）を満たすために必要な変更であり、 26件超の単体テストで機能要件（母集団カウント・除外規則・採り方・切り出し・バイト予算・ 全件除外時の表示）を全て確認済み。計画mdへの反映は次のコミットで行う。
確かめられなかったこと（詳細） `sectionText`はbash側で複数行になりうる値としてコマンド置換で受けるため、Windows native jqの CR付与対策（`tr -d '\r'`）をこの1箇所へ適用した。この対策自体はコードとして実装済みだが、 CRが実際に付与されるWindows/git bash環境での動作確認はできていない。

2. isSidechain false-as-falsy回帰の発見・修正 ◎良

jqの`//`演算子は`false`もfalsyとして扱うため、`($row.isSidechain // null) != false`と書くと `isSidechain: false`の行まで`null`へ書き換えられ、母集団が常に0件になるバグを実装中に発見した。 `elif $row.isSidechain != false then empty`（`// null`を使わず直接比較）へ修正した。

結論 修正済み。単体テスト「isSidechain=falseの行のみ母集団に入る（false-as-falsy回帰防止）」で 固定し、再発を検知できるようにした。

3. append_size_warningの第3引数追加 ◎良

計画どおり、末尾へ`excluded_bytes`（省略可・既定0）を追加した。

結論 既存の`test_session_start.sh`6箇所の呼び出し（2引数4箇所・1引数2箇所）はすべて無変更で 通過することを確認済み（`excluded_bytes`省略時は`effective_bytes = bytes`となり従来と 同じ判定になるため）。
