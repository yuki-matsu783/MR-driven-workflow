**同じ理屈が辞書の他の語にも及ぶ。** このワークフローでは、レビュー合意・着手承認・方針同意が

**既存の注入量をこの環境で測り直した**（全体作業計画の 1.2KB は issue #57 時点の古い値）。

| 内訳 | バイト数 |

### 問い8 — ロケール非依存に文字単位で切れるのは `jq` だけ

日本語10文字（`あいうえお漢字テスト`）の先頭5文字を切り出し、`LANG`/`LC_ALL` を**空にした環境**と
`LC_ALL=C.UTF-8` の両方で比較した。期待値は `あいうえお`。

| 手段 | `LANG` 空 | `LC_ALL=C.UTF-8` | 判定 |
|---|---|---|---|
| **`jq` の `.[0:5]`** | **正しい** | **正しい** | **両方で正しい → 採用** |
| `awk` の `substr`（mawk 1.3.4） | 壊れる（バイト単位） | 壊れる（バイト単位） | 不可 |
| `${s:0:5}` | 壊れる（バイト単位） | 正しい | **ロケール依存 → 不可** |
| `perl -CSDA` | 正しい | 正しい | 可（ただし外部プロセスが増える） |

- **`${var:0:N}` がロケール依存で落ちることを再現した**（`.claude/rules/shell-script-style.md`
  「日本語を含む文字列の先頭を `${var:0:N}` で切り出して比較しない」の実測どおり）。
- `awk` は同ルールの記述どおり **mawk では `length()`・`substr()` がバイト単位**。
  gawk では文字単位になるため、**環境によって結果が変わる手段は採らない**。
- `perl` は当初 `-CSD` で試して壊れたが、これは**呼び方の誤り**（`@ARGV` のデコードには `-CA` が
  要る）。`-CSDA` なら両条件で正しい。**perl 自体の欠陥ではない**ため、そう記録する。
- **切り出しは既に jq の中で行うため、`jq` の `.[0:N]` を使えば外部プロセスは増えない。**

### 問い11 — 走査コスト

空関数（`jq -nc '1'`）をベースラインに取り、差で見た（20回ずつ、同一セッション内で連続測定）。

| 測定対象 | 20回の所要 | 1回あたり | ベースラインとの差 |
|---|---|---|---|
| ベースライン `jq -nc '1'` | 54ms | 2.7ms | — |
| 本番フィルタ（4.26MB 全走査） | 1,068ms | 53.4ms | **+50.7ms** |

**サイズ別の走査レート**（線形であることの確認）:

| transcript サイズ | 差分/回 | レート |
|---|---|---|
| 1,064KB | 14ms | 76KB/ms |
| 2,129KB | 26ms | 81KB/ms |
| 4,258KB | 56ms | 76KB/ms |

**約76〜81KB/ms で線形。**

| 環境 | 内訳 | 合計 | しきい値200ms |
|---|---|---|---|
| **Linux（実測）** | 走査 50.7ms | **50.7ms** | **合格**（1/4） |
| **git bash（見積もり）** | jq 起動 138ms ＋ 走査 56ms | **約194ms** | **肉薄（97%）** |

**「Linux で50ms、余裕十分」で片付けてはいけない。** git bash では **jq の起動だけで138ms**を
消費し、合計で200msに肉薄する。しかもこの4.26MBは約9時間のセッションの値であり、
**より長いセッションでは走査時間が伸びて超える**（レート76KB/ms なら、**約+4.6MB で200msを超える**）。

**判定: Linux 上では合格。ただし git bash 実機の見積もりは約194msで、合格は暫定である。**
フェーズ3で実機再測を行い、超過するなら実装方式（例: 全走査をやめ、末尾からの逆走査と
先頭固定件数の2パスにする）を見直す。

### 問い7 — git bash 実機でのパス表記は**未確認**

本調査はリモート実行環境（Linux）で行ったため、**Windows / git bash で `transcript_path` が
どの表記（Windows形式 `C:\...` / MSYS形式 `/c/...`）で渡るかは確認できていない。**
**「確認できた」ことにしない。**

**ただし、回避手段が同値であることは確認した。** `jq` へパス名を引数で渡す形と、
標準入力へ繋ぐ形の出力が**バイト単位で一致**する（md5 が一致）。

```bash
jq -R -n -r -f filter.jq "$path"   # パス名を渡す（MSYS のパス変換・native jq の制約を受ける）
jq -R -n -r -f filter.jq < "$path" # 標準入力へ繋ぐ（パス名を渡さないので影響を受けない）
```

`.claude/rules/shell-script-style.md` は「`jq ... < <(...)` のように標準入力へ繋ぐのは、
パス名を渡していないので問題なく動く」としている。**フェーズ3では標準入力へ繋ぐ形を採る**
ことで、パス表記の不確実性を実装から切り離せる（リダイレクトは fork を伴わないので
問い11 のコストも増えない）。
