8. 調査レポートの訂正6箇所と、grep 検査の限界 △注意

「例外は設けない／例外を認めない」を md 3箇所・html 3箇所の計6箇所訂正し、現在の結論（禁じるのは「参照」だけで「アンカー」は対象外）へ揃えた。1箇所だけ直すと、同じレポート内で古い結論と新しい結論が併存する、より悪い状態になる。

$ grep -c -- '例外は設けない\|例外を認めない'    # 0
$ grep -c -- '例外は設けない\|例外を認めない'   # 0
検査が「主張」と「引用」を区別できない 節3の根拠へ「当初この節は『例外を認めない』と書いていたが」と歴史的経緯として引用したところ、完了条件11の grep が1件を返した。引用は主張ではないので実害は無いが、機械的な検査はそれを見分けられない。 「当初この節は例外なしと書いていたが」と言い換えて検査を成立させた——検査を通すために意味を曲げてはいない（言い換え後も同じことを述べている）。

13. md/html の4点検証 ◎良

検証スクリプト自身が壊れていた 見出しの抽出が grep -oE '<h[123]>.*</h[123]>' と属性なしのタグ決め打ちだったため、issue #186 のテンプレートが h3 へ振る id="fN" に一致せず、章見出しが1つも比較対象に入っていなかった。エラーは出ず「見出し一致」と報告される。
  • 発覚したのは、本レポートのHTMLを新テンプレートから作って初めて h3 に id が付いたためである。旧テンプレート由来のペアでは h3 に属性が無く、症状が出なかった。
  • <h[123][^>]*> へ直して再実行し、全6ペアで通過することを確認した。
