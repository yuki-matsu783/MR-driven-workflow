## 実施した内容と結果

### 1. テンプレート（slides.template.html）

`.claude/skills/html-slides/assets/slides.template.html` を新規作成。plans/reportsテンプレートの
共通規約（冒頭使い方コメント・`:root` CSS変数＋`prefers-color-scheme: dark`・日本語フォント
スタック・`<!-- ここに書く` プレースホルダ）を踏襲し、8種の見本スライド・進行表示（`.progress`）・
操作ヒント・素朴なJS（keydown＋左右30%クリック領域。0枚・`.progress` 欠落でも例外で止まらない
ガード付き）・`@media print`（`:root` をライトへ上書きし、ダークモード環境でも印刷は常にライト）を
持つ。図解はCSSのみのフロー図（node＋arrow）。話者ノートは `<aside class="notes">`（非表示）。
内容あふれ対策として `.slide` は `justify-content: safe center`（上端を守る）。

検証（計画の1・2・2b）:

```
EXT_REF_NONE / EXT_CSS_NONE            # 外部参照 2種とも0件
data-type一意数 = 8、期待8種との comm -3 = 空
@media print = 2件、keydown|ArrowRight = 2件
```

### 2. ページ送り・進行表示・印刷（動的検証）

サンプル8枚をヘッドレスChromiumで駆動した（計画の検証8。敵対的レビュー2回目の指摘対応後に
再実測した最終値）。

```
initial: 1/8 → ArrowRight: 2/8 → PageDown: 3/8 → PageUp: 2/8 → End: 8/8 → Home: 1/8
右30%クリック: 2/8 → 左30%クリック: 1/8
page.pdf() のページ数 = 8（ライト・ダーク両方。スライド枚数と一致）
scrollHeight > clientHeight のスライド = 0枚（あふれの無言切り落としなし）
ダークモード時の印刷背景 = rgb(255,255,255)（@media print のライト固定が有効）
.progress 削除版: ページ送り動作・ページエラー0 ／ スライド0枚版: ページエラー0（ガード有効）
```

playwrightは調査Q8の制約どおり絶対パスで `require` した。Chromium 1種の観測であることが限界
（上記「確かめられなかったこと」）。

### 3. スキーマ（slide-outline.schema.json）

`.claude/skills/html-slides/references/slide-outline.schema.json` を新規作成。JSON Schema
draft-07。トップレベルは `{meta: {title, subtitle, date, author, issue}, slides[]}`、各スライドは
型ごとの定義（`definitions`）を `oneOf` で束ね、全型が任意の `speakerNotes` を持つ（.pptx の
ノート・ドキュメントプロパティ対応）。

調査Q5の例示フィールドからの変更点（「Q5準拠」と言い切れるのは meta・8種enum・speakerNotes・
HTML固有表現ゼロの骨格であり、型ごとの固有フィールドは次のとおり意図的に変えた）:

| Q5の例示 | 実装 | 理由 |
|---|---|---|
| 表紙の型名 `title`・全型で `title` 必須 | 型名 `cover`。cover のみ `title`/`subtitle` は任意（省略時は `meta` から採る） | 型名とフィールド名 `title` の衝突回避（計画レビューで確定）。表紙の文言は meta と重複させない |
| `bullets.items[]` は入れ子1段まで | 文字列の平坦配列（1〜6個） | 投影で読める粒度に絞る。入れ子が要る内容はスライドを分ける |
| `two-column` は `left`/`right` | `columns[]`（2要素固定） | 転記処理が左右で分岐せず、カラム見出し（`heading`）を持てる |
| `table` は `headers[]`/`rows[][]` | `columns[]`/`rows[][]` | 意味は同じ。名称を .pptx の表現に寄せた |
| `comparison` は `options[]`（名前・利点・欠点・採否） | `sides[]`（`name`/`points[]`/`tone`） | 利点・欠点を別配列にせず、見た目の色分けだけを `tone`（pro/con/neutral）で表す |
| `diagram` は `nodes[]`/`edges[]`＋`caption` | `nodes[]` のみ（左→右のフロー図） | 初版は直列フローに限定。`edges`/`caption` が要る図は将来拡張（テンプレートのCSS図が直列のみのため） |

検証（計画の3・4）:

```
[ -s ] && jq -e . → SCHEMA_OK
構造検査フィルタ: 正常サンプル ok=0 / type不正サンプル ok=1 / 空ファイル ok=1 / 0枚 ok=1
```

構造検査フィルタの型8種は文字列の再掲ではなくスキーマから導出する
（`jq -c '[.properties.slides.items.oneOf[]."$ref" | sub(".*/";"")]'`。敵対的レビューの指摘
「正が複数箇所に増えている」への対応）。0枚（`"slides": []`）はスキーマの `minItems: 1` と
食い違って合格していたため、フィルタへ `(.slides | length) > 0` を加えた。

### 4. SKILL.md

`.claude/skills/html-slides/SKILL.md` を新規作成。手順6段（コピー→構成案→スキーマ検査→
穴埋め→機械検査→任意の動的検証）、成果物の置き場所（`wip/reports/*.slides.html`＋同名
`.slides.json`。flow-id 5-5 で削除される寿命と恒久保存時の指定を明記）、サブエージェント2本との
境界表、動的検証を実行できない環境での「件数を出してスキップ」、人間に確認してもらう3項目を
記載。型8種の名前と見出し構成の正はテンプレート側に置き、SKILL.mdには文字列を再掲しない
（手順3・5の検査はスキーマから型名を導出する）。各検査は結果が必ず出力される形
（`echo "ok=$?"`・`COUNT_OK`・フォールバック文言）に統一し、手順5だけを別シェルで実行しても
変数が未定義にならないよう各ブロックで変数を定義している（いずれも敵対的レビューの指摘対応）。

### 6. サンプル生成と検証スイート

scratchpadに構成案JSON（8種の型を1枚ずつ使う8枚構成）と、typeを不正値にした異常サンプルを
作成し、SKILL.mdの手順どおりコピー→穴埋め→機械検査→動的検証を一連で実行した。

```
プレースホルダ残存 = 0 / data-typeとスキーマの照合 = 差分なし

動的検証: 1/8→2/8→8/8→1/8（キー）・クリック・PDF8ページ・あふれスライド 0枚
```

サンプルはリポジトリへコミットしない（計画どおり。wip/reports/ へ置くと本物の成果物と
紛れるため）。
