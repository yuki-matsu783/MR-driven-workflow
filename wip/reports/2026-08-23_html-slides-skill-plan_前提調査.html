Q5. 構成案JSONスキーマの置き場所・形式・内容 ◎良

置き場所は語彙定義（assets=出力に使うもの／scripts=実行するもの／references=AIが読むもの）から references/ を採用（スキーマは①②とSKILL.mdが「読む」契約定義）。形式はJSON Schema（draft-07互換）。構造検査はjqの必須キー確認で行う（完全な検証器はリポジトリに無い）。jqで機械判定できることは実測で確認済み: 8種のenum判定を含む最小フィルタに4入力を与え、正しいJSON→終了コード0、type未定義値→非0、必須キー欠落→非0、空ファイル→jq -e では検知できないことがあるため [ -s ] の空チェックを先に置いて弾く、という結果を得た。

保持すべき情報（受け入れ条件6のため）: meta（タイトル・日付・作成者・issue番号）、slides[]（type 8種のenumと title を必須、型ごとの固有フィールド）、speakerNotes（任意）。HTML固有の表現（色・座標・CSSクラス）を含めない（HTMLからの逆変換を避けるissue本文の要求）。

結論.claude/skills/html-slides/references/slide-outline.schema.json に置き、SKILL.md・エージェント定義からはパスで参照する（再掲しない）。

Q8. ページ送り・進行表示・印刷の実装方式と検証 ◎良

実装方式: 単一ファイル内の <script>（DOM操作のみ、file:// で動く）。keydown（←→/Space/Home/End）とナビボタンのクリックで .slide を切り替え、「n / N」とプログレスバーで進行表示。印刷は @media print でナビUIを隠して全スライドへ break-after: page を当て、16:9の1スライド1ページに割り付ける（CSSのみで成立させ、JS無効環境でも印刷可能にする）。

検証: 静的grep検査（プレースホルダ・外部参照・@media print・キーハンドラ・8種のsection存在）に加え、3枚スライドのプロトタイプ（keydown/クリックハンドラ＋break-after: page）をヘッドレスChromiumで実駆動して動的検証の成立を確かめた: page.keyboard.press('ArrowRight') で進行表示が 1 / 3 → 2 / 3、クリックで 3 / 3、Home/End で 1 / 3 / 3 / 3、page.pdf() の出力が3ページ（スライド枚数と一致）。当初の調査計画は「ブラウザの無い実行環境」を前提としていたが、実測で覆った（良い方向の想定外）。

動的検証の制約と位置づけPlaywrightのnodeモジュールはグローバル配置（/opt/node22/lib/node_modules/playwright）で、素の require('playwright') は ERR_MODULE_NOT_FOUND で失敗する（実測）。絶対パスrequireで解決でき、chromium.launch() は executablePath 無しで動く（環境変数 PLAYWRIGHT_BROWSERS_PATH による解決。実測）。動的検証はこの実行環境でのみ実行する任意の検証と位置づけ、リポジトリの恒久テスト（.claude/scripts/test/ はbash・passed=N failures=N 規約、.claude は丸ごと配布される）には加えない。検証スクリプトはscratchpadへ置き、SKILL.md の検証手順は環境の存在確認をしてから動的検証を行い、無い環境では静的grep検査のみでスキップした事実を件数付きで出す形にする。
結論受け入れ条件1〜3は静的＋動的の機械検証で担保し、見た目の品質・実プリンタ・他ブラウザのみ人間の実機確認に残す（フェーズ3のレビュー依頼へ明記する）。受け入れ条件4はSKILL.mdの手順どおりにサンプル1本を実生成して確認する。
確かめられなかったこと（詳細）実プリンタでの印刷・Firefox/Safariでの表示とキー操作はこの環境では確認できない。PDF化検証はChromiumの印刷エンジンと同一のため代表性は高いが、ブラウザ差は人間の実機確認に残る。
