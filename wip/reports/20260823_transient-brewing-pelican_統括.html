何を変えたか／なぜそうしたか

ディレクトリ改名・設定・スクリプトの追従

  • git mv plans wip/plans / git mv worklog wip/worklogs / git mv reports wip/reports（先にmkdir -p wip）。
  • .mrworkflow.json / .claude/settings.json（plansDirectory: "./wip/plans"）/ .gemini/settings.json を更新。
  • cleanup-task.shのKEEP_PATHSを.mrworkflow.json由来の動的組み立てへ変更。
  • Provider.shのフォールバック既定値は意図的に変更しなかった（DDR i0165-01。既存配布先との後方互換）。
  • install-to-project.shのディレクトリ生成対象をwip/3構成へ変更。
  • 約100ファイルのドキュメント参照を更新（DDR本文・spec changelogの過去エントリは対象外）。

なぜそうしたか

wip/を採用した理由 「未完了・一時的で正史ではない」という寿命を表す慣用語。flow/（「フロー＝手順」の語と衝突）・tasks/（TODO管理と衝突）・work/（汎用的すぎ導入先と衝突）・scratch/（「使い捨て」の含意が強すぎる）はいずれも却下（DDR i0165-02）。
コード側フォールバック既定値を変更しなかった理由 既存配布先の実際のディレクトリ構成と食い違うと、作業ファイル列挙・片付け対象判定が無言で壊れるため（DDR i0165-01）。
.claude/VERSIONを0.3.0のまま据え置いた理由 AIエージェントによるMAJOR適用は実行環境の権限クラシファイアによりブロックされた。この事実を人間へ報告し「0.3.0で良い」との回答を得て、現状維持が人間の判断として確定した。
